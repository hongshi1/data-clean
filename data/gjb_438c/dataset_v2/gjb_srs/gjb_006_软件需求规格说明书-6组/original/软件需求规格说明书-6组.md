### 1.2 系统概述

“软课程管理平台（校园网版）”是北京航空航天大学软件学院软件工程基础课程的大作业项目，旨在基于校内网络环境，为教师、助教和学生提供完整的在线教学管理与学习平台，并让学生团队实践需求分析与规格编写方法。

- **项目背景与目标**：
  - 随着校内混合教学需求增加，需要一套稳定、安全并与学校统一认证系统集成的课程管理与在线学习方案；
  - 本项目兼具教学与实践价值，学生团队负责从需求调研、分析到文档编写的全过程，实现 SRS 的产出。
- **核心功能**：
  1. **课程与班级管理**：教师/助教可在平台上创建和管理课程、班级，学生注册并加入；布置作业和项目，跟踪提交与完成状态。
  2. **教学资料管理**：支持 PPT、PDF、视频、代码等多格式资源的上传、分类存储、版本控制与在线预览；设置资源访问权限（仅校园网内访问）。
  3. **在线练习**：基于题库的选择题、编程题在线答题；自动批改客观题，助教手动评阅主观题；实时反馈、错题重做与收藏。
  4. **学习记录与报告**：展示学生学习轨迹、练习成绩和班级排名；可导出 PDF/Excel 报告，用于教师评估和学生自我复盘。
  5. **用户与权限管理**：基于角色的注册、登录与权限控制；采用学校 CAS 统一认证；支持用户信息管理与密码修改。
- **技术架构与运行环境**：
  - **前端**：Vue 3 + Vite + Element Plus
  - **后端**：Spring Boot 3.x（Java 17）、Maven 构建
  - **数据库**：MySQL 8.0（InnoDB）
  - **认证**：CAS 或 OAuth2 与校内统一身份认证系统对接
  - **部署环境**：
    - **开发环境**：IntelliJ IDEA、Node.js 18.x、npm 9.x、JDK 17
    - **测试环境**：校内虚拟机（Ubuntu 20.04、Tomcat 10.0、MySQL 8.0）
    - **生产环境**：校园网内物理服务器（CentOS 7），反向代理 Nginx + Spring Boot 容器，HTTPS 加密，支持内网访问与备份策略。
  - **运维支持**：由北航信息化建设中心提供网络与服务器保障，定期备份与安全巡检。
- **干系人**：

## 3 需求

本章描述构成软课程管理平台（校园网版）验收条件的功能和性能需求。每个需求均赋予唯一标识以支持测试和可追溯性。

### 3.1 所需的状态和方式

本系统仅在“正常运行”模式下工作。无需区分其他特殊模式——系统上线后持续提供教学与学习服务；维护模式或紧急应急由运维人员线下切换，并不直接影响CSCI功能需求。

### 3.2 ==需求概述==

#### 3.2.1 目标

- 实时反馈，提升教学效率与学生自主学习体验。
- **主要功能与数据流程**：
  1. 教师发布课程→学生注册并加入→教师上传资料与布置任务→学生查看学习资料并提交→系统自动/手动评阅→成绩与报告生成
  2. 外部接口：CAS 认证服务、校内用户管理系统、邮件/通知服务

#### 3.2.2 运行环境

- **硬件环境**：校园网内物理服务器（CPU Intel Xeon 8 cores、RAM 32 GB、磁盘 2 TB SSD）、负载均衡器及备份存储设备。
- **软件环境**：
  - 操作系统：Windows；
  - Web 服务器：Nginx 1.18；
  - 应用容器：Spring Boot Jar 或 Tomcat 10；
  - 数据库：MySQL 8.0；
  - 中间件：Redis 6.x（缓存、会话管理）。

#### 3.2.3 用户的特点

- **教师**：具备基本计算机操作能力，偏重内容组织与评阅；
- **助教**：参与题库管理与主观题评阅，需频繁使用练习管理模块；
- **学生**：网络原住民，对在线学习平台交互性、即时反馈有较高期望；希望资料检索与练习体验流畅。

#### 3.2.4 关键点

- **统一认证集成**：CAS 单点登录；
- **自动评测沙箱**：编程题在线编译与安全隔离；
- **实时反馈**：客观题自动批改与错题重做；
- **高并发支持**：峰值至少支持 200 并发用户；
- **数据安全与隐私**：HTTPS、数据库加密、权限细粒度控制。

#### 3.2.5 约束条件

- **经费与资源**：仅限校内虚拟机与物理服务器资源；
- **开发期限**：2025年4月开始开发，2025年5月完成测试；
- **技术栈**：前端 Vue3，后端 Spring Boot，数据库 MySQL；
- **法律与政策**：遵守《高等教育法》及学校信息化安全管理条例；不得使用国外敏感云服务。

### 3.3 需求规格

本节详细说明系统各功能模块的对象结构与交互流程，以及全局开发与接口约定。

#### 3.3.1 软件系统总体功能/对象结构

系统采用 MVC 架构，以模块化方式组织：

- **Model（持久层）**：
  - **实体类**：User、Course、ClassGroup、Resource、Exercise、Submission、Report 等；
  - **关系**：
    - User 与 ClassGroup：多对多；
    - Course 与 ClassGroup：一对多；
    - Resource 与 Course：多对一；
    - Exercise 与 Course：多对一；
    - Submission 与 Exercise、User：多对一；
    - Report 与 Submission、User：多对一；
- **View（前端 SPA）**：
  - 基于 Vue 3 的单页面应用，路由分区：
    - **/login**、**/dashboard**：用户认证与首页；
    - **/courses**：课程列表与详情；
    - **/class/****:id**：班级成员与任务情况；
    - **/resources**：教学资料管理；
    - **/exercise**：在线练习与题库；
    - **/report**：学习记录与导出；
    - **/admin**：系统管理后台；
- **Controller（RESTful API 层）**：
  - 按资源划分的接口路由：
    - **/api/users/**：注册、登录、角色管理；
    - **/api/courses/**：课程增删改查；
    - **/api/classes/**：班级管理、成员加入；
    - **/api/resources/**：上传、预览、下载、版本；
    - **/api/exercises/**：练习发布、答题、评测；
    - **/api/reports/**：查询与导出；
    - **/api/admin/**：系统监控、日志查询；
  - **请求/响应格式**：JSON，统一包装 { code, message, data }
  - **异常处理**：全局异常拦截，返回标准错误对象 { code, message, details }
- **总体流程示意**：
  1. 用户发起浏览器请求 → 前端路由匹配组件 → 调用后端 API → 后端 Controller 触发 Service，DAO 操作数据库 → 返回 JSON → 前端渲染。
  2. 资源上传流程：前端 FormData 上传至 `/api/resources/upload` → 后端接收并存储至 OSS → 记录元数据 → 返回资源信息。
  3. 编程题评测流程：前端提交代码至 `/api/exercises/{id}/submit` → 后端发送至评测沙箱 → 收集结果 → 存储并返回报告。

#### 3.3.2 软件子系统功能/对象结构

各子系统内部进一步细化：

1. **用户管理子系统**：
   - **对象**：User、Role、Permission；
   - **关键流程**：
     - 注册/登录 → 调用 CAS → 获取票据 → 生成本地 Session/Token；
     - 角色授权 → Role-Permission 关联表管理；
2. **课程管理子系统**：
   - **对象**：Course、ClassGroup、Enrollment；
   - **关键流程**：
     - 教师创建 Course → DAO 保存；
     - 创建 ClassGroup → 自动生成代码 → 对应 Course；
     - 学生通过邀请码加入 → 写入 Enrollment 关联表；
3. **资料管理子系统**：
   - **对象**：Resource、Version；
   - **关键流程**：
     - 上传/版本更新 → 写入 OSS 和数据库；
     - 在线预览 → 调用第三方渲染服务；
4. **练习管理子系统**：
   - **对象**：Exercise、Question、Submission、Evaluation；
   - **关键流程**：
     - 教师发布 Exercise → 关联 Question 列表；
     - 学生作答 → Submission 写入；
     - 客观题自动评测 → 立即返回；编程题异步评测 → WebSocket 推送结果；
5. **报告生成子系统**：
   - **对象**：ReportTemplate、ReportData；
   - **关键流程**：
     - 查询数据 → 组装 ReportData → 调用 PDF/Excel 渲染组件 → 存储并生成下载链接；
6. **系统管理子系统**：
   - **对象**：LogEntry、MonitorMetric；
   - **关键流程**：
     - 定时采集监控指标 → 记录 MonitorMetric；
     - 管理员查询日志 → 分页返回 LogEntry；

### 3.4 CSCI 能力需求

本节将关键功能划分为若干“能力”，并针对每个能力制定细化需求，包括输入、处理、输出、性能与异常处理等。编号前缀采用 FR（功能需求）或 NFR（非功能需求），支持可追溯性。

#### 3.4.1 课程与班级管理能力

能力描述：提供课程与班级的创建、维护、成员管理以及状态跟踪。

- **FR-1: 创建课程**
  - **输入**：课程名称（字符串，1–64 字符）、课程代码（字符串，唯一）、教学大纲（文档）
  - **处理**：校验名称唯一性，存储课程基本信息，生成课程 ID
  - **输出**：课程 ID（UUID 格式）、确认消息
  - **性能**：响应时间 ≤ 2s (95% 请求)
  - **错误处理**：若名称或代码重复，返回错误码 400 与友好提示；若数据库写入失败，返回 500
- **FR-2: 管理课程信息**
  - **输入**：课程 ID、更新字段（可选：名称、简介、大纲 URL）
  - **处理**：权限校验（教师/助教）、校验数据格式、更新记录
  - **输出**：更新后课程详情对象
  - **异常情况**：无权限 403；课程不存在 404
- **FR-3: 创建班级**
  - **输入**：课程 ID、班级名称、班级代码（6 位字母数字）
  - **处理**：校验课程存在、生成班级记录、绑定课程
  - **输出**：班级 ID、邀请码
  - **性能**：响应时间 ≤ 2s
- **FR-4: 学生批量导入**
  - **输入**：班级 ID、CSV 文件（字段：学号、姓名、邮箱）
  - **处理**：解析文件、验证字段格式、事务批量写入（最大 500 条）
  - **输出**：导入结果报告（成功/失败条数、错误详情）
  - **性能**：500 条记录完成导入 ≤ 10s
  - **错误处理**：文件格式错误返回 400；单记录校验失败列出行号与原因
- **FR-5: 学生加入班级**
  - **输入**：班级邀请码、学生身份令牌
  - **处理**：校验邀请码有效性、校验学生身份、添加成员
  - **输出**：学生-班级关系记录、成功提示
  - **异常情况**：邀请码无效或过期返回 404；已加入返回 409

#### 3.4.2 教学资料管理能力

能力描述：支持多格式教学资源的上传、预览、下载、分类和版本控制。

- **FR-6: 资源上传**
  - **输入**：文件（PPT/PDF/MP4/ZIP，≤ 500MB）、所属课程/章节、上传人 ID
  - **处理**：校验文件类型与大小、病毒扫描、存储至对象存储、生成元数据
  - **输出**：资源 ID、访问 URL
  - **性能**：单文件上传完成 ≤ 5s
  - **异常**：文件超限或不支持类型返回 415；存储失败 500
- **FR-7: 在线预览与下载**
  - **输入**：资源 ID、用户角色令牌
  - **处理**：权限检查、调用预览服务或下载接口
  - **输出**：渲染后的文档视图或下载流
  - **性能**：文档加载 ≤ 3s；视频缓冲首帧 ≤ 2s
  - **异常**：无权限返回 403；资源不存在返回 404
- **FR-8: 版本管理**
  - **输入**：资源 ID、更新文件
  - **处理**：创建新版本记录、保留历史版本（最多 10 个）、更新元数据
  - **输出**：版本号、资源历史列表
  - **异常**：版本超限返回 409

#### 3.4.3 在线练习能力

能力描述：管理题库、发布练习、在线答题、自动与手动评阅、反馈与错题重做。

- **FR-9: 题库管理**
  - **输入**：题目数据（类型、题干、选项/代码模板、答案）、题目分类
  - **处理**：存储题目信息、关联分类、生成题目 ID
  - **输出**：题目 ID 列表
  - **性能**：单题创建 ≤ 1s
- **FR-10: 发布练习**
  - **输入**：练习名称、题目 ID 列表、开放/截止时间、多次提交规则
  - **处理**：校验时间逻辑、权限校验、写入练习记录
  - **输出**：练习 ID、练习详情
- **FR-11: 客观题自动批改**
  - **输入**：练习 ID、学生作答 JSON 包含题目 ID 与答案
  - **处理**：对比答案、计算得分、写入成绩表
  - **输出**：得分明细、正确率统计
  - **性能**：批改 50 道题 ≤ 2s
- **FR-12: 编程题评测**
  - **输入**：代码文件、测试用例集
  - **处理**：沙箱隔离执行、编译与运行、资源限额（CPU 1s，内存 256MB）、结果收集
  - **输出**：评测报告（编译日志、运行结果、内存/CPU 使用情况）
  - **性能**：单提交评测 ≤ 5s
  - **异常**：超时中断并返回超时状态；内存超限返回错误码
- **FR-13: 反馈与错题重做**
  - **输入**：学生 ID、题目 ID
  - **处理**：查找第一次提交记录、提供解析与答案
  - **输出**：错题列表与解析视图

#### 3.4.4 学习记录与报告能力

能力描述：记录并展示学生学习与练习数据，支持可视化查询与导出。

- **FR-14: 学习轨迹查询**
  - **输入**：学生 ID、查询时间范围
  - **处理**：聚合课程完成比例、章节进度、作业提交状态
  - **输出**：轨迹报告（JSON）
  - **性能**：单次查询 ≤ 3s
- **FR-15: 报告导出**
  - **输入**：学生/班级 ID、格式（PDF/Excel）
  - **处理**：渲染文档、写入文件存储
  - **输出**：下载链接
  - **性能**：50 条记录导出 ≤ 10s

#### 3.4.5 用户与权限管理能力

能力描述：基于角色的用户认证、授权与个人信息维护。

- **FR-16: CAS 单点登录**
  - **输入**：CAS 登录请求
  - **处理**：重定向至 CAS，票据校验，获取用户信息
  - **输出**：平台会话令牌
  - **性能**：登录完成 ≤ 1s
- **FR-17: 角色权限校验**
  - **输入**：API 请求、用户令牌、目标资源
  - **处理**：解析令牌、判断角色与资源访问控制列表
  - **输出**：允许访问或拒绝（403）
  - **性能**：校验过程 ≤ 50ms
- **NFR-5: 系统可用性**
  - **指标**：全年平均可用性 ≥ 99.5%
  - **恢复**：单次故障恢复时间 ≤ 30min

   - 单次批量导入上限：1000条（支持CSV/XLSX格式）  

2. 课程与班级数据（`t_course`、`t_class`表）  
   - 课程元数据：`name`（课程名称）、`syllabus`（大纲，TEXT类型）、`assMethod`（考核方式）、`score`（学分）、`time`（学时）  
   - 班级信息：`name`（班级名称）、`course_id`（关联课程ID）  
   - 约束：`course_id`外键关联`t_course`表  

3. 教学资源（`t_resource`表）  
   - 文件类型：支持PPTX、PDF、MP4、ZIP、TXT、代码文件（如.py/.java）  
   - 存储方式：`data`字段以BLOB存储文件内容，`type`字段记录文件后缀（无后缀默认`txt`）  
   - 版本管理：`res_code`唯一标识资源项，历史版本通过`date`字段区分  
   - 单文件大小限制：≤500MB  

4. 练习与题目数据（`t_exen`、`t_prob`表）  
   - 练习任务：`name`（任务名称）、`begin_time`（开始时间）、`end_time`（截止时间）、`is_public`（是否公开）、`is_multi`（允许多次提交）  
   - 题目数据：`type`（1-选择题，2-判断题，3-解答题，4-编程题）、`description`（题目描述）、`content`（选项/内容）、`answer`（答案）、`analysis`（解析）  
   - 约束：`prob_id`为-1时表示任务总分表  

#### 输出数据  

1. 用户操作结果  
   - 注册/登录状态反馈（JSON格式，含`status`和`message`）  
   - 文件上传结果（成功返回`res_code`，失败返回错误码）  

2. 练习批改结果  
   - 客观题自动评分（JSON格式，含`score`、`correct_answer`、`analysis`）  
   - 主观题教师批改结果（含`score`、`comment`、`is_check`状态）  

3. 统计报表  
   - 班级练习完成率报表（CSV/PDF，字段：`class_id`、`student_id`、`completion_rate`）  
   - 学生个人错题报告（HTML/PDF，含`prob_id`、`submit`、`correct_answer`、`analysis`）  

#### 数据管理能力  

- 存储容量  
  - 用户表支持100万条记录（`t_user`）  
  - 资源表支持1TB存储（`t_resource`）  
  - 练习记录表支持500万条记录（`t_stu_prob_exer`）  
- 并发处理  
  - 支持500用户同时提交练习答案（峰值事务处理≥200 TPS）  
  - 数据库事务隔离级别：`READ_COMMITTED`，避免脏读  
- 数据一致性  
  - 使用乐观锁（`@Version`注解）处理并发更新冲突  
  - 外键约束（如`t_class.course_id`关联`t_course.course_id`）  
- 备份与恢复  
  - 每日凌晨执行全量备份（保留7天）  
  - 支持按`res_code`或`class_id`快速恢复特定数据  

### 3.16 操作

#### 常规操作  

1. **用户登录与角色切换 **
   - 根据`t_user.identity`字段动态加载权限（如教师可管理课程，学生仅查看）  
   - 登录失败3次触发账户锁定（需管理员通过`t_user`表解锁）  

2. **课程与班级管理  **
   - 教师创建课程时自动生成`t_course`记录，并关联`t_user_course_class`（`identity=0`）  
   - 学生通过班级邀请码（`t_class.class_id`）加入班级，写入`t_user_course_class`（`identity=1`）  

3. **资源上传与版本控制  **
   - 教师上传资源时：  
     - 公共资源：`t_resource.process_id=-1`  
     - 关联进度资源：`t_resource.process_id`对应`t_process.process_id`  
   - 版本更新时保留历史记录（`res_code`不变，`date`字段更新）  

#### 特殊操作  

1. **紧急数据修复  **
   - 管理员可直接操作数据库：  
     - 重置密码：`UPDATE t_user SET password=‘加密值’ WHERE username=‘学工号’`  
     - 删除违规资源：`DELETE FROM t_resource WHERE res_code=xxx`  

2. **批量操作  **
   - 批量导入学生名单：通过CSV文件写入`t_user`和`t_user_course_class`表  
   - 批量导出班级成绩：生成`t_stu_prob_exer`中`prob_id=-1`的总分记录  

#### 初始化与恢复操作  

1. **系统首次部署  **
   - 执行SQL脚本初始化表结构（含外键和索引）  
   - 创建默认管理员账号（`identity=0`，手动插入`t_user`）  

2. **数据恢复  **
   - 从备份文件中恢复特定表（如`t_resource`按`res_code`恢复）  
   - 事务回滚：通过`@Transactional`注解保证操作原子性  

### 3.17 故障处理

- **数据库连接失败**  
  - 前端显示错误码`DB_001`，提示“数据库服务不可用，请稍后重试”  
  - 后端自动重试机制：最大重试次数3次，间隔5秒  
- **并发冲突（乐观锁异常）**  
  - 捕获`ObjectOptimisticLockingFailureException`，返回错误码`LOCK_001`  
  - 提示用户“数据已被修改，请刷新后重试”  

- **文件上传中断**  
  - 支持断点续传（基于`res_code`和`date`标识上传进度）  
  - 网络中断后，用户可重新选择文件继续上传  

- **服务高可用**  
  - 数据库主从架构：主库故障时自动切换至从库（基于`t_user_course_class`读写分离）  
  - 前端静态资源CDN缓存，确保资源访问可用性  

### 3.18 算法说明

**核心算法与计算逻辑描述：**  

1. **客观题自动批改算法**  

   - **输入**：学生答案（JSON，`t_stu_prob_exer.submit`）、标准答案（`t_prob.answer`）  
   - **处理**：  
     - 选择题/判断题：字符串精确匹配（区分大小写）  
     - 编程题：通过沙箱执行代码，比对输出与测试用例  
   - **输出**：得分（`score=正确题数/总题数×总分`），写入`t_stu_prob_exer.score`  

2. **错题推荐算法**  

   - **输入**：学生历史错题（`t_wrong`）、题目标签（`t_tag`）  
   - **处理**：基于协同过滤算法，推荐相同`tag_id`的高频错题  
   - **输出**：推荐题目列表（按错误率排序）  

3. **班级成绩排名计算**  

   #### **排名公式**  

   班级成绩排名基于学生在任务中的总分（`t_stu_prob_exer.score`，其中 `prob_id = -1` 表示任务总分记录），采用 **标准分排名法**，公式如下：  

   $$
   \text{排名} = \text{RANK() OVER (ORDER BY } \text{total\_score DESC)}
   $$

   其中： 

   - **total_score**：学生在某班级所有任务中的总分（`SUM(score) WHERE class_id = ?`）  

   - **DESC**：降序排列，总分越高排名越靠前  

   - **同分处理**：若总分相同，则按 `student_id` 字典序升序排列（通过 `RANK()` 函数自动处理并列排名，如第1、2、2、4名）
