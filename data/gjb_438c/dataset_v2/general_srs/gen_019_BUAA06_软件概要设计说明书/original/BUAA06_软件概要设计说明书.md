本文档旨在明确软课程管理平台系统的总体设计框架，阐述系统的基本处理流程、模块划分、功能分配及数据结构设计，为后续详细设计与开发提供技术依据。预期读者包括项目开发团队、测试人员、系统架构师及项目管理人员，同时可作为后续运维和功能扩展的参考文档。

### 1.2 背景  

**a. 待开发软件系统名称**  
软课程管理平台（Soft Course Management Platform，简称 SCMP）。  

**b. 项目相关方**  

- **任务提出者**：软件工程基础课程组。  
- **开发者**：由5名成员组成的学生开发团队（承包方）。  
- **用户**：高校教师、助教及学生。

	- **硬件环境**：部署于华为云服务器或高校内部服务器，支持 Windows/Linux 操作系统。

- **RESTful API**：基于 REST 架构风格的网络接口，用于前后端数据交互。

- **t_user/t_course等**：数据库表名，分别存储用户信息和课程信息（参见数据库设计文档）。  
- **敏捷开发**：以迭代增量方式推进开发，结合 Scrum 方法进行任务管理与协作。

## 2 系统需求概述

### 2.1需求规定

**输入输出项目**

- **输入**：
	- 课程信息（名称、代码、大纲、考核方式等）、学生/教师信息（学工号、姓名、角色）、班级代码、本地文件（学生名单、教学资源等）、题目与任务数据、学生提交的答案。
	- 支持文件格式：CSV、XLSX、XLS、PPT、PDF、视频、代码文件等。
- **输出**：
	- 课程预览报告、学生完成情况统计、成绩单、反馈报告（PDF/Excel）、练习记录、错题集、历史版本资料等。

**功能性能要求**

- 支持多角色并发操作（教师、助教、学生）。
- 资源上传/下载响应时间 ≤ 3秒。
- 支持至少 1000 人同时在线使用。

### 2.2业务目标

1. **提升教学管理效率**：通过课程创建、班级管理、批量导入学生名单等功能，简化教师日常管理工作。
2. **支持个性化学习**：提供错题集、收藏题目、学习进度跟踪等功能，帮助学生针对性复习。
3. **强化教学反馈**：自动批改与反馈报告生成功能，帮助教师快速评估教学效果。
4. **保障数据安全**：通过加密存储、权限控制等手段保护用户隐私和教学数据。

### 2.3运行环境

#### 2.3.1设备 

- **服务器**：
	- CPU：8核及以上（支持多线程处理）。
	- 内存：32GB 及以上。
	- 存储：SSD 1TB 及以上（支持高并发读写）。
- **客户端**：
	- 浏览器：Chrome 90+、Firefox 85+、Edge 90+。
	- 分辨率：支持 1920×1080 及以上。

#### 2.3.2支持软件

- **后端**：
	- 操作系统：windows。
	- 开发框架：Spring Boot 2.6+、MySQL 8.0、OSS阿里云存储。
- **前端**：
	- 框架：Vue.js 3.0+、Element PLUS。
	- 依赖：Node.js 16+、Webpack 5.0+。

### 2.4设计约束

![image-20250504232711478](C:\Users\12298\AppData\Roaming\Typora\typora-user-images\image-20250504232711478.png)

#### 1. 实体关系约束

- **课程与班级**：
	- 一个课程可包含多个班级（1:N），班级必须归属于唯一课程。
	- 班级需绑定唯一教师（1:1），可分配多个助教（1:N）。
- **学生与班级**：
	- 一个学生可加入多个班级（N:M），需通过中间表维护关联关系。
- **任务与题目**：
	- 任务可包含多个题目（1:N），题目可被多个任务复用（N:M）。
	- 私有题目仅限所属任务使用，公开题目存入题库供全局调用。
- **教学进度与资源**：
	- 每个教学进度绑定唯一班级（1:1），可关联多个资源（1:N）。

#### 2. 数据模型约束

- **核心实体主键**：
	- 课程、班级、用户等实体需采用全局唯一标识（如UUID或自增ID）。
- **外键级联操作**：
	- 删除课程时，需级联删除关联的班级、教学进度和资源。
	- 删除题目时，需保留已关联任务的引用完整性（标记为“已删除”状态）。
- **资源版本控制**：
	- 资料更新时需保留历史版本，通过链表结构（`prev`字段）追溯版本链。

#### 3. 权限与业务逻辑约束

- **角色操作隔离**：
	- 教师仅可管理自己创建的课程和班级，助教仅限被分配班级的操作权限。
	- 学生不可修改课程结构、班级成员或任务设置。
- **任务状态流转**：
	- 任务发布后，截止时间前允许学生多次提交（若开启开关），截止后禁止修改。
	- 未批改的任务不允许生成反馈报告。

#### 4. 性能与扩展性约束

- **高频操作优化**：
	- 学生名单批量导入需支持异步处理，避免阻塞主线程。
	- 题库与任务查询需通过 Redis 缓存热点数据（如高频访问的题目）。
- **接口设计规范**：
	- RESTful API 需遵循标准 HTTP 状态码，分页查询参数统一（如 `page`、`size`）。
	- 微服务间通信采用轻量级协议（如 gRPC 或 HTTP/JSON），保证低延迟。

#### 5. 安全与合规约束

- **数据加密**：
	- 用户密码需 BCrypt 加密存储，敏感操作（如密码修改）需二次验证（邮箱/短信）。
- **防作弊机制**：
	- 学生端练习界面禁止复制粘贴，答题过程记录操作日志（如离开页面次数）。
- **审计与日志**：
	- 关键操作（如删除资源、修改成绩）需记录操作人、时间及变更详情。

### 2.5功能需求

#### 设计概要

1. **分层架构设计**
	- **前端层**：基于 Vue.js 的响应式界面，适配 PC 端与移动端，提供角色差异化的交互逻辑。
	- **网关层**：Nginx 反向代理实现负载均衡与请求分发，保障高并发场景下的稳定性。
	- **业务层**：微服务架构（Spring Cloud），模块包括课程服务、资源服务、练习服务、用户服务，各服务独立部署，通过 RESTful API 通信。
	- **数据层**：
		- **关系型数据库**（MySQL）：存储结构化数据（课程、用户、任务、题目等）。
		- **文件存储**（MinIO）：管理教学资源（课件、视频等）。
		- **缓存**（Redis）：优化高频查询（如题库加载、活跃课程列表）。
2. **核心设计原则**
	- **模块化**：各功能模块（课程管理、资源管理、练习评估）解耦，支持独立扩展。
	- **权限隔离**：基于 RBAC（角色访问控制）模型，严格区分教师、助教、学生的操作权限。
	- **数据一致性**：通过事务管理（如课程删除级联操作）和版本控制（资源历史记录）保障数据完整。
3. **关键实体交互**
	- **课程** ↔ **班级** ↔ **学生**：课程包含多个班级，学生通过班级代码加入。
	- **教学进度** ↔ **资源**：每个进度绑定资源，支持按章节分类和版本追溯。
	- **任务** ↔ **题目**：任务从题库选取题目，支持公开/私有题目复用。

#### 处理流程

1. **教师端流程**

```
创建课程 → 创建班级（导入学生） → 设计教学进度（绑定资源） → 发布任务（选题/手动录入） → 批改作业 → 生成反馈报告
```

2. **学生端流程**

```
加入班级 → 查看资源/进度 → 完成练习（自动保存答案） → 查看成绩与错题 → 导出学习报告
```

3. **系统交互流程示例（任务发布与提交）**

```
教师发布任务 → 系统调用题库服务加载题目 → 任务数据写入数据库 → 学生端接收任务通知 → 
学生提交答案 → 系统自动批改客观题 → 教师手动批改主观题 → 生成成绩单与反馈报告
```

### 2.6非功能需求

- **性能**：支持 1000 QPS（每秒查询率），页面加载时间 ≤ 2秒。
- **安全性**：
	- 数据传输使用 HTTPS，密码加密。
	- 权限校验（如学生无法访问教师管理界面）。
- **可用性**：提供操作引导提示，支持响应式布局（适配移动端）。
- **容错性**：数据库主从备份，异常操作时自动回滚事务。

### 2.7系统总体架构

![image-20250504232655719](C:\Users\12298\AppData\Roaming\Typora\typora-user-images\image-20250504232655719.png)

#### 1. 用户管理模块

- **实体**：教师、学生、助教
- **功能**：支持分角色注册/登录，权限控制（如教师可创建课程，学生仅参与学习），个人信息与密码加密存储。

#### 2. 课程管理模块

- **实体**：课程、班级、教学进度
- **功能**：
	- 教师创建课程并关联教学大纲、考核方式；
	- 按课程创建班级，批量导入学生或通过班级代码加入；
	- 按周划分教学进度，绑定章节资源（如课件、视频）。

#### 3. 教学资源模块

- **实体**：资源、历史版本
- **功能**：
	- 教师上传多格式资源（PPT/PDF/代码等），按章节标签分类；
	- 版本控制支持历史记录追溯与回滚；
	- 学生可基于标签检索、预览或下载资源。

#### 4. 练习与评估模块

- **实体**：任务、练习、题库、题目、反馈报告
- **功能**：
	- 教师从题库选择题目发布任务，支持公开/私有题目；
	- 学生完成练习后，系统自动批改客观题，教师手动批改主观题；
	- 生成反馈报告（含成绩、排名、答案解析），学生可导出记录；
	- 错题自动归集，支持收藏与复习。

#### 5. 数据存储与交互

- **结构化数据**：课程信息、用户数据、任务记录等存储于关系型数据库（MySQL）；
- **非结构化数据**：教学资源文件通过分布式存储（如MinIO）管理；
- **缓存机制**：高频访问数据（如题库、活跃课程）通过Redis缓存提升性能。

------

### 核心实体交互流程

1. **教师端**：
	- 创建课程 → 绑定班级 → 设计教学进度 → 上传资源 → 发布任务（从题库选题） → 批改作业 → 生成反馈报告。
2. **学生端**：
	- 加入班级 → 查看教学进度与资源 → 完成练习 → 查看成绩与错题 → 导出学习报告。

------

### 架构特点

- **权限隔离**：通过角色（教师/学生/助教）严格划分数据访问与操作权限。
- **模块解耦**：课程、资源、练习等模块独立部署，通过API通信，支持灵活扩展。
- **性能优化**：异步任务处理（如批量导入学生）、缓存机制保障高并发场景稳定性。
- **数据完整性**：版本控制与事务回滚机制确保教学资源与任务记录的可靠性。

#### 3.3.2 物理结构设计要点

1. **存储平台与设备**

	- 数据库：MySQL 8.0 InnoDB 引擎，部署于专用 SSD 存储阵列
	- 索引文件与数据文件分离，索引建立于独立 SSD 分区

2. **存取方法与单位**

	- 访问方法：基于 B+ 树的随机读取，范围扫描和聚簇索引
	- 存取单位：行级锁（InnoDB 聚簇索引按主键有序存储），事务隔离级别 REPEATABLE READ

3. **存储要求与物理组织**

	| 数据表            | 行大小估算 | 存储区域            | 索引类型                     | 设计考虑                                    | 保密条件                    |
	| ----------------- | ---------- | ------------------- | ---------------------------- | ------------------------------------------- | --------------------------- |
	| User              | ≈200 Bytes | db_main.user_data   | PK: B+ 树，UNIQUE(username)  | 密码哈希单向存储，字段加密备份              | 密码字段 AES-256 加密存储   |
	| Course            | ≈300 Bytes | db_main.course_data | PK: B+ 树，索引(course_code) | 大纲字段使用外部文件存储，TEXT 字段溢写优化 | 大纲资料访问需教师/助教权限 |
	| Class             | ≈150 Bytes | db_main.class_data  | PK: B+ 树                    | 按学期分区，便于归档管理                    | 班级代码限可见范围          |
	| Resource          | ≈400 Bytes | db_files.resource   | PK: B+ 树                    | URL 字段指向对象存储桶                      | 资源文件按班级隔离 ACL      |
	| Exercise/Question | ≈500 Bytes | db_main.exercise    | PK: B+ 树                    | 大量随机访问，需内存缓存                    | 答案解析仅限教师/助教查看   |
	| Submission        | ≈250 Bytes | db_main.submission  | PK: B+ 树                    | 高并发写入，启用事务批量提交                | 学生成绩仅学生本人/教师可见 |

4. **访问与安全**

	- 网络访问通过 TLS 1.2 加密
	- 敏感字段（密码、解析）在应用层和数据库层双重加密
	- 定期备份：完整备份+增量备份，备份存储于独立 NAS，备份数据加密

| ------------------------------- | ------------------------------ | -------------------------------------- |
| 用户管理模块（UserService）     | User、Role                     | 注册/登录、角色分配、权限校验          |
| 课程管理模块（CourseService）   | Course、Class、Enrollment      | 课程创建、班级创建、学生选课           |
| 教学资料模块（ResourceService） | Resource、ResourceVersion      | 资料上传/更新、版本控制、权限校验      |
| 在线练习模块（ExerciseService） | Exercise、Question、Submission | 练习发布、题目管理、自动批改与手动批阅 |
| 历史记录模块（RecordService）   | LearningRecord、Submission     | 学习轨迹查询、练习记录汇总报表         |

- **调用关系**：各模块通过 DAO/Mapper 层与对应表做增删改查，Service 层封装业务流程，Controller 层对外提供 RESTful API。
- **事务管理**：涉及多表操作（如发布练习时同时插入 Exercise 与多个 Question）采用 Spring 事务，保证原子性。
- **缓存设计**：Course、Question 等高频查询表在 Redis 缓存，减少数据库压力。

## 4 系统数据库设计

### 数据库设计总览

本系统旨在构建一个支持教师、助教和学生多种角色协同工作的教学管理平台，数据库设计需保证数据一致性、安全性和可扩展性。用户角色包括教师、学生和助教三类，系统使用 `identity` 字段对角色进行编码（0=教师，1=学生，2=助教）。数据库设计支持课程、班级、作业、资源和题库等功能模块。

### 数据表设计

#### `t_user`（用户表）

`t_user` 表存储所有用户的基本信息，包括教师、助教和学生。主要字段有用户ID（user_id）、账号（username）、密码（password）、姓名（name）、邮箱（mail）、出生日期（birthday）和身份标识（identity）等。`identity` 字段标识用户角色，取值为0、1或2分别表示教师、学生和助教。

| 字段     | 类型         | 说明                               |
| -------- | ------------ | ---------------------------------- |
| user_id  | INT          | 用户ID，主键                       |
| username | VARCHAR(255) | 用户账号（学工号）                 |
| password | VARCHAR(255) | 登录密码（已加密）                 |
| name     | VARCHAR(255) | 姓名                               |
| mail     | VARCHAR(255) | 邮箱地址                           |
| birthday | DATE         | 出生日期                           |
| identity | INT          | 身份标识（0=教师；1=学生；2=助教） |

#### `t_course`（课程表）

`t_course` 表保存课程的基本信息，包括课程ID（course_id）、课程名称（name）、创建者ID（creator_id，对应 `t_user.user_id`）、课程大纲（syllabus）、考核方式（assMethod）、学分（score）和学时（time）等。

| 字段       | 类型         | 说明                       |
| ---------- | ------------ | -------------------------- |
| course_id  | INT          | 课程ID，主键               |
| name       | VARCHAR(255) | 课程名称                   |
| creator_id | INT          | 创建者用户ID（教师或助教） |
| syllabus   | TEXT         | 课程大纲                   |
| assMethod  | VARCHAR(255) | 考核方式                   |
| score      | FLOAT        | 学分                       |
| time       | INT          | 学时                       |

#### `t_class`（班级表）

`t_class` 表记录课程下的班级信息，每个班级属于一个课程。`class_code` 字段为系统生成的班级代码，学生通过该代码搜索并加入班级。

| 字段       | 类型         | 说明                                    |
| ---------- | ------------ | --------------------------------------- |
| class_id   | INT          | 班级ID，主键                            |
| name       | VARCHAR(255) | 班级名称                                |
| course_id  | INT          | 所属课程ID（对应 `t_course.course_id`） |
| class_code | VARCHAR(255) | 班级代码（学生加入班级的标识）          |

#### `t_process`（进度表）

`t_process` 表用于跟踪课程教学进度或教学环节，每条记录关联一个课程和一个班级。主要字段包括进度ID（process_id）、进度名称（name）、关联课程ID（course_id）、关联班级ID（class_id）和日期（time）等。

| 字段       | 类型         | 说明         |
| ---------- | ------------ | ------------ |
| process_id | INT          | 进度ID，主键 |
| name       | VARCHAR(255) | 进度名称     |
| course_id  | INT          | 关联课程ID   |
| class_id   | INT          | 关联班级ID   |
| time       | DATE         | 日期         |

#### `t_resource`（资源表）

`t_resource` 表存储课程资源文件（如教材、课件、习题等）。当 `process_id` 字段为 -1 时，表示该资源为公共资源，不隶属于具体进度。对于公共资源，系统在公共区和进度区各保存一份。其他字段包括资源ID（res_id）、资源编码（res_code，用于标识同一项资源的历史版本）、资源名称（name）、所属课程ID（course_id）、文件类型（type，取文件后缀，默认为 `txt`）、资源内容（data）、上传日期（date）和标签（tag）等。

| 字段       | 类型         | 说明                           |
| ---------- | ------------ | ------------------------------ |
| res_id     | INT          | 资源ID，主键                   |
| res_code   | VARCHAR(255) | 资源编码（历史版本一致）       |
| name       | VARCHAR(255) | 资源名称                       |
| process_id | INT          | 所属进度ID，-1 表示公共资源    |
| course_id  | INT          | 所属课程ID                     |
| type       | VARCHAR(255) | 文件类型（后缀名，缺省为 txt） |
| data       | BLOB         | 资源内容                       |
| date       | DATETIME     | 上传时间                       |
| tag        | VARCHAR(255) | 资源标签                       |

#### `t_exer`（作业/练习表）

`t_exer` 表存储布置的作业或练习信息。每个作业关联一个班级或课程（`class_id` 和 `course_id`），其中当 `class_id` 和 `course_id` 同时为 -1 时，表示该作业模板属于题库。其他字段包括创建者ID（creator_id）、开始时间（begin_time）、结束时间（end_time）、是否公开（is_public，表示是否在题库中公开以供克隆）、题目列表（problems，JSON 格式存储题目ID 列表）、作业名称（name）、是否允许多次提交（is_multi）和总分（score）等。

| 字段       | 类型         | 说明                        |
| ---------- | ------------ | --------------------------- |
| exer_id    | INT          | 作业ID，主键                |
| class_id   | INT          | 所属班级ID，-1 表示题库模板 |
| course_id  | INT          | 所属课程ID，-1 表示题库模板 |
| creator_id | INT          | 创建者用户ID（教师或助教）  |
| begin_time | DATETIME     | 开始时间                    |
| end_time   | DATETIME     | 结束时间                    |
| problems   | TEXT         | 题目ID列表（JSON 格式）     |
| is_public  | BOOLEAN      | 是否公开（题库中可见）      |
| name       | VARCHAR(255) | 作业名称                    |
| is_multi   | BOOLEAN      | 是否允许多次提交            |
| score      | INT          | 作业总分                    |

#### `t_prob`（题目表）

`t_prob` 表存储题目信息。主要字段包括题目ID（prob_id）、是否公开（is_public，表示题库中是否可见）、题目类型（type：0=选择题；1=判断题；2=简答题；3=编程题）、创建者ID（creator_id）、创建时间（create_time）、题干（description）、内容（content，如选择题的选项列表）、正确答案（answer）和详细解析（analysis）等。对于选择题，`content` 字段存储 JSON 格式的选项列表（如 `["选项A","选项B",...]`）；`answer` 字段存储标准答案（例如 `"A"`），`analysis` 字段存储题目解析。

| 字段        | 类型         | 说明                                               |
| ----------- | ------------ | -------------------------------------------------- |
| prob_id     | INT          | 题目ID，主键                                       |
| is_public   | BOOLEAN      | 是否公开（题库可见）                               |
| type        | INT          | 题目类型（0=选择题；1=判断题；2=简答题；3=编程题） |
| creator_id  | INT          | 创建者用户ID                                       |
| create_time | DATETIME     | 创建时间                                           |
| description | VARCHAR(255) | 题干描述                                           |
| content     | VARCHAR(255) | 题目内容（如选项列表，JSON格式）                   |
| answer      | VARCHAR(255) | 正确答案                                           |
| analysis    | VARCHAR(255) | 详细解析                                           |

#### `t_user_course_class`（用户-课程-班级关系表）

`t_user_course_class` 表用于关联用户、课程和班级的对应关系。`user_id` 字段为 -1 时表示该记录仅描述课程与班级的关系（查询课程下所有班级时使用）；`class_id` 字段为 -1 时表示该教师或助教已经进入课程但尚未被分配到具体班级。该表还记录用户在课程中的身份（identity），供权限控制使用。

| 字段      | 类型 | 说明                               |
| --------- | ---- | ---------------------------------- |
| user_id   | INT  | 用户ID（对应教师、助教或学生）     |
| course_id | INT  | 课程ID                             |
| class_id  | INT  | 班级ID                             |
| identity  | INT  | 用户身份（0=教师；1=学生；2=助教） |

#### `t_stu_prob_exer`（学生-题目-作业关系表）

`t_stu_prob_exer` 表记录学生作答情况及评分，关联学生（stu_id）、题目（prob_id）和作业（exer_id）。当 `stu_id` 为 -1 时表示该记录保存作业标准分配分数（即各题的参考分值），当 `prob_id` 为 -1 时表示该学生的作业总分。其他字段包括学生得分（score）、教师批改意见（comment）、学生提交内容（submit）、是否完成标志（is_finish）和是否已批改标志（is_check），以及题目在作业中的序号（index）等。

| 字段      | 类型         | 说明               |
| --------- | ------------ | ------------------ |
| stu_id    | INT          | 学生ID             |
| prob_id   | INT          | 题目ID             |
| exer_id   | INT          | 作业ID             |
| score     | INT          | 得分               |
| comment   | VARCHAR(255) | 教师评语           |
| submit    | VARCHAR(255) | 学生提交答案/代码  |
| is_finish | BOOLEAN      | 是否完成           |
| is_check  | BOOLEAN      | 是否已批改         |
| index     | INT          | 题目在作业中的序号 |

#### `t_wrong`（错题表）

`t_wrong` 表记录学生做错的题目，用于后续复习和统计分析。该表关联学生和题目以及相应的作业（stu_id、prob_id、exer_id）。

| 字段    | 类型 | 说明   |
| ------- | ---- | ------ |
| stu_id  | INT  | 学生ID |
| prob_id | INT  | 题目ID |
| exer_id | INT  | 作业ID |

#### `t_collect`（收藏表）

`t_collect` 表记录学生收藏（标记）的题目，以便快速复习。字段包括学生ID（stu_id）和题目ID（prob_id）。

| 字段    | 类型 | 说明   |
| ------- | ---- | ------ |
| stu_id  | INT  | 学生ID |
| prob_id | INT  | 题目ID |

#### `t_tag`（标签表）

`t_tag` 表用于存储标签信息，可对资源或题目进行标记分类。字段包括标签ID（tag_id）和标签名称（name）。

| 字段   | 类型         | 说明     |
| ------ | ------------ | -------- |
| tag_id | INT          | 标签ID   |
| name   | VARCHAR(255) | 标签名称 |

### 表之间的逻辑关系

- **用户、课程与班级：** 通过 `t_user_course_class` 表将用户与课程和班级关联，实现教师/助教与各班级的管理关系。`t_user_course_class` 中的 `identity` 字段区分用户身份。
- **课程与班级：** 一门课程可对应多个班级（`t_class.course_id` 关联 `t_course.course_id`），每个班级再对应其教学进度记录（`t_process`）和布置的作业（`t_exer`）。
- **班级与进度：** 每个班级在教学过程中会产生多条进度记录（`t_process`），记录教学环节的名称和日期。
- **资源与进度/课程：** `t_resource` 表通过 `course_id` 关联对应课程，通过 `process_id` 关联具体进度；当 `process_id` = -1 时表示公共资源可被所有班级共享。
- **作业与题目：** `t_exer` 表记录布置的作业，一个作业包含多个题目；`t_exer` 中的 `problems` 字段（JSON 格式）列出题目ID 列表，学生的作答结果由 `t_stu_prob_exer` 表记录，每条记录对应一名学生在该作业某题的答题和得分情况。
- **错题与收藏：** `t_wrong` 和 `t_collect` 表分别用于记录学生做错题目和收藏题目，便于后续复习与统计；这两张表都关联学生ID和题目ID。

### 特殊设计说明

- **公共资源 (`process_id=-1`) 规则：** 当 `t_resource` 表中的 `process_id` 字段值为 -1 时，表示该资源为公共资源，不属于任何具体进度。系统对公共资源保存两份，一份归于进度结构中，一份存放在公共资源区，供所有课程/班级共享使用。
- **题库模板识别：** 在 `t_exer` 表中，当 `class_id` 和 `course_id` 均为 -1 时，表示该条作业记录为题库中可克隆的任务模板。系统通过此规则区分正式作业和题库模板。
- **错题表和收藏表用途：** `t_wrong` 用于保存学生在作业或测试中做错的题目记录，以便学生后续复习和教师分析易错题目；`t_collect` 用于保存学生收藏标记的题目，以便学生快速复习自己关注的题目。

## 5 运行设计

### 5.1运行模块组合

系统运行期间，各模块按照既定流程协同工作。模块组合分为前端展示模块、业务逻辑模块和数据管理模块三层结构：

- 前端展示模块：
	通过浏览器访问Vue页面，负责收集用户输入并展示反馈信息,主要使用axios向业务逻辑发送请求，主要包括post、get等请求。

- 业务逻辑模块：
	由Spring Boot构建的控制层和服务层组成，负责处理用户请求、执行业务规则、调用数据接口等操作，主要使用Mybatis对数据管理模块进行操作。

- 数据管理模块：
	基于 MySQL 实现的数据持久化与访问支持，包括存储用户信息、课程信息、任务信息等。

### 5.2运行控制

系统运行控制机制主要体现在以下几个方面：

- 启动控制：
	系统初始化时，Spring Boot自动加载配置文件并初始化相关Bean，前端模块通过Web服务器加载静态资源，数据库需在后台运行。

- 权限控制：
	系统按角色划分权限（如教师、学生），前端将用户账号、密码信息交付服务端统一校验，接收后端传来的用户权限信息，并在网页展示中控制操作权限和对应的内容。

- 异常处理机制：
	异常处理运行在后端，对每种可能出现的异常都做了整理和应对措施，以及分别配置了向前端返回的信息，并且使用日志进行记录，保证每次出现的异常都是可预知和可恢复的。

- 状态监控与日志记录：
	状态监控体现在后端便是使用log进行状态输出，体现在前端在于使用console.log进行状态记录，并且对于数据库和数据库通信的记录会被保存在服务器上，同步在日志里。

### 5.3运行时间

系统设计为支持 7×24 小时不间断运行，保障多用户并发访问，具备较强的容错与恢复能力。
在设计时，我们需要考虑以下几种运行时间场景：

- 日常运行：
	系统部署为常驻进程，随服务器启动自动运行。

- 高峰期运行：
	在学期初选课时期或资料上传高峰期，系统需支持高并发访问，避免响应卡顿和数据冲突。

- 维护时段：
	建议安排在凌晨等非高峰时段进行数据库备份、系统升级等操作,避免对用户使用造成影响。
