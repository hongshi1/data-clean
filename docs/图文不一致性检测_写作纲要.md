# 图文不一致性检测技术调研——写作纲要

> 本文档是「图文不一致性检测技术调研」的写作纲要，供后续其他模态对（如时序↔文本、结构化模型↔时序仿真）的调研参照。每个小节标注了**写什么、怎么写、写多深、用什么素材**。

---

## 总体结构：三大章

| 章 | 标题 | 篇幅占比 | 核心任务 |
|----|------|---------|---------|
| 一 | 研究背景 | ~15% | 讲清"什么是不一致性检测"+"为什么重要"+"行业已有什么" |
| 二 | 真实数据与模态对齐挑战 | ~20% | 贴真实数据样例+提炼对齐难点 |
| 三 | 不一致性检测方法 | ~65% | 逐方法讲清原理+技术细节+行业指标+真实结果 |

**写作原则**：
- 结论先行：每节开头一句话讲清本节结论
- 真实数据：凡有数据处必贴真实样例（图片+文本原文）
- 技术深度：讲"怎么做到的"而非"做了什么"
- 对标行业：每个方法附论文出处+量化指标（AUC/F1/κ等）

## 第一章：研究背景

### 1.1 什么是不一致性

**写什么**：用一句话定义"图文不一致性"，再用一个具体场景说清楚"对不上"是什么样的。

**怎么写**：
1. 先描述理想状态（两份数据应当完全一致）
2. 再描述现实（实际会出哪些问题：漏写、矛盾、误判）
3. 给出定义：不是简单的相似度计算，而是在**语义空间**上比对两者是否矛盾

**参考句式**：
> 在XX领域，每次XX都会产生一对天然配对的数据：一份XX + 一份XX。理想状态下两者应当完全一致……但实际中两者时常**对不上**：……

**深度要求**：3–5句话，不需展开。

### 1.2 为什么重要

**写什么**：用行业数据证明这个问题的严重性。

**怎么写**：
1. 引用行业错误率/不一致率（需有出处）
2. 给出数据规模（如"单数据集就含XX万张"）
3. 点明人工核对不可行 → 自动化是刚需

**素材要求**：必须有可查证数字，不能笼统说"大量"。

### 1.3 行业验证基础

**写什么**：用一张表概括行业已有的技术栈。

**怎么写**：表格形式，列出：

| 能力 | 代表工具/方法 | 行业指标 | 来源 |
|------|-------------|---------|------|
| （侧1分析） | 工具名 | 量化指标 | 论文/会议 |
| （侧2分析） | 工具名 | 量化指标 | 论文/会议 |
| （跨模态方法） | 方法名 | 量化指标 | 论文/会议 |

**深度要求**：表格+一句话总结即可，细节留给第三章。

## 第二章：真实数据与模态对齐挑战

### 2.1 真实配对数据

**写什么**：展示3个真实数据样例，每个样例必须**同时贴上两种模态的原始内容**。

**怎么写**：每个样例包含：
- **模态1原始内容**（如真实图片，用 `![](路径)` 嵌入）
- **模态2原始内容**（如真实文本，用引用块 `>` 展示原文）
- **2–3句话标注关键特征**（如"这段报告同时包含肯定/否定/不确定三种表述"）

**3个样例的选取原则**：
1. 样例一：**典型复杂样本**（包含多种状态/最易触发冲突的场景）
2. 样例二：**简短正常样本**（极简，但AI可能判异常——典型冲突场景）
3. 样例三：**内部矛盾样本**（同份数据内部自相矛盾）

**深度要求**：每个样例配图+原文+特征标注，不展开分析。

### 2.2 数据规模与来源

**写什么**：一张表列出所有相关数据集。

**怎么写**：

| 数据集 | 来源 | 规模 | 模态 | 特点 |
|--------|------|------|------|------|
| 数据集名 | 机构 | 数量 | 哪几种模态 | 公开/凭证/特点 |

### 2.3 模态对齐的技术挑战

**写什么**：提炼2–3个"为什么对齐难"的技术挑战。这是本章的核心深度所在。

**怎么写**：每个挑战包含：
1. **挑战名称**（如"三态语义对齐"）
2. **问题描述**（为什么两侧不能直接比对）
3. **对比表格**（展示两侧状态空间的差异）
4. **一句话点出解决方向**（如"必须在四态空间上定义冲突矩阵"）

**参考挑战维度**：
- **语义状态空间不对齐**：一侧二值，一侧多态 → 需要冲突矩阵
- **配对/时戳对齐**：两份数据可能不是同源的 → 需要配对验证
- **粒度不对齐**：一侧逐元素，一侧全局结论 → 需要多粒度对齐

**深度要求**：每个挑战 1 个表格 + 3–5 句解读，是本章重点。

## 第三章：不一致性检测方法（核心章）

### 总体原则

- 按**技术组件**组织（侧1分析 → 侧2分析 → 比对方法 → 进阶方法），不按场景组织
- 每个方法必须包含：**原理 + 真实结果/行业指标 + 技术细节**
- 方法之间用**对比表格**串联，不各自孤立

### 3.1 侧1分析（如图像侧AI模型）

#### 3.1.1 代表模型

**写什么**：介绍该侧最主流的分析工具/模型。

**怎么写**：
1. 模型全名+出处（论文/会议/arXiv编号）
2. 工作原理（输入→处理→输出，用编号列表）
3. 行业基准指标表格（AUC/F1/准确率，逐类别列出）
4. 真实推理结果表格（用自己的数据跑出来的结果）

**素材要求**：AUC等指标必须有出处（如"官方BENCHMARKS.md"），真实推理结果用自己的数据。

#### 3.1.2 模型校准/预处理

**写什么**：讲清"直接用模型原始输出是错的"以及怎么校准。

**怎么写**：
1. 为什么原始输出不能直接用（如"logits不是概率""统一阈值导致假阳性"）
2. 校准方法对比表（方法名/原理/适用场景/效果）
3. 关键规律总结（如"低患病率类别阈值偏高"）

**深度要求**：这是体现技术深度的关键小节，必须有对比表+规律总结。

#### 3.1.3 边界带处理

**写什么**：当模型输出在判定边界附近时怎么处理。

**怎么写**：
1. 定义边界带（如"阈值±0.05"）
2. 三档处理逻辑（确信/边界/确信阴性）
3. 给具体例子（如"概率0.515在边界带内，应降级"）

**深度要求**：3–5句话+一个例子即可，但不可省略——这直接影响假阳性率。

### 3.2 侧2分析（如文本侧NER标注）

#### 3.2.1 核心难点

**写什么**：点明该侧分析的主要难点。

**怎么写**：用2–3个真实例子说明"简单方法为什么不行"（如纯关键词匹配会误判否定表述）。

#### 3.2.2 方法演进对比

**写什么**：用表格展示从简单到复杂的方法演进。

**怎么写**：

| 方法 | 来源 | 原理 | 关键能力1 | 关键能力2 | 准确率 |
|------|------|------|---------|---------|--------|

**深度要求**：至少4种方法对比，标注每种方法的局限性。

#### 3.2.3 行业标准方法详解

**写什么**：选最准确的方法展开讲技术原理。

**怎么写**：
1. 流程图/表格展示处理阶段（如三阶段流水线）
2. 核心算法逻辑（用伪代码或编号步骤）
3. 与简单方法对比表（同一输入，不同方法的判定结果）

**深度要求**：必须有"同一输入不同方法判定对比表"——这是体现方法价值的关键。

#### 3.2.4 工程简化版

**写什么**：行业标准方法的轻量替代方案。

**怎么写**：
1. 简化版步骤（3步以内）
2. 真实标注结果表格（用自己数据跑的结果）
3. 选型建议（何时用完整版/简化版）

**可配SVG图**：简化版的处理流程图。

### 3.3 比对方法：冲突矩阵

#### 3.3.1 冲突矩阵定义

**写什么**：用矩阵图展示两侧状态的所有组合及冲突判定。

**可配SVG图**：冲突矩阵图（横轴侧1状态，纵轴侧2状态，格内标注冲突类型+颜色编码）。

#### 3.3.2 冲突类型表

**写什么**：用表格列出所有冲突类型。

**怎么写**：

| 冲突类型 | 触发条件 | 严重度 | 实际含义 |

#### 3.3.3 严重度分级机制

**写什么**：严重度不是写死的，而是由模型确信度动态决定。

**怎么写**：
1. 分级规则（如"概率≥0.7→HIGH"）
2. 结合边界带处理的完整逻辑
3. 具体例子（同一冲突在不同确信度下的分级）

#### 3.3.4 假阳性来源分析

**写什么**：分析检测出的冲突里有多少是误报、为什么。

**怎么写**：

| 假阳性来源 | 典型表现 | 缓解手段 |

**深度要求**：必须有此节——不分析假阳性的检测方法不可部署。

#### 3.3.5 真实案例完整演示

**写什么**：用一个真实样本走完全流程，展示从输入到检出冲突的完整过程。

**可配SVG图**：真实案例演示图（输入→侧1结果→侧2结果→冲突清单）。

**怎么写**：
1. 输入（图+文）
2. 侧1分析结果（表格）
3. 侧2分析结果（表格）
4. 检出的冲突清单（逐条列出，含类型+严重度+证据）
5. 汇总统计（共检出多少条、分布如何）

### 3.4 通用框架方法（如VDC）

**写什么**：介绍学术界提出的通用不一致性检测框架。

**怎么写**：
1. 是什么（一句话定义+核心发现）
2. 架构图（三段式/多段式，配SVG）
3. 各阶段表格（阶段名/全称/做什么/类比）
4. 完整版 vs 工程简化版对比表
5. 该方法的价值定位（一句话）

### 3.5 领域SOTA方法（如FAMDR）

**写什么**：展开讲当前准确率最高的方法的技术原理。

**怎么写**：
1. 方法全名+出处+解决的核心问题
2. **逐组件展开技术原理**（这是深度所在）：
   - 每个组件：名称→做什么→怎么做→关键创新
   - 不能只列名称，必须讲技术机制
3. 性能指标（F1/precision/recall + 数据集 + baseline对比）
4. 与其他方法的关系（如"粗粒度vs细粒度，可级联"）

**深度要求**：这是全篇技术密度最高的部分，每个组件至少一段话。

### 3.6 跨模态对齐方法（如CLIP）

#### 3.6.1 通用方法原理
**写什么**：基础原理（如对比学习）+ 输出（如余弦相似度）。

#### 3.6.2 局限性
**写什么**：用表格列出3个关键局限+对该领域的影响。

#### 3.6.3 领域专用变体
**写什么**：该领域的改进版本对比表。

| 方法 | 来源 | 训练数据 | 核心改进 | 领域能力 |

### 3.7 端到端方法（如多模态大模型）

**写什么**：与分段式方法对比的端到端替代方案。

**怎么写**：
1. 范式转变说明（从分段式到端到端）
2. 代表模型介绍（全名+出处+能力+临床/实际验证结果）
3. 端到端 vs 分段式对比表（至少6个维度）

### 3.8 兜底方法（如LLM+Guard）

**写什么**：规则和模型都覆盖不了的复杂语义冲突怎么处理。

**怎么写**：
1. 方法描述
2. 关键发现（如"LLM会幻觉"）
3. Guard机制（流程图+真实数据验证表）

### 3.9 方法谱系与选型

#### 谱系图

**写什么**：用ASCII/文本图展示所有方法在"可解释性↔语义覆盖广"轴上的位置。

#### 技术细节对比大表

**写什么**：所有方法在10+技术维度上的横向对比。

**怎么写**：表格列 = 技术维度，行 = 方法。维度包括：

| 维度 | 说明 |
|------|------|
| 技术原理 | 每种方法的核心机制一句话 |
| 输入 | 吃什么数据 |
| 输出 | 吐什么结果 |
| 关键模型/组件 | 用什么实现 |
| 对齐方式 | 两份数据怎么对齐（字段级/元素级/向量级/像素级/端到端） |
| 阈值机制 | 怎么判"是不是冲突" |
| GPU需求 | 部署成本 |
| 可解释性 | 能否追溯原因 |
| 假阳性控制 | 怎么防误报 |
| 新领域迁移 | 换到其他领域要改什么 |
| 出处 | 论文/会议 |

#### 选型决策树

**写什么**：用文本决策树引导读者选方法。

**格式**：
```
有明确领域规则？
  ├─ 是 → 知识库规则
  └─ 否 → 有现成领域AI？
            ├─ 是 → 冲突矩阵
            └─ 否 → ...
```

#### 推荐级联策略

**写什么**：多层递进的实战策略，一句话说清每层职责。

**写什么**：所有方法/工具的指标汇总表。

| 方法/工具 | 出处 | 关键指标 | 数据集 |

## 配图制作规范

| 图类型 | 工具 | 内容要求 |
|--------|------|---------|
| 流程图 | SVG（Python生成） | 分步骤+箭头+颜色编码（蓝=侧1，橙=侧2，黄=比对，绿=输出） |
| 冲突矩阵 | SVG | 横纵轴标注状态，格内标注冲突类型+严重度，颜色编码（红=严重/橙=中等/黄=轻微/绿=一致） |
| 真实案例 | SVG | 三栏：输入→侧1结果→侧2结果→冲突清单，用真实数据填充 |
| 方法原理 | SVG | 分模块+箭头+类比文字 |

**SVG生成方式**：Python脚本生成，存入 `../svgs/` 目录，md中用 `![](../svgs/xxx.svg)` 引用。
