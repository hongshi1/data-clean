> 本文档是基于 deep research 的领域认知与技术规划，用于指导 `docs/feishu/图片_文本一致性调研-医疗方向.md` 的内容填充。

## 一、领域认知：这个领域在解决什么问题

### 1.1 核心问题定位

我们的方向是**多模态数据集治理中的跨模态冲突检测**——检测数据集中图像与文本/标签之间是否存在语义矛盾。这与"报告生成一致性"是不同层面的问题：

| 维度 | 数据集治理/冲突检测（我们） | 报告生成一致性（主流） |
|------|--------------------------|---------------------|
| 检测对象 | 静态数据集中的已有图文对（训练数据） | 模型生成的报告与输入图像 |
| 冲突来源 | 数据采集/标注/爬取引入的错误 | 模型幻觉/生成错误 |
| 时间点 | 训练前（数据清洗） | 推理时/推理后（输出校验） |
| 目标 | input validation | output validation |

### 1.2 Deep Research 核心发现

通过 arXiv 9组关键词检索 + 5组补充检索（详见 `docs/literature_survey_multimodal_data_governance.md`），发现：

**这是一个"框架性空白"而非"技术空白"：**

| 维度 | 现状 | 说明 |
|------|------|------|
| 精确命中"多模态数据治理+冲突检测" | **0篇** | 检索词尚未被学界固化为独立方向 |
| A类（图文冲突检测） | ~10篇 | 分散在虚假信息/幻觉/foil检测等不同框架下 |
| B类（多模态数据清洗框架） | ~7篇 | Data-Juicer 2.0/TADS/DOSE，但无冲突检测算子 |
| C类（标签噪声检测） | ~5篇 | DeFT/CLIPCleaner，但只做分类标签噪声 |
| 统一benchmark | **无** | FOIL-COCO/NewsCLIPpings/HalDec-Bench各测一种不一致 |

**三大数据治理工具均不支持跨模态冲突检测：**

| 工具 | 多模态支持 | 跨模态冲突检测 |
|------|-----------|--------------|
| Data-Juicer 2.0（NeurIPS 2025 Spotlight） | 支持（100+算子） | **不支持**（只有CLIP score对齐过滤，无语义冲突检测算子） |
| CleanLab | 主要单模态 | **不支持**（confident learning做标签噪声，无跨模态概念） |
| Great Expectations | 无多模态 | **不支持**（传统表格数据验证） |

**技术积木已存在但未被组装成框架：**
- CLIP score 做图文对齐 → 存在，但只做粗粒度过滤
- NLI 文本蕴含 → 存在，用于假新闻检测
- Foil 检测 → 存在（FOIL-COCO 2017），但只做单词级
- VLM 幻觉检测 → 存在（HalDec-Bench 2025），最接近数据集质量校验
- Confident learning → 存在（CleanLab），但只做分类标签
- **没有人把这些组装成"多模态数据集治理的冲突检测框架"**

### 1.3 最接近的已有工作（A类论文）

| 论文 | 年份 | 做了什么 | 与我们的差距 |
|------|------|---------|------------|
| **FOIL-COCO** (arXiv:1705.01359) | 2017 ACL | 最早系统化做"图文单点不一致"诊断，构建foil caption数据集 | 目的是测试模型理解能力，非治理数据集 |
| **NewsCLIPpings** (arXiv:2104.05893) | 2021 EMNLP | 大规模"图文错配"数据集，检测out-of-context媒体 | 框架是虚假信息检测，非数据质量校验 |
| **HalDec-Bench** (arXiv:2511.20515) | 2025 | 评测caption幻觉检测器，**明确提出"用幻觉检测策划高质量图文对"** | 最接近数据治理视角，但仍以"幻觉"为框架 |
| **MicroVQA++** (arXiv:2511.11407) | 2025 | 首个联合建模(image,caption,QA)的异构图，做跨模态一致性过滤 | 领域特定（显微镜VQA），非通用框架 |
| **VLM-UQBench** (arXiv:2602.09214) | 2026 | 600样本，明确把"图文不对齐"作为不确定性来源 | 框架是不确定性量化，非冲突检测 |
| **DeFT** (arXiv:2409.19696) | 2024 NeurIPS | 用VLM检测分类标签噪声 | 标签级噪声，非图文语义冲突 |
| **CLIPCleaner** (arXiv:2408.10012) | 2024 ACMMM | 用CLIP零样本选干净样本 | 分类标签清洗，非语义冲突 |

### 1.4 关键判断（修正版）

1. **不是"只有FAMDR做这个方向"**——有~10篇A类工作检测图文不一致，但分散在虚假信息/幻觉/foil等不同框架下
2. **真正的空白是"框架性空白"**——没有人把跨模态冲突检测定义为多模态数据集治理的核心校验方法，建立系统化的冲突类型分类、检测算子库和benchmark
3. **技术积木已存在**——CLIP/NLI/foil检测/VLM幻觉检测/confident learning都有，但未被组装成数据治理框架
4. **工具缺失**——Data-Juicer/CleanLab/Great Expectations三大工具均不支持
5. **可立项方向**："面向多模态数据集治理的跨模态冲突检测框架"——定义冲突类型分类、设计检测算子、构建benchmark、集成到Data-Juicer类工具

## 三、我们已有实验的关键发现（deep research from local data）

### 3.1 图像侧：统一0.5阈值导致系统性假阳性

NLMCXR 20样本×6病种实测：
- Pneumothorax：14个阳性中**13个在边界带[0.45,0.55]**（93%假阳性率）
- Consolidation：11个阳性**全部在边界带内**（100%）
- 根因：TorchXRayVision输出是logit非概率，未做sigmoid且用统一0.5阈值

### 3.2 文本侧：三态语义是核心难点

放射报告同时包含肯定/否定/不确定三种表述：
- "No evidence of effusion" → 否定（关键词法会误判为"提及"）
- "may represent consolidation" → 不确定
- CheXpert Labeler用依存句法+60条ngrex规则解决，κ>0.6

### 3.3 冲突矩阵：42/62冲突(68%)是"图片↔报告结论"

- HIGH冲突仅3条，全在AI概率≥0.786
- 最主要冲突模式：AI见病灶但报告没提且称正常（42条，68%）
- 胸腔积液冲突最多(15条)，与其AUC最高(0.92)一致

### 3.4 LLM+Guard：Guard后假阳性归零

- 60候选测试：TP 27/30(90%)，Guard前FP 3个，**Guard后FP=0**
- LLM负责语义判定，代码负责数值核验

## 四、差距分析：当前工作缺什么

| 差距 | 现状 | 影响 | 优先级 |
|------|------|------|--------|
| **无ground truth冲突集** | 检出的62条冲突没有人工标注确认 | 无法算precision/recall | 🔴最高 |
| **未用CheXpert Labeler** | 用30字窗口简化版替代 | 文本侧准确率可能偏低 | 🔴高 |
| **未做模型校准** | 未用op_threshs逐病种阈值 | 边界假阳性93%/100% | 🔴高 |
| **FAMDR未跑通** | 只有论文F1=0.83，无本地验证 | SOTA方法未验证 | 🟡中 |
| **CheXagent未接入** | MLLM端到端方法未尝试 | 最新范式未覆盖 | 🟡中 |
| **无跨数据集验证** | 只在NLMCXR 20样本上测 | 泛化性未知 | 🟡中 |
| **CoEV/CLEAR未纳入** | 新发现的2026方法未调研 | 方法谱系不完整 | 🟢低 |

## 五、方案设计：要做什么

### 5.1 总体架构

```
已有图像-报告对
    │
    ├─ 图像侧：TorchXRayVision + 逐病种阈值校准 + 边界带降级
    │   → 每疾病{概率, 阳性/阴性, 确信度}
    │
    ├─ 文本侧：CheXpert Labeler（或30字窗口简化版）
    │   → 每疾病{阳性/否定/不确定/未提及} + report_normal
    │
    ├─ 比对层：三态冲突矩阵
    │   → 5类冲突 + 严重度分级（HIGH/MEDIUM/LOW）
    │
    ├─ 深度复核层：FAMDR / CheXagent（对HIGH冲突做像素/短语级定位）
    │
    └─ 兜底层：LLM+代码Guard（处理前三层遗漏的复杂语义冲突）
```

### 5.2 分阶段执行计划

**阶段一：补齐已验证方法的缺陷（1-2周）**

| 任务 | 具体内容 | 产出 |
|------|---------|------|
| 模型校准 | 把统一0.5改为`model.op_threshs`，加sigmoid+边界带降级 | 消除93%边界假阳性 |
| CheXpert Labeler接入 | Docker部署，替换30字窗口 | 文本侧κ>0.6 |
| Ground truth标注 | 人工抽检20样本的62条冲突，标注真/假阳性 | 算出precision/recall |
| 扩大验证集 | 从NLMCXR 20样本扩到200样本 | 统计显著性 |

**阶段二：接入SOTA方法（2-3周）**

| 任务 | 具体内容 | 产出 |
|------|---------|------|
| FAMDR复现 | 按论文实现4组件（噪声对齐+检索+定位+不确定性） | F1对标0.83 |
| CheXagent接入 | 用CheXagent做HIGH冲突的端到端复核 | MLLM方法验证 |
| CoEV纳入 | 实现双向验证+四象限诊断图 | MICCAI 2026方法覆盖 |

**阶段三：评估体系建立（1周）**

| 任务 | 具体内容 | 产出 |
|------|---------|------|
| CLEAR指标接入 | 5维属性级评估（首次出现/变化/严重度/位置/建议） | 临床对齐评估 |
| 跨数据集验证 | NLMCXR→MIMIC-CXR子集 | 泛化性验证 |

### 5.3 军工迁移路径

医疗验证的"图像AI推理→文本三态标注→冲突矩阵"范式，迁移到军工场景只需替换：
- 图像侧：TorchXRayVision → 领域视觉模型（SARCLIP/监控视觉模型）
- 文本侧：疾病词典+否定词表 → 领域术语词典+否定词表
- 冲突矩阵5种类型和严重度分级逻辑可直接复用

## 七、信息密度标准

每个方法描述必须包含：
1. **具体架构**（模型名+层数+参数+训练数据规模）
2. **具体数字**（AUC/F1/TPR/FPR/κ，附数据集）
3. **技术机制**（怎么做的，不是做什么）
4. **真实结果**（从本地实验数据算出来的发现，不是抄规格表）
5. **与SOTA的关系**（是不是SOTA，比baseline好多少）

**禁止**：科普解释、类比、空话、无数字的论断。
