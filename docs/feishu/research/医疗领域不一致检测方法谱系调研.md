## 二、图像-报告一致性检测方法

### A1. 疾病级冲突矩阵法

**出处**: 工程实践 + `nlmcxr_operators.py`已验证

**解决什么问题**: 胸片图像和放射报告在疾病级别是否矛盾——AI在片子上看到了积液，但报告明确写"No effusion"。

**技术原理**:

将检测分解为三条独立支路，在疾病级别做交叉比对：

```
图像支路: 胸片 → TorchXRayVision DenseNet121 → 18病理logits → sigmoid → 概率
                                                                → 逐病种阈值 → 阳性/阴性

文本支路: 报告 → CheXpert Labeler/30字窗口NER → 14病种四态标注
          (阳性positive / 否定negative / 不确定uncertain / 未提及unmentioned)
          + report_normal标志(报告是否称正常)

比对层:   逐疾病交叉比对 → 5类冲突 + 严重度分级
```

**5类冲突定义**:

| 冲突类型 | 触发条件 | 严重度 | 临床含义 |
|---|---|---|---|
| 图片↔报告否定 | 图阳性 ∧ 报告否定 | HIGH/MED/LOW | AI见病灶但报告明确否认——疑似漏诊 |
| 图片↔报告不确定 | 图阳性 ∧ 报告不确定 | LOW | AI见病灶但报告含糊——需复核 |
| 图片↔报告结论 | 图阳性 ∧ 报告未提及 ∧ 称正常 | MEDIUM | AI见病灶但报告没提且称正常 |
| 报告↔图片 | 图阴性 ∧ 报告阳性 | MEDIUM | 报告称有病但AI没看到 |
| 报告内部 | 报告有阳性病种 ∧ 称正常 | MEDIUM | 报告自相矛盾 |

**严重度分级机制**（关键创新: 由图像AI确信度决定，非写死）：
- 概率 ≥ 0.7 → **HIGH**（AI高度确信有病灶，报告却否认）
- 概率 ≥ 0.55 → **MEDIUM**
- 其他 → **LOW**
- 边界带(概率∈[θ±0.05]) → 降一级

**为什么用四态而非二态**: 报告有"No effusion"（否定）、"may represent consolidation"（不确定）、"associated atelectasis"（肯定）、全文未提edema（未提及）四种表述。纯关键词匹配会把"No effusion"误判为"提到了effusion"——这是假阳性泛滥的根源。

**关键指标**: NLMCXR 20样本检出62条冲突（17份有问题），HIGH 3条全在AI概率≥0.786

**关键缺陷**: 统一0.5阈值导致Pneumothorax 93%假阳性、Consolidation 100%假阳性。根因: TorchXRayVision输出是logit非概率，未做sigmoid且用统一阈值。改进: 用`model.op_threshs`逐病种Youden's J阈值 + 边界带降级。

**适用场景**: 有现成领域图像AI + 领域NER工具的场景。医疗场景的TorchXRayVision+CheXpert Labeler是最成熟的组合。

**局限性**: 只做疾病级整体比对，不定位具体矛盾位置（哪个像素区域与哪句话矛盾）。不检查属性矛盾（"左侧"vs"右侧"）。

### A2. 跨模态对齐评分法

**出处**: CheXzero (You et al., 2022) / MedCLIP (Wang et al., 2022) / CLIP (Radford et al., ICML 2021, arXiv:2103.00020)

**解决什么问题**: 图像和报告是否在整体语义上匹配——粗筛明显不匹配的图文对。

**技术原理**:

用对比学习将图像和文本映射到同一语义空间，计算余弦相似度：

1. **训练阶段**(CheXzero): 在227,835张MIMIC-CXR胸片+报告对上做自监督对比学习
   - 正样本: 真实图文配对
   - 负样本: batch内其他图文组合
   - 损失: InfoNCE = `-log(exp(sim(正)/τ) / Σexp(sim(负)/τ))`
   - 关键: 不需要人工疾病标签，仅靠胸片+报告的自然配对

2. **推理阶段**:
   - 图像 → Vision Transformer → 512维向量 `v_img`
   - 文本 → Text Transformer → 512维向量 `v_text`
   - 相似度 `S = cos(v_img, v_text)`
   - S极低 → 配对可能错误

**MedCLIP的改进**: 标准CLIP要求图文严格配对，MedCLIP**解耦配对约束**——利用unpaired数据（只有图像无报告，或只有报告无图像）增强训练，解决医疗数据配对稀缺问题。

**关键指标**: CheXzero零样本胸片分类接近监督模型；MedCLIP比标准CLIP在医疗图文检索上提升显著

**CLIP的三大局限**（对医疗的影响）:

| 局限 | 技术含义 | 医疗影响 |
|---|---|---|
| Bag-of-Words | 文本当"词袋"，忽略词序 | "左侧积液"和"右侧积液"无法区分 |
| 细粒度差 | 疾病细节区分接近随机 | 不适合疾病级冲突检测 |
| 属性绑定失败 | 多物体时属性绑定不可靠 | 多病共存场景失效 |

**适用场景**: 粗筛层——快速过滤明显不匹配的图文对（如完全无关的图配了报告），再交由更细粒度方法做深度检测。

**局限性**: 只输出一个相似度分数，不输出冲突类型和位置。不适合疾病级冲突检测——AUC 0.92的胸腔积液做冲突检测可信度远高于AUC 0.74的骨折。

### A3. 像素/短语级定位法

#### A3-a. FAMDR (Feature-Aligned Multimodal Denoising)

**出处**: AAAI 2026, DOI:10.1609/aaai.v40i9.37623

**解决什么问题**: 不仅回答"图文是否矛盾"，更回答"**哪个图像区域与哪句话矛盾**"。

**四大组件**:

**组件一: 噪声感知多模态对齐**

传统对齐假设两个模态都"干净"，直接做特征融合。FAMDR反其道而行——**保留差异特征作为冲突线索**：

```
F_img = CNN(胸片) → 图像特征图 [H×W×C]
F_text = BERT(报告) → 文本特征序列 [L×C]
D = |F_img - F_text|  → 差异矩阵
保留 D > τ 的通道 (这些是"不一致信号")
语义连贯性约束: 确保留的"差异"是真矛盾非随机噪声
```

**组件二: 跨模态检索增强**

模糊案例（不确定是否一致）时不硬判，检索外部医学知识辅助：

```
对齐分数 S_align = f(F_img, F_text)
门控 g = f(S_align)  ← S_align越低(越模糊)，g越大
output = g × retrieved_evidence + (1-g) × original_prediction
```

检索源: 放射学术语库、影像生物标志物数据库、类似病例。门控融合机制让模型在高置信时自主判断，低置信时引入外部证据。

**组件三: 像素/短语级噪声定位**

FAMDR区别于粗粒度方法的核心能力:
- **像素级**: 在胸片特征图上用自适应阈值标记噪声区域
  - 例: 右下肺野区域被标记为"与报告矛盾"（类似GradCAM，但针对"不一致区域"）
- **短语级**: 在报告token序列上标记噪声短语
  - 例: "No effusion"中的"effusion"被标记为"与图像矛盾"

**组件四: 不确定性量化**

为每个冲突判定输出置信度:
- 不确定性 = 预测熵 `H = -Σ p(y)·log p(y)`
- 高置信冲突直接报告，低置信标记"需人工复核"

**关键指标**: 扩展MIMIC-CXR F1=**0.83**

**适用场景**: HIGH冲突的深度复核——冲突矩阵先做粗筛检出候选冲突，FAMDR对高严重度冲突做深度复核，定位到具体图像区域和文本短语，输出可解释的冲突证据链。

**与A1的关系**: A1冲突矩阵是规则驱动的粗粒度方法（疾病级，判定有/无冲突），FAMDR是模型驱动的细粒度方法（像素/短语级，定位哪里冲突+为什么冲突）。两者可级联。

#### A3-b. Phrase-grounded Fact-checking

**出处**: MICCAI 2025, arXiv:2509.21356

**解决什么问题**: 胸片报告中疾病发现和位置标注是否准确——专为胸片报告设计的事实检查。

**技术原理**:

1. **合成数据生成**: 通过扰动报告中的**发现**(findings)和**位置**(location)生成训练数据
   - 原始: "右侧胸腔积液" → 扰动1: "左侧胸腔积液"（位置扰动）
   - 原始: "右侧胸腔积液" → 扰动2: "右侧气胸"（发现扰动）

2. **多标签跨模态对比回归网络**:
   - 输入: 胸片图像 + 报告文本
   - 同时预测两个输出:
     - 发现真实性 (findings是否与图像一致)
     - 定位准确性 (位置是否与图像一致)
   - 用对比学习训练: 真实配对 vs 扰动配对

3. **同时预测真实性和定位**: 不仅判断"报告对不对"，还定位"报告描述的发现对应图像哪个区域"

**关键指标**: 与ground truth验证的一致性相关系数**0.997**

**适用场景**: 直接部署做自动化事实检查——检测报告中疾病发现和位置标注的准确性。相关系数0.997意味着模型判断与人工标注几乎完全一致。

**与FAMDR的区别**: FAMDR是通用医学影像不一致定位（4组件架构），Phrase-grounded是胸片报告专用（扰动+对比回归）。Phrase-grounded更轻量、更专精。

### A4. 端到端联合推理法

#### A4-a. CheXagent

**出处**: Chen et al., arXiv:2401.12208, Stanford, 2024

**解决什么问题**: 让一个模型同时"看图+读文+做推理"，直接输出"图和报告是否一致"——模拟放射科医生同时看片子和报告的判断过程。

**技术原理**:

CheXagent是为胸片解读训练的**视觉-语言基础模型**，在大规模CheXinstruct数据集上训练，可执行8类任务（图像理解/报告生成/报告质量评估等）。

```
输入: 胸片图像 + 报告文本
  ↓ 联合编码(cross-attention做图文交互)
  ↓ 推理(模型内部隐式对齐)
输出: 一致性判断 + 自然语言解释
```

**关键指标**: 8名放射科医生评估，使用CheXagent起草的报告，住院医生节省**36%时间**，主治医生在81%的病例中效率提升且不损失质量

**适用场景**: HIGH冲突的端到端复核层——捕获分段式方法（A1冲突矩阵）遗漏的交互型不一致。

**与A1的区别**: A1是分段式（图像AI+NER+规则比对各自独立），CheXagent是端到端（一个模型联合推理）。分段式可解释性高但丢失图文交互信息，端到端捕获交互但黑盒。

---

#### A4-b. VDC (Versatile Data Cleanser)

**出处**: ICLR 2024, arXiv:2309.16211

**解决什么问题**: 通用脏数据清洗——各类脏数据的共同特征是"视觉-语言不一致"。

**三段式架构**:

```
VQG(视觉问题生成): 基于标签用ChatGPT生成关于图像的问题
  → 每个标签生成2个general + 4-6个label-specific问题
  → 例: 标签"胸腔积液" → "图像中是否有胸腔积液？" "积液在左侧还是右侧？"

VQA(视觉问答): 用InstructBLIP/MLLM看图回答这些问题
  → 获取图像语义(不依赖标签，从图像直接提取)

VAE(视觉答案评估): 字符串匹配 + ChatGPT评估回答正确性
  → 一致性分数 = 正确回答数 / 总问题数
  → 阈值α=0.5: 低于阈值=脏数据(图文不一致)
```

**关键指标**: CIFAR-10毒化样本 TPR **99.91%** / FPR **2.75%**

**适用场景**: 通用兜底——处理前几层遗漏的复杂语义冲突。已可在本地用Qwen2.5-VL-7B通过vLLM部署。

**与CheXagent的区别**: VDC是三段式流水线（提问-回答-评分），CheXagent是单模型端到端。VDC更模块化可替换组件，CheXagent更一体化但难替换。

## 三、报告内一致性检测方法

### B1. 分段NLI矛盾检测法

**解决什么问题**: 放射报告的Findings段（客观发现）和Impression段（主观结论）可能矛盾——正文写了胸腔积液，结论却说正常。

**技术原理**:

将报告内矛盾检测建模为**自然语言推理(NLI)**问题:

```
Findings段 → 提取为"前提"(premise)
Impression段 → 提取为"假设"(hypothesis)
  ↓ NLI三分类
  → 蕴含(entailment): Findings支持Impression → 一致
  → 矛盾(contradiction): Findings否定Impression → 内部矛盾
  → 中立(neutral): 两者无关 → 需人工判断
```

**CheXpert的分段策略**: `--sections_to_extract`参数可指定只分析Findings/Impression段。CheXpert论文证实**Impression段标注一致性最高、噪声最低**，Labeler默认优先分析Impression段。

**仓库原型实现**: `nlmcxr_operators.py:ImageReportConflictFilter`检测"报告有阳性病种 ∧ report_normal=True"——report_normal通过短语匹配判定(`clear`/`no acute`/`no active`/`unremarkable`/`within normal`/`heart size normal`)。NLMCXR 20样本实测检出4条报告内部矛盾。

**适用场景**: 任何有结构化分段的报告——放射报告、病理报告、手术报告。

### B2. 三态聚合一致性法

**出处**: CheXpert Labeler Aggregator (AAAI 2019)

**解决什么问题**: 同一篇报告内，同一疾病可能出现多次且状态不同——"no effusion"在第2句，但"effusion present"在第5句，最终该标什么？

**技术原理**:

CheXpert Labeler的**Aggregator**阶段将一篇报告内多个mention合并为该疾病单一标签，按**优先级聚合**:

```
同一疾病的所有mention → 按状态优先级聚合:
  若任一mention = POSITIVE → 最终标 POSITIVE(1)  ← 阳性优先
  否则若任一mention = UNCERTAIN → 最终标 UNCERTAIN(-1)
  否则若任一mention = NEGATIVE → 最终标 NEGATIVE(0)
  否则 → UNMENTIONED(空)
```

**聚合冲突检测**: 如果报告内同时出现"no effusion"(否定)和"effusion present"(阳性)，Aggregator会标为POSITIVE——但这本身说明**报告内部存在表述矛盾**。可以检测: 聚合过程中是否消解了不同状态的mention → 若是，标记为"报告内表述不一致"。

**关键指标**: CheXpert Labeler与放射科医生一致性κ>0.6

**适用场景**: 任何用CheXpert Labeler提取标签的场景——聚合冲突可作为报告质量信号。

### B3. 逻辑推理链验证法

**出处**: NeuroSymb-MRG (arXiv:2603.01756, 2026)

**解决什么问题**: 报告的逻辑推理链是否完整——如果Findings提了"胸腔积液"，Impression应该推理出可能的并发症（如肺不张），如果推理链断裂说明逻辑不一致。

**技术原理**:

将神经符号推理(NeuroSymbolic)与溯因推理(abductive reasoning)结合:

```
Step 1: 图像特征 → 概率临床概念
  胸片CNN特征 → 映射到概率化概念 {胸腔积液:0.85, 肺不张:0.62}

Step 2: 可微分逻辑推理链
  前提1: 胸腔积液(0.85)
  前提2: 积液可导致肺不张 (领域知识规则)
  推理: 可能存在肺不张(0.85×0.62=0.527)
  → 生成推理链: 积液 →(导致)→ 肺不张

Step 3: 模板子句 → 检索+约束编辑 → 最终报告

Step 4: 主动采样循环
  规则级不确定性驱动 → 对不确定的推理步骤主动采样更多信息
```

**如何检测不一致**: 如果推理链断裂（如"积液"推理到"肺不张"但Impression只提了"积液"没提"肺不张"），说明存在逻辑矛盾——Findings与Impression之间的因果推理不完整。

**关键指标**: 在标准基准上事实一致性持续提升

**适用场景**: 需要验证报告逻辑完整性的场景——特别适合复杂多病共存报告的逻辑一致性检查。

## 四、标签一致性检测方法

### C1. 双重prompt标签检测法 (DeFT)

**出处**: NeurIPS 2024, arXiv:2409.19696

**解决什么问题**: CheXpert标签是从报告NLP提取的，提取过程引入噪声——标签标注"肺炎"但片子可能并无肺炎。如何检测标签-图像不匹配？

**技术原理**:

DeFT (Denoising Fine-Tuning) 两阶段框架，核心创新是为每个类别学习**双重文本prompt**:

**Phase 1 (噪声标签检测)**:

```
为每个疾病类别学习两个prompt:
  Positive prompt: 揭示类别区分性特征
    → "A chest X-ray showing pleural effusion"
  Negative prompt: 作为可学习阈值区分clean/noisy
    → (学习得到的负向描述)

计算样本与正/负prompt的CLIP相似度:
  sim_pos = cos(clip_image(x), clip_text(positive_prompt))
  sim_neg = cos(clip_image(x), clip_text(negative_prompt))

clean概率 = softmax([sim_pos, sim_neg])
若 sim_pos > sim_neg → 判定为clean样本
若 sim_pos < sim_neg → 判定为noisy样本(标签错误)

用PEFT(Visual Prompt Tuning)适配视觉编码器
  → 避免FFT在噪声下扭曲表征
损失 = L_dp(双prompt检测损失, 含正学习+负学习) + L_sim(正prompt对齐损失)
```

**Phase 2 (模型适配)**: 用Phase 1筛选出的clean样本做全量微调(FFT)。

**关键指标**: 7个数据集样本选择P/R = **85.81% / 85.72%**；Clothing1M比TURN提升4.51%

**为什么不用训练动态检测**: 传统噪声检测依赖loss大小(loss大的可能是噪声)，但有self-confirmation bias——模型会逐渐适应噪声。DeFT用CLIP的视觉-文本对齐能力做零样本判断，不依赖训练动态。

**适用场景**: 检测CheXpert/MIMIC-CXR标签噪声——为每个疾病标签学习正/负prompt，判断标签是否正确。

---

### C2. 零样本标签清洗法 (CLIPCleaner)

**出处**: ACMMM 2024, arXiv:2408.10012

**解决什么问题**: 不训练任何模型，直接用CLIP零样本能力清洗标签噪声。

**技术原理**:

```
对每个样本:
  1. 构建类别文本prompt: "a photo of {class_name}"
  2. 计算图像与所有类别prompt的CLIP相似度
  3. 按相似度排序选top-k作为clean样本
  4. 相似度低的样本标记为noisy
```

**关键指标**: Clothing1M 74.83%清洗准确率

**与DeFT的区别**: CLIPCleaner无需训练（纯零样本），DeFT需学习prompt但有更高精度。CLIPCleaner适合快速原型，DeFT适合生产部署。

### C3. 置信学习法 (Cleanlab)

**出处**: JAIR 2021, arXiv:1911.00068

**解决什么问题**: 估计标签噪声率并自动识别错误标签——不需任何先验知识。

**技术原理**:

```
1. 用交叉验证获得每个样本的预测概率矩阵 P(ŷ|y)
   → P是|样本数|×|类别数|的矩阵

2. 估计噪声标签与真实标签的联合分布 P(y~, y)
   → y~ = 给定(噪声)标签, y = 真实标签
   → 通过置信度阈值过滤off-diagonal entries

3. 排序识别噪声样本
   → 对每个类别，按预测概率排序
   → 概率最低的样本最可能是噪声
```

**关键指标**: 仓库已验证✅

**适用场景**: 任何分类任务的标签噪声检测——不依赖多模态，只需模型预测概率。

### C4. 标签互斥约束法

**出处**: 仓库 `medical_operators.py:DiagnosisConsistencyFilter` 已验证

**解决什么问题**: CheXpert 14病种中"No Finding"(无异常)与其他诊断标签逻辑互斥——"无异常"和"胸腔积液"不能同时为阳性。

**技术原理**:

```
规则1: No Finding=1 ∧ 其他任一诊断=1 → 互斥冲突 (HIGH)
规则2: No Finding=1 ∧ 其他诊断=-1(不确定) → 潜在冲突 (MEDIUM)
规则3: 同一标签值非{1,0,-1} → 编码异常 (LOW)
```

**关键指标**: MedTVT 10k样本中No Finding阳性=1368例，其中部分与其他诊断阳性共存→互斥冲突

**适用场景**: 任何有互斥约束的标签体系——医疗诊断分类特有。

## 五、临床知识一致性检测方法

### D1. 三层规则库法

**出处**: 仓库 `medical_operators.py` + `knowledge/medical_kb.json` 已验证

**解决什么问题**: 血检指标与诊断标签是否矛盾——乳酸>5.0(严重酸中毒)但诊断标签="No Finding"(无异常)→漏诊冲突。

**三层递进结构**:

```
L1 单指标范围检测 (MedicalLabRangeFilter):
  50项血检指标 × 临床参考范围(UpToDate/Mayo Clinic)
  → 乳酸: normal [0.5, 2.0] mmol/L
  → 超范围: 2.0→MEDIUM, 5.0→CRITICAL
  → 输出: 异常项列表 + 严重度
  → 实测: 1000异常/10k样本

L2 血检↔诊断冲突 (LabDiagnosisConflictFilter):
  5条规则: 血检严重异常 ∧ 诊断=No Finding → 漏诊冲突
  → 乳酸>5.0 ∧ No Finding → 乳酸酸中毒漏诊 (CRITICAL)
  → 肌酐>2.0 ∧ No Finding → 肾功能异常漏诊 (HIGH)
  → 血糖>300 ∧ No Finding → 高血糖漏诊 (MEDIUM)
  → 钾>6.0 ∧ No Finding → 高钾血症漏诊 (CRITICAL)
  → pH<7.20 ∧ No Finding → 严重酸中毒漏诊 (CRITICAL)
  → 实测: 1368冲突/10k样本

L3 多指标协同检测 (CrossLabConsistencyFilter):
  5条规则: 多指标组合异常 → 综合征
  → 乳酸>5.0 ∧ pH<7.35 → 乳酸酸中毒伴酸血症 (CRITICAL)
  → 血糖>300 ∧ pH<7.35 → DKA样代谢性酸中毒 (CRITICAL)
  → 肌酐>2.0 ∧ 钾>6.0 → 肾衰竭伴高钾血症 (CRITICAL)
  → 血糖>300 ∧ 钾>6.0 → 多代谢异常 (HIGH)
  → 肌酐>2.0 ∧ 乳酸>5.0 → 多器官损害 (CRITICAL)
```

**规则库JSON结构** (`medical_kb.json`):
```json
{
  "L1_lab_ranges": {"50893": {"name_cn":"乳酸", "normal_low":0.5, "normal_high":2.0,
    "severity_high":[{"threshold":2.0,"level":"MEDIUM"},{"threshold":5.0,"level":"CRITICAL"}]}},
  "L2_lab_diagnosis_rules": [{"itemid":"50893","op":">","threshold":5.0,
    "conflict_if":"No Finding","severity":"CRITICAL"}],
  "L3_cross_lab_rules": [{"name":"乳酸酸中毒伴酸血症",
    "conditions":[{"itemid":"50893","op":">","val":5.0},{"itemid":"50820","op":"<","val":7.35}],
    "severity":"CRITICAL"}]
}
```

**关键指标**: 1444冲突/10k样本（14.4%冲突率）

**适用场景**: 有明确临床参考范围的检验指标 + 诊断标签的场景。规则库可迁移到军用场景——换GJB参数约束规则。

### D2. LLM+代码Guard法

**出处**: 仓库 `unified_operators.py:_llm_detect_medical` 已验证

**解决什么问题**: 规则库难以覆盖的复杂语义冲突——如"血糖180是否算严重"需结合上下文判断，纯规则不够灵活。

**技术原理**:

```
LLM语义判定: 输入图像AI分析结果+报告文本 → LLM判断是否一致
  → LLM输出: is_conflict=true/false + 原因

代码数值核验(Guard): LLM判定is_conflict=true时
  → 代码核验: 真实数值是否真的达到严重阈值？
  → 是 → 保留冲突
  → 否 → 丢弃(判定为LLM幻觉)
```

**关键发现**: LLM对数字比较不可靠——会把正常值报为冲突、混淆数值方向。

**实测效果** (60候选样本, 5项指标各12个):

| 指标 | 应检出 | LLM正确 | Guard前误报 | **Guard后误报** |
|---|---|---|---|---|
| 乳酸 | 6 | 6 | 0 | **0** |
| 肌酐 | 6 | 5 | 0 | **0** |
| 血糖 | 6 | 6 | 2 | **0** |
| 钾 | 6 | 4 | 1 | **0** |
| pH | 6 | 6 | 0 | **0** |

**加Guard后误报归零**。LLM负责语义理解，代码负责数值核验——"LLM+规则"混合架构的工程范式。

### D3. KG约束传播法 (KGDMC)

**出处**: ACM 2025, DOI:10.1145/3696410.3714813

**解决什么问题**: 知识图谱中没有显式"contradicts"矛盾边——KG的真实用法是**规范化+关系推理**，配合多粒度置信度做矛盾判断。

**技术原理**:

**组件一: 解耦VAE模块(DMR)**
- 将每个模态数据解耦为**模态特定**和**模态不变**特征空间
- 用准确的文本模态不变特征 → 指导可疑视觉模态信息的跨模态重构
- 重构误差大 = 视觉模态可能有误

**组件二: 多粒度三元组置信度(MTC)**

三层评估事实自洽性:

```
局部三元组层: 单个(头实体, 关系, 尾实体)三元组的置信度
  → 例: (肌酐>2.0, indicates, 肾功能异常) 的置信度

全局邻居层: 三元组在KG中的邻居结构一致性
  → 例: "肾功能异常"的邻居(并发症/治疗方法)是否也一致

全局路径层: 从诊断到证据的多跳推理路径置信度
  → 例: 肌酐>2.0 →(导致)→ 肾衰 →(并发症)→ 高钾 → 检验是否与数据一致
```

**适用场景**: 有医学知识图谱(UMLS/SNOMED CT)的场景——三层评估可迁移到医疗: 局部(单个疾病-症状三元组)→全局邻居(相关并发症)→全局路径(诊断推理链)。

### D4. 神经符号多层验证法 (Hybrid-Code v2)

**出处**: arXiv:2512.23743, 2026

**解决什么问题**: 纯神经方法（如ClinicalBERT/BioBERT/GPT-4）在ICD-10编码任务中产生6-18%的幻觉（生成无效或不支持的编码），在安全关键临床场景中不可接受。纯规则系统消除幻觉但覆盖率低。如何兼顾零幻觉和高覆盖？

**技术原理**:

Hybrid-Code v2是**神经符号框架**——神经候选生成 + 符号KB验证层，通过多层验证实现零I型幻觉(Type-I hallucination, 即生成无效编码)：

```
Step 1: 神经候选生成
  临床文本 → 神经模型(ClinicalBERT/BioBERT) → ICD-10候选编码列表
  → 高召回但不保证正确性

Step 2: 符号KB验证层(5层验证)
  ① 格式验证(format): 候选编码是否符合ICD-10格式规范
  ② 证据接地验证(evidence grounding): 编码是否有临床文本证据支持
  ③ 否定检测(negation detection): 证据是否被否定("no evidence of..."不算支持)
  ④ 时序一致性(temporal consistency): 编码与患者时序信息是否矛盾
  ⑤ 排除规则(exclusion rules): 编码是否违反互斥约束(如某些编码不能共存)

Step 3: 自动KB扩展
  从无标签临床文本提取和验证编码模式
  → 解决规则系统的人工KB维护瓶颈
  → 新模式经验证后加入KB
```

**关键指标**: MIMIC-III上 85%覆盖率、92%精确率、**0% I型幻觉**。比纯规则系统+40%覆盖率，消除神经基线6-18%幻觉。

**核心创新**: 形式化安全保证(formal safety guarantee)——符号验证层保证输出的编码在语法上有效，神经层提供高覆盖。这是"安全约束下的有效性"设计模式。

**适用场景**: 任何需要零幻觉保证的临床编码/分类任务——ICD编码、SNOMED CT编码、LOINC检验编码。可迁移到军用场景的GJB标准条文编码验证。

**与D1/D2的区别**: D1三层规则库是纯规则(确定性高但覆盖有限)，D2 LLM+Guard是LLM+代码(灵活但LLM可能幻觉)，D4是神经+符号(神经提供高覆盖+符号保证零幻觉)。

### D5. 临床知识嵌入LLM审查法

**出处**: Li et al., "Reviewing Clinical Knowledge in Medical Large Language Models", Knowledge-Based Systems 2025, arXiv:2502.20988

**解决什么问题**: 医疗LLM如何获取和验证临床知识？临床知识(病因/预后/诊断/治疗)如何嵌入模型并保证可追溯？

**三种临床知识嵌入路径**:

```
路径1: 训练式嵌入(training-based)
  临床知识 → 专用训练数据集 → 模型微调
  → 知识隐式编码在模型参数中
  → 问题: 知识不可追溯、不可审计、可能过时

路径2: 知识图谱支持(KG-supported)
  临床知识 → 医学KG(UMLS/SNOMED CT/DrugBank)
  → 模型推理时查询KG
  → KG提供显式可追溯的知识来源
  → 问题: KG覆盖不全、查询延迟

路径3: 检索增强生成(RAG-assisted)
  临床知识 → 向量数据库(临床指南/文献)
  → 模型推理时检索相关文档
  → 检索结果作为上下文输入
  → 问题: 检索质量依赖embedding、可能检索到过时信息
```

**知识来源分层**:

| 层级 | 来源 | 可靠度 | 示例 |
|---|---|---|---|
| L1 | 临床指南(UpToDate/Mayo) | **最高** | "乳酸>5 mmol/L提示严重酸中毒" |
| L2 | 医学KG(UMLS/SNOMED CT) | 高 | 疾病-症状-药物关系 |
| L3 | 临床文献(PubMed) | 中 | 最新研究证据 |
| L4 | 临床数据集(MIMIC) | 中 | 数据驱动的统计规律 |
| L5 | LLM内部知识 | **最低** | 模型预训练获得，可能过时/错误 |

**不一致检测应用**: 将LLM输出与L1-L4的外部知识源做交叉验证——如果LLM诊断与临床指南(L1)矛盾，或与KG(L2)中定义的疾病关系矛盾，标记为知识不一致。

**适用场景**: 任何医疗LLM的知识一致性验证——特别是诊断建议、药物推荐等安全关键场景。

### D6. LLM编排合规性检查法

**出处**: arXiv:2606.09489, 2026

**解决什么问题**: 传统临床合规性检查需要预先将临床指南形式化为计算机可解释指南(CIG)，但CIG构建成本高、维护难。能否用LLM直接做合规性检查，不需要CIG？

**技术原理**:

```
传统方式:
  临床指南(PDF) → 人工形式化 → CIG(GLIF/SAGE格式) → 执行引擎 → 合规性报告
  → 问题: 形式化耗时数月，指南更新需重新形式化

LLM编排方式:
  临床指南(PDF) → LLM直接阅读理解
  + 患者临床数据(EHR)
  → LLM编排: 提取指南中的规则 → 与患者数据比对 → 生成合规性报告
  → 无需CIG形式化，指南更新时LLM直接重新阅读
```

**合规性检查内容**:
- 患者治疗路径是否符合指南推荐
- 用药剂量/频率是否在指南范围内
- 检查项目是否按指南时机执行
- 诊断结论是否与检查结果一致

**适用场景**: 临床路径偏差检测——检测实际诊疗过程与临床指南的偏离。可迁移到军用场景的GJB合规性检查。

### D7. RadGraph实体-关系奖励法

**出处**: Delbrouck et al., "Improving the Factual Correctness of Radiology Report Generation with Semantic Rewards", EMNLP 2022 Findings, arXiv:2210.12186

**解决什么问题**: 放射报告生成系统在BLEU/CIDEr等NLG指标上表现好，但生成内容在事实上不完整或不一致——如何用结构化知识验证生成报告的事实正确性？

**技术原理**:

利用**RadGraph数据集**（胸片报告的实体+关系标注）构建语义奖励:

```
Step 1: RadGraph实体-关系标注
  报告 → RadGraph标注 → 实体节点(疾病/解剖位置/设备)
                       + 关系边(位于/导致/提示)

Step 2: 语义奖励计算
  奖励1 - 实体一致性: 生成报告的实体集合 vs 参考报告的实体集合
    → 鼓励生成与参考一致的放射领域实体

  奖励2 - 关系一致性: 实体间关系是否推理一致
    → 用NLI判断实体描述是否蕴含一致

  奖励3 - BERTScore: 语义等价度

Step 3: 强化学习优化
  三个奖励组合 → RL训练报告生成模型
```

**关键指标**: 事实正确性和完整性提升**14.2%和25.3%**

**与B1 NLI矛盾检测的关系**: RadGraph奖励法是训练时方法（优化生成模型使其事实一致），B1 NLI矛盾检测是推理时方法（检测已有报告的内部矛盾）。两者互补: RadGraph从源头减少不一致，B1在末端检测不一致。

**适用场景**: 报告生成系统的事实一致性训练——用结构化实体-关系知识作为奖励信号，引导模型生成事实正确的报告。

## 六、生成幻觉检测方法

### E1. 8类幻觉分类检测法 (HalluCXR)

**出处**: arXiv:2605.20469, 2026

**解决什么问题**: 医学VLM生成的报告含哪些类型的幻觉？临床严重度如何？

**技术原理**:

1. **数据构建**: 856张MIMIC-CXR胸片，3种查询类型，15,408次模型评估
2. **8类幻觉分类 + 临床严重度评分**:

| 幻觉类型 | 含义 | 医疗场景实例 |
|---|---|---|
| Attribute | 属性错误 | "左侧积液"实际在右侧 |
| Object | 对象错误 | 报告提到不存在的病灶 |
| Number | 数量错误 | "一个病灶"实际两个 |
| Location | 位置错误 | 解剖位置标错 |
| Illusion | 错觉 | 将正常结构误读为病灶 |
| Direction | 方向错误 | 左右搞反 |
| Text | 文本错误 | 术语拼写/用词错误 |
| Relation | 关系错误 | 因果关系错误 |

3. **两层检测pipeline**: 第一层粗筛 + 第二层精检
4. **关键发现**:
   - 61.9-82.3%的输出含幻觉
   - **正常胸片反而吸引最严重幻觉**——AI倾向对正常片子"过度诊断"
   - 响应长度可预测幻觉风险（AUC 0.908）
   - 检测器在Direction和Number类上表现最差

**适用场景**: 评估医学VLM的幻觉风险——8类分类法可直接用于医学数据集质量审计。

### E2. 语义熵不确定性法

#### E2-a. DSE (Discrete Semantic Entropy)

**出处**: Eur Radiol 2026, arXiv:2510.09256

**解决什么问题**: AI对某个图文对的判断是否可信——如果AI多次回答不一致，说明这个图文对存在模糊/争议/冲突。

**技术原理**:

```
Step 1: GPT-4o对每个问题回答15次 (温度1.0, 引入随机性)

Step 2: 双向蕴含检查(bidirectional entailment check)聚类
  回答A="胸腔积液" vs 回答B="pleural effusion" → 双向蕴含 → 同一聚类
  回答A="有积液" vs 回答C="无积液" → 矛盾 → 不同聚类

Step 3: 计算离散语义熵
  DSE = -Σ p(cluster) · log p(cluster)

Step 4: DSE > 0.3 → 高熵 → 标记"模糊/可能冲突"
```

**关键指标**: DSE>0.3过滤后，GPT-4o准确率从**51.7%→76.3%**

**适用场景**: 检测数据集中"模糊/有争议"的图文对——高熵=不确定=可能存在冲突。特别适合检测"may represent"这类不确定表述。

---

#### E2-b. UniVRSE (ALFA原子事实对齐)

**出处**: arXiv:2503.20504, 2025

**解决什么问题**: 将报告分解为原子事实，逐条验证与图像的一致性——比整体比对更精细。

**技术原理**:

两个核心组件:

**1. 视觉条件化语义熵**:
```
原始图+报告 → AI预测分布P₁
扭曲图(模糊/遮挡/旋转)+报告 → AI预测分布P₂
若P₁≈P₂ → AI没真正"看图"(幻觉风险高)
若P₁≠P₂ → AI确实依赖图像内容
```

**2. ALFA (Atomic Facts Alignment ratio)**:
```
报告"心影增大。右侧胸腔积液。左肺清晰。"
  → 分解为3个原子事实:
    原子事实1: "心影增大" → 与图像验证 → 一致/矛盾
    原子事实2: "右侧胸腔积液" → 与图像验证 → 一致/矛盾
    原子事实3: "左肺清晰" → 与图像验证 → 一致/矛盾
ALFA = 一致原子事实数 / 总原子事实数
```

**关键指标**: 在6个医学VQA/VRG数据集上显著超越基线

**与DSE的区别**: DSE做整体语义熵(多次采样一致性)，UniVRSE做原子事实级对齐(逐条验证)。UniVRSE更精细——能定位到"哪句话矛盾"。

---

### E3. 双向证据验证法 (CoEV)

**出处**: MICCAI 2026, arXiv:2606.18609

**解决什么问题**: 单向验证(只检查"文本说的在图像中是否有证据")会遗漏"图像中的证据在文本中是否被提及"——需要双向验证。

**技术原理**:

```
方向1: 文本断言 → 视觉证据验证 (Text→Vision)
  从报告提取文本断言: "右侧胸腔积液"
  在图像中搜索该断言的视觉证据区域
  判断视觉证据是否支持该断言

方向2: 视觉证据 → 文本断言验证 (Vision→Text)
  从图像提取视觉证据区域 (AI检出的病灶区域)
  检查这些视觉证据在文本中是否有对应断言
  判断文本是否提及了所有视觉证据

四象限诊断图:
                    视觉接地(Vision Grounded) | 视觉未接地(Not Grounded)
文本事实性=True     | Q1: 一致                  | Q2: 漏写(文本说有,图找不到)
文本事实性=False    | Q3: 矛盾                  | Q4: 无关(文本虚假,图也无证据)
```

- Q1=一致, Q3=矛盾(否定矛盾), Q2=漏写(实体多余), Q4=无关
- 每条断言被分到四象限之一 → 生成诊断报告

**关键指标**: PR-AUC +3.0%, ROC-AUC +3.9%, 特定VQA场景提升达**18.5%**

**适用场景**: 四象限诊断图可作为数据质量标签——"文本虚假+视觉未接地"(Q4)的数据应标记为冲突。

### E4. 反事实扰动法 (Counterfactual Visual Grounding)

**出处**: arXiv:2606.28520, 2026

**解决什么问题**: AI是否真正"看到"了实体——如果AI对"胸腔积液"和"气胸"给出相同的视觉定位区域，说明它在"幻觉"。

**技术原理**:

```
Step 1: 从LVLM响应中提取可验证实体 (如"胸腔积液""肺不张")

Step 2: 视觉定位
  用医学Qwen-VL定位每个实体在图像中的位置
  → 事实定位: 定位"胸腔积液" → 得到定位结果R₁

Step 3: 反事实扰动
  将实体替换为反事实实体
  → 反事实定位: 定位"气胸" → 得到定位结果R₂

Step 4: 不确定性计算
  若R₁≈R₂ → AI对"胸腔积液"和"气胸"给出相同定位 → 高不确定性 → 幻觉风险
  若R₁≠R₂ → AI确实区分了两个实体 → 低风险
```

**核心洞察**: 如果AI对不同实体给出相同的视觉定位，说明AI没有真正理解实体含义——它在"幻觉"。

**关键指标**: 在多种医学成像模态和LVLM骨干上持续提升幻觉检测性能

**适用场景**: 检测"报告标注了不存在的病灶"这类冲突——反事实扰动可发现虚假标注。

---

### E5. 幻觉成因分类基准法 (MedHEval)

**出处**: Chang et al., arXiv:2503.02157, 2025

**解决什么问题**: 现有幻觉基准只检测"有没有幻觉"，不分析"为什么产生幻觉"。不同成因的幻觉需要不同的缓解策略——视觉误判和知识缺乏需要完全不同的解决方案。

**技术原理**:

将医学VLM幻觉按**根本成因**分为3类:

```
成因1: 视觉误判(Visual Misinterpretation)
  → AI看到了图像内容但理解错误
  → 例: 将正常结构误读为病灶
  → 缓解方向: 增强视觉理解能力

成因2: 知识缺乏(Knowledge Deficiency)
  → AI没有足够的医学知识做出正确判断
  → 例: 不了解某疾病的影像特征
  → 缓解方向: 注入临床知识(D5方法)

成因3: 上下文错位(Context Misalignment)
  → AI的回答与问题上下文不匹配
  → 例: 问左肺情况，答右肺
  → 缓解方向: 增强上下文理解
```

**评估设计**:
- 构建close-ended和open-ended医疗VQA数据集
- 11个流行(Med)-LVLM评估
- 7种SOTA幻觉缓解技术评估
- **关键发现**: 现有缓解方法对知识型和上下文型错误效果有限——需要改进对齐训练和专门缓解策略

**适用场景**: 幻觉诊断——先用MedHEval诊断幻觉成因，再选对应缓解策略。视觉误判→VGS-Decoding(E7)；知识缺乏→RAG(D5)；上下文错位→Med-VCD(E8)。

### E6. 语义一致性不确定性量化法 (SC-UQ)

**出处**: Wang et al., arXiv:2412.04606, 2025

**解决什么问题**: 放射报告生成模型会产生幻觉，但如何在不修改模型、不访问模型内部状态(如logits)的情况下检测幻觉？

**技术原理**:

**即插即用(plug-and-play)**的不确定性量化框架——不需要修改底层模型或访问内部状态:

```
Step 1: 多次采样
  对同一胸片，模型生成报告N次(不同温度/随机种子)
  → 得到N个报告变体

Step 2: 语义一致性计算
  报告级: N个报告变体间的语义相似度
    → 用NLI双向蕴含检查判断语义等价
    → 高一致性=低不确定性=可信
    → 低一致性=高不确定性=可能有幻觉

  句子级: 对每个句子，检查其在N个变体中的语义一致性
    → 标记最低一致性的句子为"最可能幻觉句子"

Step 3: 弃权策略
  报告级不确定性 > 阈值 → 拒绝该报告(弃权)
  → 弃权的高不确定性报告由人工复核
```

**关键指标**: MIMIC-CXR + Radialog模型，拒绝20%报告可提高事实性**10%**；句子级不确定性以**82.9%**成功率标记最低精确度的句子。

**与E2 DSE的区别**: DSE对VQA回答做语义熵(单句)，SC-UQ对报告生成做报告级+句子级不确定性(整篇报告)。SC-UQ不需要访问模型内部状态，真正的即插即用。

**适用场景**: 任何放射报告生成系统的不确定性量化——作为后处理模块，不修改原模型。高不确定性报告转人工复核。

### E7. 视觉接地分数引导解码法 (VGS-Decoding)

**出处**: Kolli et al., arXiv:2603.20314, 2026

**解决什么问题**: 医学VLM生成报告时依赖语言先验而非视觉证据——生成的文字"听起来像放射报告"但与实际图像不符。如何在解码阶段抑制这种幻觉？

**核心洞察**:

```
幻觉token: 当视觉信息退化(模糊/遮挡)时，概率保持或增加
  → 因为它依赖语言先验而非视觉证据
  → 视觉退化不影响语言先验

视觉接地token: 当视觉信息退化时，概率下降
  → 因为它依赖视觉证据
  → 视觉退化导致证据丢失
```

**技术原理**:

```
Step 1: 计算视觉接地分数(VGS)
  对每个生成token t:
    P_orig(t) = 模型在原始图像上的token概率
    P_dist(t) = 模型在退化图像上的token概率
    VGS(t) = P_orig(t) - P_dist(t)
    → VGS > 0: token依赖视觉(接地) → 应放大
    → VGS ≤ 0: token不依赖视觉(幻觉) → 应抑制

Step 2: 自适应解码
  P_final(t) = P_orig(t) × (1 + α × VGS(t))
  → α为自适应权重
  → 与固定权重对比解码不同: VGS提供per-token自适应控制
  → 视觉接地的token被放大，幻觉token被抑制
```

**关键指标**: MIMIC-Diff-VQA和VQA-RAD上，LLaVA-Med/CheXagent/MedGemma均一致提升，最高**+9.12%**整体提升、**+8.98%**开放召回。仅**2×推理开销**(需额外一次退化图像前向传播)，无需训练。

**与E4反事实扰动的区别**: 反事实扰动替换实体检测幻觉(实体级)，VGS-Decoding在解码时逐token调整概率(token级)。反事实是检测方法(事后)，VGS是缓解方法(事中)。

**适用场景**: 医学VLM推理时的实时幻觉缓解——训练免费、低开销，适合临床部署。

### E8. 稀疏视觉对比解码法 (Med-VCD)

**出处**: Mahdavi et al., arXiv:2512.01922, Computers in Biology and Medicine 2026

**解决什么问题**: 现有对比解码方法需要二次解码(先正常解码再对比解码)，推理速度慢。如何在无二次解码开销的情况下缓解幻觉？

**技术原理**:

```
Step 1: Token稀疏化(token-sparsification)
  在解码过程中，实时选择"视觉信息token"
  → 裁剪冗余token(如停用词/模板词)
  → 保留关键视觉token(如疾病名/解剖位置)
  → 平衡效率与可靠性

Step 2: 视觉对比解码(无需二次解码)
  在单次解码过程中:
  → 正常解码路径: 基于完整图像
  → 对比解码路径: 基于退化/遮蔽图像(共享同一前向传播)
  → 两条路径在同一解码步骤中并行计算
  → 对比分数 = 正常路径概率 - 退化路径概率
  → 放大对比分数高的token(视觉接地的)

Step 3: 稀疏化+对比解码融合
  只对"视觉信息token"做对比解码
  → 冗余token直接用正常路径
  → 减少计算开销
```

**关键指标**: 8个医学数据集(眼科/放射/病理)，事实准确率平均**+13%**，幻觉准确率**+6%**。

**与E7 VGS-Decoding的区别**: VGS做per-token自适应权重(需要额外退化图像前向传播,2×开销)，Med-VCD做token稀疏化+单次解码对比(无额外前向传播)。Med-VCD更快但精度略低。

**适用场景**: 对推理速度要求高的场景——实时放射报告生成。

### E9. 实体一致性+NLI奖励法

**出处**: Miura et al., "Improving Factual Completeness and Consistency of Image-to-Text Radiology Report Generation", NAACL 2021, arXiv:2010.10042

**解决什么问题**: 报告生成系统在BLEU/CIDEr等NLG指标上表现好，但生成内容事实不完整(遗漏疾病)或不一致(描述矛盾)。NLG指标无法衡量事实正确性。

**技术原理**:

设计两个简单但有效的奖励，用强化学习优化:

```
奖励1: 实体一致性奖励(entity consistency reward)
  从生成报告中提取放射领域实体(疾病名/解剖位置)
  从参考报告中提取相同实体
  奖励 = 生成实体集合与参考实体集合的F1
  → 鼓励生成与参考一致的疾病实体

奖励2: NLI推理一致性奖励(inferential consistency reward)
  对每个实体，用NLI判断生成描述与参考描述的关系
  → 蕴含(entailment) = 一致 → 奖励
  → 矛盾(contradiction) = 不一致 → 惩罚
  → 中立(neutral) = 无关 → 不奖不罚

奖励3: BERTScore语义等价度
  生成报告与参考报告的BERTScore

总奖励 = w₁×实体F1 + w₂×NLI一致率 + w₃×BERTScore
→ RL训练(PPO)优化报告生成模型
```

**关键指标**: 临床信息提取F1提升**+22.1**(Delta **+63.9%**)。人工评估证实生成更事实完整和一致。

**适用场景**: 报告生成系统的事实一致性训练——用实体+NLI奖励替代BLEU/CIDEr等表面指标。

---

### E10. 专家-外行差距检测法 (MEDLAYXPLAIN)

**出处**: arXiv:2606.21194, 2026

**解决什么问题**: 医学VLM生成的报告可能过于专业化(专家视角)或过于简化(外行视角)，与目标受众不匹配——这是一种"受众错位"型不一致。

**技术原理**:

```
评估维度1: 专家-外行内容差距
  同一图像 → 生成专家版报告 vs 外行版报告
  → 测量两者差异: 医学术语密度/细节程度/可读性
  → 差距过大 = 可能存在受众错位

评估维度2: 事实一致性跨受众验证
  专家版报告的疾病诊断 vs 外行版报告的疾病描述
  → 两者应在事实层面一致(只是表述不同)
  → 若事实矛盾 = 幻觉或知识不一致
```

**适用场景**: 医疗AI系统的受众适配性检测——确保AI对不同受众生成的内容在事实层面一致。

## 六B、跨数据集/时序一致性检测方法

### F1. 域偏移标签噪声检测法

**出处**: Rafferty et al., arXiv:2509.15107, 2025

**解决什么问题**: CheXpert Labeler在MIMIC-CXR上训练的ngrex规则，迁移到其他数据集(NLMCXR/CheXpert/PADCHEST)时，因域偏移导致标签质量下降。如何检测和量化这种跨数据集的标签噪声？

**技术原理**:

```
Step 1: 跨数据集标签一致性测量
  同一批报告 → 用不同数据集训练的Labeler标注
  → 测量标签一致率(同一报告不同Labeler给出相同标签的比例)
  → 一致率低 = 域偏移导致标签不稳定

Step 2: AUPRC/F1跨数据集衰减分析
  在源数据集(MIMIC-CXR)上评估 → AUPRC=X
  在目标数据集(NLMCXR)上评估 → AUPRC=Y
  → 衰减率 = (X-Y)/X
  → 高衰减 = 严重域偏移

Step 3: 噪声源定位
  分析哪些疾病/哪些表述模式的标签最容易受域偏移影响
  → Rafferty发现: 否定和不确定场景最易受影响
  → 原因: 不同数据集的否定表述习惯不同
```

**关键发现**: CheXpert Labeler在否定/不确定场景下引入标签错误，跨数据集域偏移导致AUPRC和F1大幅下降。

**适用场景**: 任何跨数据集使用CheXpert标签的场景——评估标签可靠性，决定是否需重新标注。

### F2. 纵向时序一致性检测法

**出处**: SADM (arXiv:2212.08228) + MIMIC纵向评估 (arXiv:2303.10501)

**解决什么问题**: 同一患者多次就诊的影像和报告是否时序一致——随访报告应与历史报告在疾病进展/消退上保持一致。

**技术原理**:

```
Step 1: 纵向数据对齐
  患者P的就诊序列: {就诊1(胸片₁+报告₁, t₁), 就诊2(胸片₂+报告₂, t₂), ...}
  → 按时间排序，构建纵向序列

Step 2: 疾病进展/消退一致性检测
  对同一疾病d:
    报告₁: "右侧胸腔积液"(阳性, t₁)
    报告₂: "右侧胸腔积液较前吸收"(阳性+消退, t₂)
    报告₃: "No pleural effusion"(阴性, t₃)
  → 预期序列: 阳性→消退→阴性 (逻辑一致的进展)
  → 异常序列: 阳性→阴性→阳性 (可能是配对混淆或诊断不一致)

Step 3: 图像时序一致性
  胸片₁ vs 胸片₂: 同一解剖位置的病灶变化
  → 用图像配准(registration)对齐同患者不同时间胸片
  → 比较病灶区域的变化趋势
  → 若报告称"消退"但图像显示"增大" → 时序不一致
```

**适用场景**: 随访患者的纵向数据一致性——检测疾病进展/消退描述与图像变化的矛盾。

---

### F3. DICOM时戳配对校验法

**解决什么问题**: 多就诊场景下，旧片子可能配了新报告——这种配对混淆不是语义矛盾而是时序配对错误。

**技术原理**:

```
Step 1: DICOM元数据提取
  每张胸片的DICOM头包含:
  → StudyInstanceUID: 唯一检查标识
  → StudyDate/StudyTime: 检查时间
  → PatientID: 患者标识
  → AccessionNumber: 检查流水号

Step 2: 配对一致性校验
  图像的StudyDate vs 报告签署时间
  → |时间差| > 30天 → 配对混淆警报(可能旧片配新报告)
  → |时间差| < 1天 → 正常配对

  图像的PatientID vs 报告关联PatientID
  → 不一致 → 患者配对错误

  图像的ViewPosition(AP/PA/Lateral) vs 报告描述体位
  → 不一致 → 体位配对错误
```

**适用场景**: 任何使用DICOM影像的配对校验——MIMIC-CXR多就诊场景尤其重要。

### F4. 因果框架域偏移检测法

**出处**: arXiv:1905.11374, 2019 (A Unifying Causal Framework for Analyzing Dataset Shift-stable Learning)

**解决什么问题**: 跨数据集性能下降的根因是什么？是图像分布变了还是标签分布变了？需要因果框架区分不同类型的域偏移。

**技术原理**:

用因果图区分3种域偏移类型:

```
类型1: 协变量偏移(covariate shift) — P(X)变化, P(Y|X)不变
  → 图像分布变了(不同医院/设备), 但疾病-图像关系不变
  → 缓解: 域适应(DANN/CORAL)

类型2: 标签偏移(label shift) — P(Y)变化, P(X|Y)不变
  → 疾病流行率变了(不同人群), 但疾病表现不变
  → 缓解: 重要性加权

类型3: 概念偏移(concept shift) — P(Y|X)变化
  → 疾病-图像关系本身变了(新标准/新设备特性)
  → 最难处理, 需重新训练
```

**不一致检测应用**:
- 检测到概念偏移 → 标签-图像关系已变 → 现有标签可能不一致
- 检测到协变量偏移 → 图像分布变化 → CLIP对齐分数不可靠
- 检测到标签偏移 → 标签分布变化 → 互斥约束可能不再适用

**适用场景**: 跨数据集部署前的域偏移诊断——确定需要哪种不一致检测策略。

---

### F5. 协同域适应诊断一致性法

**出处**: arXiv:1911.07293, 2019 (Collaborative Unsupervised Domain Adaptation for Medical Image Diagnosis)

**解决什么问题**: 不同医院的胸片AI诊断结果不一致——同一张片子在不同模型上给出不同诊断。如何检测和缓解这种跨机构诊断不一致？

**技术原理**:

```
Step 1: 多机构诊断一致性测量
  同一张胸片 → 机构A模型诊断 + 机构B模型诊断
  → 测量诊断一致率(同疾病同标签的比例)
  → 不一致 = 至少一个模型有误

Step 2: 协同域适应
  机构A数据 + 机构B数据 → 协同无监督域适应
  → 对齐两个机构的特征分布
  → 减少跨机构诊断差异

Step 3: 不一致样本标记
  域适应后仍不一致的样本 → 标记为"高不确定"
  → 转人工复核
```

**适用场景**: 多机构AI系统部署——确保不同机构AI给出一致诊断。可迁移到多基地/多型号军用场景。

### 7.3 按部署约束选型

| 约束 | 推荐方法组合 | 理由 |
|---|---|---|
| **无GPU/纯CPU** | A1冲突矩阵 + B2三态聚合 + C4互斥 + D1规则库 | 全部规则驱动，无需训练 |
| **有CPU+小LLM** | 上述 + D2 LLM+Guard + B1 NLI | LLM 7b可CPU运行 |
| **有GPU(单卡)** | 上述 + A2 CheXzero + C1 DeFT + E2 DSE | 中等算力可跑CLIP/DeFT |
| **有多GPU** | 上述 + A3 FAMDR + A4 CheXagent + E3 CoEV | SOTA方法需大模型推理 |

### 7.4 推荐级联策略

```
输入: 图文对(胸片+报告) + 血检 + 诊断标签
  │
  ├─ 第1道: A1冲突矩阵(疾病级快速筛) → 5类冲突+严重度
  │   → HIGH冲突进入第3道深度复核
  │
  ├─ 第2道: D1三层规则库(血检↔诊断) + C4标签互斥
  │   → 规则确定性检测，零假阳性
  │
  ├─ 第3道: A3 FAMDR(HIGH冲突深度复核)
  │   → 像素/短语级定位，输出证据链
  │
  ├─ 第4道: B1 NLI矛盾(报告内) + E2 DSE语义熵(模糊检测)
  │   → 检测A1遗漏的报告内矛盾和模糊争议
  │
  ├─ 第5道: E3 CoEV双向验证(兜底)
  │   → 双向四象限诊断，捕获前4道遗漏的交互型不一致
  │
  └─ 第6道: D2 LLM+Guard(终极兜底)
      → 处理前5道都遗漏的复杂语义冲突
      → LLM语义判定 + 代码数值核验 → FP=0
```

**级联原则**: 召回率递减、精度递增。前道快速过滤大量明确冲突，后道对未决样本做深度分析。每道只处理前道未决的样本——避免重复计算。
