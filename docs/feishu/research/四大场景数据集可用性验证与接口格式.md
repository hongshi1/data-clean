## 二、仓库已有数据格式（已验证的Data-Juicer JSONL接口）

### 2.1 通用Data-Juicer JSONL格式

所有场景的数据最终需要转成以下格式才能对接Data-Juicer管道：

```jsonl
{
  "text": "文本内容（报告/工单/SRS正文/故障描述）",
  "images": ["图片路径1", "图片路径2"],
  "meta": {
    "场景特有字段": "值",
    ...
  }
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `text` | string | 是(有文本时) | 文本内容 |
| `images` | array[string] | 是(有图像时) | 图片路径列表 |
| `meta` | object | 是 | 业务字段，后续算子从中读取 |
| `meta.{业务字段}` | any | 按场景定义 | 各场景不同 |

## 三、每个场景需要的数据接口格式

### 场景1·SRS数据治理（文本↔表格）

#### 需要的JSONL格式

```jsonl
{
  "text": "3.2 性能要求\n系统响应时间应≤50ms，吞吐量应≥1000tps。\n3.3 接口要求\n系统应提供RS422串行接口...",
  "images": [],
  "meta": {
    "doc_id": "SRS-2024-001",
    "doc_type": "SRS",
    "gjb_version": "GJB 438C-2021",
    "sections": {
      "functional": "3.1 系统应实现...功能要求正文...",
      "performance": "3.2 系统响应时间应≤50ms...",
      "interface": "3.3 系统应提供RS422接口...",
      "data_dict": "3.4 数据字典定义...",
      "environment": "3.5 运行环境...",
      "security": "3.6 安全保密...",
      "acceptance": "3.7 验收准则..."
    },
    "tables": [
      {"table_id": "表3-1", "table_type": "性能指标表", "header": ["指标名","运算符","数值","单位"], "rows": [["响应时间","≤","50","ms"],["吞吐量","≥","1000","tps"]]},
      {"table_id": "表3-2", "table_type": "接口定义表", "header": ["接口名","类型","协议","字段"], "rows": [["串口1","串行","RS422","数据帧格式..."]]},
      {"table_id": "表3-3", "table_type": "数据字典", "header": ["参数名","类型","单位","范围","说明"], "rows": [["响应时间","float","ms","[0,100]","系统响应延迟"]]}
    ],
    "params": [
      {"param_name": "响应时间", "op": "≤", "value": 50, "unit": "ms", "source_section": "3.2", "source_table": "表3-1", "type": "性能"},
      {"param_name": "吞吐量", "op": "≥", "value": 1000, "unit": "tps", "source_section": "3.2", "source_table": "表3-1", "type": "性能"},
      {"param_name": "接口类型", "value": "RS422", "source_section": "3.3", "source_table": "表3-2", "type": "接口"}
    ]
  }
}
```

#### 字段说明

| 字段 | 类型 | 说明 | 哪步生成 | 哪个算子消费 |
|---|---|---|---|---|
| `text` | string | SRS文档全文（或段落） | ①解析输出 | ②NER算子 |
| `meta.sections` | object | GJB七大块切分结果，key=块名 | ①章节切分 | ③一致性校验(检测点1-4) |
| `meta.tables` | array | 表格抽取结果，每个表含表头+行数据 | ①表格抽取 | ②表格映射 + ③校验(检测点1/3) |
| `meta.params` | array | 参数化条目，每个参数含名称/运算符/数值/单位/来源 | ②NER+参数化 | ③校验(检测点1/3/4) |

#### 对接的公开数据集

| 公开数据集 | 原始格式 | 需转换 | 转换方式 |
|---|---|---|---|
| TabFact | JSON(表格+声明+标签) | 是 | 表格→`meta.tables`，声明→`text`，标签→`meta.label` |
| Infotabs | JSON(表格+假设+标签) | 是 | 表格→`meta.tables`，假设→`text`，标签→`meta.label` |
| PubTables-1M | 图像+XML | 是 | XML解析→`meta.tables` |
| DocLayNet | 图像+JSON(版面标注) | 是 | 版面标注→`meta.sections`(按布局类型切分) |

## 五、总结：每个场景的可用数据组合

### 场景1·SRS（文本↔表格）

**可用组合**：
```
TabFact(HF) + Infotabs(HF)  → 文本↔表格一致性检测的训练/评估数据
PubTables-1M(GH) + TableBank(GH)  → 表格抽取的基线数据
DocLayNet(HF)  → 文档版面分析的基线数据
仓库: weapon_multimodal.jsonl + weapon_specs.csv  → 原型验证
已有: GJB 438C-2021标准文本  → ⑤知识融合的规则来源
```
**判断**：数据充足，可立即开始。

### 场景2·引信方案设计（SysML+仿真）

**可用组合**：
```
OMG SysML v2示例(GH)  → SysML模型解析的基线
Modelica标准库(GH)  → 仿真模型解析的基线
自建: 引信领域SysML模型 + Simulink仿真  → 必须自建
```
**判断**：有解析工具(Modelica标准库/SysML v2示例)但无领域数据，需自建引信模型。

### 场景3·引信溯源（故障/缺陷）

**可用组合**：
```
NEU表面缺陷(仓库已有/Kaggle)  → 缺陷图像分类原型
MVTec AD(官网)  → 工业异常检测基线
自建: 故障树 + 工艺规程 + 故障报告  → 必须自建
```
**判断**：缺陷图像有数据，故障树/工艺规程需企业脱敏自建。

### 场景4·航发维护（时序↔文本↔图像）

**可用组合**：
```
NASA CMAPSS(Kaggle)  → 航发退化时序(场景4核心)
CWRU轴承(官网)  → 旋转机械故障诊断
NAB(GH) + SMD(GH) + PSM(GH)  → 通用时序异常补充
仓库: H4R焊接(已验证)  → 时序+图像+标签原型
自建: 时序↔工单配对  → 用CMAPSS时序+LLM生成模拟工单
```
**判断**：数据最充足，CMAPSS+CWRU+H4R焊接三组合覆盖核心需求。
