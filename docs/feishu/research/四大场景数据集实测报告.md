## 场景1·SRS数据治理

### TabFact — 已下载已测试

**下载**: ✅ GitHub Archive 187MB，16573个表格CSV + 12779条测试声明

**真实数据格式**:
```
表格CSV (#分隔):
  表头: tournament#wins#top-5#top-10#top-25#events#cuts made
  数据: masters tournament#0#1#2#4#4#4

声明JSON:
  key: "2-1570274-4.html.csv" (表格ID)
  value: [声明列表, 标签列表, 表格标题]
  声明: "tony lema be in the top 5 for the master tournament"
  标签: 1 (支持) / 0 (反驳)
```

**已转Data-Juicer JSONL**: ✅ `data/tabfact_dj.jsonl`

**与4个检测点匹配度**:
| 检测点 | 需要 | TabFact提供 | 匹配 |
|---|---|---|---|
| 检测点1 正文↔指标表数值 | 正文段落"≤50ms" + 指标表 | 单句声明 + Wikipedia知识表 | ⚠️ 有表格+声明+标签，但格式/领域不同 |
| 检测点2 接口正文↔接口表 | 接口正文 + 接口表 | 不涉及接口 | ⚠️ |
| 检测点3 字典↔术语 | 正文术语 + 字典定义 | 不做术语检测 | ❌ |
| 检测点4 跨条目矛盾 | 同参数多处出现 | 每声明只对应一张表 | ❌ |

**结论**: 不能直接用于场景1的检测点。可用于训练"表格事实验证"基础能力。

### Infotabs — 已下载已测试

**下载**: ✅ HuggingFace `table-benchmark/infotabs`，训练16538条 + 测试5400条

**真实数据格式**:
```
表格: key-value格式 (维基百科infobox)
  {'Official languages': ['Faroese', 'Danish'], 'Capital': ['Torshavn'], ...}
假设: "Faroe Islands only has one official language."
标签: Contradiction (三分类: Entailment/Neutral/Contradiction)
```

**已转Data-Juicer JSONL**: ✅ `data/infotabs_dj.jsonl`

**与TabFact相比的优势**: 三分类(蕴含/矛盾/中立)比二分类(支持/反驳)更接近SRS场景——SRS中可能有"不确定"的情况

**结论**: 同TabFact——不能直接用于检测点，但三分类NLI能力可迁移。

## 场景2·引信方案设计

### OMG SysML v2 — 已下载已查看

**下载**: ✅ GitHub `Systems-Modeling/SysML-v2-Release`，1592个文件，含309个.sysml

**真实数据格式** (SysML 2.0文本):
```
standard library package Requirements {
    private import Parts::Part;
    
    abstract constraint def RequirementConstraintCheck {
        constraint assumptions[0..*] :> constraintChecks;
        constraint constraints[0..*] :> constraintChecks;
        return result = allTrue(assumptions()) implies allTrue(constraints());
    }
    
    abstract requirement def RequirementCheck :> RequirementConstraintCheck {
        ...
    }
}
```

**包含的视图类型**: Requirements / Constraints / Actions / Flows / Interfaces / Ports / States / Views / Items / Allocations / Calculations / Attributes / UseCases / AnalysisCases / VerificationCases / StandardViewDefinitions

**与3个检测点匹配度**:
| 检测点 | 需要 | SysML v2提供 | 匹配 |
|---|---|---|---|
| 检测点1 要求↔方案覆盖性 | 设计要求 + SysML视图 + 覆盖标注 | ✅ SysML 2.0文本解析方法 | ✅ 可学解析，❌ 无引信领域模型 |
| 检测点2 静态↔动态 | SysML参数 + 仿真输出 | ✅ Constraints/Attributes有参数定义 | ✅ 可学参数提取，❌ 无仿真输出 |
| 检测点3 跨视图传递链 | 参数传递路径 + 完整性标注 | ✅ 有Flows/Allocations视图 | ✅ 可学传递结构，❌ 无传递链标注 |

**结论**: ✅ 可学习SysML 2.0文本的解析方法（309个.sysml文件覆盖全部视图类型）。❌ 无引信领域模型，需自建。

### Modelica标准库 — 已下载已查看

**下载**: ✅ GitHub `modelica/ModelicaStandardLibrary`，5574个文件，2674个.mo

**真实数据格式** (Modelica文本):
```
within Modelica.Blocks;
package Interaction
  block RealValue
    parameter Boolean use_numberPort = true "= true, if numberPort enabled";
    input Real number = 0.0 "Number to visualize";
    parameter Integer significantDigits(min=1) = 2 "Number of significant digits";
    
    Modelica.Blocks.Interfaces.RealInput numberPort if use_numberPort;
    Modelica.Blocks.Interfaces.RealOutput showNumber;
  equation
    if use_numberPort then
      connect(numberPort, showNumber);
    else
      showNumber = number;
    end if;
  end RealValue;
```

**包含的领域**: Electrical(电路) / Mechanical(机械) / Blocks(控制块) / Thermal(热学) / Fluid(流体) / Media(介质) / Math(数学) / Complex(复数)

**与检测点匹配度**: ✅ 可学习Modelica文本解析(parameter/input/output/equation)。❌ 无引信领域仿真模型，需自建。

**场景2总结**: 两个数据集都✅可下载、✅可查看、✅可学解析方法。但都❌无引信领域模型、❌无仿真一致性标注。场景2必须自建引信SysML模型和Simulink仿真模型。

## 四场景综合结论

### 数据集可用性

| 场景 | 数据集 | 可用 | 可直接用于检测点 | 需自建 |
|---|---|---|---|---|
| 场景1 | TabFact + Infotabs | ✅ | ❌ 只能训练基础NLI能力 | SRS参数矛盾标注 |
| 场景2 | SysML v2 + Modelica | ✅ | ❌ 只能学习解析方法 | 引信SysML模型+仿真+一致性标注 |
| 场景3 | NEU(需重下) | ⚠️ | ❌ 只能做缺陷图像分类 | 故障树+工艺规程+故障报告 |
| 场景4 | NAB+SMD+SKAB+H4R | ✅ | ✅ H4R已验证三模态原型 | 航发工单+孔探图像 |

### 每个场景"完全符合需求"的判断

| 场景 | 完全符合? | 原因 | 缺什么 |
|---|---|---|---|
| 场景1 | ❌ | TabFact/Infotabs是Wikipedia表格事实验证，不是SRS参数矛盾 | 需自建SRS文档+参数矛盾标注 |
| 场景2 | ❌ | SysML/Modelica只有解析方法，无领域模型 | 需自建引信SysML+Simulink仿真+一致性标注 |
| 场景3 | ❌ | NEU只有缺陷图像，无故障树/工艺 | 需企业脱敏故障报告+工艺规程+故障树 |
| 场景4 | **⚠️ 部分** | H4R焊接已验证三模态原型，NAB/SMD/SKAB可训练时序异常 | 缺航发工单文本+孔探图像，可用替代方案 |

### 最接近"完全符合需求"的数据

**场景4的H4R焊接数据**是四个场景中唯一已验证的、可直接用于Data-Juicer管道的、含三模态配对(时序+文本+图像)的数据。虽然不是航发领域数据(是焊接数据)，但：
- ✅ 时序↔文本配对(检测点1)——时序CSV + 缺陷文本描述
- ✅ 标签↔图像配对(检测点3)——缺陷标签 + 缺陷图像
- ✅ 多通道时序(检测点4)——9通道焊接参数
- ✅ 已转成Data-Juicer JSONL格式
- ✅ `timeseries_operators.py`已跑通验证

**其他场景的公开数据集都不能直接用于检测点**——它们只能用于训练基础能力(表格NLI/SysML解析/时序异常检测)，检测点需要自建领域数据。
