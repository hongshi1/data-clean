## 0. 概述

### 0.1 场景定位

以航空发动机时序运行数据（振动/温度/转速/压力传感器）为核心，融合故障工单（文本）与孔探/拆解图像（图像），搭建面向**故障诊断、寿命预测、维护决策**三类智能体的微调数据集，实现发动机智能维护保障。

**与场景1的本质差异**：场景1是"文本↔表格"双模态（无时序无图像）；场景4是课题**三模态最齐全场景**——时序↔文本为主、时序↔图像为次，且时序是**第一公民**（医疗场景中图像是第一公民）。

### 0.2 五步治理链路全景

```
原始航发数据(传感器时序 + 故障工单 + 孔探/拆解图像) + 维护手册 + 专家经验(隐性)
    │
  ①标准化预处理   时序清洗重采样→工单解析→孔探图像增强→涉密脱敏
    │              → 归一化航发数据(统一时戳+结构化工单+标注图像)
    ↓
  ②结构化转化     时序异常段检测(TAB/MTAD) / 工单NER三态 / 孔探损伤标注 / 多模态配对
    │              → 结构化故障事件库(#2) + 多模态对齐关系
    ↓
  ③一致性校验     4类检测点(规则+LLM两路) → 标记冲突不删
    │              → 事件库+冲突标记
    ↓
  ④质量评估       完整性/一致性/合规性/准确性/可用性/隐私性/多样性打分
    │              → 分级数据集(A/B/C级)
    ↓
  ⑤知识融合       维护手册映射 + 物理约束KG + 专家经验显性化
    │              → 知识增强微调数据集
    ↓
  微调数据集 → 三类智能体(故障诊断/维护问答/健康预测) → 回灌维护全链路 → 闭环迭代
```

### 0.3 数据模态

| 模态 | 数据类型 | 采样特征 | 对应医疗场景 | 场景4角色 |
|---|---|---|---|---|
| **时序** | 振动/温度/转速/压力传感器 | 振动10kHz、温度1Hz、转速10Hz | ECG心电 | **第一公民**（主分析对象） |
| **文本** | 故障工单/维护手册/维护记录 | 事件触发型、非连续 | 放射报告 | 工单NER三态标注 |
| **图像** | 孔探图像/拆解图像 | 维护触发型、离散 | CXR胸片 | 时序↔图像一致性校验 |

> **关键对比**：医疗场景"图像AI读片→文本NER→冲突矩阵"，场景4是"**时序异常检测→工单NER→冲突矩阵**"——时序异常检测器替代TorchXRayVision，工单NER替代放射报告NER，冲突矩阵逻辑直接复用。

### 0.4 航发场景硬约束（贯穿5步）

| 约束 | 含义 | 影响 |
|---|---|---|
| 数据不出域 | 全程本地推理，禁外发API | 优先开源可私有化模型（Qwen2:7b非GPT-4） |
| 可审计 | 每步产出可追溯依据 | 时序异常须保留异常段+分数+检测器版本 |
| 物理可解释 | 冲突判定须符合物理律 | 多传感器约束须挂热力学/转子动力学依据 |
| 涉密脱敏 | 型号/架次/基地/战术参数需脱敏 | 脱敏后仍需可用于微调 |
| 罕见故障扩充 | 罕见故障占比<5%，样本极度不均衡 | 需合成增强或迁移学习 |

## 1. ①标准化预处理

### 1.1 时序数据清洗与重采样

**核心问题**：航发传感器多源异构（振动10kHz vs 温度1Hz vs 转速10Hz），采样率差异达4个数量级，且存在缺失、漂移、时戳不同步。

| 问题 | 典型表现 | 处理方法 | 工具/依据 |
|---|---|---|---|
| **采样率差异** | 振动10kHz vs 温度1Hz | 统一重采样到公共时间轴（振动降采样→RMS包络1Hz，温度保持） | scipy.signal.resample / pandas.resample |
| **缺失值** | 传感器掉线致NaN | 前向填充（短缺失<5s）+ 线性插值（中缺失）+ 标记（长缺失>60s不插补） | pandas.interpolate(method='linear') |
| **传感器漂移** | 温度零点偏移系统性偏差 | 基线校正（启动段均值归零）+ 定期校准因子 | 仓库 `timeseries_operators.py` TimeSeriesStatsMapper 已用启动段筛选 |
| **时戳不同步** | 传感器A早0.3s于传感器B | NTP时戳对齐 + 互相关峰值对齐（振动↔转速相位补偿） | numpy.correlate 互相关求延迟 |
| **单位不一致** | 振动g vs mm/s² | 统一国际单位制（SI）+ 通道元数据标注单位 | 自定义通道注册表 |

**关键设计**：振动信号降采样不是简单抽取——先做FFT→提取频带能量（低频<1kHz、中频1-5kHz、高频>5kHz）→RMS包络→1Hz特征序列。保留频域信息的同时对齐到温度/转速的低频时间轴。

> **仓库原型验证**：`timeseries_operators.py:TimeSeriesStatsMapper`（`:150-230`）已实现焊接段筛选（电流>10A）+ 4路时序统计（CO2/压力/电流/电压），场景4需扩展为航发多通道（振动/温度/转速/压力/滑油）。

### 1.2 故障工单解析与结构化

**核心问题**：故障工单多为Word/PDF/手写扫描件，含故障现象、排查过程、处置措施、结论等半结构化文本。

| 工单字段 | 解析方法 | 难点 |
|---|---|---|
| **故障现象描述** | 章节标题锚点 + 段落抽取 | 手写件需OCR |
| **故障发现时间** | 正则 `(20\d{2}-\d{2}-\d{2}[\sT]\d{2}:\d{2})` | 多种格式混杂 |
| **故障类型/代码** | 故障代码词典匹配 | 代码体系不统一 |
| **排查结论** | 章节锚点（"结论"/"处置"）抽取 | 长文本需摘要 |
| **涉及部件** | 部件NER（压气机/涡轮/燃烧室/轴承） | 术语多义 |

**推荐**：Word走python-docx直抽（同场景1）；PDF扫描件走MinerU+PaddleOCR；手写件走PaddleOCR（中文手写最强）。章节切分用故障工单模板锚点词典（"故障现象"/"排查过程"/"处置措施"/"结论"）。

### 1.3 孔探/拆解图像预处理

**核心问题**：孔探图像（borescope）光照不均、散斑噪声、视角畸变；拆解图像背景复杂、损伤区域占比小。

| 预处理 | 方法 | 目的 |
|---|---|---|
| **光照均衡** | CLAHE（限制对比度自适应直方图均衡） | 孔探暗角补偿 |
| **去噪** | 非局部均值去噪 / 双边滤波 | 保边缘去散斑 |
| **畸变校正** | 孔探标定参数去畸变（cv2.undistort） | 桶形畸变修正 |
| **损伤区域增强** | 对比度拉伸 + 形态学Top-Hat | 突出裂纹/烧蚀 |
| **标注对齐** | 损伤标注框/掩码与图像配对 | 供CV检测模型训练 |

### 1.4 涉密信息识别与文本脱敏

**复用场景1的三级级联+分层算子架构**（SurrogateShield arXiv:2606.29567 验证 F1≈98.87%），航发场景敏感实体替换：

| 敏感实体 | 脱敏算子 | 语义保留 | 对微调影响 |
|---|---|---|---|
| 型号代号（WS-10/AL-31） | **伪名化**(ENGINE_01确定性映射) | 高(保共指一致) | 极小 |
| 架次/批次号 | **泛化为区间**(第12架→第[10,15)架) | 中高(保分布) | 小 |
| 基地/部队番号 | **删除**(redact) | 低 | 大(无语义价值) |
| 战术参数(推力/耗油率) | **泛化为区间**(推力120kN→[100,140)kN) | 中高(保量级) | 小 |
| 传感器通道名/故障代码 | **保留**(非敏感) | — | 微调必需 |

> **推荐**：Presidio V2（开源私有化部署），复用场景1配置，替换Recognizer为航发实体词典。

### 1.5 ①推荐Pipeline

```
传感器时序(CSV/parquet) ──→ 重采样+缺失插补+漂移校正+时戳对齐 ──┐
                                                                ├──→ 统一IR(公共时间轴+结构化工单+标注图像)
故障工单(Word/PDF) ──→ python-docx/MinerU解析+章节切分 ──────────┤
                                                                │
孔探/拆解图像(JPG) ──→ CLAHE+去噪+畸变校正+标注配对 ────────────┘
                                          ↓
                                  涉密脱敏(Presidio三级级联+分层算子)
                                          ↓
                                  归一化航发数据(脱敏后)
```

**落地优先级**：P0时序清洗重采样(基础) → P1工单解析+孔探预处理 → P2脱敏 → P3质量闭环。

## 2. ②结构化转化

### 2.1 时序异常段检测与特征化

**核心问题**：从连续传感器流中检测异常段（start, end, severity, score, channel），输出"什么时候、哪个通道、多严重"的结构化异常事件。这是场景4的**侧1分析**，对应医疗场景的TorchXRayVision读片。

#### 2.1.1 TAB基准与MTAD工具包

**TAB基准**（PVLDB 2025, arXiv:2506.18046）是当前最全面的时序异常检测评测框架：
- **29个公共多变量数据集** + **1,635个单变量时间序列**
- 统一评估**5种方法族**：非学习（统计检验）、机器学习（Isolation Forest）、深度学习（AutoEncoder/Transformer）、LLM-based（UniTS/Timer）、时序预训练（TimesFM）
- 核心发现：**没有单一检测器在所有数据集上占主导**；基础模型在zero-shot下仍不及精心设计的轻量监督基线

**MTAD工具包**（arXiv:2401.06175）集成**15种多变量时序异常检测方法**，4个维度评测（准确率/显著性/效率/延迟）：

| 方法族 | 代表方法 | 原理 | 航发适用性 | GPU |
|---|---|---|---|---|
| **机器学习** | Isolation Forest | 随机孤立划分，异常点路径短 | ★★★★★(轻量基线/可审计) | 无 |
| | OCSVM | 单类SVM超球面边界 | ★★★★ | 无 |
| **深度-重构** | AutoEncoder | 重构误差>阈值→异常 | ★★★★(频域特征) | 中 |
| | USAD | 对抗式AE，Unsupervised | ★★★★ | 中 |
| | InterFusion | 跨通道融合重构 | ★★★★★(多传感器) | 中 |
| **深度-预测** | LSTM-AE | 时序预测误差 | ★★★ | 中 |
| | AnomalyTransformer | **关联差异**Associate/Adjacent注意力(ICLR 2022) | ★★★★★(SOTA) | 高 |
| **深度-图** | MTAD-GAT | **图注意力**建模通道间依赖(KDD 2020) | ★★★★★(传感器关系) | 高 |
| **概率** | DAGMM | 深度高斯混合模型 | ★★★ | 中 |
| | GANF | 归一化流+GAN | ★★★ | 高 |

**推荐**：**Isolation Forest轻量基线（可审计、无GPU）+ AnomalyTransformer/MTAD-GAT深度SOTA（精度上限）双路并行**，规则层优先、深度层补充。

> **仓库原型验证**：`timeseries_operators.py:TimeSeriesAnomalyFilter`（`:60-150`）已实现 IsolationForest 检测4路时序异常点，算异常比例输出 `ts_anomaly_score`。场景4需扩展为多通道+异常段（不只是点异常）。

#### 2.1.2 异常段输出格式

```json
{
  "anomaly_segments": [
    {
      "start_ts": "2026-03-15T14:23:00",
      "end_ts": "2026-03-15T14:25:30",
      "channel": "vibration_hpf",
      "score": 0.87,
      "severity": "HIGH",
      "pattern": "频带能量突增(5-8kHz)",
      "detector": "AnomalyTransformer"
    }
  ]
}
```

#### 2.1.3 时序异常校准：score≠概率，边界带降级

类比医疗场景"DenseNet logit≠概率，统一0.5阈值导致系统性假阳性"（`方法章节_深度版.md:3.1.2`），时序异常分数同样不是概率：

| 校准方法 | 原理 | 改变阈值 | 改变概率 | 适用 |
|---|---|---|---|---|
| **逐通道Youden J** | 验证集ROC最优点argmax(TPR-FPR) | 是 | 否 | **最实用**，按通道设阈值 |
| Temperature Scaling | score/T，T在验证集学习 | 否 | 是(校准概率) | 检测器整体过自信 |
| Platt Scaling | σ(a·score+b)拟合 | 否 | 是 | 数据充足精细校准 |

**边界带降级机制**（复用医疗场景设计，δ=0.05）：

| 分数区间 | 判定 | 冲突严重度处理 |
|---|---|---|
| score > θ_ch + δ | 确信异常 | 正常定级（HIGH/MEDIUM/LOW） |
| θ_ch - δ ≤ score ≤ θ_ch + δ | **边界异常** | **降一级**（HIGH→MEDIUM, MEDIUM→LOW） |
| score < θ_ch - δ | 正常 | 不触发冲突 |

> **规律**（类比医疗低患病率病种阈值偏高）：高频振动通道（罕见异常）阈值偏高避免假阳性；温度通道（频繁超限）阈值偏低避免假阴性。

### 2.2 工单NER三态标注

**核心问题**：故障工单含肯定（"2号轴承振动超限"）、否定（"未见异常""排除轴承故障"）、不确定（"疑似""待查"）三种表述混杂。纯关键词匹配把"排除XX故障"误判为"提及XX故障"——这是时序↔工单冲突检测假阳性的根源。

**这是场景4的侧2分析**，对应医疗场景的CheXpert Labeler三态NER（`方法章节_深度版.md:3.2`）。

#### 2.2.1 方法演进

| 方法 | 原理 | 否定 | 不确定 | 准确率 | 航发适用 |
|---|---|---|---|---|---|
| 纯关键词 | `report.find("振动")` | 无 | 无 | 低 | ❌假阳性泛滥 |
| negspacy(NegEx) | spaCy + 4类短语模式 | 二态 | 无 | 中 | ★★★(快速原型) |
| **CheXpert Labeler迁移版** | BllipParser依存句法 + ngrex图规则 | **三态** | **三态** | **κ>0.6** | ★★★★★(精度上限) |
| **30字窗口否定检测** | 关键词前30字窗口正则否定/不确定词 | 二态 | 二态 | 中高 | ★★★★(工程轻量) |

#### 2.2.2 航发版三态标注（迁移自医疗30字窗口简化版）

复用医疗场景已验证的30字窗口否定检测（`nlmcxr_operators.py:232-297`），替换词典：

**故障类型词典**（替代医疗14类疾病）：
- 振动超限 / 温度过热 / 转速波动 / 滑油压力低 / 滑油温度高
- 轴承故障 / 压气机喘振 / 涡轮叶片损伤 / 燃烧室积碳 / 密封泄漏

**否定词表**（复用医疗`_NEG_PATTERN`）：
```python
_NEG_PATTERN = re.compile(r"\b(未见|无|排除|未发现|正常|无异常|未检出|否认)\b")
```

**不确定词表**（复用医疗`_UNC_MARKERS`，航发补充）：
```python
_UNC_MARKERS = ["疑似","待查","可能","不能排除","建议复查","尚需确认","初步判断"]
```

**四态输出**：positive(故障确认) > uncertain(待查) > negative(排除) > unmentioned(未提及)

**NLMCXR迁移示例**（医疗→航发对照）：

| 医疗报告原文 | 医疗标注 | 航发工单原文 | 航发标注 |
|---|---|---|---|
| "No pleural effusion" | 否定(命中"no") | "未见滑油泄漏" | 否定(命中"未见") |
| "may represent consolidation" | 不确定(命中"may represent") | "疑似2号轴承磨损" | 不确定(命中"疑似") |
| "associated atelectasis" | 阳性(无否定词) | "2号轴承振动超限" | 阳性(无否定词) |
| (全文无"edema") | 未提及 | (全文无"喘振") | 未提及 |

**时间戳提取**：故障发现时间是时序↔工单时戳对齐的关键。正则匹配多种格式 + 工单章节锚点（"发现时间"/"故障时刻"）。

### 2.3 孔探/拆解图像损伤标注

**核心问题**：从孔探/拆解图像中检测损伤（裂纹/烧蚀/磨损/积垢/叶片撕裂），输出损伤类型+位置+严重度。这是场景4的**侧3分析**（医疗场景无直接对应，但可类比TorchXRayVision输出18维疾病logits）。

| 损伤类型 | 视觉特征 | 检测方法 | 严重度 |
|---|---|---|---|
| 裂纹 | 线状高对比度边缘 | U-Net分割 / 边缘检测 | 按长度分级 |
| 烧蚀 | 局部颜色变深/发黑 | 语义分割(YOLOv8-seg) | 按面积分级 |
| 磨损 | 表面纹理粗糙化 | 纹理分类(GLCM+CNN) | 按深度分级 |
| 积垢 | 表面附着物 | 语义分割 | 按覆盖率 |
| 叶片撕裂 | 缺口/变形 | 目标检测(YOLOv8) | 按撕裂尺寸 |

**CLIP图文匹配**（复用医疗CLIP粗筛思路）：孔探图像 vs 损伤描述文本（"blade with crack"/"clean turbine blade"）计算余弦相似度，粗筛损伤有无。

> **仓库原型验证**：`timeseries_operators.py:CrossModalConflictFilter`（`:227-380`）已实现CLIP零样本图像分类（`_CLIP_CACHE`缓存模型），场景4可直接复用CLIP部分，替换类别为航发损伤类型。

### 2.4 多模态配对与时戳对齐

**核心问题**：时序异常段、工单时间戳、图像拍摄时间三者须对齐到同一时间轴，才能做跨模态冲突检测。

| 对齐类型 | 配对对象 | 对齐方法 | 容差 |
|---|---|---|---|
| **时序↔工单** | 异常段start_ts ↔ 工单故障发现时间 | 时戳匹配 + 容差窗口 | ±1h（维护登记延迟） |
| **时序↔图像** | 异常段 ↔ 图像拍摄时间 | 时戳匹配 | ±24h（拆解可能数日后） |
| **工单↔图像** | 工单故障部件 ↔ 图像拍摄部位 | 部件标签匹配 | 精确匹配 |

> **关键挑战**：医疗场景NLMCXR的image和text天然配对（parquet同一行），场景4的三模态**不天然配对**——时序连续流、工单事件触发、图像维护触发，三者时戳粒度差异大。这是场景4比医疗场景更难的核心原因。

### 2.5 ②推荐Pipeline

```
归一化航发数据(时序+工单+图像)
    ├──时序支路──→ 多通道重采样 → IsolationForest(基线)+AnomalyTransformer(SOTA) → 异常段+分数
    │                              → 逐通道校准+边界带降级
    ├──工单支路──→ 故障词典匹配 → 30字窗口否定/不确定检测 → 四态标注+时间戳
    ├──图像支路──→ U-Net/YOLO损伤检测 → CLIP图文匹配 → 损伤类型+位置+严重度
    │
    └──多模态配对──→ 时戳对齐(时序↔工单↔图像) → 部件标签匹配
                                                        ↓
                              结构化故障事件库(#2) + 多模态对齐关系
```

### 4.3 质量分级标准

| 等级 | 分数 | 判定条件 | 用途 | 处置 |
|---|---|---|---|---|
| **A级** | ≥85 | 通道齐全、4类冲突0、规程对标≥95%、脱敏语义保持≥90%、无残留敏感、罕见故障占比≥5% | **直接微调** | 入库+dataset card |

**评分模型**：加权综合分 = w1·完整性 + w2·一致性 + w3·合规性 + w4·准确性 + w5·可用性 + w6·隐私性。**隐私性为一票否决项**（残留敏感直接降C）。

**分层评估架构**（复用场景1）：

```
数据集
  ├─ L1规则层(GX)：完整性(通道覆盖)+一致性(4类冲突)+合规性(规程对标) → 自动评分

  ├─ L4隐私层(Presidio复检+k匿名)：残留敏感 → 一票否决
  ├─ L5多样性层(TADS)：故障类型分布+罕见故障占比 → 均衡度评分
  └─ 汇总 → 自定义评分模型 → A/B/C分级 → 路由处置
```

### 5.2 物理约束知识图谱

**核心问题**：构建发动机部件-传感器-故障-物理律的知识图谱，用物理约束传播验证多传感器数据一致性。

**KG在冲突检测中的真实角色**（`entity_research.md:80-110`关键结论 + `multimodal_conflict_detection_analysis.md:3`）：

> 标准ontology**没有显式"contradicts"矛盾边**。KG做**规范化+关系推理**，配合LLM/规则判断矛盾。航发场景的独特优势：**物理定律（热力学/转子动力学/润滑原理）是硬约束**，比医疗的"经验规则"更强。

**场景4的KG设计**：

```
节点：传感器通道 / 发动机部件 / 故障模式 / 物理约束 / 维修规程条文
边：  MEASURED_BY(传感器→部件)        // 振动传感器测量轴承
      LOCATED_IN(部件→发动机段)        // 轴承位于压气机段
      CAUSES(故障模式→异常模式)        // 轴承外圈故障→高频振动
      CONSTRAINED_BY(异常耦合→物理律)  // 温度↑∧转速↓←热力学保护
      TREATED_BY(故障→维修步骤)        // 轴承故障→更换轴承
```

**约束验证流程**（物理律驱动，比医疗更强）：
1. 传感器通道实体链接到KG（通道→部件→故障模式）
2. KG本体定义物理约束（热力学第一定律/转子动力学耦合/润滑原理）
3. 约束传播推理检测违反物理律的数据冲突（检测点4）
4. 记录推理路径（物理依据溯源——"温度↑但转速无响应违反热力学保护逻辑"）
