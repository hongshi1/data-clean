## 二、逐场景调研结论

### 场景1：数智研发领域·软件需求规格设计

#### 2.1.1 模态需求

| 模态 | 具体内容 | 在五步链路中的用途 |
|---|---|---|
| **文本** | SRS自然语言正文(功能需求/性能指标/接口定义/数据字典/运行环境/安全保密/验收准则) | ①解析→②NER→③校验的输入 |
| **表格** | 性能指标表(参数名\|运算符\|数值\|单位)、接口定义表(接口名\|类型\|协议\|字段)、数据字典(参数名\|类型\|单位\|范围) | ①表格抽取→②结构化→③校验比对对象 |

#### 2.1.2 4个检测点

| 检测点 | 检测什么 | 需要什么配对 |
|---|---|---|
| 1 | 性能指标正文↔指标表数值矛盾 | 正文"≤50ms" ↔ 表格[响应时间\|≤\|50\|ms] |
| 2 | 接口定义正文↔接口表字段矛盾 | 正文"RS422" ↔ 表格[接口名\|串行\|RS422\|字段] |
| 3 | 数据字典↔正文术语不一致 | 正文"响应时间" ↔ 字典[参数名\|float\|ms\|[0,100]] |
| 4 | 跨条目参数矛盾 | 同参数在多个条目/表中取值 |

#### 2.1.3 找到的数据集

**PURE数据集**——公开的软件需求规格文档语料库

| 维度 | 详情 |
|---|---|
| 来源 | Zenodo (record/1414117) + GitHub (MeMartijn/PurePlainDataset) |
| 规模 | 19份真实SRS/FRS文档 |
| 原始格式 | 12个.doc + 46个.pdf + 18个.xml + 2个.html + 1个.rtf + 1个.xsd = **80个文件** |
| 领域 | 消费产品/图书馆/司法/信息系统/电商/医疗/3D可视化/交易系统/航空航天等 |
| 许可 | 开源 |
| 已下载 | 65/80个原始文件(35.7MB), 含11个.doc + 36个.pdf + 15个.xml |

**关键发现：原始Word/PDF文档含完整表格**

- 纯文本版(.txt)在转换时丢失了表格结构——之前误判为"无表格"
- 原始.doc文件用macOS textutil转换后确认有**76个表格行**(多列数据)
- 原始Word/PDF中的表格包括：性能指标表、接口定义表、数据字典等
- 正文文本和表格在**同一份文档中天然配对**

**PURE-MMQA**——基于PURE的多模态QA数据集

| 维度 | 详情 |
|---|---|
| 来源 | GitHub SoftALL/PURE-MMQA |
| 规模 | 306条QA(197条text_only + 109条multimodal) |
| 基于文档 | 10份PURE SRS文档(Word+PDF) |
| 4类任务 | GOV(57条)治理约束 / EXE(98条)执行工作流 / EVL(59条)评估指标 / DIS(92条)发现 |
| 字段 | ID, Question, Answer, Document name, Task, type, Difficulty, section number, page reference |
| 作用 | 提供正文↔图表配对关系 + QA答案中含21条数值参数 |

#### 2.1.4 配对关系确认

```
PURE原始Word/PDF文档(含表格)
    │
    ↓ 文档解析(python-docx/MinerU/LibreOffice)
    │
    ├── 正文文本(功能/性能/接口描述) ← 文本模态 ✅
    └── 表格数据(指标表/接口表/字典) ← 表格模态 ✅
         │
         ↓ 天然配对(同一文档)
         │
    4个检测点全部可验证:
      检测点1: 正文"≤50ms" ↔ 表格[响应时间|≤|50|ms] ✅
      检测点2: 正文"RS422" ↔ 表格[接口名|串行|RS422] ✅
      检测点3: 正文"响应时间" ↔ 字典[参数名|float|ms|范围] ✅
      检测点4: 同参数在多个条目/表中取值 ✅
```

#### 2.1.5 结论

**场景1可以完美cover。**

- ✅ 文本模态：19份真实SRS文档(6872行正文)
- ✅ 表格模态：原始Word/PDF含完整表格(性能指标表/接口定义表/数据字典)
- ✅ 天然配对：正文和表格在同一文档中
- ✅ 4个检测点全部可验证
- ✅ 规模可用：19份文档 + 306条QA
- ⚠️ 需做的：用文档解析工具从原始Word/PDF中提取表格结构

### 场景2：引信领域·科研生产方案设计

#### 2.2.1 模态需求

| 模态 | 具体内容 | 在五步链路中的用途 |
|---|---|---|
| **文本** | 设计技术要求(功能/性能/工作流程/接口/通用质量特性5部分) | ①解析→②参数化的输入 |
| **SysML多视图** | 九视图(需求/活动/块定义/接口/参数/状态/用例/分配/视图) | ②结构化转化的输出 |
| **仿真时序** | Simulink/Modelica仿真运行后的时序输出数据 | ③静态↔动态比对的动态侧 |
| **追溯映射** | 要求→SysML视图→仿真的对应关系 | ③覆盖性/传递链检测的依据 |

#### 2.2.2 3个检测点

| 检测点 | 检测什么 | 需要什么配对 |
|---|---|---|
| 1 | 设计要求↔总体方案覆盖性矛盾 | 要求条目 ↔ SysML视图元素 + 覆盖关系 |

| 3 | 跨视图指标传递断裂 | 参数从需求→结构→行为→参数的传递链 |

#### 2.2.4 配对关系确认

| 检测点 | SimpleVehicleModel | Crazyflie | MathWorks | VehicleAnalysisDemo |
|---|---|---|---|---|
| 1.覆盖性 | ✅ 18需求↔40部件 | ✅ allocate分配链 | ✅ 需求↔slreqx追溯 | ✅ satisfy关系 |
| 2.静态↔动态 | ❌ 无仿真 | ⚠️ 可运行未运行 | ✅ 参数超差(Ki) | ❌ 无仿真 |
| 3.传递链 | ✅ import+allocate | ✅ 跨文件分配链 | ✅ 需求→模型→数据 | ✅ 需求→分析→满足 |

#### 2.2.5 结论

**场景2不能完美cover。**

- ✅ 有SysML多视图(SimpleVehicleModel 152定义/9类视图)
- ✅ 有需求↔模型配对(Vehicle Analysis Demo的satisfy关系)
- ✅ 有参数超差实例(MathWorks Ki=0.2 vs 0.19998)
- ✅ 有跨视图分配链(Crazyflie功能→硬件→软件)
- ❌ 没有同时有SysML多视图+仿真运行结果的单一数据集
- ❌ SimpleVehicleModel有SysML无仿真; MathWorks有仿真非SysML
- ⚠️ 需组合: SimpleVehicleModel做检测点1/3 + MathWorks做检测点2

### 场景3：引信领域·科研生产质量缺陷溯源

#### 2.3.1 模态需求

| 模态 | 具体内容 | 在五步链路中的用途 |
|---|---|---|
| **文本** | 故障现象报告(检验过程/工况/现象描述/引信组成原理) | ①解析→②故障NER的输入 |
| **表格** | 工艺规程(工序号/工序名/设备/工艺参数/检验方式) + 故障树底事件(编号/名称/状态:排除/排查/确认/排查结论) | ②底事件建模→③校验比对对象 |

#### 2.3.2 3个检测点

| 检测点 | 检测什么 | 需要什么配对 |
|---|---|---|
| 1 | 故障现象↔工艺底事件对应缺失 | 故障描述(文本) ↔ 底事件列表(表格) |
| 2 | 故障树底事件间逻辑矛盾 | 底事件状态(排除/排查/确认)之间矛盾 |
| 3 | 排查结论↔影响因素确定矛盾 | 排查结论 ↔ 最终确认结果 |

#### 2.3.3 找到的数据集

**NTSB航空事故数据库**

| 维度 | 详情 |
|---|---|
| 来源 | NTSB官网 + GitHub doublegate/NTSB-Dataset_Analysis + data.ntsb.gov |
| 规模 | 179,809条事件(1962-2025, 64年) / ~1.3M行(13个表) |
| 文件 | avall.mdb(553MB, 2008至今) + Pre2008.mdb(893MB) + PRE1982.MDB(188MB) |
| 许可 | 美国政府公共领域(完全开放) |
| 已下载 | ✅ avall.mdb(553MB) + mdb-tools已安装 |

**核心表结构与配对关系**

| 表名 | 行数 | 模态 | 场景3对应 | 关键字段 |
|---|---|---|---|---|
| **narratives** | 519,630 | 文本 | 故障现象报告 | narr_accp(事故叙述) / narr_cause(原因叙述) / narr_inc(纠正措施) |
| **Findings** | 72,092 | 表格 | 故障树底事件 | finding_code(编码) / finding_description(描述) / Cause_Factor(C=原因/F=因素) / cm_inPc(是否在可能原因中) |
| events | 31,104 | 表格 | 事故主表 | ev_type / ev_date / 伤亡数 / 天气 |
| aircraft | 31,333 | 表格 | 设备信息 | acft_make / acft_model / damage / num_eng |
| engines | 28,270 | 表格 | 发动机详情 | eng_type / eng_mfgr / eng_model |
| Events_Sequence | 65,795 | 表格 | 事件序列(故障链) | Occurrence_Description / phase_no |

**配对关系**：通过ev_id + Aircraft_Key天然关联

```
narratives(519,630条文本叙述)
    ↓ ev_id + Aircraft_Key 天然配对
Findings(72,092条结构化发现)
    ↓ 同一事故调查的叙述+发现
3个检测点全部可验证:
  检测点1: narr_accp描述的现象 ↔ Findings.finding_description(对应缺失) ✅
  检测点2: 同一ev_id多条Findings之间(逻辑矛盾) ✅
  检测点3: Findings.Cause_Factor(C/F) ↔ narratives.narr_cause(排查↔确认矛盾) ✅
```

**真实配对样例**

```
事件 ev_id=20080107X00026:

  narratives(文本):
    narr_accp: "On January 1, 2008, about 1430 Pacific standard time,
      a Piper PA 28-180 and a Glastar collided in flight at Sonoma County
      Airport. Both pilots operating under 14 CFR Part 91. Piper sustained
      minor damage, Glastar substantial damage. VMC prevailed..."

  Findings(表格):
    finding 1: "Personnel issues-Action/decision-Info processing/decision-
               Identification/recognition-Pilot of other aircraft - C" (原因)
    finding 2: "Personnel issues-Action/decision-Info processing/decision-
               Identification/recognition-Pilot - C" (原因)

  events(主表):
    ev_type: ACC / ev_date: 01/01/08 / inj_tot_n: 2(未伤) / wx: VMC
```

#### 2.3.4 结论

**场景3可以完美cover。**

- ✅ 文本模态：519,630条事故叙述(narr_accp + narr_cause + narr_inc)
- ✅ 表格模态：72,092条结构化发现(finding_code + finding_description + Cause_Factor)
- ✅ 天然配对：通过ev_id + Aircraft_Key关联，同一事故调查
- ✅ 3个检测点全部可验证
- ✅ 规模超大：519K + 72K，远超研究需求
- ✅ 数据质量：100%外键完整性，零重复
- ✅ 已下载：553MB MDB文件 + mdb-tools已安装 + 表已导出

## 五、调研方法说明

### 5.1 调研范围

- GitHub: 200+关键词搜索, 覆盖SysML/MBSE/故障诊断/预测性维护/AIOps/SCADA/航空发动机/焊接等领域
- HuggingFace: 50+关键词搜索, 覆盖数据集/模型/基准
- arXiv: 80+关键词搜索, 覆盖最新论文
- Zenodo: 尝试访问(部分403)
- NTSB官网: 直接下载(90.8MB zip)
- NASA: DASHlink/GAIA/CMAPSS等

### 5.2 验证方法

每个数据集都经过以下验证:
1. **真实下载**: 所有标"✅已下载"的数据集都已实际下载到本地
2. **格式确认**: 用Python(openpyxl/scipy/pandas)或mdb-tools打开确认格式
3. **内容验证**: 读取真实数据内容, 确认字段/值/配对关系
4. **逐检测点对标**: 每个检测点逐一确认数据集能否支撑验证

### 5.3 未找到的数据

经过广泛搜索, 以下类型的数据在公开领域**确实不存在**:
- 航空发动机领域的"传感器时序+故障工单文本"天然配对
- 大规模"时序+文本+图像"三模态天然配对(除Intel焊接需申请外)
- SysML多视图+仿真运行结果的同一系统配对
- 引信领域的工艺规程/故障树(含工艺机密不公开)
