## 场景1·SRS（文本↔表格）

### TabFact

**下载**：`huggingface.co/datasets/wenhu/tab_fact`
**原始格式**：HuggingFace Dataset（JSON）

| 原始字段 | 类型 | 说明 |
|---|---|---|
| `id` | int | 样本ID |
| `table_id` | string | 表格来源(如"2-12345832-1.html") |
| `table` | dict | 表格内容 `{header: [...], rows: [[...], ...]}` |
| `statement` | string | 待验证的自然语言声明 |
| `label` | int | 0=反驳, 1=支持 |

**转成我们的JSONL**：
```
table.header + table.rows  →  meta.tables[0].header + meta.tables[0].rows
statement                  →  text
label                      →  meta.label (0=矛盾, 1=一致)
```

**样例**：
```json
{
  "text": "Czech Republic is a country in the European Union.",
  "images": [],
  "meta": {
    "table_id": "2-12345832-1",
    "tables": [{"header": ["Country", "Capital", "Population"], "rows": [["Czech Republic", "Prague", "10600000"]]}],
    "label": 1,
    "label_meaning": "支持"
  }
}
```

### Infotabs

**下载**：`huggingface.co/datasets/table-benchmark/infotabs`
**原始格式**：HuggingFace Dataset（JSON）

| 原始字段 | 类型 | 说明 |
|---|---|---|
| `premise` | dict | 表格(以key-value形式存储) |
| `premise_text` | string | 表格的文本序列化 |
| `hypothesis` | string | 待验证的自然语言假设 |
| `label` | string | entailment=蕴含, contradiction=矛盾, neutral=中立 |

**转成我们的JSONL**：
```
premise               →  meta.tables[0] (key-value表)
hypothesis            →  text
label                 →  meta.label (entailment/contradiction/neutral)
```

**样例**：
```json
{
  "text": "The film was directed by James Cameron.",
  "images": [],
  "meta": {
    "tables": [{"header": ["Field", "Value"], "rows": [["Director", "James Cameron"], ["Year", "2009"], ["Title", "Avatar"]]}],
    "label": "entailment"
  }
}
```

### DocLayNet

**下载**：`huggingface.co/datasets/docling-project/DocLayNet`
**原始格式**：图像(PNG) + COCO格式JSON标注

| 原始字段 | 类型 | 说明 |
|---|---|---|
| `image` | PIL.Image | 文档页面图像 |
| `annotations` | array | 版面布局标注列表 |
| `annotations[].bbox` | [x,y,w,h] | 边界框坐标 |
| `annotations[].category_id` | int | 11类布局: 1=文本, 2=标题, 3=列表, 4=表格, 5=图, 6=标题, 7=脚注, 8=公式, 9=页码, 10=日期, 11=水印 |

**转成我们的JSONL**：
```
image                      →  images[0]
annotations(category=文本)  →  meta.sections.正文
annotations(category=表格)  →  meta.tables 区域(需进一步OCR/抽取)
annotations(category=标题)  →  meta.sections 标题
```

**样例**：
```json
{
  "text": "",
  "images": ["doclaynet/page_001.png"],
  "meta": {
    "doc_id": "doclaynet_001",
    "layout_blocks": [
      {"type": "标题", "bbox": [100, 50, 500, 80], "text": "第3章 性能要求"},
      {"type": "文本", "bbox": [100, 90, 500, 200], "text": "系统响应时间应≤50ms..."},
      {"type": "表格", "bbox": [100, 210, 500, 350], "text": ""}
    ]
  }
}
```

### PubTables-1M

**下载**：`github.com/microsoft/table-transformer`
**原始格式**：图像(PNG) + XML(Pascal VOC格式) + JSON

| 原始字段 | 类型 | 说明 |
|---|---|---|
| `image` | PNG | 含表格的文档页面 |
| `xml.filename` | string | 图像文件名 |
| `xml.objects` | array | 表格结构标注 |
| `objects[].name` | string | "table"/"row"/"column"/"header"/"spanning cell" |
| `objects[].bndbox` | [xmin,ymin,xmax,ymax] | 边界框 |

**转成我们的JSONL**：
```
image                      →  images[0]
objects(table)             →  meta.tables[0].bbox
objects(row/column/header) →  meta.tables[0].structure (行列结构)
```

**样例**：
```json
{
  "text": "",
  "images": ["pubtables/page_001.png"],
  "meta": {
    "tables": [{
      "table_id": "pubtables_001",
      "bbox": [50, 100, 800, 400],
      "header": ["指标名", "运算符", "数值", "单位"],
      "rows": [["响应时间", "≤", "50", "ms"], ["吞吐量", "≥", "1000", "tps"]],
      "structure": {"num_rows": 3, "num_cols": 4, "merged_cells": []}
    }]
  }
}
```

## 场景2·引信方案设计（SysML+仿真）

### OMG SysML v2 示例

**下载**：`github.com/Systems-Modeling/SysML-v2-Release`
**原始格式**：SysML 2.0文本文件(.sysml) + XMI

SysML 2.0文本示例：
```
package FuseSystem {
  part def Fuse {
    attribute threshold : Scalar(0.0..10.0) = 5.0 [V];
    attribute delay : Scalar(0.0..10.0) = 3.0 [s];
    port input_voltage : VoltageValue;
    part detonator : Detonator;
    flow input_voltage -> detonator.voltage;
  }
  constraint { input_voltage >= threshold implies detonator.fired }
}
```

**转成我们的JSONL**：
```
package名               →  meta.sysml_views.block_definition.package
part def(块定义)         →  meta.sysml_views.block_definition.elements[]
attribute(属性)          →  element.attributes[] (含name/value/unit)
constraint(约束)         →  meta.sysml_views.parametric.constraints[]
port(端口)               →  element.ports[]
flow(流)                 →  element.flows[]
```

**样例**：
```json
{
  "text": "引信设计技术要求...",
  "images": [],
  "meta": {
    "sysml_views": {
      "block_definition": {
        "package": "FuseSystem",
        "elements": [{
          "id": "Fuse",
          "type": "part def",
          "attributes": [
            {"name": "threshold", "value": 5.0, "unit": "V", "type": "Scalar"},
            {"name": "delay", "value": 3.0, "unit": "s", "type": "Scalar"}
          ],
          "ports": [{"name": "input_voltage", "type": "VoltageValue"}]
        }]
      },
      "parametric": {
        "constraints": [{"id": "CON-001", "expression": "input_voltage >= threshold implies detonator.fired"}]
      }
    }
  }
}
```

### Modelica标准库

**下载**：`github.com/modelica/ModelicaStandardLibrary`
**原始格式**：Modelica文本文件(.mo)

Modelica文本示例：
```modelica
model FuseDetonator
  parameter Real threshold = 5.0 "引爆阈值(V)";
  parameter Real delay = 3.0 "解保延时(s)";
  Real voltage "输入电压";
  Boolean fired "是否引爆";
equation
  fired = voltage >= threshold and time >= delay;
end FuseDetonator;
```

**转成我们的JSONL**：
```
model名              →  meta.simulation.model_name
parameter            →  meta.simulation.parameters[] (含name/value/unit/comment)
Real/Boolean变量     →  meta.simulation.outputs[] (含name/type)
equation             →  meta.simulation.equations[]
```

**样例**：
```json
{
  "text": "引信设计技术要求...",
  "images": [],
  "meta": {
    "simulation": {
      "sim_tool": "Modelica",
      "model_name": "FuseDetonator",
      "model_path": "models/FuseDetonator.mo",
      "parameters": [
        {"name": "threshold", "value": 5.0, "unit": "V", "comment": "引爆阈值"},
        {"name": "delay", "value": 3.0, "unit": "s", "comment": "解保延时"}
      ],
      "outputs": [
        {"name": "voltage", "type": "Real", "comment": "输入电压"},
        {"name": "fired", "type": "Boolean", "comment": "是否引爆"}
      ],
      "equations": ["fired = voltage >= threshold and time >= delay"]
    }
  }
}
```

## 场景3·引信溯源（故障/缺陷）

### NEU表面缺陷

**下载**：`kaggle.com/datasets/kaustubhdikshit/neu-surface-defect-database`（仓库已有`data/material_data/`）
**原始格式**：图像(JPG) + 文件名含缺陷标签

6类缺陷：`crazing`(龟裂) / `inclusion`(夹杂) / `patches`(斑块) / `pitted_surface`(麻点) / `rolled-in_scale`(轧入氧化皮) / `scratches`(划痕)

文件名格式：`{缺陷类型}_{序号}.jpg`，如`crazing_1.jpg`

**转成我们的JSONL**：
```
图像文件               →  images[0]
文件名中的缺陷类型      →  meta.fault_info.fault_mode
缺陷类型中文映射        →  meta.fault_info.fault_mode_cn
```

**样例**：
```json
{
  "text": "",
  "images": ["neu/images/crazing_1.jpg"],
  "meta": {
    "defect_label": "crazing",
    "defect_label_cn": "龟裂",
    "defect_category": "surface",
    "material_type": "steel"
  }
}
```

### MVTec AD

**下载**：`mvtec.com/company/research/datasets/mvtec-ad`
**原始格式**：图像(PNG) + 异常掩码(PNG)

目录结构：
```
{category}/
  train/good/                    # 正常训练图像
  test/good/                     # 正常测试图像
  test/{defect_type}/            # 缺陷测试图像
  ground_truth/{defect_type}/    # 缺陷掩码(PNG,白色=缺陷区域)
```

15类物体：bottle(瓶) / cable(电缆) / capsule(胶囊) / carpet(地毯) / grid(网格) / hazelnut(榛子) / leather(皮革) / metal_nut(金属螺母) / pill(药丸) / pixel(像素) / screw(螺丝) / tile(瓷砖) / toothbrush(牙刷) / transistor(晶体管) / zipper(拉链)

每类含5种缺陷类型(物体相关)，如metal_nut含: bent(弯曲) / color(色差) / flip(翻转) / scratch(划痕) / hole(孔洞)

**转成我们的JSONL**：
```
图像文件                →  images[0]
掩码文件                →  meta.defect_mask_path
物体类别                →  meta.object_category
缺陷类型                →  meta.defect_type
split(train/test)      →  meta.split
```

**样例**：
```json
{
  "text": "",
  "images": ["mvtec/metal_nut/test/scratch/001.png"],
  "meta": {
    "object_category": "metal_nut",
    "defect_type": "scratch",
    "defect_mask_path": "mvtec/metal_nut/ground_truth/scratch/001_mask.png",
    "split": "test"
  }
}
```

## 场景4·航发维护（时序↔文本↔图像）

### NASA CMAPSS

**下载**：`kaggle.com/datasets/behrad3d/nasa-cmaps`
**原始格式**：TXT(空格分隔时序数据)

4个子集(FD001-FD004)，每行一条时序采样：

| 列号 | 字段 | 说明 |
|---|---|---|
| 1 | unit_number | 发动机编号(1-100) |
| 2 | time_in_cycles | 运行周期数(从1到故障) |
| 3-5 | setting_1/2/3 | 运行工况设置 |
| 6-26 | s_1 ~ s_21 | 21个传感器读数 |

标签：每台发动机最后一条记录 = 故障时刻，之前所有记录的RUL = 总寿命 - 当前周期

**转成我们的JSONL**：
```
unit_number                →  meta.engine_id
time_in_cycles             →  meta.timeseries.time_axis
s_1~s_21                   →  meta.timeseries.channels[] (21通道)
setting_1~3                →  meta.timeseries.operating_conditions
总寿命 - 当前周期           →  meta.fault_info.rul (剩余寿命)
```

**样例**：
```json
{
  "text": "",
  "images": [],
  "meta": {
    "engine_id": "FD001-unit001",
    "timeseries": {
      "channels": ["s_1", "s_2", ..., "s_21"],
      "sampling_rate": 1,
      "data_path": "cmapss/FD001-unit001.parquet",
      "time_range": [1, 192],
      "units": {"s_1": "RPM", "s_2": "°R", ..., "s_21": "ratio"}
    },
    "fault_info": {
      "rul": 130,
      "fault_type": "性能退化",
      "discovery_time": "cycle 192"
    }
  }
}
```

### CWRU轴承

**下载**：`engineering.case.edu/bearingdatacenter`
**原始格式**：MAT文件

数据结构：
| 字段 | 说明 |
|---|---|
| `X.Y_DE_time` | 驱动端加速度计时序(主要分析对象) |
| `X.Y_FE_time` | 风扇端加速度计时序 |
| `X.Y_BA_time` | 基座加速度计时序 |
| `X.YRPM` | 转速(RPM) |

文件命名：`{负载}{故障位置}_{故障直径}_{故障类型}.mat`
- 负载: 0/1/2/3 HP
- 故障位置: DE(驱动端)/FE(风扇端)
- 故障直径: 0.007/0.014/0.021/0.028 inch
- 故障类型: 无后缀=内圈故障, `_Ball`=滚珠, `_Outer`=外圈

**转成我们的JSONL**：
```
DE_time时序               →  meta.timeseries.channels["vibration_DE"]
FE_time时序               →  meta.timeseries.channels["vibration_FE"]
RPM                       →  meta.timeseries.rpm
故障位置(文件名解析)       →  meta.fault_info.fault_location
故障直径(文件名解析)       →  meta.fault_info.fault_severity
故障类型(文件名解析)       →  meta.fault_info.fault_type
```

**样例**：
```json
{
  "text": "",
  "images": [],
  "meta": {
    "engine_id": "CWRU-007-DE",
    "timeseries": {
      "channels": ["vibration_DE", "vibration_FE"],
      "sampling_rate": 12000,
      "data_path": "cwru/007_DE_time.npy",
      "units": {"vibration_DE": "g", "vibration_FE": "g"}
    },
    "fault_info": {
      "fault_type": "内圈故障",
      "fault_location": "驱动端(DE)",
      "fault_diameter": 0.007,
      "fault_diameter_unit": "inch",
      "load_hp": 0
    }
  }
}
```

| `caption` | string | 图像对应的caption(前提) |
| `hypothesis` | string | 待验证的文本假设 |
| `label` | int | 0=矛盾, 1=中立, 2=蕴含 |

**转成我们的JSONL**：
```
image        →  images[0]
hypothesis   →  text
label        →  meta.label (0=矛盾, 1=中立, 2=蕴含)
caption      →  meta.caption (图像原始描述)
```

**样例**：
```json
{
  "text": "There are no people in the image.",
  "images": ["snli-ve/img_001.jpg"],
  "meta": {
    "caption": "A group of people playing soccer.",
    "label": 0,
    "label_meaning": "矛盾"
  }
}
```

### CIFAR-100N

**下载**：`huggingface.co/datasets/hirundo-io/Noisy-CIFAR-100`
**原始格式**：HuggingFace Dataset

| 原始字段 | 类型 | 说明 |
|---|---|---|
| `image` | PIL.Image | 32×32彩色图像 |
| `fine_label` | int | 精细标签(100类) |
| `coarse_label` | int | 粗粒度标签(20超类) |
| `noisy_label` | int | 人工噪声标签 |
| `clean_label` | int | 干净标签(ground truth) |

**转成我们的JSONL**：
```
image           →  images[0]
noisy_label     →  meta.noisy_label
clean_label     →  meta.clean_label
label_match     →  meta.label_is_clean (noisy==clean ? true : false)
```

**样例**：
```json
{
  "text": "",
  "images": ["cifar100n/img_001.png"],
  "meta": {
    "noisy_label": 15,
    "clean_label": 15,
    "noisy_label_name": "man",
    "clean_label_name": "man",
    "label_is_clean": true
  }
}
```
