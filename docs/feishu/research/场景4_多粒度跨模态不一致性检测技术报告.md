> 版本: v1.0 | 日期: 2026-07-08
> 核心思想：将医疗图文不一致检测的**七层多粒度体系**，系统性迁移到航发维护场景（时序↔文本↔图像三模态）
> 依据: `图文不一致性检测_技术调研.md`(医疗多粒度体系) + `方法章节_深度版.md`(方法谱系) + `数据场景分析.md`场景4 + 仓库已验证原型

## 0. 概述：从医疗图文到航发三模态的多粒度迁移

### 0.1 场景定位

场景四（航空发动机维护保障）以时序运行数据为核心，融合故障工单（文本）与孔探/拆解图像（图像），是课题**三模态最齐全场景**：

| 模态 | 数据 | 采样特征 | 对应医疗场景 |
|---|---|---|---|
| **时序** | 振动/温度/转速/压力传感器 | 振动10kHz、温度1Hz | ECG心电（医疗中非第一公民） |
| **文本** | 故障工单/维护手册 | 事件触发型、非连续 | 放射报告（医疗第一公民文本侧） |
| **图像** | 孔探/拆解图像 | 维护触发型、离散 | CXR胸片（医疗第一公民图像侧） |

**核心差异**：医疗场景"图像是第一公民"（TorchXRayVision读片→报告NER→冲突矩阵）；航发场景"**时序是第一公民**"（时序异常检测→工单NER→冲突矩阵）。时序异常检测器替代图像AI读片模型，工单NER替代放射报告NER，冲突矩阵逻辑直接复用。

### 0.2 核心思想：七层粒度递进检测

医疗图文不一致检测已形成成熟的**七层多粒度谱系**（`方法章节_深度版.md:3.9`），从可解释性最高到语义覆盖最广递进：

```
可解释性高 ◄─────────────────────────────────────────► 语义覆盖广
    │                                                        │
 第1层      第2层        第3层        第4层      第5层     第6层      第7层
通道级     故障级      全局向量级    问答级    时间点/     端到端     LLM+
规则校验   冲突矩阵    CLIP粗筛     VDC三段式  短语级      MLLM       Guard
(字段级)   (事件级)    (向量级)     (QA级)    (定位级)   (隐式级)   (语义级)
 L1规则    图像×文本   cos相似度    VQG→VQA   FAMDR      CheXagent  Qwen+代码
 无GPU     DenseNet    CheXzero     →VAE      F1=0.83    36%省时    FP=0
```

**每一层解决不同粒度的不一致**：第1层查"单个传感器数值是否越限"，第2层查"时序异常和工单故障类型是否矛盾"，第5层定位到"哪段时序和工单哪句话冲突"，第7层处理"多传感器耦合故障的复杂语义判定"。

### 0.3 粒度谱系总表：医疗→航发迁移映射

| 层 | 对齐粒度 | 医疗原型（已验证） | 航发迁移 | 仓库原型 |
|---|---|---|---|---|
| **1** | 字段/通道级 | 知识库规则（血检范围↔诊断标签，L1） | **传感器通道范围规则**（ISO 10816↔工单） | MedicalLabRangeFilter ✅ |
| **2** | 事件/故障级 | 三态冲突矩阵（DenseNet概率×报告四态） | **时序异常段×工单四态冲突矩阵** | CrossModalConflictFilter ✅ |
| **3** | 全局向量级 | CheXzero/MedCLIP（图文嵌入cos相似度） | **时序嵌入↔工单文本嵌入对齐** | timeseries_op CLIP ✅ |
| **4** | 问答级 | VDC（VQG→VQA→VAE，TPR 99.91%） | **时序VQG→工单VQA→VAE** | — |
| **5** | 时间点/短语级 | FAMDR（4组件，F1=0.83，像素/短语定位） | **时间段+工单短语级定位** | — |
| **6** | 端到端隐式 | CheXagent（联合编码图+文，36%省时） | **多模态大模型联合推理** | — |
| **7** | 语义级 | LLM+Guard（Qwen2:7b+代码核验，FP=0） | **LLM判定+物理约束代码核验** | _llm_detect ✅ |

### 0.4 检测任务与模态对

场景四定义4个不一致性检测点（`数据场景分析.md:117-126`），分布在不同粒度层：

| 检测点 | 模态对 | 核心矛盾 | 主检测层 |
|---|---|---|---|
| 1 时序异常↔工单故障类型 | 时序↔文本 | 振动谱异常但工单记"电气故障" | **第2层**（冲突矩阵）+第5层（定位） |
| 2 时序异常时戳↔工单登记时间 | 时序↔文本 | 传感器异常T1但工单登记T2 | **第1层**（数值约束） |
| 3 健康预测↔拆解记录 | 时序↔图像 | RUL预测"健康"但拆见解严重损伤 | **第3层**（向量粗筛）+第6层（端到端） |
| 4 多传感器物理约束 | 时序内部 | 温度↑但转速无响应 | **第1层**（L3物理约束）+第7层（Guard核验） |

## 1. 第一层：通道级规则校验（字段级）

### 1.1 医疗原型：知识库规则L1

医疗场景的字段级检测已由仓库 `medical_operators.py:MedicalLabRangeFilter` 验证：50项血检指标逐项查正常范围，超出即标记异常+严重度。知识库 `medical_kb.json` 的L1层结构为：

```python
"50893": {"name":"乳酸","unit":"mmol/L","normal":(0.5,2.0),
          "severity_high":{2.0:"MEDIUM", 5.0:"CRITICAL"}}
```

**验证效果**：10000样本检出1444条跨模态冲突（`medical_conflict_results.json`），其中L1范围检测是L2冲突检测的前置——先查出指标异常，再比对诊断标签。

### 1.2 航发迁移：传感器通道范围规则

航发场景的"字段"是传感器通道，"正常范围"来自行业标准（ISO 10816振动评级）。构建 `aero_kb.json` 的L1层：

```json
{
  "L1_sensor_ranges": {
    "vibration_rms": {
      "normal_op": "<=", "normal_val": 7.1, "unit": "mm/s",
      "severity_high": [
        {"threshold": 11.2, "level": "HIGH"},
        {"threshold": 18.0, "level": "CRITICAL"}
      ],
      "standard": "ISO 10816 振动评级"
    },
    "exhaust_temp": {
      "normal_op": "<=", "normal_val": 650, "unit": "℃",
      "severity_high": [
        {"threshold": 720, "level": "HIGH"},
        {"threshold": 800, "level": "CRITICAL"}
      ]
    },
    "oil_pressure": {
      "normal_op": "in_range", "normal_val": [0.25, 0.45], "unit": "MPa",
      "severity_low": [
        {"threshold": 0.20, "level": "HIGH"},
        {"threshold": 0.15, "level": "CRITICAL"}
      ]
    }
  }
}
```

**迁移要点**：血检itemid（如"50893"乳酸）→ 传感器通道名（如`vibration_rms`）；医学正常范围 → ISO 10816限值；严重度阶梯保留（MEDIUM/HIGH/CRITICAL）。

### 1.3 多通道物理约束（L3层）

航发独有优势：**物理定律是硬约束**，比医疗经验规则更强。`aero_kb.json` 的L3层编码热力学/转子动力学/润滑原理：

```json
{
  "L3_physics_constraints": [
    {
      "name": "过热保护响应",
      "conditions": [
        {"channel": "exhaust_temp", "op": ">", "val": 720},
        {"channel": "rotor_speed", "op": "should_decrease", "within_min": 2}
      ],
      "conflict_if": "温度超限但转速2分钟内未降",
      "severity": "CRITICAL",
      "physics": "热力学保护逻辑：超温应触发减速"
    },
    {
      "name": "轴承故障耦合",
      "conditions": [
        {"channel": "vibration_rms", "op": ">", "val": 11.2},
        {"channel": "oil_temp", "op": ">", "val": 120}
      ],
      "conflict_if": "振动+滑油温同步升高但工单未记轴承故障",
      "severity": "HIGH",
      "physics": "轴承磨损→摩擦热→滑油温升（转子动力学耦合）"
    }
  ]
}
```

> **与医疗L3对比**：医疗L3是"pH低∧Bicarbonate低=代谢性酸中毒"的经验组合规则；航发L3是"温度↑∧转速无响应"违反热力学第一定律的**物理硬约束**——后者更强、更可审计。

### 1.4 局限与向上递进

| 局限 | 表现 | 向哪层递进 |
|---|---|---|
| 只查单通道/硬编码约束 | 无法检测"振动谱型变化"等模式异常 | →第2层（时序异常检测） |
| 不理解工单语义 | 无法比对"时序异常"与"工单记什么故障" | →第2层（冲突矩阵） |
| 物理约束有限 | 复杂多传感器耦合关系难穷举 | →第7层（LLM+物理Guard） |

## 2. 第二层：故障级冲突矩阵（事件级）

### 2.1 医疗原型：三态冲突矩阵

医疗场景的核心方法——图像AI读片（DenseNet输出18维概率）× 报告NER四态（阳性/否定/不确定/未提及）→ 冲突矩阵判定5类冲突（`方法章节_深度版.md:3.3`）。

**NLMCXR 20样本实测统计**（`conflict_stats.json`）：

| 统计项 | 数值 |
|---|---|
| 总样本 | 20 |
| 有冲突样本 | 17（85%） |
| 总冲突数 | 62 |
| 每样本冲突中位数 | 3（范围0-6） |

**冲突类型×严重度交叉表**：

| 冲突类型＼严重度 | HIGH | MEDIUM | LOW | 合计 |
|---|---|---|---|---|
| 图片↔报告结论 | 0 | **42** | 0 | 42 |
| 图片↔报告否定 | **3** | 2 | 7 | 12 |
| 报告内部 | 0 | 4 | 0 | 4 |
| 报告↔图片 | 0 | 2 | 0 | 2 |
| 图片↔报告不确定 | 0 | 0 | 2 | 2 |

**关键发现**：42/62冲突(68%)为"图片↔报告结论"——AI检出病灶但报告未提及且称正常。

### 2.2 航发迁移：时序异常段×工单四态

迁移映射：医疗"图像AI概率→阳/阴性" → 航发"时序异常检测→异常/正常"；医疗"报告NER四态" → 航发"工单NER四态"。

#### 2.2.1 时序侧分析（替代TorchXRayVision）

| 维度 | 医疗图像侧 | 航发时序侧 |
|---|---|---|
| 模型 | DenseNet121（18维logits） | IsolationForest(基线)+AnomalyTransformer(SOTA) |
| 输入 | 224×224灰度胸片 | 多通道传感器时序（振动/温度/转速/压力） |
| 输出 | 18维疾病概率 | 异常段(start,end,score,channel) |
| 校准 | sigmoid(logit)→概率 | 异常分数→概率（逐通道Youden J） |
| 阈值 | 逐病种op_threshs | 逐通道θ_ch |
| SOTA出处 | MIDL 2022 AUC 0.81-0.92 | AnomalyTransformer ICLR 2022 |

**时序异常检测方法选型**（TAB基准 PVLDB 2025, arXiv:2506.18046 + MTAD arXiv:2401.06175）：

| 方法 | 原理 | 航发适用 | GPU |
|---|---|---|---|
| **Isolation Forest** | 随机孤立划分，异常路径短 | ★★★★★(轻量基线/可审计) | 无 |
| **AnomalyTransformer** | 关联差异Associate/Adjacent注意力 | ★★★★★(SOTA) | 高 |
| **MTAD-GAT** | 图注意力建模通道间依赖 | ★★★★★(多传感器关系) | 高 |
| AutoEncoder | 重构误差>阈值 | ★★★★(频域特征) | 中 |
| USAD | 对抗式AE | ★★★★ | 中 |

> TAB基准核心发现：**没有单一检测器在所有数据集上占主导**。推荐Isolation Forest(基线)+AnomalyTransformer(SOTA)双路并行。

> **仓库原型验证**：`timeseries_operators.py:TimeSeriesAnomalyFilter`已实现IsolationForest检测4路时序异常点，输出`ts_anomaly_score`。场景4需扩展为多通道+异常段。

#### 2.2.2 工单侧NER三态（替代CheXpert Labeler）

迁移映射：医疗"放射报告NER" → 航发"故障工单NER"。

| 维度 | 医疗文本侧 | 航发文本侧 |
|---|---|---|
| 文本类型 | 放射报告（Findings+Impression） | 故障工单（故障现象+排查+结论） |
| 词典 | 14类疾病mention_phrases | 航发故障类型词典（振动超限/温度过热/轴承故障…） |
| 否定检测 | CheXpert Labeler依存句法/30字窗口 | 30字窗口否定检测（复用） |
| 四态 | 阳性/否定/不确定/未提及 | 阳性(故障确认)/否定(排除)/不确定(待查)/未提及 |

**航发故障词典**（替代医疗14类疾病）：

```
振动超限 / 温度过热 / 转速波动 / 滑油压力低 / 滑油温度高
轴承故障 / 压气机喘振 / 涡轮叶片损伤 / 燃烧室积碳 / 密封泄漏
```

**否定词表**（复用医疗`_NEG_PATTERN`，航发补充）：
```python
_NEG_PATTERN = re.compile(r"\b(未见|无|排除|未发现|正常|无异常|未检出|否认)\b")
_UNC_MARKERS = ["疑似","待查","可能","不能排除","建议复查","尚需确认","初步判断"]
```

**医疗→航发标注对照**：

| 医疗报告原文 | 医疗标注 | 航发工单原文 | 航发标注 |
|---|---|---|---|
| "No pleural effusion" | 否定(命中"no") | "未见滑油泄漏" | 否定(命中"未见") |
| "may represent consolidation" | 不确定(命中"may represent") | "疑似2号轴承磨损" | 不确定(命中"疑似") |
| "associated atelectasis" | 阳性(无否定词) | "2号轴承振动超限" | 阳性(无否定词) |

> **仓库原型验证**：`nlmcxr_operators.py:232-297`的30字窗口否定检测已在NLMCXR 20样本上验证。场景4换词典即可。

#### 2.2.3 冲突矩阵定义

类比医疗图像×报告冲突矩阵，定义航发时序×工单冲突矩阵：

| 时序状态＼工单状态 | 阳性(故障确认) | 否定(排除) | 不确定(待查) | 未提及 |
|---|---|---|---|---|
| **确信异常(HIGH)** | ✅一致 | 🔴**HIGH冲突** | 🟡LOW冲突 | 🟠MEDIUM冲突 |
| **边界异常** | ✅一致 | 🟡LOW冲突(降级) | ⚪待复核 | ⚪待复核 |
| **正常** | 🟠MEDIUM(误报?) | ✅一致 | ✅一致 | ✅一致 |

**五种冲突类型**（与医疗同构）：

| 冲突类型 | 触发条件 | 严重度 | 航发含义 |
|---|---|---|---|
| 时序↔工单否定 | 时序异常∧工单否定 | HIGH/MED/LOW | AI见异常但工单明确否认——疑似漏诊 |
| 时序↔工单不确定 | 时序异常∧工单不确定 | LOW | AI见异常但工单含糊——需复核 |
| 时序↔工单结论 | 时序异常∧工单未提及∧称正常 | MEDIUM | AI见异常但工单没提且称正常——漏诊 |
| 工单↔时序 | 时序正常∧工单阳性 | MEDIUM | 工单称有故障但AI没检测到 |
| 工单内部 | 工单有阳性故障∧称正常 | MEDIUM | 工单自相矛盾 |

> **R9冲突映射**（`R9_可立项方向细化.md:219`）：检测点1的"时序异常但工单记正常"= **C8否定矛盾**，正是场景4核心需求。

### 2.3 边界带降级机制

复用医疗边界带设计（`方法章节_深度版.md:3.1.4`），δ=0.05：

| 异常分数区间 | 判定 | 冲突严重度 |
|---|---|---|
| score > θ_ch + δ | 确信异常 | 正常定级 |
| θ_ch - δ ≤ score ≤ θ_ch + δ | **边界异常** | **降一级** |
| score < θ_ch - δ | 正常 | 不触发冲突 |

**医疗→航发对照**：医疗Pneumothorax概率0.515在边界带→降级LOW（`方法章节_深度版.md:3.1.4`实测）；航发振动通道score=0.52在边界带→降级LOW。

**规律**（类比医疗低患病率病种阈值偏高）：高频振动通道（罕见异常）阈值偏高避免假阳性；温度通道（频繁超限）阈值偏低避免假阴性。

### 2.4 冲突检测精度上限

> **关键公式**（`方法章节_深度版.md:3.3.4`）：冲突检测精度 = 侧1精度 × 侧2精度。

医疗场景：用AUC 0.92的胸腔积液做冲突检测可信度远高于AUC 0.74的骨折。

航发场景：用F1高的振动异常检测器做冲突检测可信度远高于低F1的滑油压力。**实际部署应按通道检测精度分优先级**。

### 2.5 航发实例

```
输入：某航发2026-03-15运行数据
  时序侧：振动高频通道 14:23-14:25 异常段 score=0.87 (确信异常HIGH)
          排气温度 14:20-14:28 持续超温 score=0.78 (确信异常HIGH)
  工单侧："14:30例行检查，未见异常，排气温度正常范围内"
          → 振动超限=未提及, 温度过热=否定(命中"正常范围内")

冲突检出：
  ① 振动↔工单结论 → MEDIUM（时序异常但工单未提及且称正常）
  ② 温度↔工单否定 → HIGH（时序确信异常score=0.87 vs 工单否定"正常范围内"）
  ③ 物理约束 → CRITICAL（温度↑∧振动↑→轴承故障耦合，但工单未记轴承故障）
```

### 2.6 局限与向上递进

| 局限 | 表现 | 向哪层递进 |
|---|---|---|
| 逐通道/逐故障独立比对 | 不捕获通道间交互异常 | →第5层（FAMDR噪声感知对齐） |
| 依赖预定义故障词典 | 新故障类型无法检测 | →第6层（MLLM端到端） |
| 只判"有无冲突"不定位"哪里冲突" | 无法精确到时序段/工单短语 | →第5层（时间点/短语级定位） |
| 词典匹配不理解语义 | "排除了轴承问题"vs"轴承无异常"难区分 | →第7层（LLM语义判定） |

---

## 3. 第三层：全局向量级粗筛（CLIP迁移）

### 3.1 医疗原型：CheXzero/MedCLIP

医疗场景的全局向量级检测用CLIP对比学习将图文映射到同一语义空间（`方法章节_深度版.md:3.6`）：

- **CheXzero**（You et al., 2022）：227,835张MIMIC-CXR胸片+报告自监督学习，零样本胸片分类接近监督模型
- **推理**：`cos(emb_img, emb_txt) < μ` → 判为不一致
- **角色**：粗筛层——快速过滤明显不匹配的图文对

**CLIP三大局限**（均有论文实测）：
1. **Bag-of-Words行为**（arXiv:2502.03566）：分不清属性-对象绑定
2. **细粒度区分差**（arXiv:2404.03539）：疾病细节区分接近随机
3. **属性-对象绑定失败**（arXiv:2507.07985）：多物体共存时失效

### 3.2 航发迁移：时序嵌入↔工单文本嵌入

航发场景需要将**时序信号**和**工单文本**映射到同一语义空间。医疗CLIP的图像编码器替换为时序编码器：

| 组件 | 医疗CLIP | 航发跨模态对齐 |
|---|---|---|
| 编码器1（图像/时序） | ViT-L/14视觉编码器 | **时序编码器**（TS2Vec/TF-C/TimesNet） |
| 编码器2（文本） | GPT-2文本编码器 | BERT/RoBERTa文本编码器 |
| 训练数据 | 4亿图文对 | 时序-工单配对（需自建或C-MAPSS+合成） |
| 对齐目标 | InfoNCE对比损失 | InfoNCE对比损失（同构） |
| 推理 | cos(emb_img, emb_txt) | **cos(emb_ts, emb_text)** |

**时序编码器选型**：

| 编码器 | 原理 | 出处 | 适用 |
|---|---|---|---|
| **TS2Vec** | 时间增强+分层对比学习 | AAAI 2022 | 通用时序表示 |
| **TF-C** | 时间-频率双视角对比 | NeurIPS 2022 | 跨域时序迁移 |
| **TimesNet** | 1D→2D重排+Inception | ICLR 2023 | 周期性时序 |
| **Timer** | 生成式预训练大模型 | ICML 2024 | 大规模时序 |

**推理流程**：
```
时序窗口(过去N小时) → TS2Vec编码 → emb_ts (d维向量)
                                          ↓
工单文本 → BERT编码 → emb_text (d维向量) → cos(emb_ts, emb_text)
                                          ↓
                               cos < μ → 粗筛标记"可能不一致"
```

### 3.3 时序↔图像跨模态对齐（检测点3）

检测点3（健康预测↔拆解记录）需要时序↔图像对齐。两种路径：

| 路径 | 方法 | 原理 | 适用 |
|---|---|---|---|
| **A. 时序→健康标签→图像** | 时序预测RUL→健康分级→CLIP比对拆解图像 | 两步：先预测再比对 | 有现成RUL模型 |
| **B. 时序编码→图像编码直接对齐** | TS2Vec(时序)+ViT(图像)→对比学习 | 端到端嵌入对齐 | 有配对训练数据 |

### 3.4 局限与适用定位

| 局限 | 航发场景表现 | 定位 |
|---|---|---|
| 粗粒度（整窗vs整段） | 无法定位"哪段时序和哪句工单冲突" | 粗筛层，高FP可接受 |
| 时序-文本语义鸿沟大 | 图文有天然视觉对应；时序-文本语义距离更大 | 需更多训练数据 |
| 缺乏训练数据 | 无公开"时序+工单"配对数据集 | 需自建或合成（见第10节） |

> **定位**：第3层是**粗筛层**——快速过滤明显不匹配的时序-工单对，再交由第2层冲突矩阵或第5层FAMDR做细粒度检测。类比医疗"CLIP粗筛→冲突矩阵细检"。

## 4. 第四层：片段级VQA校验（VDC三段式迁移）

### 4.1 医疗原型：VDC

VDC（Versatile Data Cleanser, ICLR 2024, arXiv:2309.16211）的核心发现：各类脏数据的共同特征是**视觉-语言不一致**（`方法章节_深度版.md:3.4`）。

**三模块级联**（论文Figure 1）：

| 模块 | 全称 | 医疗实现 | 输出 |
|---|---|---|---|
| VQG | Visual Question Generation | ChatGPT(GPT-3.5)基于标签生成问题 | N_q个问题+期望答案 |
| VQA | Visual Question Answering | InstructBLIP看图回答问题 | MLLM回答 |
| VAE | Visual Answer Evaluation | 字符串匹配+ChatGPT评估 | 每题正确/错误 |

一致性分数 `s = Σ𝟙(e_i=true) / N_q`，阈值α=0.5。s<α→判为脏数据。

**实验结果**：
- 毒化样本检测（CIFAR-10）：TPR **99.91%**, FPR **2.75%**（无需干净数据）
- 非对称噪声检测：TPR **99.60%**（是对称噪声3.6倍难度，VDC优势最大）
- 混合脏数据：TPR 99.41%, FPR 2.79%

**医疗工程简化版**（`图文不一致性检测_技术调研.md:3.4.3`）：

| VDC阶段 | 完整版 | 简化版 | 简化理由 |
|---|---|---|---|
| VQG | 训练提问模型 | 直接用图像AI输出当提问 | TorchXRayVision已提供推理 |
| VQA | 训练问答模型 | 30字窗口否定检测 | 快、可解释、无需GPU |
| VAE | 训练评判模型 | 预定义冲突矩阵规则 | 透明可审计 |

### 4.2 航发迁移：时序VQG→工单VQA→VAE

| VDC阶段 | 医疗简化版 | 航发迁移版 | 航发实现 |
|---|---|---|---|
| **VQG** | TorchXRayVision输出当提问 | **时序异常段→预期故障问题** | 异常段(channel,pattern)→故障词典映射→"该时段{pattern}，工单是否记录{expected_fault}？" |
| **VQA** | 30字窗口否定检测 | **工单NER四态回答** | 工单中查找{expected_fault}→30字窗口判定四态 |
| **VAE** | 冲突矩阵规则 | **冲突矩阵规则（复用第2层）** | 时序异常(阳)×工单四态→冲突判定 |

**航发VQG实例**：

```
时序异常段: {channel: "vibration_hpf", pattern: "频带5-8kHz突增", score: 0.87}
    ↓ 故障词典映射
预期故障: "轴承外圈故障"
    ↓ VQG生成问题
问题: "该时段振动高频突增(5-8kHz)，工单是否记录轴承故障？"
期望答案: "是"（因为高频振动突增通常对应轴承故障）
    ↓ VQA: 工单NER检索
工单原文: "14:30例行检查，未见异常"
NER结果: 轴承故障=否定(命中"未见异常")
实际答案: "否"
    ↓ VAE: 期望"是" vs 实际"否" → 不一致
冲突标记: 时序↔工单否定, 严重度HIGH(score=0.87)
```

### 4.3 通用性价值

> VDC的价值在于其**通用性**——不针对特定脏数据类型训练，靠"视觉-语言不一致"这一共性特征实现跨类型检测（`图文不一致性检测_技术调研.md:343`）。

**航发迁移的理论依据**：只要存在"一份数据描述状态（时序异常段）+另一份数据给判断（工单故障记录）"的模式，VDC框架就适用。航发"时序异常→预期故障→工单验证"与医疗"图像异常→预期疾病→报告验证"完全同构。

### 4.4 局限与向上递进

| 局限 | 表现 | 向哪层递进 |
|---|---|---|
| VQG依赖故障词典映射 | 新故障模式无法生成问题 | →第6层（MLLM自动生成问题） |
| VQA是关键词级匹配 | 复杂语义表述难捕获 | →第7层（LLM语义判定） |
| 不定位具体冲突位置 | 只判"有无"不定位"哪里" | →第5层（FAMDR定位） |

## 5. 第五层：时间点/短语级精确定位（FAMDR迁移）

### 5.1 医疗原型：FAMDR

FAMDR（Feature-Aligned Multimodal Denoising, AAAI 2026, DOI:10.1609/aaai.v40i9.37623）是当前医学图文不一致性检测的SOTA（`方法章节_深度版.md:3.5`），在扩展MIMIC-CXR上 **F1=0.83**。

**四大组件**：

| 组件 | 医疗功能 | 技术原理 |
|---|---|---|
| ①噪声感知多模态对齐 | 保留判别性差异特征（非softmax平滑） | 保留\|img_feat - text_feat\|>τ的差异通道 |
| ②跨模态检索增强 | 模糊案例引外部医学知识 | 门控融合g=f(对齐分数)，g→0引检索证据 |
| ③像素/短语级噪声定位 | 定位到具体图像区域+文本短语 | 自适应阈值在特征图/token序列上标记噪声 |
| ④不确定性量化 | 输出置信度而非硬判 | 预测熵，高置信直接报告，低置信人工复核 |

**与冲突矩阵的关系**：冲突矩阵是规则驱动的粗粒度方法（疾病级，判"有无冲突"），FAMDR是模型驱动的细粒度方法（像素/短语级，定位"哪里冲突+为什么"）。两者级联——冲突矩阵粗筛→FAMDR对高严重度冲突做深度复核。

### 5.2 航发迁移：四组件适配

#### 组件①：噪声感知多模态对齐

| 维度 | 医疗 | 航发 |
|---|---|---|
| 模态1特征 | 胸片图像特征图（DenseNet） | **时序特征序列**（AnomalyTransformer编码） |
| 模态2特征 | 报告文本token序列（BERT） | **工单文本token序列**（BERT） |
| 差异保留 | \|img_feat - text_feat\| > τ | **\|ts_feat - text_feat\| > τ** |
| 语义连贯约束 | 确保差异是真实矛盾非随机噪声 | 同（确保时序-文本差异是真实冲突非传感器噪声） |

**航发适配关键**：标准cross-attention做特征融合时会将不一致特征平滑掉。FAMDR在特征图上保留差异通道——航发场景中，保留"时序异常段特征"与"工单正常描述特征"的差异，使冲突信号不被平滑。

#### 组件②：跨模态检索增强

| 维度 | 医疗 | 航发 |
|---|---|---|
| 检索源 | 放射学术语库、影像生物标志物、类似病例 | **维护手册、故障代码库、历史故障案例、物理约束知识库** |
| 门控融合 | g=f(对齐分数)，g→1原始判断，g→0引检索 | 同 |
| 模糊区间 | 图文对齐分数处于模糊区间 | **时序-工单对齐分数处于模糊区间** |

**航发实例**：振动高频异常(0.52)但工单否定→对齐分数模糊→门控g→0→检索历史案例"高频振动+工单否认→80%最终确认轴承早期故障"→辅助判定为MEDIUM而非HIGH。

#### 组件③：时间点/短语级噪声定位（核心迁移）

这是FAMDR区别于粗粒度方法的核心能力。医疗场景定位到"像素区域+文本短语"，航发场景定位到**"时间段+工单短语"**：

| 定位维度 | 医疗 | 航发 |
|---|---|---|
| 模态1定位 | 像素区域（如右下肺野） | **时间段**（如14:23:15-14:24:30振动高频段） |
| 模态2定位 | 文本短语（如"no effusion"） | **工单短语**（如"未见异常"） |
| 实现方式 | 自适应阈值在图像特征图上标记 | 自适应阈值在时序特征序列上标记异常段 |
| 输出 | "右下肺野像素区域与报告'no effusion'短语矛盾" | **"14:23-14:25振动高频段与工单'未见异常'短语矛盾"** |

**航发输出格式**：
```json
{
  "conflict_located": true,
  "ts_segment": {
    "start": "2026-03-15T14:23:15",
    "end": "2026-03-15T14:24:30",
    "channel": "vibration_hpf",
    "feature": "频带5-8kHz能量突增"
  },
  "text_phrase": {
    "phrase": "未见异常",
    "position": "工单第2段第3句",
    "negation": true
  },
  "evidence_chain": "时序段异常(score=0.87) ↔ 工单否定('未见异常')",
  "confidence": 0.82
}
```

#### 组件④：不确定性量化

| 维度 | 医疗 | 航发 |
|---|---|---|
| 来源 | 预测熵（越接近决策边界越高） | 同 |
| 高置信 | 直接报告冲突 | 直接报告 |
| 低置信 | 标记"需人工复核" | **标记"需维护工程师复核"** |

### 5.3 与第2层冲突矩阵的级联

```
第2层冲突矩阵（粗筛）
    ↓ 检出候选冲突（如时序↔工单否定 HIGH）
第5层FAMDR（深度复核）
    ↓ 定位到具体时间段+工单短语
    ↓ 输出证据链+置信度
高置信冲突 → 直接报告
低置信冲突 → 标记需人工复核
```

> **类比医疗**（`方法章节_深度版.md:3.5.2`）：冲突矩阵做疾病级粗筛（"有无冲突"），FAMDR做像素/短语级精确定位（"哪里冲突+为什么"）。航发：冲突矩阵做故障级粗筛，FAMDR做时间段/短语级定位。

### 5.4 局限与向上递进

| 局限 | 表现 | 向哪层递进 |
|---|---|---|
| 需训练4组件神经网络 | 航发缺乏标注训练数据 | 需自建数据集（第10节） |
| 定位仍限于"已检测到的异常段" | 无法发现全新异常模式 | →第6层（MLLM端到端） |
| 检索增强依赖知识库完备性 | 维护手册/案例库不全时退化 | →第5层组件②持续扩充 |

## 6. 第六层：端到端多模态判定（MLLM迁移）

### 6.1 医疗原型：CheXagent

医疗场景的端到端方法用多模态大模型同时编码图+文，内部cross-attention做隐式对齐，直接输出一致性判断（`方法章节_深度版.md:3.7`）。

**CheXagent**（Chen et al., arXiv:2401.12208, Stanford, 2024）：
- 在CheXinstruct数据集上训练的视觉-语言基础模型
- 可执行8类任务（图像理解/报告生成/报告质量评估等）
- 能同时接收胸片+报告做联合推理
- **临床验证**：8名放射科医生评估，住院医生节省**36%时间**，81%病例效率提升

### 6.2 航发迁移：多模态大模型联合推理

航发场景的端到端需要同时处理**时序+文本+图像三模态**，比医疗的图文双模态更复杂。

| 维度 | 医疗MLLM | 航发多模态大模型 |
|---|---|---|
| 输入 | 胸片图像 + 报告文本 | **时序窗口 + 故障工单 + 孔探图像** |
| 编码 | 视觉编码器 + 文本编码器 | **时序编码器 + 文本编码器 + 视觉编码器** |
| 对齐 | cross-attention(图↔文) | **三路cross-attention(时序↔文本↔图像)** |
| 输出 | 一致性判断+自然语言解释 | 一致性判断+冲突定位+物理依据 |

**航发技术路线**：

| 路线 | 方法 | 原理 | 成熟度 |
|---|---|---|---|
| **A. 时序大模型+MLLM组合** | Timer/UniTS(时序) + LLaVA/Qwen-VL(图文) | 时序大模型编码时序→文本描述→MLLM联合图文 | ★★★(可落地) |
| **B. 统一多模态大模型** | LANISTR/Table+Image+TS联合编码 | 三模态统一编码器+cross-attention | ★★(研究阶段) |
| **C. 时序→文本化+MLLM** | 时序异常段→自然语言描述→LLM联合工单+图像 | 时序检测结果转文本→LLM推理 | ★★★★(最务实) |

**路线C实例**（最务实）：
```
时序异常检测 → "14:23-14:25振动高频突增(5-8kHz), score=0.87"
    ↓ 转自然语言
时序描述: "检测到2分钟内振动高频异常，疑似轴承故障"
    ↓ 联合输入MLLM
输入: [时序描述] + [工单全文] + [孔探图像]
问题: "时序描述的异常与工单记录和孔探图像是否一致？"
    ↓ MLLM推理
输出: "不一致。时序显示轴承高频振动异常，但工单记录'未见异常'，
       孔探图像见2号轴承外圈轻微磨损。判定：时序↔工单否定冲突(HIGH)，
       时序↔图像一致（均指向轴承问题）。建议复核工单。"
```

### 6.3 端到端 vs 分段式对比

| 维度 | 分段式（第1-5层） | 端到端（第6层） |
|---|---|---|
| 模态交互 | 无（各模态独立处理） | **三路cross-attention隐式对齐** |
| 可解释性 | 高（每步可追溯） | 中（模型黑盒） |
| 部署成本 | 中（CPU可跑IsolationForest） | 高（需大模型GPU） |
| 精细控制 | 可逐通道调阈值 | 难以控制 |
| 灵活性 | 可替换单个组件 | 整体替换 |
| 新故障适应 | 需更新词典+规则 | 可通过prompt适配 |

> **推荐**（`方法章节_深度版.md:3.7.3`）：分段式为主方法（覆盖率），MLLM为高价值冲突深度复核（交互型不一致）。

### 6.4 局限与向上递进

| 局限 | 表现 | 向哪层递进 |
|---|---|---|
| 需大模型GPU推理 | 部署成本高 | 分段式为主、MLLM仅复核HIGH冲突 |
| 模型黑盒 | 无法追溯判定依据 | →第5层FAMDR提供定位证据 |
| 可能幻觉 | MLLM可能编造不存在的冲突 | →第7层（LLM+Guard核验） |

## 7. 第七层：LLM+Guard兜底（语义级）

### 7.1 医疗原型：LLM+代码Guard

对规则和模型难以覆盖的复杂语义冲突，用本地LLM做语义级判定（`方法章节_深度版.md:3.8`）。

**关键发现**：LLM对数字比较不可靠——会把正常值报为冲突、混淆数值方向。

**解决方案**：代码Guard数值核验。

```
预筛(代码): No Finding=1 ∧ 指标超正常范围 → 候选(样本,指标)对
    ↓ 10000行×5指标 → ~2900候选
per-lab prompt → Qwen2:7b → {is_conflict, reason}
    ↓
代码Guard: 真实数值是否达到严重阈值？是→保留，否→丢弃(LLM幻觉)
```

**实测效果**（60候选，5指标各12个）：

| 指标 | severe总数 | TP(LLM正确) | FN(漏判) | FP(Guard前) | **FP(Guard后)** |
|---|---|---|---|---|---|
| 乳酸 | 6 | 6 | 0 | 0 | **0** |
| 肌酐 | 6 | 5 | 1 | 0 | **0** |
| 血糖 | 6 | 6 | 0 | 2 | **0** |
| 钾 | 6 | 4 | 2 | 1 | **0** |
| pH | 6 | 6 | 0 | 0 | **0** |

**Guard后FP归零**。TP率27/30=90%。LLM负责语义理解，代码负责数值核验，二者互补。

### 7.2 航发迁移：LLM判定+物理约束代码核验

| 维度 | 医疗 | 航发 |
|---|---|---|
| LLM | Qwen2:7b(本地Ollama) | Qwen2:7b(同，本地) |
| LLM职责 | 判断血检↔诊断标签语义一致性 | **判断时序异常↔工单故障记录语义一致性** |
| Guard类型 | 医学指标数值核验（乳酸>5.0?） | **物理约束数值核验**（温度↑但转速无响应?） |
| Guard实现 | Python代码查阈值 | Python代码查物理约束规则 |

**航发Guard机制**：

```
第2-6层检出候选冲突（如"温度超温但工单未记过热"）
    ↓ 候选(时序段, 工单片段)对
per-event prompt → Qwen2:7b → {is_conflict, reason}
    ↓
代码Guard: 物理约束核验
    ├─ 温度数值是否真的>720℃? → 是→保留, 否→丢弃(LLM幻觉)
    ├─ 转速是否在温度超限后2分钟内下降? → 否→确认物理约束违反
    └─ 振动+滑油温是否同步升高? → 是→确认轴承故障耦合
    ↓
Guard后FP→0
```

**航发Guard实例**：
```
LLM判定: "温度过热但工单称正常，is_conflict=true, reason='排气温度持续超限'"
    ↓ 代码Guard核验
检查exhaust_temp原始数据: max=738℃ > 720℃阈值 → 温度超限属实 ✓
检查rotor_speed: 超温后2分钟内转速未下降 → 物理约束违反 ✓
    ↓ Guard通过
保留冲突，严重度CRITICAL（物理硬约束违反）
```

```
LLM判定: "振动异常但工单称正常，is_conflict=true, reason='振动值偏高'"
    ↓ 代码Guard核验
检查vibration_rms原始数据: max=6.8 mm/s < 7.1正常上限 → 未超限 ✗
    ↓ Guard拦截
丢弃（LLM幻觉，实际振动在正常范围内）
```

### 7.3 航发独有优势：物理Guard比医学Guard更强

| 维度 | 医疗Guard | 航发物理Guard |
|---|---|---|
| 核验依据 | 医学参考范围（经验值） | **物理定律**（热力学/转子动力学，硬约束） |
| 可审计性 | 中（参考范围有争议） | **高**（物理定律无争议） |
| 约束强度 | 软约束（个体差异大） | **硬约束**（物理律不可违反） |

> **关键结论**：航发场景的物理Guard是**比医疗Guard更强的核验机制**——物理定律的确定性远高于医学参考范围的个体变异性。

### 8.2 推荐级联

```
第1层(通道级规则) ──快速检出单通道越限+物理约束违反──→ 标记CRITICAL/HIGH
    ↓ 候选异常段
第2层(故障级冲突矩阵) ──时序异常×工单四态──→ 检出5类冲突(HIGH/MED/LOW)
    ↓ 候选冲突
第3层(全局向量粗筛) ──时序嵌入↔工单嵌入──→ 过滤明显不匹配(粗筛)
    ↓ 候选不一致对
第4层(VDC问答级) ──异常段→预期故障→工单验证──→ 逐事件一致性分数
    ↓ HIGH冲突
第5层(FAMDR定位) ──时间段+工单短语级定位──→ 证据链+置信度
    ↓ 低置信/复杂冲突
第6层(MLLM端到端) ──三模态联合推理──→ 交互型不一致深度复核
    ↓ 所有冲突
第7层(LLM+Guard) ──语义判定+物理约束核验──→ Guard后FP=0
```

**四层递进原则**（`方法章节_深度版.md:3.9`）：逐层提高精度、降低覆盖率，在效率和准确率间取得平衡。第一层快速过滤硬约束违反，第二层检出故障级冲突，第三层粗筛不匹配对，第四层逐事件验证，第五层定位到具体时间段/短语，第六层捕获交互型不一致，第七层处理所有层遗漏的复杂语义冲突并Guard核验。
