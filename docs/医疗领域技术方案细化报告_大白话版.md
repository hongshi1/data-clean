# 第一部分：用大白话讲清楚"我们在做什么"

## 1.1 一个生活化的例子

你去看病，医生让你拍了个胸部X光片。拍完之后，放射科的医生会看片子，然后写一份报告。

这就产生了**两份天然配对的数据**：
- 一张**胸片图像**（机器拍的）
- 一段**报告文字**（医生写的）

理想情况下，这两份应该完全一致——片子上有什么病，报告就写什么病；片子正常，报告就说正常。

但现实中，**经常对不上**：
- 片子上有个阴影，医生写报告时**漏看了**（漏诊）
- 报告说"有胸腔积液"，但其实片子上**根本看不出来**（误诊）
- 报告前面说"有肺不张"，结论却写"一切正常"（**自相矛盾**）

行业研究显示，放射诊断的错误率约**3%-5%**，其中相当部分就是这种"图和报告对不上"。MIMIC-CXR一个数据集就有**37.7万张图像**，靠人工一张张核对根本不现实。

**我们要做的，就是让计算机自动发现这种"对不上"的问题。**

## 1.2 什么是对不上（不一致）

"对不上"不是简单的相似度计算。不是说你算个图文匹配分数就完了。而是要：

1. **看懂图**：AI看片子，认出每种病的概率（比如胸腔积液80%、气胸51%）
2. **读懂字**：AI读报告，搞清楚每个病医生写的是"有""没有"还是"可能"
3. **逐病比对**：把AI看到的和医生写的，一个病一个病地放到一张表里对

**难点在于**：报告里的文字很狡猾。比如"No evidence of effusion"（无胸腔积液证据），如果你简单搜关键词"effusion"，就会以为报告提到了胸腔积液——但它其实是在**否认**。再比如"may represent consolidation"（可能代表实变），这是医生**拿不准**，既不是肯定也不是否定。

所以这不是简单的字符串匹配，而是要**理解语义**——搞清楚医生到底在说什么。

## 1.3 医疗数据长什么样

我们用到的医疗数据主要有四种模态：

| 数据类型 | 大白话 | 例子 | 特点 |
|---|---|---|---|
| **胸片图像** | X光拍的片子 | MIMIC-CXR 37.7万张 | 一张图，灰度，224×224像素 |
| **放射报告** | 医生写的文字报告 | "No pleural effusion. Lungs are clear." | 自由文本，含肯定/否定/不确定 |
| **血检表格** | 验血结果的数值表 | 乳酸7.2mmol/L、肌酐2.4mg/dL | 结构化数值，50项指标 |
| **诊断标签** | 最终诊断结论 | Atelectasis=阳性、No Finding=阴性 | 二值/三值标签 |

**核心场景**：检测"图像↔报告"和"血检↔诊断标签"这两种模态对之间的不一致。

## 1.4 已经有什么技术底座

医疗AI领域已经积累了成熟的技术栈，我们不是从零开始：

| 能力 | 大白话 | 代表工具 | 效果 |
|---|---|---|---|
| AI看片子 | 像一个看了几十万张胸片的AI实习生 | TorchXRayVision | 18种病，AUC 0.81-0.92 |
| AI读报告 | 不是搜关键词，是分析句子结构 | CheXpert Labeler | 和放射科医生一致性κ>0.6 |
| 图文对齐 | 把图和文字都变成数字，看数字近不近 | CheXzero/MedCLIP | 零样本接近监督模型 |
| 通用清洗器 | 像考试出题，针对每个异常问报告一个问题 | VDC (ICLR 2024) | 检出率99.91%，误报率2.75% |
| 精确定位 | 不仅说矛盾，还指出是图的哪个位置和报告的哪句话 | FAMDR (AAAI 2026) | F1=0.83 |
| 端到端判定 | 一个模型同时看图+读报告+判断矛盾 | CheXagent (Stanford 2024) | 住院医生省36%时间 |
| 兜底核验 | AI判完再用代码复查一遍数字 | LLM+代码Guard | 误报降到0 |

# 第二部分：完整处理流水线

## 2.1 先搞清楚一个关键问题：分开看还是一起看？

检测"图和报告对不对得上"，有两种根本不同的做法：

### 做法一：分开看再对（分段式）

**大白话**：让一个人只看片子、另一个人只读报告，各自得出结论，最后把两人的结论放一起对。

```
图 → AI看片 → "胸腔积液阳性(0.809)"
                              ↓
                        冲突矩阵比对 → "冲突！图有报告无"
                              ↑
报告 → NER标注 → "胸腔积液=否定"
```

**优势**：每一步都可追溯（AI为什么判阳性？因为概率0.809>阈值0.55；NER为什么判否定？因为命中"No"依存规则）；成本低（DenseNet在CPU上就能跑）；能逐病种调阈值。

**短板**：图像侧看片时**完全不知道报告写了什么**，文本侧读报告时**完全不知道图里有什么**——两者在各自分析阶段没有任何交互。有些不一致是**交互型**的——只有同时看图和文才能发现（比如图像的某个模糊区域，单独看像病灶，但如果同时看到报告写了"术后改变"，就知道不是病灶）。分段式会漏掉这类不一致。

### 做法二：一起看（联合式）

**大白话**：让一个人同时看片子和报告，直接判断两者是否矛盾——就像放射科医生实际工作时，同时看片和读报告。

```
图+报告 → 联合模型 → "右下肺野区域与报告'no effusion'矛盾，置信度0.82"
```

**优势**：图和文在特征层面交互（cross-attention），能发现分段式遗漏的交互型不一致；FAMDR能定位到"图的哪个区域"和"报告的哪句话"矛盾。

**短板**：模型黑盒（难以追溯为什么判冲突）；成本高（需GPU跑大模型）；难以精细控制（不能逐病种调阈值）。

### 关键结论：两种做法互补共存，不是二选一

> `entity_research.md`的核心结论：真实系统正在从"NER+规则"向"LLM/MLLM"迁移，但不是完全替代——**分段式保证覆盖率和可解释性，联合式捕获交互型不一致**。科学合理的架构是**多路并行+融合**：两种范式同时跑，结果汇总。

### 环节②六条路线速查

| 路线 | 范式 | 粒度 | 大白话 | 代表方法 | 图文交互 |
|---|---|---|---|---|---|
| **A** | 分开看再对 | 疾病级 | 一人看片一人读报告最后对 | TorchXRayVision+CheXpert Labeler+冲突矩阵 | 无（事后比对） |
| **B** | 一起看 | 向量级 | 把图和文都变成数字看近不近 | CheXzero/MedCLIP | 有（共享嵌入空间） |
| **C** | 一起看 | 定位级 | 同时看图+文，定位哪里矛盾 | FAMDR (AAAI 2026) | 有（特征级对齐） |
| **D** | 一起看 | 端到端 | 一个模型同时看图+读报告+判断 | CheXagent (Stanford 2024) | 有（cross-attention） |
| **E** | 规则驱动 | 字段级 | 查数值超不超标 | 规则库L1/L2/L3 | 无（纯数值比对） |

# 第三部分：逐环节技术方案细化

## 环节①：数据预处理——把杂乱数据变整齐

### 做什么

原始数据是乱的：图像大小不一、报告格式杂乱、血检有缺失值、还有患者隐私信息。这个环节就是把它们变整齐，方便后续AI处理。

### 技术方案细化

#### 1.1 图像标准化

**大白话**：就像把不同尺寸的照片统一冲洗成同一大小，方便比较。

```
原始胸片(各种尺寸, 彩色/灰度混杂)
    ↓ PIL加载
    ↓ convert("L") 转灰度（胸片本来就是灰度，这步去掉颜色干扰）
    ↓ normalize(img, 255) 把像素值从0-255映射到-1024到1024（医疗影像的标准范围）
    ↓ resize((224,224)) 统一尺寸（AI模型要求224×224输入）
    ↓ 标准化图像(1,224,224)
```

> 来源：`nlmcxr_operators.py:168-190` 实测的TorchXRayVision推理预处理链。

#### 1.2 报告清洗与分段

**大白话**：报告里可能有XML标签、脱敏占位符（XXXX），需要清理干净。还要按段落分开，因为"发现段(Findings)"是客观描述，"结论段(Impression)"是主观判断。

放射报告通常分5段：
1. **Comparison**（和以前的片子对比）
2. **Indication**（为什么拍这个片子）
3. **Technique**（怎么拍的，什么体位）
4. **Findings**（看到了什么——客观描述）
5. **Impression**（结论是什么——主观判断）

> **关键发现**：CheXpert论文证实Impression段（结论段）的标注一致性最高、噪声最低。所以标注时优先分析Impression段。

**分段方法**：
- **正则法**（轻量推荐）：报告段落以全大写标签开头，用正则切分
- **medspaCy**（医学NLP工具包）：内置section detector，基于规则+句法
- **CheXpert Labeler内置**：Loader接受`sections_to_extract`参数

#### 1.3 血检数据整理

**大白话**：验血结果是个表格，50项指标，有的缺值、单位不统一，需要补齐和统一。

| 处理 | 做什么 | 方法 |
|---|---|---|
| 缺失值处理 | 有的指标没测，留空 | 标记为null（不随意填充，避免引入假数据） |
| 单位统一 | 有的用mg/dL有的用mmol/L | 统一到标准单位 |
| 百分位标注 | 标注每项在全队列的百分位 | `labs_means.json`提供P95/P99统计 |

> 来源：`medical_dj_research.md:191-214`，50项血检指标清单+正常范围。

#### 1.4 涉密信息脱敏

**大白话**：患者姓名、身份证号、就诊号等隐私信息必须打码，但打完码数据还要能用。

**三级级联识别**（SurrogateShield arXiv:2606.29567 验证F1≈98.87%）：

| 级别 | 做什么 | 抓什么 |
|---|---|---|
| 1 规则/正则 | 用预设规则找 | 姓名、身份证号、电话号码 |
| 2 NER模型 | 用AI模型找 | 就诊号、科室名称、医生签名 |
| 3 LLM语义 | 用大模型理解上下文 | 隐含的隐私描述 |

**分层脱敏算子**（不一刀切）：

| 敏感信息 | 怎么处理 | 效果 |
|---|---|---|
| 患者姓名 | 直接删除 | 无语义价值 |
| 就诊号 | 替换成假号（PATIENT_001） | 保持格式一致 |
| 年龄精确值 | 泛化为区间（72岁→70-80岁） | 保持统计分布 |
| 地址描述 | 合成替换（生成等价虚构地址） | BERTScore从81%→95% |

> **反面警示**：纯DP-SGD（差分隐私训练）在1B-3B模型上F1仅0.19-0.28（arXiv:2606.28479），不能作为唯一手段。合成替换+伪名化效果远好于纯遮罩。

**推荐工具**：Presidio V2（Microsoft开源，可私有化部署，YAML配置不用写代码）。

## 环节②：多路并行检测——六路人马同时查

### 做什么

预处理后的标准化数据，**同时进入六条检测路线**。每条路线是一个完整的"看数据→判冲突"管线，只是看的方式和看的粒度不同。六路并行跑完，结果交由环节③融合。

> **核心设计原则**：不是"先做图像侧→再做文本侧→再比对"的线性流程，而是六路**同时**检测。路线A是"分开看再对"（图像和报告各自独立分析，事后比对），路线B/C/D是"一起看"（图和文从一开始就联合处理），路线E是"查规则"（数值硬约束），路线F是"语义兜底"（LLM理解含义）。每路各有所长，互补不替代。

---

### 路线A：分开看再对（分段式，疾病级）

**大白话**：让AI先独立看片子、再独立读报告，各自得出结论后放到冲突矩阵里逐病比对。

**为什么需要这条路线**：最可解释——AI为什么判阳性？因为概率0.809>阈值0.55。NER为什么判否定？因为命中"No"依存规则。每一步都可追溯、可审计。但短板是**图和文在各自分析阶段没有交互**，会漏掉交互型不一致（由路线C/D补）。

#### A-1 图像侧：AI看片子

### 做什么

让AI看胸片，输出每种病的概率。就像让一个看了几十万张胸片的AI实习生帮你"预读"片子。

### 技术方案细化

#### 2.1 AI读片模型：TorchXRayVision

**大白话**：TorchXRayVision就像一个在MIMIC-CXR（22.7万张）、CheXpert（22.4万张）、PadChest（16万张）、NIH（11万张）四个大医院数据集上**联合培训**的AI实习生。给它一张胸片，它能输出18种病的概率。

**工作原理**（4步）：
1. 输入：224×224灰度胸片
2. 推理：DenseNet121深度网络前向传播
3. 后处理：sigmoid把分数转成0-1的概率
4. 判定：概率超过该病的阈值→阳性

**行业基准AUC**（DenseNet121-res224-all, MIMIC-CXR）：

| 疾病 | AUC | 大白话 |
|---|---|---|
| 胸腔积液 | **0.92** | AI看这个很准 |
| 水肿 | **0.92** | 很准 |
| 实变 | 0.91 | 很准 |
| 肺不张 | 0.88 | 准 |
| 心脏肥大 | 0.88 | 准 |
| 气胸 | 0.81 | 还行 |
| 骨折 | 0.74 | 不太准，要小心 |

> 来源：TorchXRayVision官方BENCHMARKS.md。DenseNet121-res224-all是综合数据集训练的，跨数据集泛化最稳。ResNet50高分辨率反而更差（肺不张AUC只有0.77）。

**专家级验证**：CheXpert（Stanford, AAAI 2019）500例测试集由5名放射科医生共识标注，DenseNet在**胸腔积液、水肿、心脏肥大**三种病上ROC+PR曲线超越全部3名独立医生。但骨折(0.74)和气胸(0.81)仍低于专家——**低AUC的病种冲突判定必须更保守**。

#### 2.2 模型校准：为什么统一0.5是错的

**大白话**：AI给的分有两种——一种是"原始分数"(logit)，一种是"百分比概率"(probability)。很多人直接拿原始分数当概率用，还统一用0.5当及格线，这会导致大量假阳性。

**问题根源**：
- DenseNet输出的是**logit不是概率**，必须做sigmoid转换：`概率 = 1/(1+exp(-logit))`
- 即使转换后，**不同病的最佳及格线也不一样**：罕见病（气胸）阈值要高（避免假阳性），常见病（肺阴影）阈值要低（避免假阴性）

**NLMCXR 20样本实测**（`xray_analysis_stats.json`）——统一0.5阈值的假阳性有多严重：

| 疾病 | >0.5判阳数 | **落在灰色地带[0.45,0.55]内数** | 灰色地带占阳性比 |
|---|---|---|---|
| 气胸 | 14/20 | **13** | **93%** |
| 实变 | 11/20 | **11** | **100%** |
| 水肿 | 13/20 | 9 | 69% |

**关键发现**：气胸14个"阳性"中13个概率落在0.45-0.55的灰色地带——**AI其实拿不准**。实变11个阳性全部在灰色地带。统一0.5阈值把AI不确定的都判成了阳性。

**三种校准方法**：

| 方法 | 大白话 | 改及格线 | 改概率 | 适用 |
|---|---|---|---|---|
| **逐病种Youden J** | 每种病在验证集上找最优及格线 | 是 | 否 | **最实用**，官方已预计算 |
| Temperature Scaling | 给所有分数除个温度系数T | 否 | 是 | AI整体太自信时 |
| Platt Scaling | 在分数上套一个S型曲线 | 否 | 是 | 数据充足时精细调 |

**TorchXRayVision官方提供两种预计算阈值**：
- `model.op_threshs`（Youden's J）：ROC曲线上TPR-FPR最大的点
- `model.ppV80_thres`：使精确率≥0.8的阈值（高精度低误报）

> **规律**：低患病率病种（气胸5%、骨折）阈值偏高（避免假阳性）；高患病率病种（肺阴影40%+）阈值偏低（避免假阴性）。

#### 2.3 边界带降级：AI拿不准怎么办

**大白话**：就算校准了阈值，总有些病的概率刚好在及格线附近（比如阈值0.5，概率0.51）。这时候AI其实是在"猜"，硬判"阳性"会引入大量假冲突。

**解决方案**：在阈值附近设一个"灰色地带"（边界带，宽度δ=0.05），落在灰色地带的不直接判阳性，而是**降一级处理**。

| 概率区间 | 判定 | 怎么处理 |
|---|---|---|
| 概率 > 阈值+0.05 | 确信阳性 | 正常定冲突严重度 |
| **阈值-0.05 ≤ 概率 ≤ 阈值+0.05** | **灰色地带** | **降一级**（HIGH→MEDIUM, MEDIUM→LOW） |
| 概率 < 阈值-0.05 | 阴性 | 不触发冲突 |

**实测效果**（NLMCXR样例1）：

| 疾病 | AI概率 | 灰色地带? | 处理 |
|---|---|---|---|
| 胸腔积液 | 0.809 | 否 | HIGH（高度确信） |
| 气胸 | 0.515 | **是** | **降级为LOW** |

没有边界带降级时，气胸0.515与报告否定会被误判为MEDIUM冲突；加降级后判LOW——让人工复核聚焦真正高确信的冲突。

#### A-2 文本侧：AI读报告

### 做什么

让AI读医生写的报告，搞清楚每个病医生写的是"有""没有"还是"可能"。这不是简单搜关键词——要理解句子结构，搞清楚"否定词"修饰的是哪个病。

### 技术方案细化

#### 3.1 核心难点：否定和不确定混杂

**大白话**：报告里一句话可能同时包含三种意思：

> *"Increased opacity with associated atelectasis **may represent** focal consolidation. **No** pleural effusion. **No acute** bone abnormality."*

- **肯定**："associated atelectasis"（有肺不张）
- **否定**："No pleural effusion"（没有胸腔积液）
- **不确定**："may represent consolidation"（可能是实变）

如果你简单搜"effusion"这个词，会以为报告提到了胸腔积液——但它是在说**没有**。这是假阳性泛滥的根源。

#### 3.2 方法演进：从关键词到句子结构分析

| 方法 | 大白话 | 否定 | 不确定 | 准确率 |
|---|---|---|---|---|
| 纯关键词 | 像在文档里Ctrl+F搜词 | 搜不了 | 搜不了 | 低 |
| negspacy(NegEx) | 搜词+看附近有没有"no/not" | 二态 | 无 | 中 |
| **CheXpert Labeler** | 分析句子结构，搞清楚谁修饰谁 | **三态** | **三态** | **高(κ>0.6)** |
| 30字窗口法 | 搜词+往前看30个字有没有否定词 | 二态 | 二态 | 中高 |

#### 3.3 CheXpert Labeler三阶段流水线（行业标准）

**大白话**：CheXpert Labeler像流水线上的三个工人——第一个负责找病名，第二个负责判断是肯定/否定/不确定，第三个负责汇总。

**阶段① 找病名(Extractor)**：
- 用14类疾病的词典在报告里匹配
- 同时排除干扰词（比如"pneumothorax device"里的pneumothorax不是病）

**阶段② 判定状态(Classifier)**——核心：

三段式优先级匹配（不是简单搜"no"）：
```
1. 先看有没有"可能""疑似" → 不确定(-1)
2. 再看有没有"无""未见""正常" → 否定(0)  
3. 再看有没有"不能排除" → 不确定(-1)
4. 都没有 → 阳性(1)
```

**关键区别**：它用**依存句法分析**（BllipParser，GENIA+PubMed句法模型）对每句话做完整语法分析——搞清楚句子里的词**谁修饰谁**。然后用60+条图规则在语法树上匹配。

**同一输入不同方法对比**：

| 报告原文 | 关键词法 | CheXpert | 为什么 |
|---|---|---|---|
| "no evidence of consolidation" | 提及(误判!) | 否定 | 语法树显示no修饰evidence，evidence关联consolidation |
| "may represent consolidation" | 提及 | 不确定 | 命中"may represent" |
| "consolidation has resolved" | 提及(误判!) | 否定 | "resolved"=已消退 |
| "within normal limits" | 不提及 | 否定 | 语法路径匹配"normal limits" |

**阶段③ 汇总(Aggregator)**：一篇报告内同一个病可能被提到多次，按优先级阳性>不确定>否定汇总成一个标签。

**验证**：200例验证集由3名放射科医生标注，CheXpert Labeler与医生一致性κ>0.6。

#### 3.4 工程简化版：30字窗口否定检测

**大白话**：完整CheXpert Labeler需要装1GB的句法模型，太重了。轻量替代是——搜到病名后往前看30个字，看有没有否定词或不确定词。

**三步走**：
1. 用疾病关键词表在报告里逐一查找
2. 找到后往前看30个字符，检查有没有否定词(`no/without/not/无/未见`)或不确定词(`may represent/possible/疑似`)
3. 四态标注：阳性(无否定词) > 不确定(有不确定词) > 否定(有否定词) > 未提及(没出现)

**NLMCXR真实标注结果**：

| 疾病 | 报告原文 | 30字窗口内容 | 标注 |
|---|---|---|---|
| 胸腔积液 | "No pleural effusion" | "...No pleural " | 否定(命中"No") |
| 实变 | "may represent focal consolidation" | "...may represent focal " | 不确定(命中"may represent") |
| 肺不张 | "associated atelectasis" | "...associated " | 阳性(无否定词) |
| 水肿 | (全文无"edema") | — | 未提及 |

> 来源：`nlmcxr_operators.py:232-297`已验证。选型建议：需高准确率用CheXpert Labeler；需快速原型用30字窗口法。

#### 3.6 句子级报告错误检测（补充技术）

**SenRED**（OpenReview 2025）：把整篇报告拆成**一条条原子发现语句**，每条独立和图像做视觉-语言对齐。检测3类错误：
- **假阳性**：图像中不存在但报告声称存在
- **假阴性**：图像中存在但报告遗漏
- **定位错误**：报告说在左肺但病灶在右肺

> 这是比CheXpert Labeler更细的粒度——CheXpert是疾病级（14病种），SenRED是句子级（每句话）。

#### 3.7 3D影像-报告差异分析（补充技术）

**RADAR**（arXiv:2603.06681, 2026）：针对3D影像（如腹部CT），模拟"初诊→审核"工作流。评估三个维度：
- 图像级一致性（初诊和审核是否一致）
- 临床严重程度（差异有多严重）
- 编辑类型（修正/补充/澄清）

#### A-3 冲突矩阵比对——图和报告逐病对

### 做什么

把AI看到的（图像侧18维概率）和医生写的（报告侧14病种四态）放到一张表里，一个病一个病地比对，找出哪些对不上。

### 技术方案细化

#### 4.1 冲突矩阵

**大白话**：想象一张棋盘格——横轴是报告怎么写的（阳性/否定/不确定/未提及），纵轴是AI怎么看的（阳性/阴性）。每个格子定义是"一致"还是"冲突"，以及冲突有多严重。

| AI看图＼医生写报告 | 阳性(有病) | 否定(没病) | 不确定(可能) | 未提及 |
|---|---|---|---|---|
| **AI见病灶** | ✅一致 | 🔴**严重冲突**(漏诊) | 🟡轻微冲突 | 🟠中等冲突 |
| **AI没见病灶** | 🟠中等(误报?) | ✅一致 | ✅一致 | ✅一致 |

#### 4.2 五种冲突类型

| 冲突类型 | 大白话 | 触发条件 | 严重度 |
|---|---|---|---|
| 图↔报告否定 | AI见病灶但医生说没有 | 图阳性∧报告否定 | HIGH/MED/LOW |
| 图↔报告不确定 | AI见病灶但医生含糊 | 图阳性∧报告不确定 | LOW |
| 图↔报告结论 | AI见病灶但报告没提还说正常 | 图阳性∧未提及∧称正常 | MEDIUM |
| 报告↔图 | 医生说有病但AI没看到 | 图阴性∧报告阳性 | MEDIUM |
| 报告内部 | 报告自相矛盾 | 报告有阳性病种∧称正常 | MEDIUM |

#### 4.3 严重度由AI确信度决定（不是写死的）

**大白话**：冲突有多严重，取决于AI有多确信。AI概率越偏离0.5（越接近1），说明AI越确定有病灶，冲突越可信。

- 概率 ≥ 0.7 → **HIGH**（AI很确定，报告却否认——严重）
- 概率 ≥ 0.55 → **MEDIUM**
- 其他 → **LOW**

结合边界带降级（环节②2.3）：气胸概率0.515在灰色地带→即使和报告冲突也只判LOW；胸腔积液0.809高度确信→判HIGH。

| 有冲突样本 | 17（85%） |

#### 4.5 规则库三层体系（血检↔诊断标签场景）

**大白话**：除了"图↔报告"，还有"血检↔诊断标签"的比对。这用规则库来做，分三层：

| 层 | 大白话 | 检测什么 | 仓库原型 |
|---|---|---|---|
| **L1** | 单项指标查范围 | 乳酸>2.0就是异常 | MedicalLabRangeFilter |
| **L2** | 指标↔标签跨位置比对 | 乳酸高但诊断写"无异常"→冲突 | LabDiagnosisConflictFilter |
| **L3** | 多指标协同约束 | pH低+Bicarbonate低=酸中毒 | CrossLabConsistencyFilter |

**L1知识库示例**（`medical_kb.json`）：
```python
"50893": {"name":"乳酸","unit":"mmol/L","normal":(0.5,2.0),
          "severity_high":{2.0:"MEDIUM", 5.0:"CRITICAL"}}
```

**L2规则示例**：乳酸>2.0 但诊断=No Finding → "乳酸酸中毒漏诊" CRITICAL

**L3规则示例**：pH<7.35 ∧ Bicarbonate<22 → "代谢性酸中毒" CRITICAL

**实测效果**：10000样本检出**1444条跨模态冲突**（`medical_conflict_results.json`）：
- 乳酸酸中毒漏诊 1160条 CRITICAL
- 肾功能异常漏诊 132条 HIGH
- 高血糖漏诊 68条 MEDIUM
- 高钾血症漏诊 50条 CRITICAL
- 严重酸中毒漏诊 34条 CRITICAL

> **共性**：所有冲突都是"血检指标明显异常，但诊断标签写No Finding"——化验结果与诊断标签矛盾。

#### 4.6 假阳性来源与缓解

| 假阳性来源 | 大白话 | 实测证据 | 缓解手段 |
|---|---|---|---|
| AI边界假阳性 | AI给0.51分就判阳性 | 气胸14阳性中13个∈[0.45,0.55] | 边界带降级 |
| AI跨数据集泛化差 | 在MIMIC训练到别处误判 | 实变全员边界阳性 | 逐病种阈值校准 |
| NER否定检测失效 | "No evidence of"被误判为"提及" | 关键词法把否定句标为found=true | CheXpert Labeler依存句法 |

> **关键公式**：冲突检测精度 = 图像侧精度 × 文本侧精度。用AUC 0.92的胸腔积液做冲突检测，可信度远高于AUC 0.74的骨折。

#### 4.7 No Finding全局约束

**大白话**：CheXpert有个"No Finding"（无异常）标签。如果报告标了"无异常"但图像有病，或者报告有病但同时也标了"无异常"——这是逻辑互斥冲突。

### 路线B：一起看（联合式，向量级粗筛）

**大白话**：把图和文字都变成一串数字（向量），看这两串数字近不近。近就是一致，远就是可能有冲突。**图和文从一开始就在同一个空间里比较**，不是事后比对。

**为什么需要这条路线**：路线A是"分开看再对"——图和文各自独立分析，丢失了图文交互信息。路线B把图和文都映射到同一个语义空间，从一开始就"一起看"。虽然粒度粗（只有一个相似度分数），但能快速过滤明显不匹配的图文对。

#### CLIP跨模态粗筛

**大白话**：把图和文字都变成一串数字（向量），看这两串数字近不近。近就是一致，远就是可能有冲突。

**原理**：CLIP用对比学习把图像和文本映射到同一个"语义空间"。如果图和文字说的是同一件事，它们在这个空间里就离得近（余弦相似度高）；如果说的是不同的事，就离得远。

**医疗CLIP变体**：

| 方法 | 大白话 | 训练数据 | 关键能力 |
|---|---|---|---|
| **CheXzero** | 不用人工标注，靠胸片+报告自学 | MIMIC-CXR 22.7万对 | 零样本胸片分类 |
| **MedCLIP** | 解耦配对，用不配对的数据也能学 | MIMIC-CXR+CheXpert | 比标准CLIP提升显著 |

**CLIP的三大局限**（都有论文实测）：

| 局限 | 大白话 | 影响 |
|---|---|---|
| 像词袋模型 | 分不清"红杯子在蓝盘上"和"蓝杯子在红盘上" | 无法绑定病灶到正确位置 |
| 细粒度差 | 区分积液量级接近随机 | 不适合疾病级冲突检测 |
| 属性绑定失败 | 多病共存时搞混 | 复杂胸片失效 |

> **定位**：CLIP是**粗筛层**——快速过滤明显不匹配的图文对（比如完全无关的图配了报告），再交由冲突矩阵或FAMDR做细粒度检测。

#### 路线B补充：VDC三段式（问答级验证）

**大白话**：VDC像出了一套考试题——针对每个异常出题，看报告能不能答对。答对率低于50%就判为"脏数据"。

**三段式架构**（ICLR 2024, arXiv:2309.16211）：

| 阶段 | 全称 | 大白话 | 做什么 |
|---|---|---|---|
| VQG | 出题 | 针对标签生成关于图像的问题 | 比如标签是"气胸"→生成"图中是否有气胸？" |
| VQA | 答题 | 让多模态大模型看图回答 | InstructBLIP看图回答"是/否" |
| VAE | 评分 | 算答对率 | 一致性分数=答对数/总题数，<0.5判脏数据 |

**实验结果**：
- 毒化样本检测：检出率**99.91%**，误报率**2.75%**（无需干净数据）
- 非对称噪声检测：检出率**99.60%**（是最难的非对称噪声场景）
- 混合脏数据：检出率99.41%，误报率2.79%

**医疗工程简化版**：

| VDC阶段 | 完整版 | 简化版 | 简化理由 |
|---|---|---|---|
| 出题 | 训练提问模型 | 直接用图像AI输出当题目 | TorchXRayVision已提供现成推理 |
| 答题 | 训练回答模型 | 30字窗口否定检测 | 快、可解释、无需GPU |
| 评分 | 训练评判模型 | 预定义冲突矩阵规则 | 透明可审计 |

> **VDC的价值**：不针对特定脏数据类型训练，靠"视觉-语言不一致"这一共性特征实现跨类型检测——通用性强。

### 路线C：一起看（联合式，定位级精确）

**大白话**：FAMDR不仅说"图和报告矛盾"，还精确指出"是图的哪个区域和报告的哪句话矛盾"。像给冲突装了GPS定位。**图和文在特征层面深度交互**——不是事后比对，而是在特征对齐过程中保留差异信号。

**为什么需要这条路线**：路线A只判"有没有冲突"，不定位"哪里冲突"。路线B只有一个粗粒度相似度分数。路线C在特征层面做噪声感知对齐，保留图文不一致的特征作为冲突线索，并定位到像素/短语级。

#### FAMDR精确定位（SOTA）

**大白话**：FAMDR不仅告诉你"图和报告矛盾"，还精确指出"是图的右下肺野和报告的'no effusion'这句话矛盾"。像给冲突装了GPS定位。

**四大组件**（AAAI 2026, F1=0.83）：

**组件① 噪声感知对齐**：
- 传统方法做特征融合时会把不一致的特征"平均掉"
- FAMDR**保留**图像和文本不一致的那些特征——把它们当作冲突线索而不是噪声丢弃
- 同时确保保留的"差异"是真正的矛盾，不是随机噪声

**组件② 跨模态检索增强**：
- 当图像和报告**匹配模糊**（不确定是否一致）时，不硬判
- 而是**检索外部医学知识**辅助决策（放射学术语库、类似病例）
- 关键创新是**门控融合**：高置信时直接判，低置信时引外部知识辅助

**组件③ 像素/短语级定位**（核心能力）：
- **像素级**：在胸片上定位到具体区域（如右下肺野），该区域与报告矛盾
- **短语级**：在报告中定位到具体短语（如"no effusion"），该短语与图像矛盾
- 类似GradCAM的注意力机制，但专门针对"不一致区域"

**组件④ 不确定性量化**：
- 每个冲突判定输出**置信度**，不是简单的"是/否"
- 高置信直接报告，低置信标记"需人工复核"
- 不确定性来自预测熵——越接近决策边界越高

**与冲突矩阵的关系**：冲突矩阵是规则驱动的粗粒度方法（疾病级，判"有无冲突"），FAMDR是模型驱动的细粒度方法（像素/短语级，定位"哪里冲突+为什么"）。两者级联——冲突矩阵先粗筛，FAMDR对高严重度冲突做深度复核。

### 路线D：一起看（联合式，端到端判定）

**大白话**：让一个模型同时看图+读报告+判断矛盾——就像放射科医生实际工作时，同时看片和读报告。**图和文在模型内部通过cross-attention深度交互**，能发现分段式（路线A）遗漏的交互型不一致。

**为什么需要这条路线**：路线A/B/C都是"先各自处理再比对"或"部分联合"。路线D是**完全联合**——一个模型内部同时编码图和文，隐式对齐，直接输出一致性判断。短板是模型黑盒、成本高。

#### MLLM端到端判定

**大白话**：前面的方法都是"分段式"的——先看图、再读报告、最后比对。MLLM是让一个模型**同时看图+读报告+判断矛盾**，就像让一位放射科医生同时看片子和报告，直接判断两者是否矛盾。

**CheXagent**（Stanford 2024, arXiv:2401.12208）：
- 在CheXinstruct数据集上训练的视觉-语言基础模型
- 能执行8类任务（图像理解/报告生成/报告质量评估等）
- **临床验证**：8名放射科医生评估，住院医生节省**36%时间**，81%病例效率提升

**端到端 vs 分段式对比**：

| 维度 | 分段式 | 端到端(MLLM) |
|---|---|---|
| 图文交互 | 无（各自独立处理） | 有（联合推理） |
| 可解释性 | 高（每步可追溯） | 中（模型黑盒） |
| 部署成本 | 中（CPU可跑DenseNet） | 高（需GPU大模型） |
| 精细控制 | 可逐病种调阈值 | 难以控制 |
| 灵活性 | 可替换单个组件 | 整体替换 |

> **推荐**：分段式为主方法（覆盖率），MLLM为高价值冲突深度复核（交互型不一致）。

### 路线E：规则驱动（字段级，血检↔标签）

**大白话**：不靠AI模型，直接查数值超不超标。乳酸>2.0但诊断写"No Finding"→冲突。这是最硬的规则——不依赖任何模型推理。

**为什么需要这条路线**：有些不一致是**硬约束违反**——数值明显异常但标签说正常，不需要AI推理，规则直接判。这条路线最可审计、零GPU需求、确定性最高。

> **详细技术方案**：见前面路线A-3的"4.5 规则库三层体系"（L1单指标范围/L2指标↔标签/L3多指标协同）。仓库已验证：10000样本检出1444条冲突。

**三层规则库**：

| 层 | 大白话 | 做什么 | 效果 |
|---|---|---|---|
| L1 | 单项查范围 | 乳酸>2.0就是异常 | MedicalLabRangeFilter ✅ |
| L2 | 指标↔标签比对 | 乳酸高但诊断"No Finding"→冲突 | 1444条冲突 ✅ |
| L3 | 多指标协同 | pH低+Bicarbonate低=酸中毒 | CrossLabConsistencyFilter ✅ |

### 路线F：语义兜底（LLM+代码Guard）

**大白话**：对规则和模型都覆盖不了的复杂语义冲突，用大语言模型（如Qwen2:7b）做语义级判定。但LLM对数字比较不靠谱——会把正常值报为冲突。解决方案是**加一层代码数值核验**。

**为什么需要这条路线**：路线A-E各有所长，但都有盲区——规则库穷举不了所有矛盾对，CLIP不懂细粒度，FAMDR需要训练数据。路线F用LLM的语义理解能力兜底，处理所有其他路线遗漏的复杂语义冲突，再用代码Guard核验数字防止LLM幻觉。

```
LLM判定：is_conflict=true
    ↓
代码核验：真实数值是否真的达到严重阈值？
    ↓ 是 → 保留冲突
    ↓ 否 → 丢弃（LLM幻觉）
```

**实测效果**（60候选，5项指标各12个）：

| 指标 | 应检出 | LLM正确 | 漏判 | Guard前误报 | **Guard后误报** |
|---|---|---|---|---|---|
| 乳酸 | 6 | 6 | 0 | 0 | **0** |
| 肌酐 | 6 | 5 | 1 | 0 | **0** |
| 血糖 | 6 | 6 | 0 | 2 | **0** |
| 钾 | 6 | 4 | 2 | 1 | **0** |
| pH | 6 | 6 | 0 | 0 | **0** |

**Guard后误报归零**。LLM负责语义理解，代码负责数值核验，二者互补。

> 来源：`unified_operators.py:_llm_detect_medical`已验证Qwen2:7b本地推理。

## 环节③：多路融合——汇总六路结果

### 做什么

六条路线并行跑完，每路各自输出冲突清单。融合环节把这些结果**汇总成一份统一的冲突报告**。

### 融合策略

| 策略 | 大白话 | 怎么做 |
|---|---|---|
| **去重** | 同一条冲突被多路检出→合并 | 按冲突键(样本ID+疾病+冲突类型)去重，保留最高严重度 |
| **加权** | 各路置信度不同→加权汇总 | 综合分数 = Σ(路线置信度 × 路线权重) |
| **互补** | A路没检出但C路检出→标记来源 | 标记"仅C路检出"=交互型冲突，需重点关注 |
| **升级** | 多路同时检出→升级严重度 | 3路以上同时检出HIGH→升级为CRITICAL |

### 输出格式

```json
{
  "sample_id": "NLMCXR_0",
  "conflicts": [
    {
      "disease": "Pleural Effusion",
      "type": "图↔报告否定",
      "severity": "HIGH",
      "confidence": 0.87,
      "sources": ["A", "C", "D"],
      "evidence": {
        "route_a": "AI概率0.809 vs 报告否定",
        "route_c": "右下肺野区域与'no effusion'短语矛盾",
        "route_d": "MLLM判断: 图文不一致"
      }
    }
  ]
}
```

> **关键设计**：`sources`字段记录哪些路线检出了这条冲突。多路同时检出=高置信；仅一路检出=需人工复核。这比单路线检测的信息量更丰富——不仅知道"有没有冲突"，还知道"几路都认为有冲突"。

## 环节④：质量评估——给数据打分分级

### 做什么

检测完冲突后，给每条数据打分，分成A/B/C三级——A级直接用，B级人工复核，C级退回。

### 技术方案细化

#### 6.1 七维质量评估

| 维度 | 大白话 | 医疗场景指标 | 评估方法 |
|---|---|---|---|
| **完整性** | 该有的有没有 | 报告5段是否齐全；血检50项缺失率 | Great Expectations |
| **一致性** | 内部有没有矛盾 | 4类冲突检测通过率 | 冲突管道输出 |
| **合规性** | 符不符合标准 | CheXpert 14病种对标率 | 标准模板对标 |
| **准确性** | 标签对不对 | 术语库命中率；诊断标签合理性 | Cleanlab置信学习 |
| **可用性** | 脱敏后还能不能用 | 脱敏后BERTScore语义保持度 | Sentence-BERT |
| **隐私性** | 隐私打码彻不彻底 | 残留敏感实体数；k-匿名 | Presidio复检 |
| **多样性** | 覆盖均不均衡 | 疾病类型分布；罕见病占比 | 分布统计 |

#### 6.2 评估工具

| 工具 | 大白话 | 机制 | 效果 | 仓库验证 |
|---|---|---|---|---|
| **Great Expectations** | 像体检报告的检查项清单 | 声明式规则（300+预置） | Data Docs可视化 | ✅ |
| **Cleanlab** | 用AI找标错的标签 | 置信学习算法 | **召回100%**（MNIST找错标） | ✅ |
| **TADS** | 挑最有价值的样本 | 任务感知选择(质量+相关+多样) | 36%数据超全量+1.0% | ❌ |
| **UniFilter** | 多模态质量分类器 | 半合成训练 | EMNLP 2025 | ❌ |
| **LLM抽样复核** | AI抽查打分 | LLM-as-judge | 灵活但成本高 | ❌ |

#### 6.3 分级标准

**评分** = w1·完整性 + w2·一致性 + w3·合规性 + w4·准确性 + w5·可用性 + w6·隐私性。**隐私性一票否决**（残留敏感直接降C）。

| 等级 | 分数 | 大白话 | 判定条件 | 处置 |
|---|---|---|---|---|
| **A** | ≥85 | 优秀，直接用 | 5段齐全/4类冲突0/对标≥95%/语义保持≥90%/无残留 | **直接微调** |
| **B** | 70-84 | 还行，要人工看一眼 | 个别缺失/冲突≤3/对标80-95%/语义保持75-90% | **人工复核后用** |
| **C** | <70 | 不行，退回重做 | 大段缺失/冲突>3/对标<80%/语义损失大/残留敏感 | **退回数据源** |

## 环节⑤：知识增强——挂上专家知识

### 做什么

把医学知识（标准条文、专家经验、知识图谱）挂到数据上，让数据集不仅"干净"还"有知识"。

### 技术方案细化

#### 7.1 知识图谱的角色（关键澄清）

**大白话**：很多人以为知识图谱里有一条"矛盾边"——查一下就知道两个东西矛不矛盾。**实际上没有**。标准医学本体（SNOMED CT、ICD-10）里没有"contradicts"这种边。

知识图谱的真实角色是三个：
1. **规范化**：把"心影增大""cardiomegaly""心脏扩大"映射到同一个概念节点（解决同义词问题）
2. **关系推理**：利用"caused by""treats"等关系做多跳推理，判断两个诊断是否逻辑自洽
3. **知识增强**：用KG约束LLM输出的逻辑一致性

**SNOMED CT + Neo4j实例**（arXiv:2510.16899）：
- 节点：疾病、症状、药物
- 边："caused by""treats""belongs to"
- 用途：多跳推理验证诊断逻辑

> **结论**：KG不直接判断矛盾，而是为矛盾判断提供**结构化背景知识**。配合LLM或嵌入做矛盾判断。

#### 7.2 专家经验规则化

| 知识类型 | 大白话 | 形式化方法 | 用途 |
|---|---|---|---|
| 诊断准则 | "乳酸>5就是酸中毒" | 参数范围→L1规则 | 冲突检测规则来源 |
| 常见错误模式 | "No Finding但实际有病" | 错误模式库→检测规则 | 规则补充 |
| 指标协同约束 | "pH低+Bicarbonate低=酸中毒" | 多条件AND→L3规则 | 多指标一致性 |

## 4.5 推荐架构：多路并行+融合（不是串行级联）

**核心原则**：六条路线**并行跑**，结果在融合层汇总。不是"先做A再做B再做C"的串行流水线。

```
                    ┌─路线A：分开看再对（疾病级，可解释）──────────┐
                    │  图→AI看片  文→NER标注  →冲突矩阵          │
                    ├─路线B：一起看（向量级，快速粗筛）────────────┤
                    │  图+文 → CheXzero → cos相似度               │
                    ├─路线C：一起看（定位级，精确定位）────────────┤
  标准化数据 ──→ 分流 ├─路线D：一起看（端到端，捕获交互型）────────┤ ──→ 融合 ──→ 冲突报告
                    │  图+文 → CheXagent → cross-attention       │
                    ├─路线E：规则驱动（字段级，硬约束）────────────┤
                    │  血检+标签 → L1/L2/L3规则库                  │
                    ├─路线F：语义兜底（LLM+代码Guard）─────────────┤
                    │  各路输出 → LLM判定 → 代码核验(FP=0)         │
                    └─────────────────────────────────────────────┘
```

**为什么不是串行级联？**

| 维度 | 串行级联（旧设计） | 多路并行+融合（新设计） |
|---|---|---|
| 图文交互 | 只在"比对"阶段才有 | B/C/D从一开始就联合处理 |
| 交互型不一致 | 漏掉（A路无法捕获） | C/D路能发现 |
| 信息损失 | 每层过滤掉的数据丢了 | 全部保留，融合层汇总 |
| 容错性 | 某层出错→后续全错 | 一路出错→其他路补 |

**实际部署的分层触发优化**（可选，不是架构限制）：

虽然架构上是六路并行，但实际部署时可以**分层触发**以节省算力：

```
简单数据（规则E+A路冲突矩阵就能判）→ 不触发C/D路（省GPU）
    ↓ 发现冲突或不确定
中等数据（+B路CLIP粗筛）→ 仍不触发C/D路
    ↓ CLIP也判不匹配
复杂数据（+C路FAMDR定位+D路MLLM端到端）→ 全路开跑
    ↓ 所有路都跑完
融合层汇总 → 统一冲突报告
```

> 这是**性能优化策略**，不是架构限制。架构上六路是平行的，只是实际运行时按需触发。

**冲突样本不浪费**：检出的冲突不是"垃圾数据"——它们是**高价值微调数据**。正常数据教模型"什么是对的"，冲突数据教模型"什么是不一致、怎么改"。多路融合后的冲突报告（含来源路线+证据链）比单路线检测的信息更丰富，微调价值更高。
