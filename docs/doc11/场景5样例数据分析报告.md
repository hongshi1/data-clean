## 二、需求说明文档解读（四大块要求）

1. **数据预处理**：多源异构接入（摄像机/NVR/平台/离线）→ 统一转码；场景语义智能切片（5-30秒片段+关键帧≥1080P）；**自动脱敏**（人脸/工牌/涉密标识/元数据）；数据增强与工况均衡——**异常工况占比不低于40%**；全链路数据血缘。
2. **专家经验**：四维知识体系（场景类别/目标类别/行为类别/隐患等级）；规则+示例+自然语言经验注入；预标注+专家修正工作流；标注规范固化与培训考核；经验回流闭环。
3. **一致性校验（南开主责部分）**：四维一致性——**格式**（XML/JSON统一、字段/层级/编码）、**类别**（避免同义异名、异义同名）、**边界**（目标框/行为起止/隐患等级）、**时序**（帧级与片段级对齐）；自动化校验引擎+高风险样本强制人工复核；多人交叉标注与**Kappa/IoU一致性度量**；标注准确率≥99%、完整性≥98%；模型持续误判→反向触发该类别一致性复查。
4. **质量评估**：六维指标（真实/合规/一致/时效/均衡/难度）；分级准入；数据质量-模型效果映射；版本管理；可复制推广。

## 三、JSONL数据解析

**格式**：LLaVA式VLM微调样本 `{conversations:[{from:user},{from:assistant}], image}`
- user：`<image>\n` + 提示词（两种风格）
- assistant：结构化JSON `{task:"睡岗检测", answer:0/1, evidence:[...]}`——**结论+证据链式标注**
- image：test/目录相对路径

**7个文件的组织**：96条 = 32图 × 每图3次采样。文件名三因子组合：

| 因子 | 取值 | 含义（推断） |
|---|---|---|
| before / after | 微调前 / 微调后 | 同题同图对比模型微调前后输出 |
| all / 4bit | 全精度 / 4bit量化 | 模型变体 |
| （默认）/ simpleprompt | 任务式短提示 / 自然语言长提示 | 提示词风格 |

> 默认提示词："任务：判断图像中是否存在【睡岗行为】。"
> simpleprompt："画面中为工作场合，观察画面里所有人员的肢体动作、头部姿态，判断是否出现趴卧、低头伏案睡觉等睡岗行为。"
> 组合缺一格：**sleep-after-all-simpleprompt 不存在**（8缺1，可能漏传或未生成）

## 四、关键发现

1. **微调的核心价值体现在"格式遵循"**（最显著差异）：
   - before×simpleprompt（all和4bit两个文件）：**自然语言散答，0/96为JSON格式**，65-70条无法解析出结构化结论（"左侧女性坐姿端正……结论：未出现睡岗行为"式自由发挥）
   - after×simpleprompt（4bit）：**96/96统一输出JSON**{task,answer,evidence}
   - 微调后模型无论提示词风格如何，输出严格遵循结构化格式——这正是文档"格式一致性"要求的落地证据
2. **before/after 二分类判断完全一致**（96对0翻转）：微调前模型判断本身正确，微调提升的是输出规范性与证据质量（evidence更精炼、指向判定标准）
3. **同图3次采样判断全部一致**（32/32图）——推理稳定性
4. **异常工况占比53%**（阳性图17/32）≥ 文档要求的40%；阳性样本跨全部4种工况分布（strong_light 6 / flip_rot_color 5 / night 4 / fog 2）
5. **图像1920×1080 RGB**满足"不低于1080P"要求；32图全部为增强版本（flip_rot_color 12 / night 7 / strong_light 7 / fog 6），对应文档"光照变化、视角变换"增强要求

## 五、用南开一致性校验体系扫描这批数据（切入点演示）

对本数据可直接执行的校验项及其结果：

| 校验项 | 层级 | 本批数据实测 | 结论 |
|---|---|---|---|
| JSON schema格式一致性（task/answer/evidence字段完备） | 语法层 | 5个JSON文件96/96通过；simpleprompt-before 0/96 | before版数据格式不合规 |
| 同图多次采样答案一致性 | 语义层 | 32图×3次全部一致 | 通过 |
| before/after判断一致性 | 语义层 | 96对0翻转 | 通过 |
| evidence-answer自洽性 | 语义层 | **关键词法45个假阳性**（"未出现趴伏"的否定句含"趴伏"关键词） | 需NLI语义判定，不能靠关键词 |
| 工况×类别分布统计 | 质量画像 | 异常占比53%、工况均衡 | 通过（对应质量评估门禁） |

> 第4条正是我们三层体系的价值证明：语法层规则查不出的否定句语义问题，需要语义层NLI判定（evidence说"趴伏特征明显"而answer=0才是真矛盾，"未出现趴伏"不是）。

## 六、问题与建议

1. **缺sleep-after-all-simpleprompt**——8个组合缺1，建议向数据提供方确认
2. **before/after×all/4bit的确切语义未经确认**——本报告推断为"微调前后×模型变体"，建议核对
3. **规模是样例级**（96条/32图），距考核"数据集不少于10万条"差3个数量级——本包用于定格式与流程验证
4. **无原始帧、无视频片段**——全部为增强帧，文档要求的"时序一致性"（帧级vs片段级标注对齐）在这批数据中未体现
5. **答案无标注人/时间戳/版本**——文档要求的"数据血缘/可追溯"字段缺失
6. 包内残留WPS锁文件（~$开头，0KB）可删除
