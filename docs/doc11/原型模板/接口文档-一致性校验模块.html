一致性校验模块 对外接口与数据规范 V1.0

模块全称：数据一致性校验模块（含两个智能体：特征提取与上下文关联智能体 / 数据一致性校验智能体） 在平台中的位置：微调数据集构建平台 · 一致性校验环节（数据集管理 → 本模块 → 质量评估） 技术形态：FastAPI 服务（默认 127.0.0.1:8300）+ React 前端 + 上下文图谱数据层 数据范围：GJB 438C 软件需求规格说明（SRS），当前 16 份内置 + 支持上传

二、L1 平台集成接口（模块间数据契约）

2.1 向上：本模块消费的输入

① 专家知识（来自「数据转换」，校验的知识基准）

数据转换模块产出的专家知识进入本模块，作为一致性校验的判定依据（对应图谱 KNW 层与校验引擎规则库）：

字段 类型 必填 说明
rules object[] ✓ 校验规则集：{rule_id, type(术语/参数/逻辑/GJB合规/多模态), description, check_method, inject_methods[], applies_to[], severity, example}
dictionaries object - 术语词典：参数词典（同义词族）、单位族（换算基准）、接口/操作符词典
standards object[] - 标准条款（GJB 438C/439A等），可追溯原文行号
conflict_rules object[] - 冲突判定规则（合理差异 vs 真实矛盾的区分准则）

本模块当前内置的知识资产规模：GJB 120条规则 + 23参数/13接口/10单位族词典 + 14条四类不一致规则（全部HIGH可信度标注）。数据转换侧可增补/更新，本模块热加载。

② 数据集送检（来自「数据集管理」，汇聚问题生成+答案生成的产物）

问题生成与答案生成的问答对经数据集管理打包成数据集后统一送检：

字段 类型 必填 说明
dataset_id string ✓ 数据集唯一标识
name string ✓ 数据集名称
ver string - 数据版本（如 V1.2）
cat string - 数据分类（SRS类挂"软件需求规格数据"）
qa_pairs object[] ✓ 问答对：{id, question, answer, evidence, doc_ref, label?, is_injected?}（来自问题/答案生成）
source_docs string[] ✓ 源SRS文档清单（.docx/.md路径或ID）——校验对象
std_data object[] - 标准数据（切片/表格/图片引用）

触发方式：数据集管理页「送一致性校验」动作 / 本模块上传接口（L2-2）。

③ 模块内部数据准备（本模块自行完成，不依赖上游）

源SRS文档的解析与特征提取由本模块的特征提取与上下文关联智能体自行执行： - 文档结构化解析（章节/表格/图片，MinerU管线） - born-digital锚点提取（.doc内嵌Visio XML直读：节点/边/坐标） - Mermaid结构图导出（锚点→mermaid，89%覆盖） - 上下文图谱构建（六类节点+加权边+聚合条目）

边界说明：解析/锚点/mermaid属于本模块内部数据层（graph_store），不作为对上游的接口依赖；上游仅需提供源文档本体与专家知识。

2.2 向下：本模块输出给「质量评估」（简化契约）

① 校验结果对象（按原始数据元素组织，字段从简）

{
  "check_id": "chk-20260830-001",
  "ran_at": "2026-08-30T17:36:37",
  "summary": { "total": 12, "pass": 8, "warn": 2, "fail": 2 },
  "samples": [
    {
      "sample_id": "qa_0001_01",
      "source": { "doc_ref": "01数据获取转换分系统需求规格说明", "section": "3.2.1.2" },
      "status": "fail",
      "issues": [
        { "type": "语义不一致", "desc": "「结构化数据归集」跨位置名称冲突" }
      ]
    },
    {
      "sample_id": "qa_0003_07",
      "source": { "doc_ref": "02界面集成框架软件需求规格说明", "section": "1.8.1" },
      "status": "pass"
    }
  ]
}

设计原则： - 以原始数据元素（问答对）为标注单位：sample_id = 问答对ID；source 为可选的数据源定位（doc_ref + 章节），不按文档组织返回； - 字段从简：status（pass/warn/fail）为唯一必需字段；issues 为可选（type按语法/语义/逻辑三类 + 一句话描述）——并非所有场景都能提供明细，给不了就只回状态； - 52项分类统计、逐项明细、图谱统计属于模块内部数据：由本模块前端报告页呈现（L2 /api/check 获取），不下发给质量评估； - 处置规则：fail → 剔除（不进质量评估）；warn → 人工复核后决定；pass → 放行。

② 校验状态流转（质量评估门禁的数据源）

wait(未校验) ──发起──→ running(校验中) ──完成──→ pass / fail
                                                    │
                        质量评估模块读此状态 ←───────┘
                        （pass 才允许发起质量评估，fail/wait 阻断）

状态落点（原型平台数据模型）：DB.catCst[分类ID].st + dataset.cstStatus。质量评估页现有门禁逻辑（catCst(catId) !== 'pass' 阻断）无需改造自动对接。

2.3 上下文关联能力输出（供平台其他环节复用）

输出 结构 用途
激活子图 ActivateResult 见 4.2 证据定位、问题溯源、检索增强
聚合条目 RequirementItem {entity_id, sections[], n_occurrences, media[], chain_completeness{4格}} 条目级质检、追溯审查
图谱统计 节点/边/条目计数 数据画像、模块监控

3.0 原型集成层（页面级接口，优先实时·离线自动降级）

原型页面（《微调数据集构建平台-一致性校验增强版》）按以下契约调用本模块：

原型页面 调用接口 参数 降级行为（引擎离线时）
上下文关联图谱 POST /api/activate {question, k(1\|2), top_k(4~12), min_w(0.3~0.7)} + Basic认证 跨16份预置图谱按中心实体匹配切换；提示"启动实时引擎可任意查询"
校验总览·开始校验 执行52项（当前预置真实结果+确定性变体） 数据范围=全部/指定数据集 状态流转 wait→running→pass/fail 本地管理
不一致性校验页 52项注册表内嵌（语法12·语义22·逻辑18三级分类） — 离线只读

原型页面向平台侧提供（输出，2.2①简化契约的页面形态）： - 校验记录状态（数据范围/发现数/状态/时间）→ 质量评估门禁数据源 - 逐问答对状态（通过/发现问题）+ 可选问题摘要（语法/语义/逻辑三类 + 一句话描述） - 报告钻取链（记录→批次→52项明细→证据）为模块内部呈现，不下发 - 问答对↔数据源配对关系表（12条，doc_ref可追溯）

四、核心数据结构定义

类型 含义 规模 关键载荷

TXT 文本章节 1444 title、level、text_preview、text_len
TBL 表格 1197 caption、table_type、row_count、headers[]
IMG 图片 373 caption、img_type、path、mermaid_key
SEQ 时序结构（步骤链/异常流） 783 seq_type、steps[]、dangling[]（悬空引用红色标记）

边：{s, t, type, w(0~1), ev(证据文本)}。边类型含同模态（章节层级/版本对齐/接口拓扑/步骤链）与跨模态（实体出现/位置邻接/交叉引用/图-表映射/规则适用）两大类，权重三档（确定性0.85-0.95 / 计算0.4-0.8 / 对齐置信）。

4.3 52项校验项注册表（CHECK_ITEMS）

每项：{id(TERM/PARAM/LOGIC/GJB/MM-01~12), category, name, desc, modality, mode(auto|llm)}。 呈现分类（原型页面）：语法不一致12项（命名与代号规范1·结构完备性8·模态格式规范3）+ 语义不一致22项（术语语义7·参数取值10·业务语义完备3·值与完备性冲突2）+ 逻辑不一致18项（控制与推理11·时序与流程2·拓扑与结构3·内容对应2）。 执行方式：auto 35项（图谱规则/单位换算/Z3/资产统计，确定性）+ llm 17项（kimi-k2.6业务推理）。
