# 41 · SRS一致性校验 M3 Pilot 标注手册

> 版本：v1.0 | 日期：2026-10-20 | 状态：pilot草案（κ达标后冻结）
> 依据：`docs/srs_project/40_method_reconstruction_plan.md` 第2–3节（三态语义、闭世界规则）。判例均取自04数据统一访问服务SRS真实内容。
> 配套：`data/gjb_438c/scene1_qa_audit.json`（91条对方示例QA，90条证据可定位）；`knowledge/consistency_taxonomy_v2.json`（40项定义）。

## 1. 目标与范围

每条数据产出四件事：**三态verdict、适用check_item、evidence_refs、label_basis**。判定对象只有一个——**answer与冻结context的关系**。

明确不做：

- **不评召回**：context漏召、排序差、截断一律不评价；因漏导致的后果按规则记为NIE，不记为"错"。
- **不比表图互比**：不比较表格与图片、正文与表格之间是否一致；context来源之间的矛盾只按§7.2记录诊断，不作为answer判定的独立目标。
- **不用context之外的知识**：包括GJB规则库内容（§6情形A除外）、互联网知识、对04号文档未召回章节的记忆。
- **不判answer质量**：不评是否完整、语气是否恰当；answer是否"答非所问"只影响§4.1的D0步骤。

## 2. 输入材料与标注界面字段

### 2.1 只读输入（每条数据）

| 字段 | 说明 |
|---|---|
| `instance_id` | 如 `S1QA-042` |
| `question` | 原始问题，含对象限定（哪个用例/功能/参数） |
| `answer` | 待校验回答，可为多句复合回答 |
| `context.items[]` | 证据块列表，每条含 `evidence_id`、`text`（正文/表格HTML/图元素声明文本）、`source_type`（text/table/figure）、`source_ref.section`（如3.2.1.4.1.1）、`completeness`（open/closed） |

界面**不显示**：旧gold标签、构造来源、injected/mutation标记、split、他人标注。看到即违规（§9-1）。

context条目示例：

```json
{"evidence_id":"e4","text":"…BLOB数据操作功能包括BLOB数据插入、BLOB删除数据记录、BLOB数据查询功能…","source_type":"table","source_ref":{"doc_id":"doc04","section":"3.2.1"},"completeness":"closed"}
```

`completeness`只读不改：`closed`=该证据自证覆盖完整（如表题"所有能力标识"、用例表单值字段）；`open`=未作完整性声明。**标注者不得把open自行升级为closed**（40号文档§3.1）。

### 2.2 标注填写字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `verdict` | 是 | support / refute / not_in_evidence 三选一 |
| `applicable_check_items` | 是 | 40项ID多选（定义见taxonomy v2）；无合适项留空并写note |
| `evidence_refs` | 是 | S/R必须非空；NIE可为空或引用用于说明"仅有何证据"的条目；表类可写 `e4#BLOB数据操作行` |
| `label_basis` | 是 | ≤3句：question限定、对齐/反证依据、所用策略条款号（如"依§4.1-D2b"） |
| `claims[]` | 建议 | 每条：claim_id、claim_text、claim_verdict、claim_evidence_refs |
| `dispute_note` | 选填 | 拿不准时写明卡点，进仲裁 |

## 3. 标注流程（每条数据五步）

1. **拆原子claims**：把answer拆成可独立判定的原子断言，每条=单一对象+单一谓词+单一值/成员/角色；数值、集合成员、角色（Actors/前置条件/异常处置）、条件各拆一条。answer中的解释性引申（"以保证可靠性"之类）question未问时标为detail claim。
2. **逐claim定位证据**：在context.items中找对象可对齐的条目（用例名、功能ID、表行、参数名），允许§4.2换算/同义对齐；找不到可对齐条目就记"无"。
3. **判S/R/N**：逐claim走§4.1决策树，得claim_verdict。
4. **选check_item**：按claim主证据形态选适用项；类型判断与verdict相互独立（40号文档§5.1）；多项适用全部列出；GJB项另标task_subtype（§6）。
5. **聚合并填写**：整体verdict按§7.1聚合；evidence_refs去重合并；label_basis写明策略条款号。

## 4. 三态判定决策树

### 4.1 决策树（逐claim执行）

```text
D0 question限定对齐
   提取question所指对象与限定（用例/功能、形态、阶段、条件）。
   answer对象与question不一致 → 记question_mismatch，按answer实际断言继续（不自动NIE）。
D1 证据对齐（含§4.2换算/同义）
   context无可对齐条目 → NIE（"没提到"≠claim为假）
D2 反证检查（refute仅在此产生）
   a 对齐证据与claim互斥（同对象/属性/条件下的不同值）→ R
   b claim在封闭字段/封闭枚举之外（completeness=closed或表题/字段自证完整）→ R
   c 封闭性存疑或open → 不得由来源类型默认闭世界 → NIE
D3 蕴含检查
   证据完整蕴含claim（换算等同/同义/更强约束蕴含较弱陈述）→ S
   claim含证据未覆盖的要件（answer过度具体、多出细节）→ NIE
```

三态速记：**S=蕴含（含等价换算）**；**R=显式反证或封闭范围排除，二者必有其一**；**NIE=冻结证据不足以支持或反驳**。

### 4.2 预注册换算表与同义表

| 表 | 收录条目（仅表内可判S） |
|---|---|
| 单位换算 | 1s=1000ms；1min=60s；1KB=1024B；1MB=1024KB；字节=byte=B；毫秒=ms |
| 同义异名 | 应用软件=应用程序软件；BLOB数据=大字段（BLOB）；sqlite3=本地数据库（手持形态语境）；达梦数据库V7.6=服务器数据库（桌面/平板形态语境） |

近似值不在表内（如65535字节与"64KB"：64KB=65536B，字面不等）→ 不判S，判NIE并写dispute_note申请扩表。

### 4.3 合理差异表（以下情形判S或NIE，禁止判R）

| 差异类型 | 04号实例 | 处理 |
|---|---|---|
| 单位换算 | 证据"小于1s"，answer"小于1000ms" | S |
| 语序/集合等价 | 证据"平板、桌面"，answer"桌面、平板" | S |
| 强弱蕴含 | 证据"<1s"（强），answer"不超过2s"（弱） | S；镜像（answer约束值比证据更强）按D2a判R |
| 形态条件差异 | 手持连sqlite3、平板/桌面连达梦 | 各自claim均S，不构成互斥 |
| 异常流编号复用 | 各用例各有"异常流E1"，提示语不同 | E1是用例内局部编号，不跨用例对齐 |
| 阶段并列 | "开发阶段、运行阶段" | 按能力行字段判，不与单一阶段互斥 |
| 父子能力差异 | SQL访问功能三形态 vs 子能力BLOB操作仅桌面/平板 | **不是合理差异**：按question限定的具体能力的封闭字段判（判例2） |

## 5. 边界案例判例（04号SRS真实内容）

evidence_id为示意，以实际界面为准。每例"标注"为唯一正确答案。

### 判例1 单位换算等同 → S
- Q：数据查询对查询1000条数据的时间有什么约束？
- A：查询1000条数据的响应时间应小于1000ms。
- ctx e5（数据查询用例·动作约束）："查询1000条数据的时间应小于1s。"
- **标注**：`S`｜[TERM-06, PARAM-01]｜refs=[e5]
- 理由：同操作同参数；1s=1000ms在§4.2换算表内，核心claim被蕴含（D3）。
- 易错：65535字节与"64KB"不在表内，不能类比判S。

### 判例2 封闭枚举排除（桌面/平板/手持） → R
- Q：SQL访问功能中的BLOB数据操作支持哪些设备形态？
- A：与SQL访问功能整体一致，在桌面版、平板版、手持版三种形态上提供。
- ctx e3（SQL访问功能行）："平板、桌面、手持"；e4（子功能标识表·BLOB数据操作行，closed）："平板、桌面"。
- **标注**：`R`｜[TERM-03]｜refs=[e4]
- 理由：question限定子能力；其方式名称字段为封闭枚举，不含手持，answer被排除（D2b）。父功能行e3不能替代子能力行（对象错位）。
- 易错：引e3判S=对象错位；若e4的completeness=open则本例应判NIE而非R；此例不违反"不比表图互比"（两条证据都只与answer比对）。

### 判例3 证据未提及的行为 → NIE
- Q：BLOB数据插入失败时，错误信息是否会写入访问审计日志？
- A：会写入访问审计日志，供事后追溯。
- ctx e14（异常流E1）："系统提示BLOB数据插入失败，用例结束。"（context内无审计日志条目）
- **标注**：`NIE`｜[GJB-04]｜refs=[e14]
- 理由：scope开放，"没提到写日志"推不出"不写"（D1→NIE）。
- 易错：不得用文档其他章节记忆或常识补判R。

### 判例4 answer过度具体 → NIE
- Q：BLOB数据插入操作的时间约束是多少？
- A：插入单条BLOB数据的时间应小于0.5秒。
- ctx e9/e15：仅有"每个BLOB数据大小应不大于65535字节"，无任何时间条目。
- **标注**：`NIE`｜[PARAM-01]｜refs=[]
- 理由：question问时间参数，context无可对齐时间证据（D1/D3→NIE）。
- 易错：数值"看着合理"不是判S的理由。

### 判例5 同义异名（Actors） → S
- Q：BLOB数据插入用例的参与角色有哪些？
- A：主要参与者是应用程序软件和数据库。
- ctx e16（用例表）："Actors：应用软件、数据库"
- **标注**：`S`｜[TERM-01]｜refs=[e16]
- 理由："应用程序软件"="应用软件"在§4.2同义表内，集合一致。
- 易错：名异≠矛盾（taxonomy v2 TERM-01规则）。

### 判例6 近实体错位（前置条件） → R
- Q：执行BLOB数据插入前需要满足什么前置条件？
- A：前置条件为数据库初始化成功。
- ctx e9（BLOB数据插入用例表）："前置条件：数据库连接正常。"；e10（读取配置文件连接用例）："前置条件：数据库初始化成功。"
- **标注**：`R`｜[LOGIC-03]｜refs=[e9]
- 理由：question限定BLOB插入用例；前置条件是封闭单值字段，answer给出不同条件值=显式反证（D2a/b）。
- 易错：e10的值真实存在但属于另一用例——判S是被"值在文档中存在"带偏；判NIE是漏看e9。

### 判例7 强弱蕴含（阈值） → S
- Q：数据查询对查询1000条数据的时间有什么要求？
- A：查询1000条数据的时间应不超过2秒。
- ctx e5："查询1000条数据的时间应小于1s。"
- **标注**：`S`｜[PARAM-03, TERM-06]｜refs=[e5]
- 理由：§4.3预注册蕴含规则：证据约束更强（<1s）蕴含较弱陈述（≤2s）→S。
- 易错：镜像情形answer"应小于0.5秒"（比证据更强）→R。

### 判例8 图内容未提供 → NIE
- Q：BLOB数据插入流程图中包含哪些判断节点？
- A：包含"JSON解析是否成功"和"SQL执行是否出错"两个判断。
- ctx e12（figure声明）："图 24 BLOB数据插入流程图"（仅标题占位，无图片内容）
- **标注**：`NIE`｜[LOGIC-05]｜refs=[]
- 理由：图元素声明无内容证据；"图没抽到"≠claim为假（D1→NIE）。
- 易错：用主事件流正文推断图节点=换了证据对象，禁止。

### 判例9 显式反证（异常处置） → R
- Q：BLOB数据插入中JSON解析失败时系统如何处理？
- A：系统自动重试解析，成功后继续执行插入。
- ctx e13："如果解析失败则直接返回错误信息，执行异常流E1"；e14："异常流E1：系统提示BLOB数据插入失败，用例结束。"
- **标注**：`R`｜[LOGIC-02]｜refs=[e13, e14]
- 理由：证据给出"直接返回错误信息+用例结束"的处置序列，无重试；answer与其互斥（D2a）。
- 易错："缺少重试描述"本身不是反证，反证来自显式的处置路径声明。

### 判例10 复合answer（S+R） → R
- Q：进行BLOB数据插入前需要满足哪些前置条件？
- A：需要满足：1）数据库连接正常；2）每个BLOB数据不大于65535字节。
- claims：c1=数据库连接正常是前置条件；c2=大小限制是前置条件。
- ctx e9（前置条件字段="数据库连接正常"，closed）；e15（动作约束："每个BLOB数据大小应不大于65535字节"）。
- **标注**：`R`｜[LOGIC-03, TERM-03]｜refs=[e9, e15]
- 理由：c1=S（引e9）；c2被封闭前置条件字段排除→R（e9排除，e15显示其真实槽位是动作约束）。按§7.1任一claim R→整体R。
- 易错：c2内容真实存在≠其角色正确；不得判"部分正确"。

## 6. GJB合规类问题的处理

GJB项（GJB-01~11）先区分子任务，`task_subtype`必填：

- `B_fact_verification`：answer只复述SRS事实（如"SRS要求每个BLOB不大于65535字节"）→ 走本手册三态。
- `C_rule_compliance`：answer声称"满足/不符合GJB某要求" → 按规则是否作为context提供分两种情形：

| 情形 | context是否含规则条目（source_type=rule，含条款号与版本） | 标注 |
|---|---|---|
| A | 提供 | 正常三态；S/R的evidence_refs须同时引用SRS证据与规则条目，缺一不可 |
| B | 未提供 | 一律NIE，label_basis写`rule_not_provided`；**禁止用记忆中的GJB规则补判** |

check_item照常选GJB-xx（类型适用与verdict独立）；规则版本与适用性由规则治理方确认，标注者不自行选规则（40号文档§6.3-6）。

## 7. 复合answer与context内部冲突

### 7.1 复合answer聚合规则（pilot冻结）

| claim组合 | 整体verdict |
|---|---|
| 全S | S |
| 含任一R | R |
| 无R、含NIE | NIE |

detail claim（§3-1）无证据时同样计NIE；pilot期间整体仍判NIE并在label_basis标`detail_nie=true`，统计后统一决定是否修订，修订前不得私自放宽。

### 7.2 context内部冲突

两条context证据互斥时（如正文"BLOB数据操作功能包括BLOB数据插入、BLOB删除数据记录、BLOB数据查询" vs 表23"BLOB数据操作所有能力标识"列修改/查询/插入）：

1. 记`context_conflict=true`及冲突证据对（e_i, e_j），不静默选边（40号文档§3.1）。
2. 冻结判定表：支持证据与反证证据并存→整体R（refs含双方）；冲突双方均不与answer矛盾→各claim独立判，冲突只作诊断；冲突证据与question对象对不齐→不参与判定，只记诊断。
3. 例：answer="BLOB数据操作包括删除数据记录"→正文支持、封闭表排除→R+context_conflict=true。

## 8. 双人标注、仲裁与一致性计算

1. **双标**：A/B独立标完全部pilot条目，期间禁交流、禁看对方结果。
2. **分歧类型**（逐条记录）：V=verdict不同（主要分歧）；T=check_item集合不同；E=evidence_refs不同；C=claim拆分不同；B=label_basis依据不同（次要分歧）。主次分歧均进仲裁。
3. **仲裁**：第三方（未参与双标）读双方标注与理由，产出final verdict+仲裁理由；不改双标原始记录；分歧条目100%留痕（初标、分歧类型、仲裁理由、final）。
4. **Kappa口径**：主指标=QA级三态Cohen's κ（unweighted）：
   - p_o=一致条数/总条数；p_e=Σ_k(mA_k·mB_k)，mA_k/mB_k为两人第k态的边际比例；κ=(p_o−p_e)/(1−p_e)；
   - 仅统计两人均完成的条目；κ用双标结果计算，**不用仲裁后的final计算**；
   - 辅助指标：逐态一致率与混淆矩阵、check_item集合Jaccard一致率、claim级一致率（按§3拆分对齐后）、次要分歧条目占比。
5. **通过阈值**：κ≥0.75→通过进M4；0.50~0.75→修订手册+重标全部分歧条目后复算κ；<0.50→手册重大修订+全量重标。仲裁final进M4 gold。

## 9. 标注质量红线

1. **禁看泄漏信息**：不看旧label、构造来源、injected标记、split、对方标注；界面意外显示即上报并停标该条。
2. **refute必须有反证**：R的evidence_refs必须指向显式反证条目或封闭字段/枚举；"感觉不对""数值可疑"不是R。
3. **NIE≠全局不存在**：NIE只表示冻结证据不足，不表示SRS全文没有该事实；label_basis禁止写"该功能/参数不存在"。
4. **禁止外部知识补洞**：GJB规则（§6情形B）、常识、未召回章节记忆一律不得作为判定依据。
5. **证据可点验**：evidence_refs必须逐条可点开核验；禁止凭相似度"大概在那条"。
6. **不私自改规则**：换算表/同义表/聚合规则表外的情形→判NIE+dispute_note交仲裁扩表；扩表须版本化并全员同步后生效。
7. **先训后标**：开标前完成判例1–10试标且全对；正式标注按随机顺序，禁跳选。
8. **留痕可查**：每条标注时长自动记录；10%条目由第三方回标抽查。
