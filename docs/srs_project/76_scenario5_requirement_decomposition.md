## 二、按比对矩阵重组的17项深拆

比"三层分类"更有操作性的维度是【谁和谁比】——直接决定实现依赖:

```
A类 QA对内部(指令vs回答)     —— 4项, 零图片零VLM
B类 图片 vs QA              —— 8项, 需感知栈
C类 跨QA样本(语料级)         —— 3项, 需聚类管道
D类 QA vs 规则知识(判定标准块) —— 2项, 需规则库
```

### A类: QA对内部比对（4项）——阶段1的直接对象

**A-1 状态术语统一（术语③）**
- 矛盾本质: 指令写"离岗状态", answer/evidence写"不在岗"——同一状态概念两种表述
- 证据双侧: 指令文本 vs answer文本（同一条QA内部）
- 比对操作: 双侧术语→概念归一（同义词表/嵌入相似）→字面不同即告警
- 抽取依赖: **纯文本NER+术语归一**——我们的L0直接可用
- 场景1对应: TERM-01的QA内部版
- 判定语义: 术语规范告警（warning）

**A-2 同名异义（术语②）**
- 矛盾本质: "通道"一处指疏散通道、一处指消防通道——同形异指
- 证据双侧: QA内多处文本（指令+evidence）
- 比对操作: 指代消解→同一术语不同指称对象
- 抽取依赖: 纯文本（指代消解是NLP难题，第一版可只做"通道"类已知歧义词表）
- 场景1对应: TERM-02
- 判定语义: 概念歧义告警（要求加限定词）

**A-3 阈值边界一致性（参数③）**
- 矛盾本质: 指令判定标准"面积≥X触发"，answer复述成">X"——边界语义改变
- 证据双侧: 指令的判定标准块 vs answer/evidence文本
- 比对操作: 数值约束抽取（≥/>/≤/<+数值）→ **符号级+数值级比对**
- 抽取依赖: 纯文本数值模式抽取——我们的numeric claim提取直接可用
- 场景1对应: **PARAM-03完全对应**
- 判定语义: refute（确定性可判！约束语义被改变）

**A-4 工况条件缺项（参数④）**
- 矛盾本质: 指令限定"夜班值守场景下"，answer丢条件直接给通用结论——前置条件被丢
- 证据双侧: 指令条件子句 vs answer条件覆盖
- 比对操作: 指令条件抽取（"X场景下/当X时"）→ answer中条件存在性检查 → 差集=丢失
- 抽取依赖: 纯文本条件子句抽取
- 场景1对应: **无对应（新方向: 条件完备性）**
- 判定语义: 条件丢失告警（answer不完整）

### B类: 图片 vs QA（8项）——感知栈的需求来源

**B-1 同义异名跨模态（术语①）**
- 矛盾本质: 图片实体类别"工作服"，QA写"工装"——同物异名跨模态
- 证据双侧: 图片实体识别输出 vs QA evidence文本
- 比对操作: 实体类别名 vs QA术语 → 同义对表/嵌入
- 抽取依赖: **目标检测/属性识别输出类别**（PPE检测的类别标签就是"图片侧术语"）
- 场景1对应: TERM-01跨模态版（场景1是正文vs表格）
- 判定语义: 术语规范告警

**B-2 对象类别全局一致（术语④）**
- 同B-1但增加QA内部交替（"安全帽/头部防护帽"混用）
- 比对操作: 图片实体类别 + QA各处表述 → 一致性矩阵
- 场景1对应: TERM-07变体

**B-3 目标行为术语（术语⑥）**
- 图片行为标签"未穿工作服" vs QA"没有穿着工装"
- 抽取依赖: **动作/穿戴属性识别输出**（行为标签=图片侧术语）
- 场景1对应: TERM-05变体（用例名→行为名）

**B-4 隐患属性跨模态冲突（参数①）**
- 矛盾本质: 图片侧隐患等级=重大, QA标=一般
- 关键认知: **图片侧的"隐患等级"不是原始感知, 是判定模型/规则的输出**——感知给的是实体+状态, 等级是"实体→规则→等级"推导的结果
- 证据双侧: 判定引擎输出（规则+感知融合） vs QA answer
- 比对操作: 同一隐患的等级值比对
- 场景1对应: PARAM-01（同参数不同值）
- 判定语义: refute（指标冲突）

**B-5 实体属性丢失（参数②）——完备性新方向**
- 矛盾本质: 图片识别出"人员摔倒", QA完全未提——**证据有, 回答缺**
- 证据双侧: 图片实体/状态清单 vs QA提及清单
- 比对操作: **应覆盖集(图片task相关实体) − 实际覆盖集(QA evidence) = 丢失集**
- 关键设计问题: "应提及"的范围如何定义——不是图片所有东西都要提, 是**与task判定相关的关键实体**（判定标准块中出现的实体类型）
- 抽取依赖: 完整感知清单 + task相关性过滤（判定标准块的实体要求）
- 场景1对应: **无（NIE的反向问题）**
- 判定语义: 可疑样本标记（丢失≠错误, 送人工）
- **进注册表范式的路径**: 图片感知输出=图片注册表, QA evidence=回答注册表, 差集运算=丢失检测——与我们的"双登记"同构, 方向相反

**B-6 值域范围（参数⑤）**
- 图片: 安全帽+工作服两项缺失; QA只报安全帽——**多值属性的子集覆盖**
- 比对操作: 图片属性集 ⊃ QA属性集 → 部分丢失（B-5的集合版）
- 抽取依赖: PPE检测多标签输出
- 判定语义: 值域错位告警

**B-7 数量指标（参数⑥）**
- 图片检测框计数3处杂物 vs QA写2处
- 比对操作: 计数值直接比对
- 抽取依赖: 目标检测计数
- 场景1对应: PARAM-01数值版

**B-8 场景-行为错配（合规③）——场景适用性新方向**
- 矛盾本质: 图片场景=疏散通道区域, QA套用工位安全规则——规则用错场景
- 证据双侧: 图片场景识别 vs QA引用的判定规则
- 比对操作: **规则的场景适用域 vs 实际场景**——判定标准块的条件子句自带场景限定（"只有当疏散通道被..."）
- 抽取依赖: 场景识别（区域分类）+ 判定标准块的条件解析
- 场景1对应: 无（场景1的规则没有"场景适用域"维度）
- 判定语义: refute（规则错配是确定性可判——如果场景和规则条件都可结构化）

### C类: 跨QA样本（3项）——语料级管道

**C-1 缩写与代号（术语⑦）**
- 同一设备编号在不同QA样本缩写不统一
- 比对操作: 全数据集术语收集 → 全局注册表 → 同指异形检测
- 抽取依赖: 纯文本（但作用域=全数据集）
- 场景1对应: TERM-08全局版——**这就是文档说的"全局召回比对"**

**C-2 业务规则引用不一致（合规②）**
- 同类违规行为, 不同QA样本的处置建议/风险判定矛盾
- 比对操作: group_by(task类别) → 组内处置结论一致性
- 抽取依赖: QA文本 + task分类
- 场景1对应: LOGIC族跨位置版（同类违规=同主体, 处置建议=值, 注册表join!）

**C-3 多样本结论矛盾（合规④）**
- 高度相似图片 → 相反结论
- 比对操作: 相似组聚类 → 组内answer比对 → 相反=可疑对
- 抽取依赖: **相似度聚类**——时序元数据(camera,timestamp)为免费主键
- 场景1对应: 无（突破单实例）
- 判定语义: **可疑标记（不判对错）**——这个的输出语义与S/R/NIE都不同, 是"对内冲突, 需人工仲裁"

### D类: QA vs 规则知识（2项）——规则驱动, 确定性最强

**D-1 枚举标签一致性（术语⑤）**
- QA输出"普通隐患" ∉ {一般,较大,重大}
- 证据双侧: QA answer vs 枚举定义（判定标准块声明）
- 比对操作: 闭集成员判定——**TERM-3直接可用**
- 判定语义: refute（非法枚举值, 确定性）

**D-2 隐患判定逻辑冲突（合规①）**
- 图片识别睡岗, QA判"合规"——违背判定标准
- 证据双侧: 图片行为识别结果 + 判定规则表 vs QA answer
- 比对操作: 行为标签→预期判定（规则表: 睡岗→违规） vs 实际answer
- 抽取依赖: 动作识别 + **判定标准块结构化为规则表**
- 场景1对应: LOGIC-02式（处置逻辑矛盾, 规则表驱动）
- 判定语义: **refute（确定性）**——判定标准块就是知识源

## 三、核心论证: "特征提取与上下文关联"=CV感知栈+关联聚合

你的直觉是对的。场景5文档段[100]说特征提取模块产出五类特征, 逐一对应:

| 文档要求的特征 | 具体是什么 | 业内成熟度 |
|---|---|---|
| 图片实体 | **目标检测**（人/安全帽/工作服/设备/通道） | 成熟(YOLO系/开放词汇检测) |
| 目标属性 | **属性识别+状态判定**（穿戴/姿态/睡岗/摔倒/离岗） | 成熟(动作识别/PPE检测有现成数据集) |
| 隐患特征 | **判定引擎输出**（实体+规则→隐患等级——注意这是感知+规则的融合层, 不是纯感知） | 规则驱动可自建 |
| QA问答对语义 | QA JSON解析+文本NER | 我们现成 |
| 上下文关联特征 | **时序关联**（同camera帧序列）+**跨样本关联**（相似组）+**跨模态关联**（图片实体↔QA术语的实体链接） | 关联逻辑我们现成 |

**所以架构翻译**:
```
场景5的"上下文关联与特征提取模块" = CV感知栈(检测/动作/属性/场景/OCR)
                                    + 跨模态实体链接(图片实体↔QA术语)
                                    + 时序/跨样本关联聚合
场景5的"特征校验模块"             = 我们的注册表+join+聚合(方向B)
                                    + 跨样本比对扩展
```

**这正是方向A在场景5的形态**: 场景1的方向A=文档内多模态内容聚合(文字/表格/图→条目); 场景5的方向A=**感知输出+QA文本→条目**。两者产出同一下游构件: **(主体, 值, 位置)注册表**——然后方向B做比对。范式不变, 换的是"多模态内容的来源"（文档解析→感知栈）。

## 四、结构性发现: 判定标准块=场景5的规则库

场景1的规则知识源=GJB 438C标准(120条规则库, 每条rule_id+source锚); 场景5的规则知识源=**每个task自带的判定标准块**:

```
判定标准块(每task一个):
  1. 只有当疏散通道被物料、设备或杂物堆放占用、影响人员通行时，才判定为 1（yes）。
  2. 通道畅通、仅有少量易移动物品且不影响通行，判定为 0（no）。
  3. 如果画面模糊、遮挡严重、无法确认，则判定为 2（uncertain）。
  4. 只判断【通道占用行为】，不要判断其他违规行为。
  5. 必须只输出合法 JSON...
```

一个判定标准块同时承担三个角色:
1. **生成时的prompt规范**（文档3.1的用途）
2. **校验时的规则库**（场景④场景适用域/枚举值域/预期判定/条件要求——全在块里）
3. **负样本构造的翻转源**（EGT式: 翻转块的阈值/条件/枚举→困难负样本）

这比GJB规则库更友好——**规则与task绑定, 天然结构化**（编号条款+条件→结论式）。可以像compile_rule那样把判定标准块编译成CompiledCheck（条件子句→场景适用域, 结论子句→预期判定, 枚举子句→值域闭集）。

## 五、判定语义的三档（比场景1多一档）

| 语义 | 适用项 | 输出动作 |
|---|---|---|
| **refute**（确定性矛盾） | 阈值改变/枚举非法/判定逻辑违背/指标冲突 | 剔除或修正样本 |
| **warning**（规范告警） | 术语①②③④⑥⑦/值域错位/条件丢失 | 劣样本优化(回流) |
| **可疑标记**（对内冲突, 不判对错） | 多样本矛盾/属性丢失 | 人工仲裁 |

场景1只有S/R/NIE三态; 场景5实际需要**四态语义**（+可疑）——因为跨样本冲突和完备性缺失本质上不能单方判错。这是聚合语义的扩展点。

## 六、行动启示（不开发, 只列结论）

1. **A类4项+D类2项=6项可在零图片零VLM下落地**（阶段1范围, 且全部有场景1直接对应件）
2. **B类8项的感知栈全是业内成熟CV任务**——不发明算法, 做的是"感知输出→注册表"的规范化桥
3. **C类3项中, C-2规则引用不一致可以用注册表join直接做**（task类别=主体, 处置建议=值）——比预想近
4. **完备性检查（B-5/B-6/A-4）是三个新方向里最系统的**——统一的"应覆盖集−实际覆盖集"差集运算, 且应覆盖集都有明确来源（判定标准块/指令条件/图片感知）
5. **判定标准块编译器**是场景5版的compile_rule——规则源比GJB标准更结构化
6. **第四态"可疑"**需要进聚合语义设计
