# 63 证据细粒度建模与原子化精选：E-Atom框架

日期：2026-10-27 | 状态：设计定稿 | 位置：`evidence_recall`(top-50)之后、QualityContract之前

---

## 一、核心思想

```text
传统方式：召回top-50 → 整块重排 → 全部送下游
E-Atom方式：召回top-50 → 拆成证据粒子 → NLI配对 → 三支决策 → 最小验证包

区别：不是"排序证据"，是"拆解证据→选择粒子→重组验证包"
     从"重排"变成"细粒度精选"
```

---

## 二、统一框架

```text
top-50 (EvidenceHit)
  ↓
[1 Atomizer: 拆成证据粒子]
  表格行 → (参数名, 操作符, 值, 单位, 条件) 每格一个粒子
  正文段 → 句子 → 原子claim (主谓宾+条件+作用域)
  图节点 → (节点文本, 类型, 边关系, 拓扑位置)
  ↓
[2 Router: 问题类型→证据类型路由]
  参数查询 → 表字段粒子 + 约束句
  术语查询 → 定义句 + 合格性行
  逻辑一致性 → 多表字段 + 追溯行 + 图三元组
  ↓
[3 NLI配对: 三支决策]
  同参数/同实体的粒子对 → 本地NLI判断:
    entailment  → 冗余簇（压缩，留代表）
    contradiction → 冲突对（升权，送不一致检测）
    neutral     → 互补（保留，新信息）
  ↓
[4 重组: 最小验证包 VerificationPack]
  主证据（冲突两侧claim）+ 辅助证据（单位/定义/作用域）
  + 反证（如有） + 上下文锚点（章节/原文位置）
  ↓
QualityContract 裁决 → Oracle / Partial / NoEv
```

## 三、五个方向详细设计

### 方向1：子单元拆分（Atomizer）

**每种模态的"最小证据粒子"**：

| 模态 | 拆分方式 | 粒子Schema | 上下文保留 |
|---|---|---|---|
| 表格行 | 按字段拆 | `{参数名, 操作符, 值, 单位, 条件/作用域}` + 行键 | `parent_id → 行 → 表 → 章节` |
| 正文段落 | 句→原子claim | `{主语, 谓语, 宾语/值, 条件, 作用域}` | `parent_id → 句 → 段 → 章节` |
| 图节点 | 节点+边+位置 | `{节点文本, 节点类型, 边三元组[], 拓扑签名}` | `parent_id → 节点 → 图 → 章节` |

**实现**：
- 表格：`srs_kb.json`的23参数+10单位族做槽位对齐（确定性规则）
- 正文：LLM拆解走`llm_client`缓存 + 规则后处理（编号/单位/条件）
- 图：复用`context_graph.py`图结构 + `anchor_v3`拓扑

**关键**：每个粒子保留完整的`parent_id`回溯链——细粒度不丢上下文。

**创新**：GJB领域专用的模态粒子schema，有据可循的槽位模板（区别于通用OpenIE）。

---

### 方向2：问题类型→证据类型路由

**问题类型到证据粒子的映射**：

| 问题类型 | 需要的证据粒子 | 优先模态 |
|---|---|---|
| 参数查询（"响应时间是多少？"） | 表字段(参数+值+单位) + 正文约束句 | table + text |
| 术语定义（"XX功能是什么？"） | 正文定义句 + 合格性行 | text + qualification |
| 逻辑一致性（"约束是否矛盾？"） | 多表字段对 + 追溯行 + 图拓扑 | multi-table + trace + diagram |
| 图文一致（"图和表是否对齐？"） | 图节点 + 对应表行 + 引用句 | diagram + table + text |

**实现**：先用规则（问题关键词→模态掩码），冷启动用`qa_synth.py`合成监督信号训练轻量分类器；规则做兜底，分歧时取并集。

**集成**：扩展`blackboard/router.py`输出模态过滤掩码。

**创新**：RE场景下"问题类型→证据模态"的路由先验（多跳QA中间推理的领域化迁移）。

---

### 方向3：NLI驱动的三支决策

**核心逻辑**：NLI的不等性（entailment/contradiction/neutral）直接指导证据选择：

```text
同参数/同实体的粒子对 → NLI判断

entailment (A包含B的信息)
  → 冗余：并簇留代表，压缩证据量
  → 例："响应时间≤200ms" 与 "response time ≤ 200ms" → 保留一个

contradiction (A与B矛盾)
  → 冲突：升权，作为不一致候选送检测
  → 例："响应时间≤200ms" 与 "响应时间≤500ms" → 升权送方向B

neutral (A与B独立)
  → 互补：保留，是新信息
  → 例："响应时间≤200ms" 与 "并发用户≥1000" → 都保留
```

**实现**：
1. 同参数/同实体的粒子先配对（BGE相似度预筛，降低NLI调用量）
2. 配对后用本地NLI模型（mDeBERTa/Erlangshen）判三支
3. 结果写入`evidence_store`，冲突对直通`adjudication.py`

**NLI调用控制**：
- BGE预筛：只有cos>0.6的粒子对才做NLI（大幅减少调用）
- 粗粒度先用：L1级别（句子/字段）先判，L0不满足才下钻到L2

**创新**：NLI不等性作为**选择信号**（留/删/升权三支），而非仅作检测结论。

### 方向4：最小验证包（VerificationPack）

**结构**：
```json
{
  "query": "SQL访问功能的响应时间约束是什么？",
  "pack_id": "VP-...",
  "primary_evidence": [
    {"atom": "响应时间≤200ms", "source": "表2行3字段2", "p_e": 0.93},
    {"atom": "响应时间≤500ms", "source": "正文3.2.1", "p_e": 0.91}
  ],
  "auxiliary_evidence": [
    {"atom": "单位: ms", "source": "表2行3字段3"},
    {"atom": "作用域: SQL访问", "source": "章节标题"}
  ],
  "conflict_pairs": [
    {"left": "≤200ms", "right": "≤500ms", "nli": "contradiction", "weight": "high"}
  ],
  "context_anchors": [
    {"section": "3.2.1", "table": "T-02-0003", "row": 3}
  ],
  "original_pool_size": 50,
  "selected_atoms": 7,
  "compression_ratio": 0.14
}
```

**特性**：
- **可审计**：每个原子可回溯到原文位置
- **可评测**：直接映射到Oracle/Partial/NoEv三级
- **可序列化**：可转为文本供人工复核

**创新**：验证包=可评测、可人工复核的中间产物，直接服务论文评测叙事。

### 方向5：自适应粒度下钻

**三档粒度**：
```text
L0（粗）：整行/整段/整个图 → 召回快但噪声多
L1（中）：句子/字段/节点 → 平衡
L2（细）：原子claim/槽位 → 精确但可能丢上下文
```

**自适应策略**：
```text
1. Router先确定入口粒度（根据问题类型）
2. 在L1上计算"信息饱和度"：
   饱和 = 粒子间NLI全为entailment的比例 + 新信息增益低于阈值
3. 不饱和才下钻到L2
4. 饱和即停止（早停省NLI调用）
```

**创新**：以NLI信号定义的"信息饱和度"作为证据下钻的停止准则。

## 五、优先级

| 优先 | 方向 | 理由 |
|---|---|---|
| **P0** | 方向1(拆分) | 粒子是一切的基础 |
| **P0** | 方向3(NLI三支) | 核心选择信号，与方向1组合即可产出消融 |
| **P1** | 方向4(验证包) | 提供评测载体 |
| **P1** | 方向2(路由) | 规则可先行，学习后补 |

## 六、预期论文贡献

1. **E-Atom粒子模型**：GJB领域多模态证据的最小单元定义与拆分
2. **NLI三支决策**：entailment/contradiction/neutral直接指导证据精选（留/删/升权）
3. **VerificationPack**：可审计、可评测的最小验证包中间产物
4. **粒度-代价trade-off**：信息饱和度作为下钻停止准则

**论文叙事**：从"召回排序"到"证据原子化精选"——不仅减少证据数量，更提升证据质量与可审计性。
