# SRS 文档不一致检测 — 交接文档

> **用途**: 供并行团队阅读后直接认领任务、复现论文、补充实验
> **数据集**: PURE (62个SRS文档, 2833页, 460万字, 1845表格)
> **数据集下载**: https://zenodo.org/records/1414117
> **代码路径**: `tools/` 目录下所有 `srs_*.py`
> **知识库**: `knowledge/srs_kb.json` (23参数/13接口/67单位)
>
> ⚠️ **重要说明**: 当前所有不一致检测结果均为**初步结果**。当前仅在 PURE 单一数据集上验证，后续需要补充 QuRE、PURE-MMQA、ReqEval 等数据集复现验证。所有 F1/精度数字均为初步值，不代表最终性能。

## 四、特征提取与上下文关联

> 把文档里散落在不同章节、表格、段落中的信息片段**关联起来**，构建知识图谱。这是三层不一致检测的**基础设施**——只有把"第3.2节的响应时间"和"表格4的响应时间"关联到同一个节点，才能检测它们之间的矛盾。

### 为什么需要这一层

当前的参数抽取是**孤立的**：我们从每个句子中独立提取参数约束，但不知道"第3.2节提到的响应时间"和"表格4里的响应时间"是不是同一个参数。如果不把它们关联起来，就无法检测正文↔表格矛盾（2.2）、跨文档矛盾（2.5）、术语不一致（2.4）。

**知识图谱的作用**就是把所有片段串起来：

```
示例图谱:
  [参数节点: 响应时间]
      ├── 定义于 → [章节3.2] "响应时间不超过50ms"
      ├── 定义于 → [表格4, 第2行] "响应时间 ≤ 100ms"
      ├── 引用于 → [章节5.1] "见3.2节响应时间要求"
      ├── 同义于 → [参数节点: 反应时间] (术语归一化)
      └── 矛盾于 → [约束C001: 50ms] vs [约束C002: 100ms] → 冲突！
```

## 六、关键发现（交接必读）

| 发现 | 数据 | 含义 |
|---|---|---|
| **银→金泛化差距巨大** | Span+LR: F1(银)=0.97 → F1(金)=0.43 | 银标准评估不可信，必须用金标准评估 |
| **银标准噪声是瓶颈** | 银标准~70%精度 | 所有监督方法上限受限，需更多高质量标注 |
| **MLM适配无帮助** | F1(金): 0.43→0.43 | 基线已强时MLM无增益 |
| **LLM抽取精度最高** | GLM-5 P~0.90(初步) | 但成本高，适合标注而非在线抽取 |
| **3条真实矛盾(初步)** | 可用性/占空比/呼叫建立 | 需更多数据集验证是否为真矛盾 |
| **知识图谱尚未构建** | — | 正文↔表格配对、跨文档比较、术语归一化都依赖图谱 |
