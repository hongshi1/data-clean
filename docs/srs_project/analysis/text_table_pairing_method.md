# SRS文档中文本与表格的配对方法

> 本文以GJB 438C调度器SRS为例，详细说明文本与表格的3种配对方式、6个检测点及其实际效果。

---

## 1. 问题定义

一份GJB SRS文档中，**正文**描述需求细节，**表格**汇总需求信息。同一个信息出现在两处：

```
📊 表格(合格性规定表)                    📄 正文(章节3.2.1)
┌──────────────────────────────┐       ┌──────────────────────────────┐
│ REQ-3.2.1 | 高精度定时器      │       │ ## 3.2.1 高精度定时器功能      │
│ 章节=3.2.1 | 方法=单元测试     │  ←→   │ "定时周期默认25ms"            │
│ 级别=关键                     │       │ "误差不超过±2ms"              │
└──────────────────────────────┘       └──────────────────────────────┘
```

**核心问题**：怎么知道表格中的"REQ-3.2.1"对应正文的哪个章节？怎么验证两处信息一致？

---

## 2. 三种配对方式

### 方式1：章节号关联

**原理**：表格在Markdown中的物理位置决定了它属于哪个章节。

**步骤**：
1. MinerU解析PDF，表格转为HTML `<table>` 插入Markdown
2. 从表格位置向上搜索最近的 `#` 标题
3. 该标题即为表格所属章节

**实际数据（调度器SRS）**：

| 表格 | 类型 | section字段 | → 关联到正文章节 |
|---|---|---|---|
| 表1 | 修改页 | 封面区域 | → 封面（无正文需求） |
| 表2 | 引用文档 | **2 引用文档** | → 正文第2章 |
| 表3 | 合格性规定 | **4 合格性规定** | → 正文第4章 |
| 表4 | 追踪表(正向) | **5 需求可追踪性** | → 正文第5章 |
| 表5 | 追踪表(逆向) | **5 需求可追踪性** | → 正文第5章 |

**用途**：确认每个表格都有对应的正文章节，章节内容与表格主题一致。

**局限**：只知道表格属于哪个章节，不知道表格中具体哪一行对应正文哪一段。

---

### 方式2：需求ID关联（最精确）

**原理**：合格性规定表中的 `REQ-3.2.X` 和章节号 `3.2.X` 直接指向正文章节。

**合格性规定表（实际数据）**：

| 需求名称 | 需求ID | 章节号 | 合格性方法 | 级别 |
|---|---|---|---|---|
| 高精度定时器 | **REQ-3.2.1** | **3.2.1** | 单元测试+精度测量 | 关键 |
| 时间漂移补偿 | **REQ-3.2.2** | **3.2.2** | 长时间运行测试 | 关键 |
| 电流序列管理 | **REQ-3.2.3** | **3.2.3** | 单元测试 | 一般 |
| 主循环调度 | **REQ-3.2.4** | **3.2.4** | 集成测试 | 关键 |
| 降采样输出 | **REQ-3.2.5** | **3.2.5** | 功能测试 | 一般 |

**配对过程**：

```
表格行: REQ-3.2.1 | 高精度定时器 | 章节=3.2.1 | 方法=单元测试
                                    ↓
                        正文章节3.2.1的约束:
                          - "定时周期默认25ms"
                          - "误差不超过±2ms"
                          - "使用CLOCK_MONOTONIC时钟源"
```

**基于此配对的3个检测点**：

**检测1：需求名称一致性**
```
表格: "高精度定时器"
正文: "3.2.1 高精度定时器功能"
→ 基本一致（正文多"功能"后缀）✅
```

**检测2：章节存在性**
```
表格列出: 3.2.1, 3.2.2, 3.2.3, 3.2.4, 3.2.5
正文实际: 3.2.1, 3.2.2, 3.2.3, 3.2.4, 3.2.5
→ 全部存在 ✅
```

**检测3：合格性方法已填写**

| 文档 | 表格内容 | 检测结果 |
|---|---|---|
| 调度器SRS | 每行都有实际方法（单元测试/集成测试等） | ✅ 正常 |
| 编译器SRS | 每行都填"占位符"（表头名称本身） | ❌ 空表检测(TP) |

编译器SRS的合格性表实际内容：
```
需求名称=《GB/T 0028》  需求ID=合规性方法  方法=合规性级别  ← 全是占位符
需求名称=《GB/T 0028》  需求ID=合规性方法  方法=合规性级别  ← 全是占位符
需求名称=《GB/T 0028》  需求ID=合规性方法  方法=合规性级别  ← 全是占位符
```
→ 检测为 `empty_table_placeholder`（HIGH，置信度0.9），这是真实检出(TP)。

### 方式3：值关联

**原理**：追踪表中的数值/关键词，在正文约束中搜索匹配。

**追踪表（实际数据）**：

| 系统级指标 | 来源 | 需求名称 | 章节号 |
|---|---|---|---|
| **25ms** 周期驱动电池模型 | 总体目标 | 主循环调度功能 | 3.2.4 |
| 处理时间漂移（补偿执行开销） | 总体目标 | 时间漂移补偿功能 | 3.2.2 |
| 周期性执行模型步进并记录输出 | 总体目标 | 降采样输出功能 | 3.2.5 |

**配对过程**：

```
追踪表: "25ms 周期驱动电池模型"
    ↓ 搜索"25ms"
正文约束: 找到11条含"25ms"的约束
    分布在8个章节:
      - 1.2系统概述: "以25ms固定周期驱动"
      - 3.1.1初始化: "设定25ms周期"
      - 3.2.1定时器: "确保平均周期为25ms"
      - 3.2.1输入: "默认25ms"
      - 3.2.4主循环: "按25ms周期驱动"
      - 3.2.5降采样: "25ms周期的内部数据"
      - 5追踪表: "25ms周期驱动电池模型" ×2
```

**基于此配对的3个检测点**：

**检测4：值一致性**
```
追踪表: "25ms周期驱动" → 正文: "25ms"出现11次 → 值匹配 ✅

假设矛盾场景:
  追踪表: "30ms周期驱动" → 正文: "25ms" → 值不匹配 → 矛盾!
```

**检测5：追踪完整性**
```
正文有5个需求: 3.2.1, 3.2.2, 3.2.3, 3.2.4, 3.2.5
追踪表只列出: 3.2.4, 3.2.2, 3.2.5
→ 缺少3.2.1和3.2.3的追踪 → 不完整 ⚠️
```

**检测6：同值跨位置一致**
```
"25ms"出现位置:
  正文6次 + 追踪表2次 = 共8次
→ 全部为25ms → 一致 ✅
（如果其中一个为30ms → 矛盾）
```

## 3. 完整配对关系

| 表格 | 配对方式 | 配对目标 | 检测内容 | 调度器SRS | 编译器SRS |
|---|---|---|---|---|---|
| 表1 修改页 | 方式1 章节 | 正文封面 | 无（空模板） | — | — |
| 表2 引用文档 | 方式1 章节 | 正文第2章 | 引用标准存在 | ✅ | ✅ |
| 表3 合格性规定 | **方式2 需求ID** | 正文3.2.1-3.2.5 | ①名称 ②章节 ③方法 | ✅ 全通过 | ❌ 空表 |
| 表4 追踪表(正向) | **方式3 值关联** | 正文约束值 | ④值一致 ⑤完整 | ⚠️ 值一致但不完整 | ❌ 空表 |
| 表5 追踪表(逆向) | **方式3 值关联** | 正文约束值 | ④值一致 | ✅ 值一致 | ❌ 空表 |

## 5. 方法特点

| 特点 | 方式1 章节号 | 方式2 需求ID | 方式3 值关联 |
|---|---|---|---|
| 精度 | 中（位置推导） | **高（精确匹配）** | 中（值匹配） |
| 适用表格 | 所有表格 | 合格性表 | 追踪表 |
| 依赖 | MinerU解析质量 | GJB标准格式 | 约束提取质量 |
| 假阳性风险 | 低 | 极低 | 中（单位转换） |
| 检测能力 | 章节存在性 | 名称/章节/方法/空表 | 值一致/完整性/同值 |

**方式2是最精确的配对**——因为GJB 438C标准规定合格性表必须包含需求ID和章节号，这提供了表格与正文之间的**确定性链接**。

**方式3是最有检测价值的配对**——通过值匹配可以发现"正文说25ms但表格说30ms"这类矛盾，这是当前语义层检测的核心。

---

## 6. 已知限制

1. **章节号关联依赖MinerU解析质量**：如果MinerU未正确识别表格在Markdown中的位置，section字段会错误
2. **需求ID关联依赖GJB格式**：非GJB格式的SRS没有REQ-ID，无法使用方式2
3. **值关联需要单位归一化**：25ms和0.025s是同一个值，但直接比较会误报为矛盾（已修复）
4. **追踪完整性判断有歧义**：追踪表缺少某需求可能是有意为之（如该需求无需追踪），不一定是错误
5. **OCR表格拆行**：MinerU解析合格性表时可能将一行内容拆成两行，影响配对
