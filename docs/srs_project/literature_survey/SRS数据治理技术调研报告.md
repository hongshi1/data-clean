# 军用SRS文档数据治理：参数化需求抽取技术调研报告

> 目标：从大量军用软件需求规格文档（SRS，已解析为结构化文本+表格）中抽取参数化需求条目 `{参数名, 运算符, 数值, 单位, 条目类型, 引用关系}`，并解析正文/表格间的交叉引用，构建「参数化需求条目库（含引用关系图）」。
> 适用标准背景：GJB 438C《军用软件开发文档通用要求》、GJB 2786A《系统需求规格说明》、GJB 5000B《军用软件研制能力等级要求》。这类文档具备强编号结构（3.2.1 三级条目）、固定表格（性能指标表/接口控制文档ICD表/数据字典）、以及密集的交叉引用（"见3.2节"、"如表4所示"、"参见GJB 438C第5.3条"）。

---

## 方向1：领域命名实体识别与参数抽取（Domain NER & Parameter Extraction）

### 1.1 任务定义
- **领域术语 NER**：识别接口类型（RS422/1553B/以太网）、参数名（响应时间/吞吐量/误码率）、性能指标、协议名称、设备型号等实体。
- **参数化结构抽取**：把"系统响应时间应≤50ms"→ `{param:响应时间, op:≤, value:50, unit:ms, type:性能}`。本质是 **实体+关系+数值属性联合抽取**，等价于关系三元组 `(参数名, 运算符, 数值)` + 单位槽填充。

### 1.2 技术方案对比

| 方案 | 代表方法/工具 | 准确率 | 标注成本 | 可解释性 | 中文/军工适配 | 适用场景 |
|---|---|---|---|---|---|---|
| **a) 规则/正则+模板** | JFlex/自定义DSL、spaCy ruler、HanLP规则 | 高（格式固定时>95%） | 低 | 极高（规则可审计） | 强（GJB句式规整） | "≤50ms""8路输入"等模式化表述 |
| **b) 预训练模型微调NER** | BERT/RoBERTa-wwm/MacBERT + CRF/BiLSTM；领域BERT续训 | 中高（F1 85-92%） | 中高（需数百-千条标注） | 中 | 中（需军工语料续训） | 术语边界模糊、多义词 |
| **c) 生成式UIE/指令IE** | UIE、DeepKE、InstructUIE、GoLLIE | 中高（监督高，少样本中） | 低（少样本/零样本） | 中 | 中（中文开源模型支持） | schema多变、低资源 |
| **d) 通用LLM抽取** | GPT-4/Claude/Qwen2.5/DeepSeek few-shot→JSON | 中（zero-shot）/高（few-shot） | 极低 | 低（黑盒） | 高（中文强模型多） | 冷启动、原型验证 |
| **e) 联合数值-单位-运算符抽取** | BERT-CRF + 数值正则槽填充；MRC式抽取 | 高 | 中 | 中高 | 中 | 本任务核心难点 |

### 1.3 关键工具与论文
- **UIE** (Lu et al., ACL 2022, arXiv:2203.12277)：提出 Structured Extraction Language (SEL) + Structural Schema Instructor (SSI)，将 NER/RE/EE 统一为 text-to-structure 生成。**对参数抽取的意义**：可用 SSI 定义 `schema: [参数名, 运算符, 数值, 单位]`，一次生成完整条目，天然支持"参数+运算符+数值"联合抽取。
- **DeepKE** (Zhang et al., EMNLP 2022 Demo, arXiv:2201.03335, zjunlp)：开源知识抽取工具包，支持 NER/RE/属性抽取，含低资源、文档级、多模态场景，提供中文预训练权重与 PyTorch 工程化实现。**优势**：开箱即用、模块可替换、有 Colab 教程，适合军工低资源场景快速落地。
- **GoLLIE** (Sainz et al., ICLR 2024, arXiv:2310.03668)：用标注指南（Python 类形式的 schema）微调 LLM，零样本迁移到未见 IE 任务，**消融实验证明详细指南是关键**。**对参数抽取的意义**：可把 GJB 438C 的参数书写规范写成 guideline，零样本抽出新类型指标。
- **InstructIE** (Gui et al., ISWC 2024, arXiv:2305.11527)：中英双语指令式 IE 数据集，覆盖12领域，提出 KG2Instruction 自动生成框架；训练后 LLM 的零样本 IE 能力提升。**意义**：中文指令 IE 基线，可直接用于构造 SRS 抽取指令数据。
- **UniRel** (Tang et al., EMNLP 2022, arXiv:2211.09039)：统一实体-关系表示与交互，用 Interaction Map 联合抽取关系三元组。**意义**：参数化条目的 `(参数名, ≤, 50)` 本质是关系三元组，UniRel 的联合建模思路可直接复用。
- **ChatGPT-IE 评测** (Li et al., arXiv:2304.11633)：发现 ChatGPT 在标准IE上差但在 OpenIE 上优秀，解释质量高但过度自信、校准低。**警示**：LLM 抽取需置信度校准与人工复核。
- **领域BERT**：Chinese-RoBERTa-wwm、MacBERT；技术文档可续训 SciBERT 思路（GJB 语料续训）。

### 1.4 针对军用SRS的推荐
**混合 pipeline：规则兜底 + 领域BERT微调主力 + LLM处理长尾/校验**

1. **规则层（高召回+可审计）**：针对 GJB 文档高规范化的"参数+运算符+数值+单位"句式，编写正则模板库（`(?P<param>...)(?P<op>[≤≥<>≈])(?P<val>\d+\.?\d*)\s*(?P<unit>ms|Mbps|路|℃)`）。军工领域要求**可追溯、可审计**，规则层保证每条抽取能给出依据，满足 GJB 5000B 配置管理。
2. **模型层（处理边界模糊/多义）**：用 RoBERTa-wwm-ext + CRF 做 NER 标注 `[PARAM][OP][VALUE][UNIT][PROTO]`，再用 UIE/DeepKE 框架做联合生成。建议在 GJB 语料上做领域续训（MLM）。
3. **LLM层（长尾+一致性校验）**：Qwen2.5/DeepSeek few-shot 抽取规则未覆盖的复杂句式（如"在满载工况下，端到端时延不超过200毫秒"），并对模型层输出做一致性校验（GoLLIE 风格 guideline 校验）。
4. **理由**：军工文档对**可解释性、稳定性、不漏抽**要求极高，纯 LLM 的幻觉与过度自信（Li et al. 2023 已证实）不可接受；纯规则覆盖不全。三者分层保证召回率、准确率与可审计性兼顾。

## 方向2：表格结构化与字段映射（Table Structuring & Field Mapping）

### 2.1 任务定义
SRS中常见三类表格：
- **性能指标表**：列如「指标项 | 指标要求 | 验证方法 | 备注」
- **接口定义表（ICD）**：列如「接口编号 | 接口类型 | 信号名称 | 方向 | 协议 | 速率」
- **数据字典表**：列如「编号 | 参数名称 | 缩写 | 数据类型 | 取值范围 | 单位 | 说明」

目标：把异构表格映射到统一 schema；做表头识别、列类型推断、单元格语义标注；并与正文术语对齐归一化（"响应时间" vs "反应时间"）。

### 2.2 技术方案对比

| 方案 | 代表方法 | 表头/列类型识别 | 跨表schema对齐 | 术语归一化 | 中文适配 | 适用场景 |
|---|---|---|---|---|---|---|
| **a) 规则+模板匹配** | 按GJB固定表头模板正则匹配 | 高（固定表头） | 弱（硬编码） | 弱 | 强 | GJB标准表格（格式稳定） |
| **b) 表格预训练模型** | TAPAS/TabBERT/TaBERT/TURL | 中高 | 中 | 中 | 弱（英文为主） | 列类型推断、表格QA |
| **c) LLM表格理解** | TableLlama/GPT-4/Qwen表格提示 | 高 | 高 | 高 | 中高 | 表头语义识别、自由文本单元格 |
| **d) 布局+多模态模型** | LayoutLM/TableMaster/DETR | 高（视觉结构） | 中 | 弱 | 中 | 扫描件/复杂合并单元格 |
| **e) 知识图谱对齐** | 本体映射+实体链接(Neo4j) | - | 高 | 高 | 中 | 术语归一化、跨表对齐 |

### 2.3 关键工具与论文
- **TableLlama** (Zhang et al., NAACL 2024, arXiv:2311.09206)：首个开源表格通才模型，构建 TableInstruct 数据集，用 LongLoRA 微调 Llama2-7B 处理长表格；8个域内任务中7个达到/超过SOTA，6个域外数据集提升5-44分。**意义**：开源可私有化部署，符合军工数据不出域要求；可直接用于 SRS 表格的字段映射与表头语义识别。
- **Table Meets LLM** (Sui et al., WSDM 2024, arXiv:2305.13062, Microsoft)：系统评测 LLM 对结构化表格的理解，设计7类任务（单元格查找/行检索/尺寸检测），发现**输入格式、内容顺序、分区标记显著影响性能**，提出 self-augmentation 结构化提示。**意义**：指导如何把 SRS 表格序列化喂给 LLM（推荐 Markdown/HTML 格式 + 关键值标注）。
- **TAMA** (Deng & Mihalcea, ACL 2025 Findings, arXiv:2501.14693)：重新审视表格指令微调，发现学习率等超参显著影响表格能力与通用能力的平衡，小学习率+少数据即能超越 GPT-3.5/4。**意义**：提供低成本微调表格 LLM 的实践指南。
- **TAPAS** (Google)：基于 BERT 的表格预训练，支持表格QA与列类型推断，但中文支持弱。
- **LayoutLM v3 / TableMaster**：处理带版面的表格，适合扫描版 GJB 文档的表格结构识别（合并单元格、跨页表）。

### 2.4 针对军用SRS的推荐
**分层：版面解析 → 表头/列类型识别 → schema映射 → 术语归一化**

1. **版面解析（已做）**：假设文档已解析为结构化表格（题目给定），跳过 OCR/版面恢复；若是扫描件用 LayoutLM v3/TableMaster 恢复。
2. **表头识别+列类型推断**：GJB 表格表头相对固定，**优先规则模板匹配**（性能指标表/ICD表/数据字典表各建模板）。对非标准表格用 TableLlama/Qwen 做 zero-shot 列类型推断（schema 提示：`列1:接口编号, 列2:接口类型...`）。
3. **统一schema映射**：定义军工 SRS 统一参数 schema（参考 GJB 438C 第5章数据需求），用本体映射把异构列名（"指标项/参数名称/信号名"）映射到统一字段。
4. **术语归一化（核心难点）**：构建**军工参数同义词典**（响应时间=反应时间=时延=延迟），用实体链接+向量相似度做表-文术语对齐。Table Meets LLM 的结论提示：把表格序列化为 Markdown 并标注关键值，可显著提升 LLM 对齐准确率。
5. **理由**：GJB 表格结构稳定但术语写法不规范，规则保证表头映射准确率，LLM/TableLlama 处理非标准表与术语歧义；术语归一化用词典+向量双保险。**军工数据敏感，优先选可私有化部署的开源模型（TableLlama/Qwen）**。

## 方向3：交叉引用解析与关系建模（Cross-Reference Parsing & Relation Modeling）

### 3.1 任务定义
- **引用解析**：识别"见3.2节""如表4所示""参见GJB 438C第5.3条""详见附录A"等引用锚点，并解析为指向目标（章节号/表号/图号/外部标准条款）。
- **关系建模**：构建条目间引用关系图——性能指标→引用→接口定义、功能需求→关联→验收准则、参数→定义于→数据字典。
- **存储查询**：图数据库存储，支持溯源查询（某性能指标依赖哪些接口/参数）。

### 3.2 技术方案对比

| 方案 | 代表方法 | 引用锚点识别 | 指向目标解析 | 复杂句处理 | 可解释性 | 适用场景 |
|---|---|---|---|---|---|---|
| **a) 正则+规则解析** | 编号模式正则 + 章节号索引表 | 高（编号模式固定） | 高（查索引表） | 弱 | 极高 | "见3.2节""表4"等显式引用 |
| **b) 依存句法分析** | HanLP/LTP/Stanza依存+规则 | 中高 | 中 | 中 | 高 | 引用嵌在句中（"该指标依据...规定"） |
| **c) LLM引用抽取** | GPT-4/Qwen few-shot→JSON | 高 | 中高 | 高 | 低 | 隐式引用、语义级关联 |
| **d) 核心指代消解** | SpanBERT/coref模型 | 中 | 中 | 中 | 中 | "该参数""上述指标"等指代 |
| **e) 图数据库存储查询** | Neo4j + Cypher | - | - | - | 高 | 关系图持久化与多跳溯源 |

### 3.3 关键方法与论文
- **正则引用解析**：GJB 文档编号高度规范（`(\d+\.)+\d+` 章节号、`表\s*\d+`/`图\s*\d+`/`式\s*\d+` 表图号），正则可覆盖90%+显式引用。建立「章节号→条目ID」「表号→表条目ID」索引表后即可精确解析指向。
- **依存句法分析**：HanLP/LTP 提供中文依存解析，可识别"性能指标见3.2节"中"见"的宾语"3.2节"及其主语"性能指标"，建立主语→引用→目标的三元关系。
- **GROBID / FOSSIL** (Foppiano & Boulanger, arXiv:2606.01109)：法律/人文学科脚注引用抽取，处理脚注中引用与评论、交叉引用交织的混合内容，对 GROBID 特化后 F1 从0.36→0.72。**意义**：GJB 文档的"参见外部标准条款"类引用与此场景类似，可借鉴其引用-评论分离与交叉引用解析思路。
- **LLM引用抽取**：对隐式引用（"按前述规定执行""同上级要求"）用 LLM 做语义级关联抽取，输出 `{source_span, relation, target}` JSON。
- **图数据库**：Neo4j 存储 `(:Requirement)-[:REFERS_TO{type:性能-接口}]->(:InterfaceDef)`，Cypher 支持多跳溯源查询。

### 3.4 针对军用SRS的推荐
**正则解析为主 + 依存句法补强 + LLM处理隐式 + Neo4j存储**

1. **正则解析层**：GJB 编号规范，用正则识别显式引用锚点，配合章节/表号索引表精确解析指向。覆盖率最高、可审计，是军工场景首选。
2. **依存句法层**：用 HanLP/LTP 解析引用所在句的依存关系，把引用锚点与被修饰实体关联（哪个参数"见"了哪个表），生成有源有宿的关系边。
3. **LLM层**：仅对隐式/语义级引用（"按上述要求""同3.2节相关条款"）用 Qwen few-shot 抽取，并做正则结果的校验/补全。
4. **关系图存储**：Neo4j 建模——节点（需求条目/参数/接口/表/外部标准），边（REFERS_TO/DEFINED_IN/VERIFIED_BY/DEPENDS_ON）。支持「某性能指标依赖哪些接口与参数」「哪些需求引用了GJB 438C第5.3条」等溯源查询，支撑 GJB 5000B 的需求可追溯性矩阵。
5. **理由**：GJB 显式引用占比高且格式规范，正则即可高覆盖；隐式引用少量用 LLM 兜底。图数据库天然适合多对多引用关系，且与需求追溯矩阵（RTM）要求一致。

## 技术选型建议：SRS → 参数化需求条目库（含引用关系图）Pipeline

```
┌─────────────────────────────────────────────────────────────────┐
│ 输入：军用SRS文档（已解析为结构化正文 + 表格）                    │
└──────────────────────────────┬──────────────────────────────────┘
                               ▼
┌─────────────────── 文本支路 ───────────────────┐  ┌──────── 表格支路 ────────┐
│ 1a. 预处理：章节切分、编号索引表建立            │  │ 2a. 表头识别：规则模板匹配 │
│ 1b. 规则参数抽取（正则：参数+op+数值+单位）     │  │     + TableLlama列类型推断│
│ 1c. NER微调：RoBERTa-wwm+CRF（军工语料续训）    │  │ 2b. schema映射→统一字段   │
│ 1d. UIE/DeepKE联合生成（参数化条目）            │  │ 2c. 术语归一化：同义词典   │
│ 1e. LLM长尾抽取+一致性校验（Qwen/DeepSeek）     │  │     + 向量相似度对齐表-文 │
└───────────────────────┬───────────────────────┘  └─────────────┬────────────┘
                        └──────────────┬───────────────────────────┘
                                       ▼
┌──────────────────── 条目融合与去重 ────────────────────────────┐
│ 3a. 文本条目与表格条目对齐合并（术语归一化后匹配）              │
│ 3b. 条目类型标注（性能/接口/功能/验收）                         │
│ 3c. 置信度排序，低置信条目人工复核（军工要求）                  │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
┌────────────────── 交叉引用解析 ──────────────────────────────┐
│ 4a. 正则解析显式引用（见3.2节/表4/GJB 438C第5.3条）           │
│ 4b. HanLP依存句法关联引用锚点↔被修饰实体                      │
│ 4c. LLM抽取隐式/语义引用 + 校验                               │
│ 4d. 指代消解（该参数/上述指标）                                │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
┌────────────────── 关系图构建与存储 ──────────────────────────┐
│ 5a. Neo4j 建模：节点(条目/参数/接口/表/外部标准)               │
│     边(REFERS_TO/DEFINED_IN/VERIFIED_BY/DEPENDS_ON)            │
│ 5b. 需求可追溯性矩阵(RTM)自动生成                             │
│ 5c. Cypher 多跳溯源查询接口                                   │
└───────────────────────────┬───────────────────────────────────┘
                            ▼
输出：参数化需求条目库（关系数据库/JSON）+ 引用关系图（Neo4j）+ RTM
```

### 选型要点
| 模块 | 主方案 | 兜底/增强 | 选型理由 |
|---|---|---|---|
| 参数抽取 | 规则 + RoBERTa-wwm+CRF微调 | UIE/DeepKE联合生成 + Qwen校验 | 军工要可审计+高召回 |
| 表格映射 | 规则模板 + TableLlama列推断 | 同义词典+向量归一化 | GJB表头稳定，开源模型可私有化 |
| 引用解析 | 正则 + HanLP依存 | Qwen隐式引用抽取 | 编号规范，正则高覆盖 |
| 关系存储 | Neo4j | — | 多对多引用天然适配，支持RTM |

### 军工场景特殊考量
1. **数据安全**：所有模型优先开源可私有化部署（Qwen/DeepSeek/TableLlama/RoBERTa），避免数据出域。
2. **可追溯性**：每条抽取保留来源段落/表格位置（span+页码），满足 GJB 5000B 配置管理与需求追溯要求。
3. **可审计性**：规则层输出带依据，模型层输出带置信度，低置信走人工复核——契合军工文档审查流程。
4. **标准化**：统一schema对齐 GJB 438C/GJB 2786A 文档结构，便于跨型号/跨项目复用。
