## 二、最关键的10篇论文（按相关度排序）

### ★★★★★ 直接对标

#### 1. Okamoto & Kusumoto (2025) — LLM for SRS Standards Conformance
- **任务**: 用LLM检查SRS是否符合标准格式要求
- **方法**: LLM (GPT-4) + 标准规则 → 合规性判断
- **与我们最相关**: 这是最接近我们任务的公开工作——用LLM检查SRS是否符合标准
- **局限**: 只检查格式合规，不检测内容矛盾

#### 2. ChartVE (ACL 2024) — Chart Visual Entailment
- **arXiv**: 2312.10160
- **任务**: 检测图表与文字描述之间的矛盾
- **方法**: 视觉蕴含(VE) — 给定图片和文字，判断是否entail/contradict/neutral
- **数据集**: CHOCOLATE (图表-标题对)
- **与我们最相关**: 直接可用于文本↔图片语义不一致检测
- **局限**: 主要针对数据图表，非架构图/流程图

#### 3. FloCA (2026) — Flowchart Consistency Checking
- **arXiv**: 2602.14035
- **任务**: 检测流程图与文字描述之间的不一致
- **方法**: 流程图解析 → 转移关系提取 → 与文字描述对比
- **与我们最相关**: SRS中大量使用流程图/状态图，FloCA方法可直接迁移
- **局限**: 仅针对流程图，不处理架构图/界面截图

#### 4. ReqV (Vuotto et al., 2018) — SMT for Requirements Consistency
- **arXiv**: 1804.10486
- **任务**: 用SMT求解器检查功能需求一致性
- **方法**: 需求条目 → 参数化 → Z3约束 → 可满足性检查
- **与我们最相关**: 直接对标我们的逻辑层检测（Z3方法）
- **局限**: 需要人工参数化，NL→形式化是瓶颈

#### 5. Chen (2025) — LLM + SMT for String Requirements
- **arXiv**: 2506.16639
- **任务**: LLM翻译自然语言需求为SMT约束 + 自动检查
- **方法**: LLM提取约束 → SMT编码 → Z3求解 → 矛盾检测
- **与我们最相关**: 解决了ReqV的NL→形式化瓶颈，可直接迁移到我们的逻辑层
- **局限**: 在简单字符串需求上验证，未在复杂SRS上测试

### ★★★★ 高度相关

#### 6. DMAP (WebConf 2026) — Document Figure-Text Correspondence
- **arXiv**: 2601.18203
- **任务**: 文档中图片与文字的对应关系建立
- **方法**: 文档结构分析 → 图文配对
- **与我们最相关**: 解决"如何定位设计图"的问题
- **局限**: Web文档为主，未在军工文档上测试

#### 7. FSARC — Requirements Conflict Detection
- **任务**: 需求文档中冲突检测
- **方法**: 规则+NLP混合
- **结果**: Recall~100%, Precision=84%
- **与我们最相关**: 语法层+语义层检测的基线方法
- **局限**: 规则需要人工定义

#### 8. Amaral et al. (IEEE TSE 2023) — NLP for Compliance Checking
- **任务**: 用NLP检查文档是否符合法规(GDPR)
- **方法**: NLP规则提取 → 合规性判断
- **与我们最相关**: 方法论模板——如何从标准中提取规则并自动化检查
- **局限**: GDPR法规，非军工标准

#### 9. SCR Toolset (Heitmeyer et al., 1995) — US Naval Requirements Tool
- **任务**: 美国海军软件需求一致性检查
- **方法**: 受控语言 → 形式化 → 一致性验证
- **与我们最相关**: 军工需求文档自动化检查的先驱系统
- **局限**: 1995年工作，方法较老

#### 10. TabFact (ICLR 2020) — Table Fact Verification
- **任务**: 验证关于表格数据的陈述是否正确
- **方法**: 表格编码 → 声明验证 → entail/contradict
- **与我们最相关**: 文本↔表格语义不一致检测的基础方法
- **局限**: 验证外部声明，非文档内部一致性

## 三、三层检测方法推荐

### 语法层：结构/格式检查
```
方法: 规则匹配 + 章节树对比
参考: FSARC (规则+NLP), Okamoto (LLM合规)
流程: SRS解析 → 章节树提取 → GJB结构规则匹配 → 缺失/格式错误报告
难度: ★★☆☆☆ (最成熟，已有实现)
```

### 语义层：文本↔表格/图片矛盾（核心）
```
文本↔表格:
  方法: 表格提取 → 实体链接 → 事实验证 (TabFact思路)
  参考: TabFact, TAPAS, HybridQA
  流程: 正则/LLM提取正文参数值 → 表格提取 → 参数配对 → NLI判断矛盾
  难度: ★★★☆☆

文本↔图片:
  方法: 图文配对 → 视觉蕴含 (ChartVE/FloCA思路)
  参考: ChartVE, FloCA, DMAP, LLaVA
  流程: 图片引用解析 → 图文配对(DMAP) → VLM判断矛盾(ChartVE/Kimi-K2.6)
  难度: ★★★★☆ (最复杂，novelty所在)
```

### 逻辑层：约束可满足性
```
方法: LLM提取约束 → SMT编码 → Z3求解 (Chen 2025思路)
参考: ReqV, Chen 2025, Event-B
流程: LLM从正文/表格提取约束 → 转换为Z3表达式 → 求解可满足性
难度: ★★★☆☆ (之前Z3全假阳性是因为参数提取差，LLM可解决)
```

## 四、关键研究空白（论文novelty点）

1. **GJB 438C无学术覆盖**: Google Scholar搜索"GJB 438"返回0条结果 → **这是我们论文的核心差异化**
2. **文档内文本↔表格矛盾检测**: 现有工作要么验证外部声明(TabFact)，要么做文本生成一致性(LogicNLG)，没有人做文档内部正文与表格的矛盾检测
3. **SRS专用图文一致性**: ChartVE针对数据图表，FloCA针对流程图，但SRS中的架构图/状态图/界面截图没有专门方法
4. **端到端SRS一致性流水线**: 没有论文整合语法+语义+逻辑三层检测到一个统一系统
5. **LLM+SMT在军工需求上的结合**: Chen(2025)在简单字符串需求上验证，未在复杂军工SRS上测试
