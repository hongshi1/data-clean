## 一、项目概述

### (一) 任务来源

本项目隶属于国防科技工业"人工智能+"专项能力提升工程数据治理有关技术方向，由北方自动控制技术研究所主承研，南开大学作为联合承研单位承担"武器装备科研生产数据一致性校验"研究任务。南开大学部分聚焦特征提取与上下文关联、数据一致性校验两个智能体的算法研究与工程实现。

### (二) 研究背景、目的及意义

#### 1 研究背景

当前，国防科技工业武器装备研制仍以传统文档驱动为主，SRS等设计文档中同一业务对象的信息分散于正文段落、表格行、用例图、流程图、追溯表等多个位置，形成多源异构、模态多样、语义粒度不一的复杂数据环境。具体而言：文本数据以自然语言表述需求条款，表格数据以行列结构承载参数约束，图像数据以流程图和用例图表达业务逻辑，时序数据以日志形式记录运行行为。这种异构性导致不同模态数据之间难以直接进行语义比较，同一对象在不同位置的表述往往存在不一致，且这些不一致关系在原始数据中是隐式存在的，缺乏统一的上下文结构进行显式表达。

#### 2 研究目的

本项目围绕数据质量管控业务需求，开展微调数据一致性校验研究，重点突破特征提取与上下文关联关键技术，解决武器装备科研生产面临的业务数据参差不齐等问题，形成跨模态一致性校验能力，能够有效支撑武器装备科研生产垂域模型应用的微调数据集一致性检验，并依托项目实施过程中积累的成熟技术体系与示范经验，积极向国防科技工业其他重点行业拓展推广。

#### 3 研究意义

（1）特征提取与上下文关联智能体是破解高质量微调数据集构建瓶颈的"攻坚利器"。同一需求ID的描述可能分散在3.2.1正文、用例表第5行、用例图第3节点、合格性表第12行等十余个位置，人工关联耗时且易遗漏。本智能体通过类型化候选链接体系（same_identity/explicit_reference/structural_membership/semantic_neighbor）实现自动化关联判定，系统性处理海量多模态数据，支撑"更好的数据训练出更好的模型"的飞轮效应。

（2）跨模态统一表征是语义级对齐校验的技术前提。文本的"响应时间不超过200ms"与表格中"≤200ms"、流程图中200的数值节点，需在统一语义空间中方能进行一致性比较。本智能体通过冻结编码器骨干加多头投影架构，实现异构数据在同一表示尺度下的语义比较与关联分析。

## 二、研究任务

### (一) 研究目标

本项目围绕数据质量管控业务需求，开展微调数据一致性校验研究，重点突破特征提取与上下文关联关键技术，解决武器装备科研生产面临的业务数据参差不齐等问题，形成跨模态一致性校验能力。

### (二) 研究内容

**1 面向武器装备科研生产数据的跨模态统一表征与上下文关联技术**

面向武器装备科研数据的多层级跨模态一致性校验技术研究，剔除冗余、修正偏差，保障数据语义与格式统一。

本研究内容从以下三个方面展开：

（1）**多模态特征提取与统一语义空间构建**主要针对文本、图像、时序数据在信息表达形式与语义粒度上存在显著差异的问题，从基于冻结编码器的多头语义投影（语义单元头/词面头/共享投影头/Procrustes正交映射头）、基于类型约束的结构化门控（same_doc/same_section/same_role/same_scope四维硬约束）、基于身份边界感知的关联损失（InfoNCE+margin ranking）三个方面开展研究，实现异构数据在统一语义空间下的高效编码、统一映射与语义比较。

（2）**跨模态多粒度语义关联与上下文关联构建**主要针对同一业务对象在不同模态、不同位置的描述存在隐式关联但缺乏统一表达的问题，从基于显式标识符共指的高置信锚点构建、基于类型化候选链接的多源数据关联判定、基于证据义务驱动的QualityContract结构化验证三个方面开展研究，实现从字段级、实体级到语义条目级的多粒度关联分析。

（3）**融合领域先验知识的结构化验证**主要针对关联结果的可信度保障问题，从基于GJB 438C标准的六路证据完备性检查（正文/用例表/流程图/能力表行/合格性行/追溯行）、基于误报全拯救的弃权机制（证据不足时不强行判定缺陷）、基于最小充分证据集的可审计输出三个方面开展研究，支撑垂域微调数据在业务逻辑上的自洽与可信。

### (二) 关键技术及解决途径

#### 1 面向武器装备科研生产数据的跨模态统一表征与上下文关联技术

##### 1.1 技术难点和解决思路

在装备科研生产场景中，数据一致性校验面临多源异构数据难以统一表达和上下文关系复杂等技术难题。文本、图像以及时序数据在信息表达形式与语义粒度上存在显著差异，这使得不同模态数据之间难以直接进行语义比较。此外，同一生产事件的数据之间存在时间与因果关联，但这些关联关系在原始数据中往往是隐式存在的，缺乏统一的上下文结构进行表达。

针对上述问题，本研究构建面向武器装备科研生产数据的跨模态统一表征与上下文关联技术。首先，通过多模态特征提取方法对文本、图像与时序数据进行语义编码：文本数据利用冻结语言模型（BGE-large-zh，1024维）提取需求条款的语义特征、参数约束与关键标识符信息；表格数据通过结构化解析器获取表头层级、行列语义与参数字段；图像数据通过Visio XML源解析获取图形拓扑、节点语义与边方向信息；时序数据通过时序建模方法提取运行参数变化模式与状态特征。随后构建共享语义投影层，将不同模态特征映射到统一语义空间（256维共享表征），使异构数据能够在同一表示尺度下进行语义比较与关联分析。在上下文关联建模方面，对同构数据采用类型化候选链接体系刻画数据之间的身份、引用与结构依赖关系；对跨模态数据，通过显式标识符共指锚点识别与结构化邻接匹配机制，将文本、表格与图形数据进行关联，构建统一的多模态证据图结构。在此基础上进一步引入GJB 438C领域先验知识，对关键需求ID、参数值与图表引用建立规则约束与语义关系映射，从而实现面向事实层面的自动化一致性检测。

##### 1.2 技术成熟度评价

依据GB/T 22900《科学技术研究项目评价通则》开展面向武器装备科研生产数据的跨模态统一表征与上下文关联技术成熟度评价。

**必要性与创新性方面**，跨模态数据的统一表达难题与上下文关联的缺失严重制约了武器装备科研生成数据一致性校验准确性，无法满足垂域大模型微调的需求，因此，亟需研究面向武器装备科研生产数据的高效表征和关联技术。本项目提出跨模态科研生产数据统一表征与上下文关联技术，其创新性体现在两个方面：一是构建冻结编码器骨干加多头语义投影的统一表征架构，实现文本、表格、图像数据的统一语义映射，其中身份边界感知损失使误合并率从1.93%降至1.22%，解决异构数据难以直接语义比较的行业痛点；二是采用类型化候选链接与证据义务驱动的QualityContract验证机制，将隐式的跨模态数据关联转化为显式的结构化条目，误报全拯救率达100%（75/75高风险误报全部转弃权，弃权率仅3.88%）。

**研究可行性方面**，在技术方面，目前冻结语言模型、结构化表格解析、Visio XML源解析等相关技术已趋于成熟，为跨模态特征提取、统一语义空间构建提供了坚实的技术支撑，且项目核心技术方案已明确，在16份真实GJB格式SRS上已完成全链路验证。在实施场景方面，武器装备科研生产领域存在大量文本、表格、图像、时序等多模态数据（本项目已处理结构化观测3771条、Claim五元组12517条、Visio图373张、结构化训练对27694对），可为技术的研发、测试与落地提供核心数据支持，可快速验证技术的有效性与适用性。此外，项目团队在跨模态特征提取、异构数据融合等方面具有扎实的研究基础，前期承担过多项国家级项目，具有丰富的研究和开发经验。

**预期成效与价值方面**，项目通过跨模态科研生产数据统一表征与上下文关联技术的研发与应用，预期可达成以下目标：（a）形成一套面向武器装备科研生产的跨模态数据统一表征与上下文关联技术方案，实现该领域多模态数据的高效编码、统一映射与关联挖掘，测试集AUC达0.9193（相对native基线提升4.2个百分点）；（b）该技术可用于武器装备科研生产数据一致性校验场景，支撑跨模态数据表征与关联，实现不一致数据自动识别，提升用于垂域微调的数据质量。

**研究基础与条件方面**，南开大学研究团队依托教育部数据与智能系统安全重点实验室等科研平台，在多模态数据分析、数据治理、异构数据融合等领域长期从事科学技术研究。在前期项目支持下，已积累跨模态医疗分析推理、面向跨模态大数据智能标注的机器学习理论与方法等研究基础，为本项目顺利实施提供技术和经验保障。

依据GJB 7688《装备技术成熟度等级划分及定义》和GJB 173《技术成熟度评价指南》，本项关键技术就绪水平为第4级，预期达到6级成熟度等级。

## 附：核心算法链路（技术内部参考）

```text
特征提取（编码器核心）
  GJB SRS原始文档(16份)
  → 解析联邦(MinerU+textutil+Visio XML+专家词典)
  → ParserObservation(3771条: text/table/image/diagram_node/diagram_edge)
  → Claim槽位填充(12517条: 45动词+23参数+10单位族, 谓词覆盖32.12%)
  → EntityCandidate(20133条: 系统/模块/功能/接口/参数/数据项)
  → 冻结编码器多头投影(BGE-large-zh 1024d → 共享空间 256d)
  → 质量信号(单位完整率4.5%/引用解析率76.4%/槽位填充率49.7%)

上下文关联（召回链路核心）
  用户查询(自然语言需求线索)
  → 场景路由(table→语义单元头 / image→词面头+语义单元头)
  → 多头并行召回(top-50)
  → 交叉精排(cross-encoder逐token)
  → EvidenceContext(冻结, 含source_ref/claim_refs/completeness)
  → CandidateLink(类型化: same_identity/explicit_reference/structural_membership/semantic_neighbor)
  → Item聚合(并查集, 408个silver items)
  → QualityContract验证(六路证据义务检查)
  → Finding(候选227/不足3505/确认)
```
