# 71 减法模块A/B实验结果：有无模块的NLI裁决对比

日期：2026-10-28 | 状态：实验完成 | 实现：`evidence_subtractor.py` + `eval_subtraction_nli.py`

---

## 一、做了什么

**模块实现**（`algorithms/consistency/evidence_subtractor.py`，纯确定性零模型，7个回归测试）：

```text
F1 scope:  证据须与问题/答案共享锚点(PZXQ式ID/英文词/中文4-gram, 大小写不敏感)
           → 删错误scope干扰证据; ID豁免: 标识符类检测项的含ID证据不删
F2 粒度:   表格HTML→"表头：值"配对的行语句(兼容<td><p>嵌套); 长文本→句切
           → NLI只吃句/行级单元(SumMaC粒度原则)
F3 形态:   无锚点命中的纯指针文本("见表X所示")→删
护栏:      F1删光→回退; 语句预算超限时按语句级锚点命中排序
```

**A/B实验**（`tools/eval_subtraction_nli.py`）：

```text
B0(无模块): NLI直接吃原始证据块文本(含表格HTML整块) — 现状基线
B3(有模块): 三级过滤+粒度归一 → NLI只吃句/行级语句
金标: violation_evalset_v1的17实例(全部期望refute, 35个gold证据引用)
裁决: premise=证据, hypothesis=答案; refute ⇔ max p_contra > τ
```

## 三、机制分解（哪些翻转、为什么）

### B3新增的5个refute（τ=0.5）——全部来自F2粒度归一

| 实例 | 检测项 | c0→c3 | 机制 |
|---|---|---|---|
| VIO-04 | TERM-07 | 0.061→**0.995** | 表格`<td><p>`嵌套整块直入NLI失效→行级"表头：值"后矛盾可见 |
| VIO-10 | GJB-05 | 0.213→0.948 | 干扰块删除+表格行化 |
| VIO-12 | GJB-05 | 0.068→0.590 | 同上 |
| VIO-14 | LOGIC-02 | 0.078→0.509 | 用例表行化 |
| VIO-16 | GJB-04 | 0.012→**0.696** | 整表→行级 |

**SumMaC预测的实锤**：文档/表格级直入NLI的失败模式，句/行级配对后恢复。

### B3保住的B0全部6个refute（无一掉点）

VIO-01/02/03/05/11/15——含上轮bug版丢掉的VIO-05(0.941)和VIO-15(0.735)。

### 仍未检出的6例（B3局限, 诚实记录）

VIO-06(0.456)/13(0.489)接近阈值；VIO-07/09(≈0.01)为NLI对长枚举/约束
比对的类型盲区；VIO-08/17为浅矛盾(NLI能力边界)。

## 四、过程中修掉的三个bug（回归测试已锚定）

1. **锚点大小写**: 英文词锚点小写化但证据文本大小写敏感→`blob`匹配不上
   `BLOB`（VIO-05的gold误删根因）
2. **单元格正则**: `(.*?)[</]`遇`<td><p>`截断为空→表格行化输出垃圾
   （VIO-04整表信息丢失根因）
3. **指针误杀**: 交叉引用型gold证据本身是指针文本("环境需求见表40")
   →改为仅删无锚点命中的指针
