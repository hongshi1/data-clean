# 场景一PPT规格

> 对标文件：`场景三+场景四.pptx`
> 目标：在完全复用其有限篇幅叙事、深色科技风和卡片/流程元素的前提下，讲清场景一的“数据难点—上下文关联—一致性校验—真实结果—研究价值”。
> 原则：不堆工程模块；每页只回答一个问题；所有数字与案例必须来自真实资产或明确标注为silver/候选。

## 1. 整体叙事

场景一的主线不是“我们实现了很多校验器”，而是：

> **GJB SRS中的同一个需求事实分散在正文、表格、图片、追溯表和合格性表中；单独看每一处都可能没有问题，真正的矛盾发生在跨位置聚合之后。因此先构建上下文条目，再按不一致性类型做分层校验，最后输出带证据定位的结论。**

建议使用11页：

```text
1 章节封面
2 数据特点与问题来源
3 证据特征提取
4 上下文关联与统一条目
5 一致性校验框架
6 技术路线
7 真实案例：ID双登记
8 真实案例：枚举/追溯/合格性
9 结果与成本
10 科研价值与边界
11 备份页：方法/基线/评测口径
```

主视觉采用场景三的深色科技研究风，不混用场景四的浅色项目风：深蓝灰背景、青/紫/橙/红语义色、统一章节导航、圆角卡片、细箭头、底部结论条。

## 2. 逐页规格

### 第1页：章节封面

**标题**：

```text
第一章
场景一：GJB军用SRS多模态一致性校验
```

**版式**：完全复用场景三第1页的全屏深色章节封面：左侧抽象证据网络，右侧章节标题，不放正文。

**讲述任务**：完成场景切换，不在封面讲数字。

### 第2页：数据特点与问题来源

**标题**：`场景一数据特点：同一需求事实分散在多个位置`

**版式**：复用场景三第2页：上部横向转换关系，下部四个挑战卡片。

**上部流程**：

```text
真实GJB SRS
  ↓
正文文字 | HTML表格 | 接口/功能图 | 追溯表/合格性表
  ↓
同一功能、接口或约束的分散登记
```

**四个卡片**：

1. 证据分散：同一功能出现在正文、能力表、用例表和图中。
2. 主体不明确：同一个ID或名称可能绑定不同功能/接口。
3. 约束跨位置：数值、单位、枚举、异常处置、追溯关系分散存在。
4. 缺席不等于矛盾：查不到只能是NIE，不能直接判refute。

**结论条**：

> 一致性校验的第一步不是直接调用模型，而是先确定哪些证据属于同一个检测对象。

### 第3页：证据特征提取

**标题**：`特征提取：把文档碎片转化为可比较的事实单元`

**版式**：复用场景三第3页四列流程卡片。

| 卡片 | 内容 |
|---|---|
| 多模态解析 | 正文/章节、HTML表格、接口/功能图片、追溯表/合格性表 |
| 结构化字段 | 主体、功能、接口、需求ID、表格行列、图节点边、页码和行定位 |
| 事实规范化 | ID归一、单位换算、枚举归一、E1模板、步骤、追溯映射 |
| 证据封装 | `(主体, 值, 位置)`、evidence_id、scope_id、completeness、span |

底部输出：

```text
事实单元 = 主体 + 值/约束 + 语义角色 + 原始位置
```

**素材**：图A、图D，或`paper/figures/fig1_cascade_architecture.png`中的输入侧局部。

### 第4页：上下文关联与统一条目

**标题**：`上下文关联：把分散登记聚合成同一个检测对象`

**版式**：复用场景三第4页“中心对象+周边证据”的图谱结构。

**中心对象**建议选“代码生成接口/需求”或“修改数据功能”。

周边节点：

- 正文描述；
- 能力表行；
- 用例表；
- 接口表；
- 接口图节点；
- 正向追溯表；
- 逆向追溯表；
- 合格性表。

右侧放聚合后的条目：

```text
Item:
主体: 代码生成
ID: PZXQ-...
功能/接口值: ...
追溯关系: 正向/逆向
合格性方法: ...
证据位置: block / row / span
```

**结论条**：

> 不先做上下文关联，后面的“矛盾”可能只是比较错对象。

**素材**：

- `docs/doc11/visio图/图A_特征提取与上下文关联智能体组成图.png`

不展示408个Item统计，不把候选聚合产物称为人工gold。

### 第5页：一致性校验框架

**标题**：`一致性校验：按不一致性类型分层处理`

**版式**：复用场景三第5页“输入—校验层—输出”。

**输入三栏**：

1. 冻结证据：正文/表格/图片/追溯/合格性；
2. Answer原子claim：术语/参数/逻辑/合规声明；
3. 40项检测体系：TERM×8、PARAM×10、LOGIC×11、GJB×11。

**三层校验**：

- L0 NER实体层：术语类，TERM-01/02/03/05/07/08；
- L1符号规则层：参数、逻辑、合规和结构术语，使用注册表、join、Z3、GJB规则库；
- L2 NLI语义层：规则无法形式化的语义残差，输出support/refute/NIE。

**统一输出**：

```text
三态判定 + 检测项ID + 证据定位 + 判定理由
```

结论条：

> 可解释的结构性矛盾先由规则处理，语义残差再交给NLI；不让一个黑盒模型承担所有类型判断。

**素材**：新版`paper/figures/fig0_research_framework.png`。

### 第6页：技术路线

**标题**：`技术路线：证据聚合、确定性校验与语义残差协同`

**版式**：参考场景三第6页“场景驱动问题+四段技术链”。

左侧场景驱动：

- 同一需求事实分散多处；
- 矛盾需要跨位置join；
- 规则可判与语义可判混合；
- 没有大规模人工gold。

右侧四段技术链：

1. 证据编译与上下文聚合；
2. L0/L1确定性校验；
3. EGT三态训练与L2残差；
4. 可选级联仲裁。

底部：

> 确定性通道负责可解释和低成本，NLI负责语义补足，LLM只负责高风险残差。

**素材**：`fig1_cascade_architecture.png`、`fig3_cost_quality_pareto.png`。

### 第8页：真实案例——枚举、追溯、合格性

**标题**：`不同类型的不一致，需要不同的比较运算`

横向三个案例卡片：

#### 枚举集合

```text

→ TERM-03 enum_join
```

#### 正逆追溯

```text

→ GJB-05 trace_join
```

```text

```

结论条：

> 一致性校验不是统一的字符串相似度问题，而是不同类型对应不同的证据比较运算。

### 第9页：结果与方法优势

**标题**：`结果：不仅判断答案，还说明为什么、错在哪里、由哪条规则发现`

三栏：

**主结果**：

```text

级联: refute F1=0.857 / refute P=1.000
held-out test: macro-F1=0.8286
```

**真实违例**：

```text

```

**成本**：


> 确定性规则提供可解释性与精确性，级联提供语义覆盖和成本控制；两者是分工关系。

## 5. 最终讲述规则

1. 一页只讲一个结论；
2. 每页最多一个主图；
3. 每页至少有一个真实证据或真实数字；
4. 不展示9个专家文件名，使用“确定性规则层”作为上位概念；
5. 不把silver数字称为人工gold；
6. 不把候选Item称为聚合准确率；
7. 不把L3 LLM画成核心算法层，它是可选工程仲裁旁路；
8. 上下文关联必须放在一致性校验之前；
9. 真实案例优先于抽象模块图；
10. 结果页同时展示能力和边界，不只展示F1。

## 6. 开场与收束台词

### 开场

> GJB SRS中的同一个需求事实，可能同时出现在正文、表格、图片、追溯表和合格性表里。单独看每一处都可能没有问题，真正的不一致发生在这些位置被放在一起之后。因此，场景一先做上下文关联，再做类型化一致性校验。

### 收束

> 场景一的技术价值不是把所有问题交给一个大模型，而是把不同类型的不一致分配给适合的检测层：术语交给实体层，参数、逻辑和合规交给确定性规则层，无法形式化的语义残差再交给NLI。最终输出不仅是“是否有问题”，还包括“哪类问题、哪条规则、哪处证据”。
