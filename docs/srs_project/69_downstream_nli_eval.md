# 69 端到端评测：打分层对下游NLI裁决的提点/掉点分析

日期：2026-10-28 | 状态：实验完成 | 前置：68号(打分器族)

---

## 一、评价指标的正确答案（回应方法学质疑）

68号评的是**中间指标**（打分器对人工标签的AUC）。但系统的价值不在打分器
本身，在它对**下游裁决**的影响。正确的指标栈：

```text
层级1(中间): 打分器质量      — AUC/P@k     [68号已做]
层级2(端到): 系统产出质量    — 下游NLI裁决的 P/R/F1 前后对比  [本文]
层级3(成本): 系统代价        — NLI调用量(60ms/对×次数)        [本文]
```

**端到端问题**：打分/筛选层介入前后，最终"报告为不一致"的查准查全
**提点还是掉点**？

48对人工标注（68号第四节）：正=真冲突+需澄清(7)，负=合理差异+抽取错误(41)

### 管线（8配置）

| 管线 | 结构 | NLI调用 |
|---|---|---:|
| **B0-report_all** | 全报不筛选 | 0 |

每个管线：阈值扫描取best-F1工作点 + 固定τ=0.5工作点。

## 四、四个发现

### 发现1：无筛选层的NLI会淹没在配置表假阳性里

B1在最优阈值τ=0.95仍有21个FP——不同设备的配置行("i7四核2.0GHz" vs
"16核1.5GHz")被NLI以>0.95的置信度判为矛盾。**NLI看不到行首的设备名
（作用域），把"两句不能同真"当成了"不一致"**——68号发现2的端到端代价
量化：查准率0.192。

### 发现2：0.02ms的规则门换掉一半NLI调用，精度0.192→1.000

P1规则门（strong+unknown=24对进NLI）自动排除24个弱候选——NLI假阳性
的主要来源。剩余的FP被高阈值τ=0.95清除（强候选中的配置行NLI置信度
~0.82<0.95）。

### 发现3：top-6排序=全量NLI的性能，1/8的成本

**P2-fusion_rank@6是最优配置**：廉价融合排序前6名，NLI在τ=0.1下
复检，5TP+0FP——与48次全量NLI的best-F1完全相同（0.833）。

```text
机制: top-6 = 5个正例 + 1个入侵者(强候选里的合理差异)
     NLI(τ=0.1)精准否决了那1个入侵者
     → 排序找候选, NLI做裁决, 各干各的活
```

### 发现4：召回天花板0.714是NLI的类型盲区, 不是筛选层的损失

漏报的2对（#06/#07 doc10分辨率）NLI得分仅0.05/0.08——**NLI是对的**：
"不低于1280"与"不低于1600、1280"是蕴含关系非矛盾。这2对是**覆盖差异型**
不一致（表83只列VGA口，表84加列DVI口），不是**值矛盾型**。

```text
→ 意外的类型学发现: 不一致分两型, 需要两种检测器
   值矛盾型: NLI可判(doc02响应时间3vs5, doc10主频2.2vs2.5) → 本轮已测
   覆盖差异型: 需表结构对齐+集合关系(表83列集⊂表84列集?) → 下一步工作
   B1基线的召回上限(5/7)就是NLI类型盲区的直接测量
```

## 九、诚实声明

1. 48对, 7正例——**ΔF1=+0.53的置信区间宽**，方向可信、幅度待扩标验证
2. best-F1工作点是**后验选择**（oracle阈值），工程部署需固定阈值的
   预验证（第五节的τ=0.5对比就是为此）
3. FN=2的"类型盲区"解释基于2个样本的个案分析
4. 抽取错误类(12对)作为负类参与——若剔除, B1精度会更差(P进一步降),
   结论方向不变
