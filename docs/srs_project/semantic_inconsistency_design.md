# 语义层不一致性检测技术设计 v1.0

> 日期: 2026-08-09
> 状态: 设计草案(待讨论)
> 数据基础: 16份GJB SRS中提取的167个真实矛盾

---

## 一、问题定义

**语义层不一致性**：同一实体（用需求ID标识）在文档不同位置（正文/章节标题/功能表/接口表/合格性表/追溯表）的属性值（名称/类型/发送方/接收方/优先级等）不一致。

**与语法层/逻辑层的区别**：
- 语法层：格式/编号/结构是否合规（不依赖语义理解）
- **语义层：同一概念在不同位置的值/含义是否一致（依赖跨位置语义比对）**
- 逻辑层：约束之间是否逻辑可满足（依赖形式化推理）

**核心挑战**：如何区分"合理差异"（简称/全称、不同视角描述）和"真实矛盾"（错字/截断/完全不同功能）。

---

## 二、真实矛盾的4种不一致模式

从38个名称不一致矛盾中提炼：

### 模式1: 截断不一致（11个, 29%）

同一实体名在不同位置被截断（子串关系）。

```
正确: "与通用智能应用交互接口"    (正文/合格性表)
错误: "与通用智能应用交互接"      (接口表, 尾部截断)
```

**特征**: 一个名称是另一个的子串。截断通常发生在表格单元格（MinerU解析或表格排版导致）。
**位置分布**: interface_table(6) > traceability_table(3) > section_title(2)

### 模式2: 错字不一致（4个, 11%）

同一实体名差1-2个字（形近/音近字错误）。

```
正确: "与数据统算交互接口"    (正文/接口表/合格性表)
错误: "与数据通算交互接口"    (追溯表, 统→通)

正确: "系统基础信息查询设置"   (功能表)
错误: "任务基础信息查询设置"   (章节标题, 系统→任务)
```

**特征**: 编辑距离≤2，通常是手误或复制粘贴后未完全修改。
**位置分布**: traceability_table(2) > section_title(1) > func_table(1)

### 模式3: 字序/空格不一致（2个, 5%）

字符顺序颠倒或空格位置不同（MinerU解析问题）。

```
正确: "对象化访问"           (正文)
错误: "象对 化访问"          (章节标题, 字序颠倒+多余空格)

正确: "数据UDP 不分段传输"    (功能表)
错误: "数据 UDP 不分段传输"   (章节标题, 空格位置不同)
```

**特征**: 字符集合相同但顺序不同，或空格分布不同。
**根因**: MinerU OCR/解析的字符分割问题。

### 模式4: 多名/完全不同（21个, 55%）

同一ID在不同位置写了完全不同的功能名（非截断/错字）。

```
正确: "界面配置保存"          (功能表)
错误: "语音交互"             (章节标题, 完全不同的功能)
       "资源占用监控"          (正文, 另一个完全不同的功能)

正确: "数据本地缓存"          (功能表)
错误: "主从服务互为备份"       (章节标题, 完全不同的功能)
       "主从服务自动发现"       (章节标题, 另一个功能)

正确: "连接池配置"            (功能表/合格性表)
错误: "连接池初始化"          (正文, 相似但不同的功能)
```

**特征**: 名称完全不同，无法用编辑距离/子串关系解释。
**根因**: 
- 复制粘贴后未修改标题（最常见，如"界面配置保存"的标题写成"语音交互"）
- 章节编号重排后标题未更新
- 功能拆分/合并后名称未同步

## 三、检测技术框架

```
输入: 聚合条目(同一ID在文档中所有位置的内容)
  │
  ├─ Step 1: 属性提取
  │   从每个位置提取: {名称, 类型, 发送方, 接收方, 优先级, 章节}
  │
  ├─ Step 2: 跨位置比对
  │   对每个属性, 比对所有位置的值
  │
  ├─ Step 3: 不一致性分类(4层检测)
  │   ├─ 层1: 字符级检测(截断/错字/字序)
  │   ├─ 层2: 语义级检测(多名/语义矛盾)
  │   ├─ 层3: 规则级检测(GJB格式/结构规则)
  │   └─ 层4: 上下文级检测(NLI/语义推理)
  │
  ├─ Step 4: 严重度评估
  │   区分"合理差异"vs"真实矛盾"
  │
  └─ 输出: 不一致性列表
      [{类型, 子类型, 位置A, 值A, 位置B, 值B, 描述, 严重度}]
```

## 四、4层检测技术详细设计

### 层1: 字符级检测（Character-level Detection）

**目标**: 检测截断、错字、字序颠倒

**技术**:

| 子类型 | 检测方法 | 判定条件 | 难点 |
|--------|---------|---------|------|
| 截断 | 子串关系检测 | name_a ⊂ name_b 或 name_b ⊂ name_a | 区分"合理简称"vs"截断错误" |
| 错字 | 编辑距离 | Levenshtein(name_a, name_b) ≤ 2 | 排除合理的同义词替换 |
| 字序 | 字符集合比对 | set(name_a) == set(name_b) but name_a ≠ name_b | 空格规范化预处理 |

**算法**:
```python
def detect_char_level(names_by_location):
    """names_by_location: {location: [name1, name2, ...]}"""
    issues = []
    all_pairs = generate_pairs(names_by_location)
    for (loc_a, name_a), (loc_b, name_b) in all_pairs:
        if name_a == name_b:
            continue  # 一致, 跳过
        # 截断
        if name_a in name_b or name_b in name_a:
            shorter = name_a if len(name_a) < len(name_b) else name_b
            longer = name_b if len(name_a) < len(name_b) else name_a
            issues.append({
                'type': 'truncation', 'subtype': 'substring',
                'correct': longer, 'wrong': shorter,
                'confidence': 0.7  # 截断可能是合理简称
            })
        # 错字
        elif levenshtein(name_a, name_b) <= 2:
            issues.append({
                'type': 'typo', 'subtype': f'edit_distance_{levenstein(name_a,name_b)}',
                'confidence': 0.9  # 差1-2字大概率是错字
            })
        # 字序
        elif set(name_a.replace(' ','')) == set(name_b.replace(' ','')):
            issues.append({
                'type': 'char_order', 'subtype': 'permutation',
                'confidence': 0.95  # 字序颠倒几乎一定是错误
            })
    return issues
```

**预期效果**: 检出17个（截断11+错字4+字序2），准确率高（字符差异明确）

### 层2: 语义级检测（Semantic-level Detection）

**目标**: 检测"多名"（完全不同的功能名配同一ID）

**技术**:

| 方法 | 原理 | 适用场景 | 局限 |
|------|------|---------|------|
| Embedding相似度 | Sentence-BERT编码名称, 余弦相似度<阈值→不一致 | 检测语义不相关的名称 | 阈值难定, 领域术语相似度低 |
| 语义角色匹配 | 提取名称的语义角色(动作+对象+修饰), 比对角色是否匹配 | "创建服务工程" vs "打开服务工程"(同动作不同对象) | 需要领域词典 |
| LLM判断 | 给LLM两个名称+ID, 问"是否描述同一功能" | 复杂语义判断 | 成本高, 需人工验证 |

**算法**:
```python
def detect_semantic_level(names_by_location, id_registry):
    issues = []
    all_pairs = generate_pairs(names_by_location)
    for (loc_a, name_a), (loc_b, name_b) in all_pairs:
        if name_a == name_b:
            continue
        # 先过层1(字符级), 已处理的跳过
        if is_char_level_issue(name_a, name_b):
            continue
        # Embedding相似度
        sim = cosine_similarity(encode(name_a), encode(name_b))
        if sim < 0.6:  # 阈值待调
            issues.append({
                'type': 'multi_name', 'subtype': 'semantic_mismatch',
                'name_a': name_a, 'name_b': name_b,
                'similarity': sim,
                'confidence': 0.8 if sim < 0.4 else 0.6
            })
        # 语义角色匹配(辅助)
        role_a = extract_semantic_role(name_a)  # {action: "创建", object: "服务工程"}
        role_b = extract_semantic_role(name_b)
        if role_a['object'] != role_b['object']:
            issues.append({
                'type': 'multi_name', 'subtype': 'different_object',
                'confidence': 0.85
            })
    return issues
```

**预期效果**: 检出21个"多名"，但需要解决"合理差异"判断问题

### 层3: 规则级检测（Rule-based Detection）

**目标**: 基于GJB 438C标准规则，验证名称格式/内容合规性

**规则示例**:

| 规则ID | 规则描述 | 检测方法 |
|--------|---------|---------|
| R-NAME-01 | 同一ID在功能表/合格性表/追溯表的名称应与正文一致 | 跨表名称比对(层1+层2) |
| R-NAME-02 | 功能名称不应含多余空格 | 正则: `\s{2,}`或首尾空格 |
| R-NAME-03 | 功能名称不应被截断(应以完整词结尾) | 子串检测+词库验证 |
| R-NAME-04 | 不同ID不应有相同名称(除非是父子关系) | 反向索引: name→[ids] |
| R-SEC-01 | 合格性表"本文档章节号"应存在于section_registry | 章节存在性检查 |
| R-TRACE-01 | 追溯表的上级章节号应存在 | 章节存在性检查 |
| R-TRACE-02 | 追溯关系应对称(A→B则应有B→A) | 图结构对称性检查 |

**与层1/层2的关系**: 规则级提供"应该一致"的约束, 层1/层2提供"如何检测不一致"的方法

---

### 层4: 上下文级检测（Contextual Detection）

**目标**: 检测名称之外的语义矛盾（功能描述矛盾、属性矛盾）

**技术**:

| 子类型 | 检测方法 | 数据需求 |
|--------|---------|---------|
| 接口属性矛盾 | 同一接口ID在接口表/正文/合格性表的{类型,发送方,接收方,优先级}比对 | 需提取接口全属性 |
| 功能描述矛盾 | NLI判断正文描述与表格标注是否矛盾 | 需正文+表格内容 |
| 合格性方法矛盾 | 规则: 性能需求应有D(测试)合格性方法, 若只有A(分析)则矛盾 | 需GJB 439A规则 |
| 图片-文字矛盾 | VLM判断图片内容与文字描述是否一致 | 需VLM能力 |

**当前数据缺口**: 接口属性提取不完整、正文描述未结构化

## 五、"合理差异"vs"真实矛盾"的判断框架

**核心问题**: 不是所有差异都是错误。如何区分？

### 5.1 合理差异的特征

| 合理差异类型 | 示例 | 判断依据 |
|-------------|------|---------|
| 简称/全称 | "数据存储" ↔ "数据存储功能" | 子串关系 + 差异在尾部功能词("功能"/"服务") |
| 不同视角 | 接口表中用接口名, 合格性表中用功能名 | 位置决定视角(接口表→接口名, 功能表→功能名) |
| 格式差异 | "名录 API 接口" ↔ "名录 API接口" | 仅空格差异 |

### 5.2 真实矛盾的特征

| 真实矛盾类型 | 示例 | 判断依据 |
|-------------|------|---------|
| 错字 | "统算" ↔ "通算" | 编辑距离=1 + 非同义词 |
| 截断(非功能词) | "与通用智能应用交互接口" ↔ "与通用智能应用交互接" | 子串关系 + 截断在非功能词位置 |
| 完全不同 | "界面配置保存" ↔ "语音交互" | 语义不相关 + 同一章节标题 |
| 复制粘贴错误 | "连接池配置" ↔ "连接池初始化" | 同领域但不同操作对象 |

### 5.3 判断决策树

```
两个名称是否相同?
├─ 是 → 一致, 无问题
└─ 否 → 字符级检测:
    ├─ 仅空格差异 → 合理差异(格式)
    ├─ 子串关系 → 
    │   ├─ 差异在功能词尾部(功能/服务/模块) → 合理差异(简称)
    │   └─ 差异在非功能词 → 真实矛盾(截断)
    ├─ 编辑距离≤2 →
    │   ├─ 形近字 → 真实矛盾(错字)
    │   └─ 同义词 → 合理差异(同义替换)
    ├─ 字符集合相同 → 真实矛盾(字序颠倒)
    └─ 完全不同 → 语义级检测:
        ├─ Embedding相似度>0.7 → 合理差异(同义描述)
        ├─ Embedding相似度0.4-0.7 → 需人工/LLM判断
        └─ Embedding相似度<0.4 → 真实矛盾(多名/复制粘贴错误)
```

## 七、研究方向与创新点

### 7.1 技术创新点

1. **ID锚定的跨位置比对**: 用需求ID作为确定性锚点(非LLM抽取), 把多模态文档理解转化为结构化的跨位置属性比对问题

2. **4层级联检测**: 字符级(高精度低覆盖) → 语义级(高覆盖低精度) → 规则级(领域知识) → 上下文级(深度理解), 逐层递进

3. **合理差异vs真实矛盾的决策框架**: 不是简单的"相同/不同"二分类, 而是区分4种合理差异和4种真实矛盾

### 7.2 与现有方法的区别

| 现有方法 | 局限 | 我们的方法 |
|---------|------|-----------|
| Requirement Smell检测 | 只检测模式(如"应该"/"必须"), 不检测跨位置一致性 | ID锚定跨位置比对 |
| NLI文本矛盾检测 | 只处理文本对, 不处理多模态/跨表格 | 多模态聚合条目比对 |
| GraphRAG | 图构建依赖LLM抽取(噪声) | 12种规则信号确定性产边 |
| LLM直接判断 | 不可靠(Korn 2026), 无法追溯 | 规则+字符+语义级联, 可追溯 |

### 7.3 开放研究问题

1. **"正确值"如何确定？** — 多数投票 vs 正文优先 vs GJB规则指定
2. **检测阈值如何设定？** — Embedding相似度阈值、编辑距离阈值
3. **方向A误差如何传播？** — 上下文关联漏召回导致检测漏报
4. **如何评测？** — Gold Standard规模够吗？需要人工标注多少？
