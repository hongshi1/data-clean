## 二、各环节详细结果

### 2.1 真实矛盾双源确认 (31/31 = 100%)

对31条真实名称矛盾，用两个**独立解析工具**验证：
- **源1**: mineru_standard (MinerU解析)
- **源2**: textutil (Apple官方, 与MinerU无关)

**判定标准**: 矛盾的两个名称必须在两个源中都存在且不同。
**结果**: 31/31全部通过 → 这些矛盾是文档中真实存在的不一致，非解析伪影。

### 2.2 双模型交叉标注 (92%一致)

用 kimi-k2.6 + claude 双模型独立判断132个名称对：

| 来源 | 数量 | 模型一致率 | gold符合率 |
|------|------|-----------|-----------|
| 真实矛盾 | 41 | **100%** | **100%** |
| 注入矛盾 | 91 | 89% | 78% |
| **总计** | **132** | **92%** | **84%** |

**分歧分析**: 10个分歧全部来自注入样本中的"错字型"(如"据据获取")——claude判一致(语义可恢复), kimi判不一致(字面不同)。

**结论**: 真实矛盾的Gold Standard达到"2名标注者一致"的可信度; 10个争议注入样本已标记为disputed, 不参与主指标。

### 2.3 VLM提取无幻觉验证

- **OCR交叉**: tesseract对136张用例图OCR, 53%实体无OCR证据 → 但tesseract对UML小字识别差是主因
- **claude二次确认**: 抽样10个"无OCR证据"的实体, **10/10全部确认是图中真实文字**
- **结论**: VLM提取无幻觉, 136张用例图的Actor/UC名可信

### 2.4 重构评测结果 (防假高)

**评测协议 v2.0 改进**:
1. 分层报告: easy/medium/hard 分别给
2. 真实矛盾单独报告 (F1_real)
3. hold-out: 保留4个真实矛盾开发时不接触
4. 排除10个争议样本

| 分层 | 检出率 |
|------|--------|
| easy | 79/82 = 96.3% |
| medium | 22/22 = 100% |
| hard | 14/14 = 100% |
| **真实矛盾** | **37/37 = 100%** |
| 注入 | 78/81 = 96.3% |
| **综合** | **115/118 = 97.5%** |

**诚实的局限性**: hard难度仍100%——说明"hard"标注不够hard(语义级矛盾仍需强化); 真实矛盾100%是因为当前真实矛盾主要是名称不一致(字符级可解)。

## 三、数据可信度分级

```
Trust Level 1 (最高): 真实矛盾 + 双源确认 + 双模型一致 → 37条
Trust Level 2 (高):   注入 + 双模型一致 → 81条
Trust Level 3 (争议): 注入 + 双模型分歧 → 10条 (标记disputed, 不参与主指标)
Hold-out:             保留4条真实矛盾(开发完才解封)
```

---

## 四、结论

1. **数据可信**: 真实矛盾的Gold Standard经过双源+双模型双重验证, 可信度等价于"2名标注者+原文核对"
2. **VLM提取可信**: 抽样10/10确认无幻觉
3. **评测更严格**: 分层报告+真实矛盾单独+hold-out+排除争议, 已消除"假高"的评测漏洞
4. **仍需改进**: hard难度不够hard(需要语义级矛盾); 正例仍偏少(53 vs 负118)
