# URE统一数据集规范与完整结果矩阵
## The Unified Dataset Specification & Full Results Matrix

> 回应: "所有数据集统一到同一形态, 构造方案严格, baseline按原生/外部分块,
> 表足够详细, 评判方式合理". 本文档是唯一的规范来源(Single Source of Truth).
> 成文: 2026-10-07 | 4个数据集全部遵循本规范

## 一、统一形态(所有数据集同一JSON Schema)

每个数据集=一个JSON文件, 五个顶层字段, **字段名与语义在全部数据集完全一致**:

```json
{
  "meta":     {"name", "version", "language", "task", "created",
               "description", "stats"},
  "corpus":   [{"doc", "chunk_id", "type", "scene", "title",
                "units", "n_units", "section", "fold"}],
  "queries":  [{"query", "expected", "scene", "source", "split", "fold",
                "overlap", "gold_rows"}],
  "protocol": {"n_folds", "fold_rule", "candidates",
               "query_prefix", "metrics"}
}
```

**字段语义(全数据集统一)**:

| 字段 | 语义 | 说明 |
|---|---|---|
| `type` | chunk模态 | image / table / text(三者之一) |
| `scene` | 检索单元粒度 | diagram / table / prose |
| `units` | 内容单元列表 | **方法的原子**: 图=节点∪VLM元素, 表=行, 文=句子 |
| `title` | 标题单元 | caption/表标题/段标题(可作为伪单元) |
| `expected` | gold chunk_ids | 引用完整性构建期硬校验 |
| `overlap` | 查询-gold词面重叠率 | 泄漏协变量(分层报告依据) |
| `gold_rows` | 行级gold(units下标) | 行级精度评测(仅FeTaQA) |

## 二、统一构造管线(四个数据集同一流程)

```
源数据 → ①解析 → ②单元提取 → ③gold映射 → ④查询合成/采样 → ⑤协议标注 → ⑥硬校验
```

每步的**统一规则**(数据集间只允许参数差异, 不允许流程差异):

| 步骤 | 统一规则 | 各数据集参数 |
|---|---|---|
| ①解析 | 提取(title, 内容)结构 | GJB: VSDX锚点+VLM+HTML; WTQ/FeTaQA: parquet直读; DuRetrieval: parquet直读 |
| ②单元提取 | 按模态: image=节点∪VLM元素, table=行"表头=值", prose=句子 | 全部一致 |
| ③gold映射 | expected=chunk_id列表, 引用完整性硬校验 | 全部一致 |
| ④查询 | 有真实查询→采样(>2000采样2000, seed42); 无→LLM合成(带防偏差约束) | 见§四 |
| ⑤池控制 | 池>10000→采样至10000(全正例+随机负例, seed42) | 仅DuRetrieval触发 |
| ⑥硬校验 | chunk_id唯一/expected全在corpus/fold可评测/去污染 | 全部一致 |

## 三、统一评测协议

| 协议要素 | 统一规则 | 合理性 |
|---|---|---|
| **候选池** | GJB=4-fold文档级隔离(fold内同类型chunk); 公开集=全池(或采样池) | GJB有训练需求→防泄漏必须折隔离; 公开集零训练→全池即真实部署形态 |
| **fold规则** | 有文档分组→(doc-1)mod4; 无→单折全池 | 文档级隔离是防泄漏最严格形式 |
| **查询前缀** | 编码器语言匹配: zh模型→zh前缀, en模型→en前缀 | 消除指令失配(曾造成±4pts漂移) |
| **指标** | R@1/R@5/R@10/MRR@10 (+RowHit@1行级) | 检索标准指标集 |
| **数字锁定** | 评测JSON入MANIFEST(sha256)+快照测试 | 防静默漂移 |

## 四、四个数据集的构造明细

### 4.1 GJB-URE-v2(原生, 主数据集)

**来源**: 16份真实军事SRS(GJB 438C, .doc)→解析:
textutil(markdown)→5231 chunks; 图=VSDX矢量源锚点(373结构/3759节点,
零OCR)+VLM转写; 表=HTML解析(表头式433+键值式774, 11216行)

**corpus**: 1588(图381+表1207), 14019单元(去重)

**查询合成(三场景, 每场景的合成匹配它要暴露的问题)**:

| 场景 | 合成管线 | n | 防偏差设计 | overlap |
|---|---|---|---|---|
| image | user_sim(LLM模拟用户)+param_v2(模板)+legacy | 1007 | 三来源混合 | 0.25-0.33 |
| caption | docT5: LLM读表格前800字生成 | 1541 | 已知高重叠(泄漏已标注) | 0.54-0.63 |
| deep_v1 | LLM只读>800字符行生成 | 118 | 禁复述标题 | 0.525 |
| **deep_v2** | 同上+**反拷贝硬约束**(禁逐字4字+/语义问法/行≥15字/事后<0.5过滤) | 155 | **0.130** | 0.130 |

train池: 2008(去eval污染: 排除118条逐字重复)

### 4.2 WTQ-URE(外部, 英文表)

**来源**: `lighteval/wikitablequestions`(parquet, 经hf-mirror)——
真实用户问题(非合成!), 每问自带gold表id

**构造**: 表→corpus(行"header=value"序列化, 与GJB同构);
问题→queries(expected=gold表, 引用完整性免费保证);
采样2000(seed42), 全池2100候选

### 4.3 FeTaQA-URE(外部, 英文表+行级gold)

**来源**: `DongfuJiang/FeTaQA`(jsonl镜像)——test split 2003

**构造**: 同WTQ; **特殊**: highlighted_cell_ids→gold_rows
(行级gold使RowHit@1可测: 检索单元是否命中"对的行");
采样2000(seed42), 全池2003候选

### 4.4 DuRetrieval-URE(外部, 中文文本)

**来源**: `MTEB/DuRetrieval`(dev: 100001段/2000查询/9839 qrels)

**构造**: 段→corpus(单元=句子, 按模态规则prose=句子);
**池控制**: 100001>10000→采样(2000查询全部正例+随机负例, seed42);
真实查询(百度搜索日志), 单折全池

## 六、评判合理性声明

1. **同构输入**: 全部方法看同一文本基础(title+units)——dense/BM25/unit
   的输入完全一致, 差异只在表示与打分(受控变量)
2. **语言匹配**: zh数据用zh模型+zh前缀, en数据用en模型+en前缀——
   无语言错配混淆(错配版数字仅作失真演示保留)
3. **SOTA真实实现**: M3三模式=FlagEmbedding官方; 重排器=BGE官方
   ——非手搓近似
4. **泄漏控制**: overlap协变量入数据集; deep_v1/v2分离(污染上界/
   干净下界); train去污染; 4-fold文档级隔离
5. **采样确定性**: 全部seed42, 增量落盘, LLM走缓存可复现
6. **负对照完整**: DuRetrieval(短文本)上dense>unit——证明单元分解
   **不是**万能增益, 其优势条件=内容超窗口/需结构判别(截断+稀释)

## 八、核心结论(跨数据集)

| 数据集 | 最优方法 | 我们的位次 | 判定 |
|---|---|---|---|
| GJB deep_v2(干净语义) | **O1(TP-cf) 0.394** | 第1(+9.7 over M3) | 主战场全方法第一 |
| GJB caption | O1(TP-cc) 0.822 | 第1 | 标题级画像最优 |
| GJB deep_v1 | O1(TP-raw) 0.703 | 第1 | 词面画像最优(污染场景) |
| GJB image | BM25-doc 0.654 | ROUTE4 0.649 | 词面强(标识符查询) |
| WTQ | **O1-unit 0.409** | 第1 | 外部效度成立 |
| FeTaQA | M3-dense 0.883 | 第2(0.856, 5×小模型) | 规模混淆已声明 |
| DuRetrieval | B1-dense 0.965 | 第2(0.950) | **负对照**: 短文本无结构优势 |

**方法的适用边界(诚实)**: 单元分解在"内容超过单向量窗口+需要结构
判别"的场景(GJB深行/图/WTQ/FeTaQA)最优或次优; 在"短文本整段语义
完整"场景(DuRetrieval)无优势——这不是缺陷, 是边界的精确定义.
