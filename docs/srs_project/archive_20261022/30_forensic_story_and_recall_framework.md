# 30 勘验叙事: 上下文关联的输入输出故事与证据召回框架

日期: 2026-10-14

## 一、勘验故事 (The Forensic Narrative)

**案件背景**: 16份GJB 438C格式SRS = 16个"案件现场"。每个"涉案事物"
(需求条目/接口/参数)的痕迹散落在多处: 正文段落(笔录)、接口表格深处
(检材样本, 1207表/2万+行)、系统组成图(现场照片, 379张)、追溯表(台账)。

**勘警任务** (方向A = 上下文关联, 为方向B一致性校验提供检测对象):

```
① 现场固证   解析文档 → 证据单元(物证袋): 表行("表头=值"=物证标签规范),
             图元素(照片标注), 正文片段(笔录)
② 线索检索   案情线索(查询) → 多头勘验 → 召回物证 → 交叉验证精排   [已建成]
③ 案卷聚合   同一涉案事物的物证归卷(条目聚合)                      [B2待建]
```

**输入/输出**:

| 阶段 | 输入 | 输出 |
|---|---|---|
| 证据库构建 | URE语料(1586 chunks, 18032证据单元) | `EvidenceStore`(物证库) |
| 证据检索 | 查询(自然语言问句) | 排序证据列表(表/图+命中单元+头来源) |
| 案卷聚合(待建) | 排序证据+共指边 | 聚合条目({文字,图,表行,章节,角色}) |

**勘验方法论三铁律** (负结果链的正面化表述):

1. **设备冻结** (frozen backbone): 勘验设备(BGE编码器)不可现场改装
   — 负结果#7/#8: 任何可训练adapter在~250对数据下必过拟合, 恒等映射
   即函数族最优点. 冻结不是妥协, 是该数据规模的定理.
2. **多头显影** (multi-head projection): 不同物证类型用不同显影技术
   — 实证: 图片场景词面头碾压语义头(0.685 vs 0.583), 表格深行场景
   语义单元头碾压词面头(0.365 vs 0.183). 单一评分函数必然顾此失彼.
3. **交叉验证** (interaction-side): 语体鸿沟(82.6%失败根因)不可用
   微调弥合, 用cross-encoder逐token交叉比对弥合(+12.1pt, p=6.7e-08).

## 二、方法架构: 多头冻结投影 + 召回 + 精排

```
                    查询(案情线索)
                         │
              ┌──────────┴──────────┐
              │   冻结骨干编码器      │  BGE-large-zh (零训练参数)
              │   (法证设备标准化)    │
              └──────────┬──────────┘
                         │ 共享冻结向量
      ┌──────────────────┼──────────────────┐
      ▼                  ▼                  ▼
 语义单元头           词面头             稠密头         ← 多头冻结投影
 sim×IDF+max池化      BM25               doc余弦        (每头=结构性投影,
 (表行/图元素通用)    (图片场景主导)     (对照)          无可训练参数)
      └──────────────────┼──────────────────┘
                         ▼
              场景路由多通道召回 (top-50)
              table→语义单元头 | image→词面头
                         ▼
              单元聚焦精排 (cross-encoder)
              doc=表内top-2单元 + 0.1×召回分融合
                         ▼
              排序证据 (owner+kind+score+头来源+命中单元)
```

**冻结投影头的形式定义** (论文符号):
- 头 = (单元提取算子π_k, 冻结投影φ_k, 评分函数s_k)
- 语义单元头: s(q,d) = max_{u∈π(d)} cos(φ_emb(q), φ_emb(u))·φ_idf(u)
- 其中φ_emb=冻结编码器, φ_idf(u)=log(1+N/df(u)) — 全部为统计量, 无梯度参数

## 三、模块落地: algorithms/evidence_recall/

| 文件 | 职责 | 勘验对应 |
|---|---|---|
| `evidence.py` | EvidenceUnit/EvidenceStore | 物证袋/物证库 |
| `heads.py` | SemanticUnitHead/LexicalHead/DenseHead + Encoder协议 | 多头显影技术 |
| `recall.py` | MultiHeadRecall(场景路由) | 多头并行勘查 |
| `rerank.py` | UnitFocusedRerank(两阶段) | 交叉验证 |
| `pipeline.py` | EvidenceRecallPipeline端到端 | 勘验流程总控 |

设计约束(全部满足AGENTS硬规则): 模块顶层零I/O; 编码器/精排器惰性注入
(测试可用确定性FakeEncoder); 无类型抑制; open带encoding.
