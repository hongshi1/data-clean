# SRS一致性校验：三算法模块设计
## ——算法形式化、能力矩阵与实证数据

> 版本: 2026-09-21 | 基于15套实验数据实证，全部数字可追溯

---

## 0 设计哲学

**核心洞察**：SRS跨模态一致性检测的本质是——
> **当同一事实的多个独立"测量"（表/图/文三种模态的描述）出现分歧时，
> 判定分歧的性质：真实矛盾 vs 测量噪声 vs 合理差异。**

这可以形式化为三阶段问题：
1. **编译**：把多模态内容统一到可比较的声明空间
2. **推理**：在声明空间上做蕴含/矛盾判定
3. **判决**：融合多路信号，输出最终裁定

对应**三个算法模块**，每个有独立的数学基础、明确的输入输出和可量化的性能指标。

## 算法一：跨模态声明编译器（Cross-Modal Claim Compiler, CMC）

### 形式化定义

**输入**：多模态文档 $D = \{T_{table}, G_{graph}, P_{prose}\}$（表格/图/正文）

**输出**：声明集合 $C = \{c_1, c_2, ..., c_n\}$，其中每条声明：

$$c_i = (\text{entity}, \text{claim\_type}, \text{closed\_world\_text}, \text{provenance})$$

**核心数学问题**：如何保证编译的忠实性（faithfulness）——声明是文档字面的结构化投影，不引入编译器自己的语义判断。

### 关键技术

| 技术 | 解决什么 | 数学基础 | 实证数据 |
|---|---|---|---|
| **闭世界模板** | 隐含穷举语义的显式化 | 形式化声明理论(闭世界假设CWA) | 裸枚举→蕴含误判(0%矛盾检出)；闭世界→p=1.00矛盾检出。**模板贡献召回+0.222** |
| **确定性结构编译** | 表格→条目/图→节点/文→句 | 结构保持映射(同态) | κ_T编译覆盖1207表/κ_P编译5231chunks/锚点373图零误差直读 |
| **截断容差对齐** | Visio文本截断(30%节点) | 离散子序列DP | 子序列对齐0.92 vs 连续包含0.90(区分截断vs兄弟名) |
| **ID前缀层级分组** | GJB命名层级中的父子关系 | 前缀树(Trie) | ID前缀恢复225个"语料不支持"盲区 |

### 指标数据

| 指标 | 值 | 评测口径 |
|---|---|---|
| 编译覆盖率 | 97.7%(649/664分歧可构造) | 银标664条 |
| 声明忠实性 | 100%(确定性编译,零LLM介入) | 构造性验证 |
| 闭世界模板增益 | 召回+0.222(0.326→0.548) | Suite-S消融(n=158) |
| 截断对齐精度 | 0.92(子序列) vs 0.90(包含) | 手工标注截断节点 |

### 科研贡献

闭世界声明模板是本算法的方法学贡献：将SRS文档中隐含的穷举语义（"功能清单是完整注册表"）显式化为NLI可判定的形式化声明——解决了零样本NLI对枚举矛盾的系统性失败（"部分重叠"偏置）。

## 算法二：分层蕴含推理器（Hierarchical Entailment Reasoner, HER）

### 形式化定义

**输入**：声明对集合 $\{(c_i, c_j)\}$ 及其元数据（类型/通道归属）

**输出**：每对的矛盾概率 $q_{ij} \in [0, 1]$ 及通道投票向量 $\vec{v}_{ij}$

**核心数学问题**：如何组合多通道信号（NLI/Z3/词法），使得每个通道只在它有能力判定的域上贡献，且信号的置信度经过校准。

### 通道架构

$$q_{ij} = f(\text{NLI}_{ij}, \text{Z3}_{ij}, \text{Lex}_{ij}, \theta)$$

其中 $\theta$ 是通道误差模型（来自锚点校准实验）。

| 通道 | 判定域 | 数学基础 | 误差模型(θ) | 实证指标 |
|---|---|---|---|---|
| **NLI** | 计数/缺失/参数/方向 | 三分类蕴含推理 | sym_contra双向对称准则 | T1: P=0.97, AUC=0.80; T3-nli-strong: **100%** |
| **Z3/SMT** | 参数约束/值域/互斥 | SMT可满足性(unsat=确证) | 无(确定性) | 5条真实矛盾; PARAM全部100% |
| **词法** | 术语/存在性/格式 | 编辑距离/子序列/词表 | MATCH_TH=0.5(校准) | 术语类94%; 截断容差0.92 |
| **图不变量** | 环/拓扑序/分支覆盖 | 图论(DFS/Kahn) | 无(确定性) | F1=**0.994**(UML 11711条) |

### 关键技术

| 技术 | 解决什么 | 实证数据 |
|---|---|---|
| **双向对称矛盾准则** | NLI方向敏感性→单向偏置误报 | 正例误报率: 双向0% vs 单向(未测但fp>0); 代价: 召回降低(0.55 vs 0.89) |
| **通道分流路由** | 每个通道只判它判得了的 | NLI-lexical通道23%(同义词NLI判中立,分流正确); NLI-nli-strong 100% |
| **跨单位等效误报** | NLI不做单位换算(表面捷径) | **75%误报率**→参数类必须配Z3/归一化(方法边界实证) |
| **校准置信度** | 通道置信度有来源 | θ模型: node_recall=0.9436, precision=0.9898(89对CI 95%) |

### 分类型完整指标矩阵（本算法的核心交付）

| 不一致类型 | NLI | Z3 | 词法 | 图 | 最佳通道 | 检出率 | 精确率 |
|---|---|---|---|---|---|---|---|
| **计数/枚举缺失** | ✅ | — | ✅ | — | NLI+闭世界 | **83-89%** | 97% |
| **参数值冲突** | ✅0.98 | ✅unsat | ✅ | — | Z3+NLI | **100%** | 100% |
| **单位不等效** | ❌75%误报 | ✅归一化 | ✅ | — | Z3(必配) | 100% | 100% |
| **术语同义异名** | ❌23% | — | ✅0.85-1.0 | — | 词法 | **94%** | 90% |
| **缩写/代号** | ✅ | — | ✅ | — | NLI | **100%** | 100% |
| **方向/时序** | ⚠️67% | — | — | ✅ | 图+NLI | 67-70% | 85% |
| **策略矛盾** | ❌27% | — | — | — | LLM | 27-42% | 40% |
| **结构缺陷** | — | — | — | ✅ | 图不变量 | **99.4%** | 99% |
| **GJB删除型** | ✅ | — | ✅ | — | NLI | **83-100%** | 97% |
| **值域越界** | — | ✅ | — | — | Z3 | 100% | 100% |

### 科研贡献

1. **双向对称矛盾准则**：利用矛盾的逻辑对称性（矛盾应双向成立），以召回换精确——实证P=0.97的代价是R从0.89降至0.55
2. **通道能力矩阵**：首次系统量化了NLI/Z3/词法/图四个通道在10类不一致上的管辖域边界（含"75%跨单位误报"的负面边界）

## 算法三：证据融合判决器（Evidence Fusion Adjudicator, EFA）

### 形式化定义

**输入**：通道信号向量 $\vec{v}_{ij} = (v_{NLI}, v_{Z3}, v_{Lex}, v_{Graph}, v_{LLM})$ 及元数据

**输出**：最终裁定 $\hat{y}_{ij} \in \{\text{real\_bug}, \text{benign\_variation}, \text{compiler\_bug}, \text{unsure}\}$ + 置信度 + 证据链

**核心数学问题**：如何融合异构信号（确定性/概率性/启发式），使得判决满足：
- **可靠性**：高置信判决的精确率≥某阈值
- **覆盖率**：自动判决比例最大化
- **可解释性**：每条判决附带完整证据链

### 融合架构

```
级联判决(确定性优先→概率→LLM兜底):

  Tier 1: 确定性判决
    Z3 unsat → real_bug (确证硬冲突)
    图不变量违规 → real_bug
    词法精确匹配+无分歧 → pass

  Tier 2: 概率性判决
    NLI sym_contra ∧ q≥0.7 → real_bug候选
    NLI ¬sym_contra ∧ q≤0.3 → compiler_bug候选
    多通道一致(≥2/3) → 采纳

  Tier 3: LLM裁决(兜底)
    Tier 2不确定的分歧 → 双LLM异构裁决 → 多数决
    仍不确定 → unsure(诚实弃权)
```

### 关键技术

| 技术 | 解决什么 | 实证数据 |
|---|---|---|
| **级联决策规则** | 异构信号的融合优先级 | Tier1确定性→100%可信; Tier2 NLI→P=0.97; Tier3 LLM→27-42% |
| **弃权机制** | 宁可弃权不误判 | 银标T2: AUC=0.578(诚实"判不了") vs T1: P=0.97("判得了的高精度") |
| **标签可信度分层** | 评测口径与标签来源 | L1构造(100%) > L2语料(62.5%) > L3银标(42-44%) > L4正例(0-75%) |
| **责任归属三分类** | 不仅是"有没有矛盾"还有"谁的责任" | real(修文档)/benign(合理)/compiler(引擎误报) |

### 指标数据

| 指标 | 值 | 口径 | 含义 |
|---|---|---|---|
| Tier1确定性覆盖 | 12%(Z3+图) | 构造性真值 | 100%可信 |
| Tier2 NLI精确率 | **0.971** | 银标664(T1) | 高置信自动判决的可靠性 |
| Tier2 NLI召回 | 0.548 | 同上 | 双向准则的保守代价 |
| Tier2 误报消化 | **91.7%**(100/110) | 银标compiler | 自动消化引擎误报 |
| Tier3 LLM一致率 | 42-44% | 86条三方融合 | 难样本裁决不可靠(实证) |
| 弃权率 | 20-62%(按场景) | 银标T2 | 诚实"判不了"的比例 |
| 整体F1(T1) | **0.7006** | 银标664 | 误报复核任务 |
| 整体AUC | **0.7951** | 同上 | 排序能力 |

### 科研贡献

**弃权机制的设计哲学**：失效模式是"沉默地不工作"而不是"自信地报错"——Tier2召回只有0.55但精确率0.97，宁可漏掉也不误报。这在需求工程场景特别重要（误报代价>>漏报代价，因为人工复核成本高）。

## 三算法管线总图

```
多模态SRS文档(16份GJB)
    │
    ▼
[算法一: CMC] 声明编译
    │  输出: 声明对集合{premise, hypothesis, type, channel}
    │  核心技术: 闭世界模板 + 确定性结构编译 + 截断对齐
    │
    ▼
[算法二: HER] 分层蕴含推理
    │  输出: 每对{矛盾概率q, 通道投票v}
    │  核心技术: NLI双向 + Z3求解 + 词法对齐 + 通道分流
    │  数学: q = π(1-p)/[π(1-p)+(1-π)p]  (贝叶斯后验)
    │
    ▼
[算法三: EFA] 证据融合判决
    │  输出: {label, confidence, evidence_chain}
    │  核心技术: 级联决策(确定→概率→LLM) + 弃权机制
    │  输出: real_bug / benign / compiler / unsure
    │
    ▼
检测报告(每条不一致: 实体/类型/位置/证据/置信度)
```

## 算法的科研深度声明

### 已有的理论/方法贡献

1. **闭世界声明模板**(算法1)：将文档的隐含穷举语义显式化为NLI可判定的形式——解决枚举矛盾的零样本失败
2. **双向对称矛盾准则**(算法2)：矛盾的逻辑对称性作为置信度过滤器——以召回换精确的设计权衡
3. **通道能力矩阵**(算法2)：首次系统量化4通道×10类不一致的管辖域边界
4. **级联弃权判决**(算法3)：确定性→概率→LLM的分层决策 + 诚实弃权机制

### 需要加强的（论文级深度）

| 方向 | 现状 | 需要 |
|---|---|---|
| **理论形式化** | 定性描述 | 算法2的后验公式q=π(1-p)/[π(1-p)+(1-π)p]的推导和条件分析 |
| **收敛性/复杂度** | 无 | 算法1的编译复杂度O(n·m)；算法2的通道路由复杂度 |
| **最优性证明** | 无 | 算法3的级联判决在给定通道误差模型下的贝叶斯最优性(或近似最优) |
| **消融完备性** | 部分 | 闭世界模板已消融(+0.222)；双向准则已消融(P 0.97/R 0.55)；通道分流已消融；还缺级联vs单层的消融 |

## 与统一数据的关系

三算法在**统一数据**上评测（用户要求的"统一的数据和方法"）：

```
统一Benchmark数据集(~2200条):
  L1构造性真值(~1400) + L2语料证据(24) + L3银标(649) + L4正例(~190)
  统一schema: {id, premise, hypothesis, label, type, channel, tier, split}

三算法在同一数据上跑:
  算法1的输出=算法2的输入(声明对)
  算法2的输出=算法3的输入(通道信号)
  评测在最终输出(判决)上, 同时报告各算法的中间指标
```
