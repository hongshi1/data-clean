# 40项变异算子完整方案：数据构建→训练→测试

> **状态：历史变异计划（2026-10-20）。** 40项/48类是旧类型本体，不代表当前answer-evidence任务已覆盖。任何算子复用前必须确认它实际修改/构造了待验证answer或SRS evidence，并由独立规则证明gold；不得直接复用旧pair标签。

> 目标: 修复全部数据缺口, 构建48种类型×多文档的统一数据集, 支撑QLoRA微调的严格评测

---

## 一、当前缺口(4个)

| 缺口 | 现状 | 影响 |
|---|---|---|
| 1. 文档偏斜 | mmqa变异100%来自文档2的81对high锚定pair | 训练/测试无法做文档级分割 |
| 2. 类型缺失 | UC_NAME_MISMATCH(1种)完全无数据 | 40种可用类型中1种空缺 |
| 3. 正例不足 | 测试集0条正例(文档3+4无L4正例) | F1虚高(全判负也能100%) |
| 4. 银标噪声 | 测试集64%标签来自银标(42-44%可信) | 评测数字不可信 |

## 二、总体架构

```
237对low锚定pair(文档1/3/4/5/7)
    ↓ 重对齐(VLM桥, 复用m25管线)
~180对升级为high锚定
    ↓ × 48种变异算子
~8000条构造真值(L1, 标签100%可信)
    + 664银标(L3) + 正例三族(L4)
    ↓ 统一Benchmark v2(~9000条)
    ↓ 文档级分割(训练:文档2+5, 测试:文档1+3+4+7)
    ↓ QLoRA微调 → 严格评测
```

## 三、48种变异算子设计(每个算子: 操作+声明模板+评测QA)

### 层1: 术语层8种

| 算子 | 变异操作 | 声明模板 | QA对设计 |
|---|---|---|---|
| **TERM-01** 同义异名 | 位置A"获取"→位置B"采集" | P:`文档A规定功能「数据获取」` H:`文档B规定功能「数据采集」` | Q:两个功能名是否一致? A:不一致(同义异名) |
| **TERM-02** 同名异义 | 同名"安全模式"在A定义=防护, B定义=保密 | P:`文档A中「安全模式」指安全防护模式` H:`文档B中「安全模式」指安全保密模式` | Q:「安全模式」在不同位置的含义? A:含义不同(同名异义) |
| **TERM-03** 枚举集合 | 正文{A,B,C} vs 图{A,B} | P:`正文规定共3项:{A,B,C}, 除此之外没有其他` H:`图中显示共2个:{A,B}, 除此之外没有其他` | Q:正文和图的功能清单是否完备? A:不一致(图缺C) |
| **TERM-04** 告警术语 | A"通信异常告警" vs B"链路故障标志" | P:`接口A中状态名为「通信异常告警」` H:`接口B中状态名为「链路故障标志」` | Q:同一状态的命名是否统一? A:不统一(术语漂移) |
| **TERM-05** 指令名 | A"数据获取指令" vs B"数据采集指令" | P:`接口A的指令名为「数据获取指令」` H:`接口B的指令名为「数据采集指令」` | Q:同一指令的命名? A:不一致(同义异名) |
| **TERM-06** 量纲单位 | A"0.2秒" vs B"200ms"(等效)或"20ms"(冲突) | P:`文档A规定响应时间不超过0.2秒` H:`文档B规定响应时间不超过200ms` | Q:两处时间约束是否一致? A:一致(等效)或:不一致(冲突) |
| **TERM-07** 接口命名 | A"数据传输接口" vs B"数据传送接口" | P:`表A中接口名为「数据传输接口」` H:`表B中接口名为「数据传送接口」` | Q:同一接口的命名? A:不一致(同义异名) |
| **TERM-08** 缩写代号 | A全称"结构化数据归集" vs B缩写"SDG" | P:`文档A使用「结构化数据归集」` H:`文档B使用「SDG」` | Q:两处是否指同一功能? A:是但命名形式不同(缩写未定义) |

### 层3: 逻辑层11种

| 算子 | 变异操作 | 声明模板 | QA对设计 |
|---|---|---|---|
| **LOGIC-01** 优先级 | 正文"应急最高" vs 图"自动→应急" | P:`正文规定应急模式优先级最高` H:`图中显示自动模式可抢占应急模式` | Q:优先级描述是否矛盾? A:矛盾 |
| **LOGIC-02** 异常策略 | A"异常时切换备用" vs B"异常时重试" | P:`文档A规定异常时切换备用通道` H:`文档B规定异常时重试3次` | Q:异常处理策略是否一致? A:不一致 |
| **LOGIC-03** 事件时序 | 正文[A,B,C] vs 图[B,A,C] | P:`正文规定步骤顺序为A→B→C` H:`图中显示步骤顺序为B→A→C` | Q:步骤顺序是否一致? A:不一致 |
| **LOGIC-04** 数据流方向 | 图"单向输入" vs 文"有反向输出" | P:`图中数据流为单向输入` H:`正文描述存在反向输出` | Q:数据流方向是否矛盾? A:矛盾 |
| **LOGIC-05** 分支完备性 | 正文{正常,降级,故障} vs 图{正常,降级} | P:`正文规定3种工况{正常,降级,故障}, 除此之外没有其他` H:`图中显示2种分支{正常,降级}, 除此之外没有其他` | Q:工况分支是否完备? A:不完备(缺故障分支) |
| **LOGIC-08** 冗余仲裁 | A"主备仲裁" vs B"负载均衡" | P:`文档A规定冗余仲裁策略为主备` H:`文档B规定冗余仲裁策略为负载均衡` | Q:仲裁策略是否一致? A:不一致 |
| **LOGIC-09** 权限控制 | 文"需管理员权限" vs 图"普通用户可进入" | P:`正文规定需管理员权限` H:`图中显示普通用户可进入` | Q:权限要求是否矛盾? A:矛盾 |
| **LOGIC-10** 故障恢复 | A"自动恢复" vs B"手动恢复" | P:`文档A规定故障自动恢复` H:`文档B规定故障手动恢复` | Q:恢复策略是否一致? A:不一致 |
| **LOGIC-11** 追踪重搜 | A"全量重搜" vs B"增量重搜" | P:`文档A规定全量重搜` H:`文档B规定增量重搜` | Q:重搜策略是否一致? A:不一致 |

(LOGIC-06/07语料不支持)

## 五、数据分割(文档级, 零泄漏)

```
训练: 文档2(81对high + 7对medium) + 文档5(重对齐后)
     → ~2000条(40种×~50条/种)

测试: 文档1(重对齐后~80对) + 文档3(重对齐后~20对)
     + 文档4(重对齐后~30对) + 文档7(重对齐后~5对)
     → ~1500条

验证: 文档1的10%(~150条)

零重叠保证: 训练文档{2,5} ∩ 测试文档{1,3,4,7} = ∅
```
