## 六、方案合理性论证

### 为什么全LLM生成比规则生成更可信?

| 维度 | 规则生成(旧) | 全LLM生成(新) |
|------|-------------|--------------|
| 问题自然度 | 模板化("表{table}中功能「X」...") | 自然口语("请核对图中用例名称...") |
| 答案多样性 | 固定模板("不一致。图中为X，若表为Y...") | LLM自由生成(每次不同表述) |
| 注入合理性 | 规则化替换(错字/截断) | LLM根据文档内容构造合理不一致 |
| 子类型多样性 | 固定5种子类型 | LLM自由生成(功能名不一致/参数缺失/流程矛盾...) |
| 适配性 | 需手动为新场景写规则 | LLM自适应任何文档内容 |

### 为什么86%正确率够用?

1. **保留了通过验证的185条** — 保留的100%正确
2. **错误的30条已被过滤** — 不会进入最终数据集
3. **86%生成正确率** — 高于FlowVQA的GPT-4 few-shot(68%)
4. **四类均>82%** — 无明显短板
