## 〇、术语表(本项目创建的名词与解释)

写论文时这些名词第一次出现都需要定义。按"创建动机→精确定义→与已有概念的区别"三段式给出。

### 0.1 检索/特征方法类

**VA-ColPali**(Vector-Anchor ColPali, 向量锚点式ColPali)
- **动机**: GMC基线实验发现文本序列化丢失图的方向信息("A→B"与"B→A"的BGE余弦差异仅0.003, 人工变异检测率3%), 证明"整图序列化成一条文本"不是图的合格特征表示。
- **定义**: 把一张图(Visio锚点结构)表示为**节点向量集合**——每个文本节点单独经BGE编码成1024维向量, 图标题(caption)作为**伪节点**追加进集合; 检索打分用**top-k均值聚合的MaxSim**: `score(q, 图) = mean(top3_i sims(节点_i, q))`。
- **与ColPali的区别**: 原版ColPali的"多向量"是视觉token级(几百个patch向量), 我们的是**语义单元级**(节点/行, 每图5~50个), 粒度由文档的天然结构决定, 且不训练任何新模型(零训练)。"Vector-Anchor"强调向量来自VSDX矢量源解析的锚点(见0.3), 不是从像素再识别。
- **实现**: `algorithms/va_colpali.py`。

**Table-Pali**(TP, 表格行级后期交互)
- **动机**: dense单向量通道对表格chunk取`text[:512]`, 而1207张表里**84%(1014张)超过512字符**——后段行内容对单向量检索完全不可见。
- **定义**: 把一张表表示为**行向量集合**: 每行序列化为"表头1=值1 表头2=值2…"(键值式用例表则直接join原文), 表标题作首行(伪行); 打分 = `max(caption相似度, top-3行均值MaxSim)`。
- **与VA-ColPali的区别**: 单元粒度(节点vs行)、聚合函数(纯top-3 vs max(caption, top-3))——差异由模态特性决定: 表的caption判别力极强需要显式gate, 图的节点与caption地位对等。
- **实现**: `algorithms/table_late.py`。

**ROUTE**(路由式组合, 无参数)
- **定义**: `ROUTE = max(zscore(dense单向量分数, 行级分数))`——两通道各自在候选集上做z-score标准化后**逐候选取最大值**。
- **与加权融合的区别**: 不是平均(平均会稀释——强通道被弱通道拉低), 而是**让每个查询自动路由到它命中证据更强的通道**: caption级查询在dense上z-score高→路由到dense; 深行内容查询在行级上z-score高→路由到行级。零参数、免训练。
- **结论数字**: 见§3.2。

**Text-Bridge / B1(文本桥接基线)**
- **定义**: 图/表→文本→单条BGE向量的传统做法。图侧文本=VLM转写(caption+key_elements+summary), 表侧=表格HTML文本前512字符。是本项目所有新方法的对照基线。

**CMSC**(Cross-Modal Structural Correspondence, 跨模态结构对应预训练)
- **动机**: GJB 438C标准的四位置共现——同一实体在正文、接口表、图、追溯表中各出现一次, 天然构成跨模态正对(3724对/1544实体)。
- **定义**: 双塔投影头预训练(1024→256), 目标是拉近"指同一实体的不同模态片段"的表示。
- **结果(负结果)**: 预训练自身评测R@5 0.177→0.560(+216%)有效, 但**替换BGE做下游检索反而降低**(R@5 0.861→0.834)。原因: 训练信号是"短片段实体对齐", 下游任务是"自然语言→图检索", 分布不匹配; 256维压缩还丢了BGE原空间的检索信息。
- **教训**: 预训练目标必须与下游任务的查询分布对齐, "自身评测有效"不构成下游增益的证据。

**GMC**(Graph Mutation Contrastive, 图变异对比)
- **定义**: 对373张锚点图施加确定性变异(节点删除/边反转/标签交换)构造对比对, 训练/评测编码器区分原图与变异图。
- **结果(负结果, 但有信息量)**: 原始BGE对变异的区分能力——节点删除73%可检测、标签交换30%、**边反转仅3%**。证明文本序列化在原理上无法编码方向, 是VA-ColPali立项的直接依据。

**SQR**(Structured Query Router, 结构化查询路由)
- **定义**: 从查询中抽取确定性信号(图号"图3"、表号、章节号、实体名), 直接查索引跳过向量检索。覆盖率16%(160/1007), 命中时R@1≈1。

### 0.2 现象/机制类

**稀释效应**(dilution effect)
- **定义**: 单向量表示随内容单元数增加而判别力下降——整图/整表编码成一个向量时, 每个具体节点/行的信号被平均摊薄。
- **证据**: 大结构(≥10节点)上VA对B1的优势(R@5 +8.2pts)远大于整体(+3.6pts), 小结构上两者持平。

**截断盲区**(truncation blind spot)
- **定义**: 单向量通道的`text[:512]`截断使超长内容后半部分对检索完全不可见。
- **证据**: 深行查询上dense R@5崩塌至0.297(而caption级0.942)——同一系统同一通道, 因查询引用的内容位置不同而性能差3倍。
- **注意**: 常规评测**测不出**该盲区(docT5query从前800字生成查询, 引用的内容本就在可见窗口内), 必须专门构造深行查询。

**深行查询**(deep-row query)
- **定义**: 只引用表格>800字符位置行内容的检索查询(由LLM从深行内容构造, 缓存于`data_assets/deep_row_queries.json`, 118条)。用于暴露截断盲区。
- **与docT5query的区别**: docT5query是"看前800字生成问题"(测常规能力), 深行查询是"看后段行生成问题"(测内容可见性)。

**伪节点/伪行**(pseudo-node / pseudo-row)
- **定义**: 把图标题(caption)追加进节点向量集合/行向量集合首位的做法。
- **必要性(消融证据)**: VA无caption时R@5=0.731, 有caption 0.812; 大量查询以"图6 文电收发用例图"这类标题为线索。

**对齐分数**(alignment score)
- **定义**: 图chunk→锚点结构的映射置信度 = VLM转写文本与结构节点文本的覆盖率(节点命中数/节点总数)。362/381图以阈值0.25锚定, 均值0.826。
- **用途**: VA-ColPali的索引质量保证; 也是m25系列工具的跨通道实体对齐技术。

**指令前缀协议**(query instruction prefix)
- **定义**: BGE检索要求查询侧加前缀`为这个句子生成表示以用于检索相关文章：`(文档侧不加), 与hybrid_recall/build_train_triples一致。
- **教训**: 一次评测忘了前缀, 基线R@1从0.515掉到0.478——**协议细节即数字**, 这也是为什么所有评测工具必须共用常量。

### 0.3 数据/系统类

**锚点**(anchor, VSDX矢量源锚定)
- **定义**: 从.doc内嵌Visio(oleObjectN.bin)直接解析出的结构化图(节点文本/类型/坐标/边), 共373图/3759节点/2680边。因为来自**矢量源**而非像素, 节点文本零OCR误差——这是本项目相对"截图+VLM识别"路线的根本优势。

**evalset_v3**: 1007条查询×4-fold×16文档的主评测集(user_sim/param_v2/legacy三类来源, 全部指向image chunk, 不可解条目已剔除)。

**docT5query假想查询**: 对每个chunk由LLM生成"如果用户想找到这段内容会怎么问"(2797条, 生成时文本截断800字符)。

**MFE/SAA/CR**: 三模块架构——多模态特征提取→自注意力关联→上下文重建(`algorithms/context_pipeline.py`)。

**后期交互**(late interaction): 检索范式术语——文档侧保留多个向量、查询与每个向量单独打分再聚合(MaxSim族), 区别于单向量(single-vector)点积。

## 一、特征提取技术系列(现状全景)

### 1.1 演化脉络与每一步的动因

```
单向量BGE dense (text[:512])
   │                          ┌── 负结果: CMSC预训练(下游-2.7pts)
   ├─(预训练增强, 失败)────────┤
   │                          └── 负结果: GMC(文本序列化丢方向, 边反转检测3%)
   │
   ├─(图模态)──→ VLM转写桥(B1) ──→ VA-ColPali节点级多向量 ✓ (+5.2 R@1)
   │                                    └─ 大结构+8.2 R@5(稀释效应)
   │
   └─(表模态)──→ dense截断512 ──→ Table-Pali行级多向量 ✓ (深行+57.7 R@5)
                                        └─ caption级-3.0 R@5(不如dense)
                                            └─ ROUTE路由 ✓ (两头通吃)
```

**设计的共同原则**(这是论文的methodology主线):
1. **结构即单元**: 不把文档内容打平成文本流, 而是按文档的天然结构单元(图节点/表格行)分别向量化和打分——"特征提取"提取的是**结构保留的表示**。
2. **零训练**: 所有增益不训练新模型, 只重组既有BGE向量的使用方式——小数据(16文档)下这是可行域, 也让结果完全可复现。
3. **负结果定义设计**: GMC的3%检测率和CMSC的下游回退不是失败, 而是划定了"文本序列化"与"短片段预训练"的适用边界, 直接导出了正确设计。

### 1.2 各方法技术细节

**VA-ColPali(图)**
- 索引: 362图(锚定率95%), 每图向量集=节点文字BGE(去重1682条)+caption BGE。
- 打分: top-3均值聚合。k=3是扫描出来的(k=1纯MaxSim次优; "富化节点文本"(节点+邻居边上下文)反而更差0.685——边上下文引入噪声)。
- 查询侧: 指令前缀+截断200字符。
- 与B1的融合(z-score加权)反而稀释(0.774<0.812), 弃用——强通道不需要弱通道陪跑。

**Table-Pali(表)**
- 解析: 健壮HTML解析器, 1207/1207全成功。两种表型: 表头式433张(行文本"表头=值"配对)+键值式774张(GJB用例描述表, 无thead, 单元格自含"字段名：值", 行文本直接join)。
- 打分: `max(caption相似度, top-3行均值)`——caption显式gate是因为表的标题判别力极强("表2 流媒体能力标识"几乎唯一确定一张表)。
- 聚合变体扫描结论: 纯max(0.422)≪cap+top3(0.783)——单行匹配太噪, 必须有聚合+caption。

**ROUTE路由**
- 无参数: `max(zscore(dense), zscore(行级))`。
- 机制: z-score把两通道拉到同一尺度, max让"证据更强者胜"。等价于一个免训练的查询自适应门控。

### 1.3 预训练路线的负结果(保留在论文里, 是诚实性的一部分)

| 尝试 | 自身评测 | 下游 | 失败机制 |
|---|---|---|---|
| CMSC(3724跨模态对) | R@5 0.177→0.560 | 0.861→**0.834** | 训练分布(短片段对齐)≠下游分布(自然问句→图); 256d压缩丢检索信息 |
| GMC(977变异对) | 边反转检测率3% | — | 文本序列化原理性丢失方向 |
| MLP/proto-attention学习投影 | — | R@1≈0.03 | 训练查询(docT5)分布≠评测查询分布 |

**共同教训**: 在16文档的小数据上, "表示学习"类方法全部失败, "表示重组"类方法(多向量/聚合/路由)全部成功。这本身是一个可写的发现。

## 二、上下文关联技术(三模块视角)

### 2.1 位置: 特征提取如何嵌入关联系统

```
查询 → SQR(确定性信号? 命中→直接返回)
     → MFE特征提取 ── 文本: BGE dense(单向量)
     │                图: VA-ColPali(节点级多向量)   ← 本次工作
     │                表: dense+Table-Pali+ROUTE      ← 本次工作
     → SAA关联(五通道混合召回+通道注意力融合)
     → CR上下文重建(GJB章节树/双粒度/MMR)
```

上下文关联(方向A)的核心问题是"把分散的多模态内容聚合成一个条目"。特征提取决定了**聚合的输入质量**: 检索不准→聚合对象就错了。本次两项工作把图/表检索的薄弱环节补上后, 五通道里的dense/multimodal通道质量直接受益。

### 2.2 SQR与向量检索的关系

SQR(16%覆盖)处理"图3在哪"这类确定性查询, 剩下84%语义查询才走向量通道。两者是分流而非竞争。SQR+Pipeline当前R@1=0.497/R@5=0.788; 纯Pipeline 0.379/0.747。VA/Table-Pali的增益发生在这84%内部, 与SQR正交可叠加。

### 2.3 锚点体系——上下文关联的粘合剂

图→锚点结构映射(对齐分数均值0.826)使得VA-ColPali的节点可以:
- 与表格行通过**实体名**互查(同一参数在图节点和表行都出现)
- 与正文章节通过**位置**关联(锚点记录来源章节)
这正是"多模态上下文聚合"需要的跨模态粘合点。锚点质量审计(117条陈旧锚点仲裁、9条零边修复)是本季度的数据质量工作, 为后续聚合粒度定义铺路。

## 三、评测体系(协议、资产、数字)

### 3.1 评测协议栈

| 要素 | 取值 | 理由 |
|---|---|---|
| 划分 | 4-fold×16文档(文档级隔离) | 防同文档信息泄漏 |
| 候选 | fold内全部图(83~112张)/表 | 真实检索池 |
| 查询侧 | BGE指令前缀+截200字符 | 与生产管线(hybrid_recall)一致 |
| 指标 | R@1/R@5/MRR@10 | 首位命中/前5/排序质量 |
| 复现 | 工具化+MANIFEST sha256+快照测试 | 数字防漂移 |

### 3.2 核心数字汇总(全部可由工具复现)

**图检索(evalset_v3, 1007查询, 4-fold)**

| B1文本桥(VLM转写单向量) | 0.515 | 0.776 | 0.626 |

| | TP行级 | 0.793 | 0.912 | 0.844 |

### 3.3 评测质量工作(本周期修的bug)

1. **zip对齐bug(评测脚本通用陷阱)**: `zip(q_texts, bge.embed(...).values())`在部分查询命中磁盘缓存、部分现算时, dict插入顺序=先缓存后现算, 与q_texts错位→指标完全失真(曾出现0.081的假数字)。修复=按key查找。这个bug模式值得写进工程文档, 任何用embedding缓存的评测都可能踩。
2. **路径匹配bug**: fig_NNN.png在每个文档同名, VLM转写匹配必须(doc, fig)双键, 否则48/381错配。
3. **协议前缀缺失**: 基线数字从0.515漂到0.478的教训→所有工具共享`QUERY_PREFIX`常量。
4. **MANIFEST保护范围**: 发现evalset_v3等评测基准不在保护列表→扩到19资产, 评测集被静默重生成会报警。
5. **深行查询的构造协议**: LLM生成走`llm_client.py`缓存(可复现), 生成prompt禁止复述表标题(防caption泄漏捷径)。

### 3.4 评测的边界与诚实声明

- 深行查询仅111条(4-fold过滤后), 数字有小样本波动, 但0.297→0.865的量级差距远超噪声。
- docT5查询由LLM从表格前800字生成——它**系统性低估**深行需求, ROUTE在真实查询分布上的收益取决于深行型查询的真实占比(未知)。论文里必须声明这一点, 不能把双场景数字直接平均。
- 图检索的B1基线(0.515)与此前记录的"raw BGE bridge 0.659"不可比(不同查询子集与候选池); 论文一律以本报告工具化数字为准。

## 四、科学结论(论文claim草案)

1. **Claim 1(方法)**: 结构单元级后期交互(节点/行多向量+top-k聚合+caption伪单元)在零训练条件下, 分别提升GJB SRS的图检索(R@1 +5.2pts)与表格深内容检索(R@5 +57.7pts)。
2. **Claim 2(机制)**: 单向量表示存在两个可量化失效模式——**稀释效应**(大结构判别力摊薄)与**截断盲区**(512字符后内容不可见); 后期交互对二者免疫。
3. **Claim 3(边界)**: 后期交互**非普遍更优**——caption级/标题线索查询仍需单向量的联合上下文(表caption级dense 0.942 > TP 0.912); 无参数z-score路由(ROUTE)在两场景同时取得最优或持平。
4. **Claim 4(负结果)**: 小数据(16文档)上"表示学习"路线(跨模态预训练/图变异对比/学习投影)系统性失败, 失败机制均为训练分布与下游查询分布错位; "表示重组"路线(多向量/聚合/路由)系统性成功。
5. **Claim 5(评测方法论)**: 常规合成查询(从可见窗口生成)无法暴露单向量截断盲区, 需要按内容位置分层构造查询(deep-row协议); 评测协议细节(查询前缀)可造成±4pts漂移, 必须工具化锁定。
