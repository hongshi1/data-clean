## 2. 方法与结果

### 指标说明

**bAcc(平衡准确率)** = (真矛盾抓到率 + 良性放行率) / 2

- 全报警(所有输入都判"不一致")= 0.500
- 完美判别 = 1.000
- 我们用bAcc代替F1,因为测试集不平衡时F1会被全报警"骗"到虚高

### 2.3 表C: 按不一致类型分族的方法效果

我们将48种不一致类型按"适合用什么方法解"归为6族（A~F），每族用对称构造保证两类样本(不一致+一致)齐全。

#### A族：数值约束（PARAM-01 ~ PARAM-10）

**这类不一致是什么**： 同一个参数（时间/周期/资源/存储/值域等）在文档的不同位置给出了不同的数值或单位。

**包含的具体类型**：

| 类型编号 | 类型名称 | 不一致示例 |
|---|---|---|
| PARAM-01 | 时间约束冲突 | 3.2节说"响应时间不大于2s"，4.5节说"不大于5s" |
| PARAM-02 | 周期参数冲突 | A处"缓存周期30s"，B处"缓存周期60s" |
| PARAM-05 | 资源占用冲突 | A处"内存512MB"，B处"内存1GB" |
| PARAM-06 | 值域范围冲突 | A处"取值范围[0,100]"，B处"取值范围[0,50]" |
| PARAM-07 | 存储容量冲突 | A处"存储256GB"，B处"存储512GB" |
| PARAM-03~04 | 阈值/多源对齐冲突 | 同一阈值在两处定义不同 |
| PARAM-08~10 | 守时精度/降级阈值/故障时长 | 精度/阈值/时长参数不一致 |

**为什么适合用Z3求解器**： 这些本质上是数学约束的矛盾——"x≤2"和"x≤5"在逻辑上可判定是否矛盾。Z3可以形式化地判断两个数值约束是否矛盾，并给出证明（unsat），100%精确，不需要统计模型。

**实际例子**：
```
陈述1: "文档3.2.1.1.6章节规定：监控间隔不大于6秒"
陈述2: "文档3.2.1.1.6章节规定：监控间隔不大于12秒"
→ Z3判定: 约束 x≤6 ∧ x≤12 → 非矛盾(取交集x≤6)
   但如果改为"等于6秒"vs"等于12秒" → unsat(矛盾)
```

#### B族：顺序时序（ORDER_CONFLICT + LOGIC-01 + LOGIC-03）

**这类不一致是什么**： 表格中规定的步骤/事件/模式的执行顺序，与流程图中画出的顺序不一致。

**包含的具体类型**：

| 类型编号 | 类型名称 | 不一致示例 |
|---|---|---|
| ORDER_CONFLICT | 步骤顺序矛盾 | 表格规定步骤3→4，图中画的是4→3 |
| LOGIC-01 | 模式优先级冲突 | 正文说"应急模式优先级最高"，图显示"自动模式优先" |
| LOGIC-03 | 事件时序冲突 | 正文规定事件A→B→C，图显示B→A→C |

**实际例子**：
```
陈述1: "表格规定开发工程生成用例的执行顺序为3→4"
陈述2: "流程图规定的执行顺序为s4→s3，与表格不一致"
→ 顺序反转，真矛盾
```

#### C族：结构存在（8种结构缺失/多余 + LOGIC-05）

**这类不一致是什么**： 表格中列出的某个条目/步骤/参与者/异常流/接口组件，在对应的流程图/接口图中找不到对应元素（或反过来，图中多出了表格没有的元素）。

**包含的具体类型**：

| 类型编号 | 类型名称 | 不一致示例 |
|---|---|---|
| TABLE_ITEM_MISSING | 功能表条目缺失 | 功能表列了"数据引接汇聚"，图中没有对应节点 |
| STEP_MISSING | 用例步骤缺失 | 表格规定7个步骤，图中只有5个节点 |
| ACTOR_MISSING | 参与者缺失 | 表格标注Actor为"开发人员"，图中没有参与者泳道 |
| EXC_MISSING | 异常流缺失 | 表格定义了异常流E1"连接失败提示"，图中没有该分支 |
| COMPONENT_MISSING | 接口组件缺失 | 接口表列了"数据上报接口"，接口图中没有该组件 |
| DIAGRAM_EXTRA | 图中多余元素 | 图中有"状态监控"节点，表格中没有对应条目 |
| DIAGRAM_EXTRA_COUNT | 图中节点计数多余 | 图中有多个节点无表格对应 |
| UC_NAME_MISMATCH | 用例名称不一致 | 表格写"数据获取"，图写"数据采集" |
| LOGIC-05 | 分支不完备 | 正文说有{正常,降级,故障}三种模式，图只画了两种 |

**这族的核心难点**： 同样是"图中没有"，有些是真矛盾（核心功能缺失），有些是良性差异（辅助功能省略/画图惯例）——需要理解内容的重要性才能判断。

**实际例子（真矛盾）**：
```
陈述1: "接口表与接口图对照中, 表格包含条目「态势数据组织应用」"
陈述2: "图中没有与该条目对应的元素"
→ 核心接口组件缺失 = 数据流断裂 → 真矛盾
```

**实际例子（良性差异）**：
```
陈述1: "开发工程生成用例的表格规定参与者为「开发人员」"
陈述2: "流程图中没有绘制参与者节点"
→ 图省略参与者泳道是GJB画图惯例 → 良性差异(不是矛盾)
```

#### D族：术语一致（TERM-01 ~ TERM-08）

**这类不一致是什么**： 文档中同一事物在不同位置使用了不同的名称、术语、缩写或代号。

**包含的具体类型**：

| 类型编号 | 类型名称 | 不一致示例 |
|---|---|---|
| TERM-01 | 同义异名 | A处叫"数据获取"，B处叫"数据采集"（指同一个功能） |
| TERM-02 | 同名异义 | A处"安全模式"指防护，B处"安全模式"指加密 |
| TERM-03 | 枚举集合不一致 | 正文说支持{桌面,平板,手持}，图只画了{桌面,平板} |
| TERM-04 | 告警术语不一致 | A处"通信异常告警"，B处"通信故障告警" |
| TERM-05 | 指令名称不一致 | A处"数据获取指令"，B处"数据查询指令" |
| TERM-06 | 量纲单位不一致 | A处"0.2秒"，B处"200ms"（同值不同单位表述） |
| TERM-07 | 接口命名不一致 | A处"数据传输接口"，B处"数据传送接口" |
| TERM-08 | 缩写代号不一致 | A处用全称"结构化数据归集"，B处用缩写"SDA" |

**实际例子**：
```
陈述1: "表格规定「数据引接汇聚」功能"
陈述2: "图中规定「数据引接汇渠」功能"
→ 术语编辑距离1（"聚"→"渠"），名称不一致
```

**为什么目前所有方法≈随机（0.50）**： 术语差异通常只有1-2个字符不同（如"聚"→"渠"），变异构造的表面差异太细微，模型无法区分"有意的术语不一致"和"无意的字符替换"。

**这类不一致是什么**： SRS文档中的需求描述不满足GJB 438C标准的合规性要求（如缺少可测试性描述、缺少容错条款等）。

**包含的具体类型**：

| 类型编号 | 类型名称 | 不一致示例 |

| GJB-03 | 安全访问缺失 | 缺少权限控制/身份认证描述 |
| GJB-04 | 审计日志缺失 | 缺少操作日志/审计要求 |

| GJB-06 | 报警要素不完备 | 报警描述缺少等级/位置/处理方式 |
| GJB-07 | 软件自检缺失 | 缺少开机自检/状态自检要求 |

**实际例子**：
```
陈述1: "文档规定：数据获取针对各业务部门的海量多源异构数据资源..."

```

**为什么目前所有方法≈随机**： GJB合规性问题本质上是"某需求是否满足标准条款"——需要理解GJB标准的120条规则，不是判断两个陈述是否矛盾。变异构造只能做"插入/删除合规关键词"，无法真正模拟合规违规的多样性。

#### F族：语义惯例（残差类）

**这类不一致是什么**： 无法归入以上五族的残余类型，需要纯粹的语义理解来判断（例如"图的粒度比表格粗是惯例"vs"图缺少关键功能是矛盾"）。

**实际例子（真矛盾）**：
```
陈述1: "表格规定该功能的步骤包括：「系统对报文进行CRC校验」"
陈述2: "流程图中没有与该步骤对应的节点"
→ CRC校验是核心功能 → 真矛盾
```

**实际例子（良性差异）**：
```
陈述1: "表格规定该功能的步骤包括：「用户确认操作」"
陈述2: "流程图中没有与该步骤对应的节点"
→ 确认类中间步骤常被省略 → 良性差异
```

**为什么这族最难**： 需要判断"什么级别的步骤在图中省略是可接受的"——完全依赖领域知识，不是规则或数值比较能解决的。

## 3. 基础结论

### 结论1: 领域数据 > 模型规模 > 方法先进性

```
102M + 896条领域数据 (0.940)  >  7B LLM零样本 (0.500)
                              >  398M+NLI迁移 (0.653)
                              >  DoRA ICML'24 (0.726)
                              >  MiniCheck EMNLP'24 (0.500)
```

### 结论2: 所有零样本方法在此任务上全部失败

所有零样本方法(含GLM-5、Qwen-7B、mDeBERTa、MiniCheck)在真实金标上全部退化为全报警(bAcc=0.500)。原因是GJB SRS的"不一致"是领域约定(图省略参与者是惯例、图粒度粗于表格是惯例),不是通用语义矛盾——零样本模型不具备这种判别能力。

### 结论3: 不同类型的不一致需要不同的方法

- 数值类 → Z3形式化求解(确定性,100%精确)
- 真实锚点/结构缺失 → v12(纯领域微调)
- 变异/合规/术语 → v13(NLI迁移+领域微调)
- 这就是"异构分派架构"的实证依据

### 结论4: 市面上没有SRS一致性检测的公开数据集

最接近的是ContractNLI(合同条款)、FEVEROUS(维基事实)、DocNLI(通用文档)——都不是SRS。我们的934条金标是此领域首个数据资产。

## 4. 方法说明

### "纯领域微调"(排名1的方法)

就是最简单的做法: 拿一个中文RoBERTa-102M,在我们的896条真实SRS锚点数据上做标准的分类微调。没有花哨的技术,就是标准微调。

### "先通用后领域"(排名2的方法)

两步走: 先在16万条通用NLI数据(OCNLI+CMNLI+PAWS+FEVEROUS+ContractNLI)上训练一轮(学通用矛盾概念),再在896条SRS锚点上微调(学领域判别)。相当于"先学通用再学专业"。

### "语言墙"

英文预训练的模型无法正确处理中文输入( tokenizer将中文转为大量UNK token),评测结果0.500反映的是"语言不兼容",不是"方法不好"。这不是我们方法的问题,是所有跨语言零样本迁移的普遍现象。
