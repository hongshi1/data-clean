# 43 因果归因探针与架构修正: 瓶颈是文档构造, 不是判别器

日期: 2026-10-21 | 依据: rerank_causal_probe(results/_causal_probe.json)

## 一、被忽视的架构事实与不可见环节

**架构数据**: 召回@50=91.1%(仅39条池外) vs R@1=0.486 →
问题=池内判别(239条), 非覆盖.

**因果探针设计** (对全部239条池内失败):
```
s_cur = CE(query, gold表top-2单元doc)     # 现行行为
s_ora = max_{u∈gold表全部单元} CE(query, u)  # oracle文档
s_win = CE(query, 赢家doc)
归因: s_ora > s_win → 文档构造失败(换对行即赢)
      s_ora ≤ s_win → CE判别失败(最优行也输)
```

## 二、结果(具体到机制)

| 归因 | n | 占比 | 含义 |
|---|:---:|:---:|---|
| **文档构造失败** | **185** | **77%** | CE从未见过答案行——top-2启发式选了gold表的冗余兄弟行 |
| CE判别失败 | 54 | 23% | 判别器真实极限(词面无判别键的弱判别查询) |

**结论**: 交叉编码器很强, 我们在饿死它. 此前所有重排增强方向
(列表级/更强CE/Qwen3)打的是23%的问题; 77%的杠杆在**文档构造环节**
——一个此前被视为实现细节、从未进入失败分析的不可见阶段.

## 三、文档构造为什么系统性失败(机制)

top-2单元按"与查询的语义相似度"选取——与召回同源的sibling混淆:
gold表内最像查询的行≠含答案的行(答案行=代码/键值行, 与查询
cos天然低; 相似行=语义描述行, 兄弟冗余). 同一个表征缺陷
在两个层级各咬一口: 表级排序(召回)+行级选择(文档构造).

## 四、通用修正原则(回答"方法不通用")

### 原则: 证据文档应最大化判别信息覆盖, 而非查询相似度

三个通用实现(按架构彻底度排序):

**R1 单元粒度CE(消除该环节)**: 每候选不再构造单一doc,
CE逐单元打分, 候选分=max单元CE分. 文档构造环节被架构性删除,
不是修补. 成本: 50候选×~11单元=550对/查询(×10) → **两遍法**:
第一遍现行top-2(粗筛), 第二遍对top-10幸存者逐单元精扫(10×11=110对,
仅×2.2成本).

**R2 覆盖最大化选择**: top-2→MMR多样性选择(相关+去冗余),
或类型覆盖选择(键行+语义行+数值行各一)——兄弟行冗余被显式抑制.

**R3 topn自适应扫描**: 简单扩大topn(3/5/8)+观察-17pt(全表dump)
与77%(top-2不足)之间的最优点——工程调参, 不作为主方案.

### 预期
R1两遍法理论上限: 213(现行命中)+185×折损率(第三候选干扰)+...
保守估计R@1 0.486→**0.62-0.68**区间(池内失败的77%打开).
