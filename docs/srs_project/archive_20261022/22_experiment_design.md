## 1. 负责场景

**任务定位**: 结构化文档的单元级检索——SRS文档中"自然语言查询→定位到具体的图/表",
是上下文关联(方向A: 多模态内容聚合)的基础层: 检索不准则聚合对象就是错的.

**三个评测场景**（按"答案藏在文档哪个位置"划分）:

| 场景 | 定义 | 真实查询示例 | 候选池 |
|---|---|---|---|
| **S1 图检索** | 自然语言→图（跨模态: 查询是prose, 目标是图节点） | "文电收发与管理的用例图在哪" | fold内381图 |
| **S2 表·标题级** | 目录型查询（看表标题可定位） | "流媒体传输服务的所有能力标识在哪个表" | fold内1207表 |
| **S3 表·深行** | 正文行型查询（只存在于表格深处某行, >800字符位置） | "非结构化数据源引接的编号ZZSJHQZHFW在哪个表" | fold内1207表 |

**为什么要分场景**: 单向量方法在S2很好(0.799)、S3崩塌(0.178)——混合评测会掩盖失效.
S3是我们专门构造来暴露"截断盲区"的（84%表格超512字符被dense截断）.

**外部效度场景**: WTQ(英文表检索) + FeTaQA(英文表检索+行级gold)——检验机制跨数据集一致性.

## 2. 数据集构成

### 2.1 自有解析数据集: GJB-URE-v1（`data_assets/evalsets/gjb_ure_v1.json`）

**来源管线**（16份真实军事SRS, GJB 438C格式）:
```
.doc文件 → textutil解析(markdown) → chunk切分(381图+1207表+3643文)
图: VSDX矢量源锚点解析(373结构/3759节点/2680边, 零OCR误差)
    + VLM转写(caption+key_elements) → 单元=节点∪VLM元素
表: HTML表格解析(表头式433+键值式774, 11216行) → 单元=行("表头=值"序列化)
```

**构成**:
- corpus: 1588 chunk（全部381图+1207表, 含3张无源空单元图）, 14019单元(去重后)
- queries: **eval 1125**（S1: 1007 + S3: 118）+ **train 2008**（去污染后）
- 4-fold文档级隔离, fold=(doc序号-1)mod4, 一致性97.3%（2.7%已知噪声）

**查询来源分解**:

| 场景 | 来源 | 合成方式 | 数量 |
|---|---|---|---|
| S1 | user_sim + param_v2 + legacy | LLM模拟用户/参数化模板/历史评测 | 1007 |
| S2 | docT5query | LLM读表格前800字生成假想查询 | 1541(作评测用) |
| S3 | deep_row_llm | LLM只读>800字位置的行内容生成, 禁止复述标题 | 118 eval + 467 train(去污染) |

**质量审计与修复**（21号文档§三）: fold约定bug已修(doc%4→(doc-1)%4)、
train泄漏已排除(118条)、单元去重(41.2%重复移除); 已知噪声: 死块gold 10条、
跨文档legacy锚定30条、复述式深行查询60%（S4, v2再生成列入待办）.

### 2.2 补充公开数据集（外部效度, 经hf-mirror转换）

| 数据集 | 规模 | 转换方式 | 特殊价值 |
|---|---|---|---|
| **WTQ-URE** | 2100表/42394单元/**18486真实用户查询** | `convert_public_dataset.py`(gold表自带→expected免费保证) | 真实问题(非合成)、英文 |
| **FeTaQA-URE** | 2003表/28358单元/2003真实查询 | 同上+**行级gold**(highlighted_cell_ids) | RowHit@1可测: 单元是否命中"对的行" |

## 3. 算法的输入与输出

### 3.1 核心方法: 单元检索 + 多通道路由（ROUTE4）

**输入**:
- 离线索引期: 文档chunks列表 → 单元提取器（每模态一个: 图=锚点节点∪VLM元素, 表=行）
- 在线查询期: 一条自然语言查询（≤200字符）

**输出**:
- 候选chunk的排序列表（chunk_id, score）
- （可解释性副产品）命中单元与注意力权重α——查询↔子单元关联证据,
  供方向A聚合使用（UAA的attention_weights接口）

**处理流程**:
```
查询 → BGE向量(指令前缀) → 与每单元相似度 → IDF加权 → MaxSim聚合(k=1)
                                              ↓(图实例)
                                    +CMSC跨模态融合λ=0.3
                                                      ↓
与其他通道(max-zscore路由): max(z(BM25-doc), z(BM25-unit), 0.8·z(dense), z(unit))
                                                      ↓
(可选精排) top-10 → BGE-Reranker, 深内容用单元片段passage
```

**模块化架构**（19号文档）: A单元提取 / B单元索引打分 / C通道路由 / D重排 / E评测协议.
参数: top_k=1, idf=True, 图cmsc_fuse=0.3, 表gate, dense阻尼0.8.

### 3.2 关键设计依据（实验钉死的）

- k=1+IDF: 多角度扫描选定（深行只引用一行, k=3均值稀释; IDF压制"序号=1"类万金油）
- UAA子注意力收敛验证: 学习聚合收敛回固定公式——零训练方法=学习族不动点
- CMSC投影头: 替换BGE失败(负迁移), 聚合键融合成功(+3.8 R@1图)

## 4. 并行baseline

### 4.1 单通道基线（同一输入, 不同表示/相似度）

| Baseline | 表示 | 相似度 | 检验什么 |
|---|---|---|---|
| **B1 dense** | 整chunk单向量(512字符) | 余弦 | 标准做法; 暴露截断盲区(S3: 0.178) |
| **BM25-doc** | 词面(中文字符二元组+英文词) | BM25 | 词面精确匹配上界; 标识符/图题查询强 |
| **BM25-unit** | 行级BM25取max | BM25 | 与O1结构同构的词面对照(隔离"结构"vs"语义") |
| **Token-MaxSim** | BGE token向量(512 token) | ColBERT式Σmax | **粒度受控实验**: token级vs单元级后期交互 |

### 4.2 系统级基线

- **B2**: dense top-10→BGE-Reranker全文重排（标准两阶段, 论文里的常见强基线）
- **ROUTE4-minus-unit消融**: 去掉单元通道的路由（证明单元通道的边际贡献）
- **O2a/O2b**: 单元召回+全文/片段重排（我们的两阶段, 与B2同重排器隔离召回因素）

### 4.3 负结果对照组（"表示学习失败"证据链）

CMSC替换BGE(-2.7pts) / GMC文本序列化(边反转检测3%) / MLP投影(R@1≈0.03) /
UAA学习聚合(收敛回固定)——支撑Claim"小数据上表示重组>表示学习".

## 5. 如何验证算法有效性

### 5.1 测试集的合成（按场景分层）

**原则**: 每场景的查询合成方式必须匹配该场景要暴露的问题——
"常规合成查询测不出截断盲区"（docT5只读前800字→引用内容必在可见窗口内）,
所以S3必须用"只读后段行"的专门协议.

| 场景 | 合成管线 | 防偏差设计 |
|---|---|---|
| S1 | user_sim: LLM模拟用户问图; param_v2: 参数化模板(实体/表号/图号槽位); legacy: 历史评测迁移 | 三来源混合防单一LLM风格 |
| S2 | docT5query: LLM读表格前800字生成假想查询(每表1条+param_v2补充) | 与生产检索同分布假设 |
| S3 | LLM只读>800字符位置的行内容(每表取深行), prompt约束: 15-40字、不得复述表标题、必须通过行内容定位 | 暴露截断盲区; LLM缓存保证可复现 |
| 公开集 | 无合成——WTQ/FeTaQA真实用户问题 | 外部效度(真实分布) |

**隔离协议**: 4-fold文档级隔离(doc-1 mod4, 16文档→4×4)——
训练(UAA/超参扫描)只用其他3折, 测试折文档不参与任何训练侧.
已知漏洞与修复: eval逐字泄漏train已排除(118条), fold约定bug已修.

### 5.2 评测协议

- 候选池: 测试fold内全部同类型chunk(图83-112/表250-360)——真实检索池
- 查询侧: BGE指令前缀+截200字符（与生产一致, 协议细节曾造成±4pts漂移, 已工具化锁定）
- 指标: **R@1/R@5/R@10/MRR@10** + **RowHit@1**(FeTaQA行级gold: 单元命中"对的行")
- 公开集: 全候选池(2100/2003), 2000查询采样(seed42)

### 5.3 数字防漂移三件套

1. **MANIFEST**(sha256×28资产): 评测JSON/数据集被静默重生成即报警
2. **快照测试**(220个): 论文数字写死在tests/, 变化即红
3. **工具化复现**: 每个数字有唯一入口命令(`tools/eval_*.py`), LLM调用走缓存

### 5.4 消融矩阵（全部已跑）

| 消融维度 | 配置 | 结论 |
|---|---|---|
| 聚合宽度k | 1/2/3/5/8 × IDF | k=1+IDF统一最优 |
| IDF | on/off | 深行TP R@1 0.559→0.748 |
| CMSC融合 | 替换/路由通道/聚合键λ∈[0.15,1.0]/UAA特征 | 聚合键λ=0.3胜出(+3.8) |
| 路由 | z-mean/RRF/max-z(阻尼0.4-1.0) | max-z阻尼0.8"不败"; RRF深行0.198崩 |
| passage构造(重排) | 全文/单元片段 | 短内容全文优, 深内容片段优 |
| 学习聚合 | UAA warm-start/正则/深行训练数据 | 收敛回固定公式(不动点) |

### 5.5 机制级验证（不只是数字好, 还要解释为什么）

- **截断盲区量化**: dense S2=0.799 vs S3=0.178（同系统同通道, 内容位置不同→3倍差）
- **粒度-窗口受控实验**: 同一BGE骨干, Token-MaxSim在S3=0.212(继承512窗口)
  vs 单元级0.703——"单元=无总量限制的多向量"是结构性优势
- **稀释效应**: 大结构(≥10节点)单元级R@5比dense +8.2pts
- **UAA不动点**: 学习注意力收敛回我们的固定公式(Δ<0.1pt)

### 5.6 外部效度验证

WTQ: 单元增益+75%相对R@1(方向与GJB一致); FeTaQA: ROUTE4反超最强单通道
(0.802 vs BM25-unit 0.788); RowHit@1: 单元级0.375>BM25-unit 0.364.

### 5.7 诚实声明（论文Limitations素材）

- 深行查询118条小样本; 60%为复述式(词面可匹配)——S3数字偏乐观, v2再生成待办
- bge-large-zh跑英文非最优(公开集绝对值偏低, 检验的是机制一致性)
- 真实查询分布未知→路由阻尼0.8是"不败"点非双场景最优
- S1含26%表号引用查询(共址锚定语义, 非纯可答性)
