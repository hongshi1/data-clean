## 二、模块一深化：多模态特征提取

### 2.1 文本特征（三个创新点）

#### 创新1·κ-SynCL：编译器引导的小数据对比学习

**文献依据**: SetFit(2209.11055)证明1000-3000配对足够 / Promptagator(2209.11755)证明LLM合成查询有效 / E5-V(2407.12580)证明文本枢纽可替代跨模态对齐

**我们的独有优势**: κ_T/κ_P编译器提供**可验证的grounding**——编译条目的同构关系天然构成正对，LLM只负责措辞多样化（标签由编译器保证为真，回应Korn 2026的警示）。

```
训练数据构造管线:
  ① 同构正对(免费): κ_T条目 ↔ κ_P同参数约束 ↔ 锚点同文字节点
     例: 表格"存储容量≥256GB" ↔ 正文"不低于256GB" ↔ 图中"存储"节点
  ② 模板难负例(免费): 同文档3.2.x子节共享句式("系统应支持...")
     → 同文档不同需求ID的chunk互为天然难负例
  ③ 变异反例(确定性): 32种变异算子
     例: "结构化"→"结操化"(一字之差) / "256GB"→"56GB"(数值冲突)
  ④ LLM查询改写(缓存): 编译条目→本地LLM多样化问句→标签由编译器验证
```

**训练目标**: A8残差适配头(1024→1024零初始化) + Matryoshka多粒度头(64d实体/chunk级/1024d全文)

#### 创新2·GJB结构感知Late Chunking + 多粒度

**文献依据**: Late Chunking(2409.04701)证明先整后切比先切后编优 / Dense X(2312.06648)证明命题级优于段落级 / Matryoshka(2205.13147)嵌套维度一次训练多粒度

**我们的差异化**: 文献的切块边界是语义估计，我们的边界是**GJB章节结构**（3.1~3.18确定性十八节）

```
编码流程:
  BGE(整节文本) → 章节边界切分(确定性) → 边界处池化
  → chunk向量携带全文上下文(修复当前切分丢失章节路径的问题)

  一次训练产出三层粒度(Matryoshka):
  ├── 64d: 实体级粗筛(κ_T条目名/锚点节点文字)
  ├── 256d: chunk级标准检索
  └── 1024d: 精排/一致性判断
```

#### 创新3·四类不一致条件化嵌入视图

**文献依据**: SCS(2609.32684, ACL 2026)证明推理期条件化免训练可行 / INSTRUCTOR(2212.09741)任务指令感知

**我们的差异化**: 文献的条件是通用任务（330类），我们的条件是**四类不一致**（术语/参数/业务逻辑/GJB合规）——封闭、领域先验给定、与温老师四类框架一一对应。

```
实现(SCS式推理期条件化, 近零成本):
  编码器: 本地Qwen3-Embedding-0.6B(开源Apache 2.0, 指令感知)
  
  查询编码: "找到与以下术语相关的不一致: {entity}"
  无条件编码: 遮蔽条件前缀 → 自注意力修正 → 条件化向量
  
  一份索引 × 4个条件视图 = 术语/参数/逻辑/合规四路检索
  Router从"模态路由"升级为"模态×不一致类型"双轴路由
```

### 2.2 图像特征（最核心创新）

#### 创新4·VA-ColPali：矢量图原生的节点级Late Interaction

**文献依据**: ColPali(2407.01449, ICLR 2025)证明patch级多向量+MaxSim大幅超越单向量 / MUVERA(2405.19504)证明多向量可归约为单向量MIPS

**我们的独有资产**: VSDX矢量源——ColPali需要VLM从像素提取patch，我们**直接从XML解析节点**（零OCR误差、零视觉模型、天然可解释）。

**文献空白**: ColPali/VisRAG/ColNanoVDR**全部假设栅格输入**。矢量图原生late interaction在2026-09前沿中是无人区。

```
架构:
  离线(每张图):
    锚点提取器 → 节点集合{(文字, 类型, 坐标), ...}
    ├── 节点文字 → BGE编码 → 1024d文本向量
    ├── 节点类型 → 可学习嵌入 → 16d (usecase/actor/process/decision/...)
    └── 节点坐标 → 归一化(0-1) → 8d (cx, cy, w, h, rx, ry, ...)
    → 节点向量 = concat(text_emb, type_emb, coord) → 1048d

  在线(查询):
    query → BGE编码 → 1024d
    图级分数 = Σ_max_sim(query_i, node_j)  ← MaxSim late interaction
    
  三层漏斗(性能保障):
    ① MUVERA-FDE单向量粗筛(复用FAISS/MIPS)
    ② 节点级MaxSim精排(top-50)
    ③ BGE-Reranker cross-encoder终排(top-5)

非Visio图(截图/SmartArt) → 降级走VLM转写单向量(现有Text-Bridge通道)
```

**预期收益**: 图像检索从CLIP 0.330水平→与VLM转写桥(0.730)持平或更高（结构信息是转写没有的加分项）；命中节点直接作为四类不一致的证据输出（检索与检测证据链统一）。

### 2.3 表格特征

#### 创新5·行级条目+表型感知嵌入

**文献依据**: TURL(2006.14806)掩码实体恢复预训练 / TAPAS(2004.02349)行列位置感知 / TableRAG(2410.04739)证明cell级检索优于全表线性化

**我们的差异化**: κ_T已编译出条目，但丢失了表内坐标。加回TAPAS式位置token。

```
κ_T条目增强:
  当前: {name: "结构化数据归集", id: "ZZSJHQZHFW-GN-SJHQ-JGHSJGJ"}
  增强: {name: "...", id: "...",
         row_token: "[row=1]",
         col_token: "[col=功能名称]",
         table_type_token: "[type=capability]",
         section_token: "[sec=3.2.1]"}

  → BGE编码(条目名+位置token) → 行级条目向量
  → 查询"3.2.1节功能表第1行是什么"时位置感知直接命中

双粒度索引:
  ├── schema层: 表头+caption+章节 → 1个向量/表(回答"有哪些接口"类查询)
  └── 条目层: 每行1个向量(回答"存储容量是多少"类查询)
```

#### 创新6·MER-Anomaly：表格实体恢复预训练→检测闭环

**文献依据**: TURL的MER(掩码实体恢复)预训练目标

**我们的差异化**: 文献中表格预训练服务QA，**无人将恢复置信度作为不一致信号**接进检测管线。

```
管线:
  1207张表 → 行列位置编码 → 掩码15%单元格 → 恢复训练(≤100M小模型)
  → 学到GJB域内表格共现规律(如"速率"行必带单位)
  
  推理期: κ_T条目 → 恢复置信度打分
  → 低置信 = 模式异常 = 潜在不一致候选
  → 作为概率化补充通道进黑板(与κ_T白名单规则正交互补)
```

## 七、三个设计原则

```
1. 确定性资产优先: VSDX矢量源、κ编译器、GJB结构——每个前沿思想
   都有我们的确定性版本(文献空白即差异化)
   
2. 查询侧适配为主: 不动文档侧索引(成本高), 动查询侧编码
   (SCS条件化/Q-REACT残差/ViSAR自适应k——2026前沿共识)
   
3. 编译器验证合成: 任何LLM生成进训练集前过编译器/变异算子校验
   (Korn 2026警示 + 可复现性硬规则)
```
