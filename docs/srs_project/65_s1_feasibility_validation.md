# 65 S1结构匹配可行性验证：真实语料上的实证结果

日期：2026-10-28 | 状态：实证完成 | 前置：64号(信号独立架构)

## 一、验证目标

在真实语料(11,869条claims)上运行S1结构匹配（64号修正架构的第一层），验证：

1. 确定性参数-值抽取是否可行
2. 同参不同值检测能发现什么
3. 假阳性率与精度瓶颈在哪

## 二、验证结果

### 总量统计

```text
总claims:            11,869
含参数+数值的claims:    397 (3.3%)
(doc, param)分组:       66
S1检出同参多值组:        60
```

### 发现1：S1机械层完全可行

- 参数表面形式匹配（GJB词典11参数+中文同义词）确定性运行
- 数值+单位抽取复用claim五元组的quantities槽位
- 全量11,869条处理时间<2秒，零成本

### 发现2：发现教科书级真实不一致候选（doc02）

```text
[doc02] 响应时间跨章节冲突:

  1.8.2.1 & 1.8.3.2:
    "支持首屏加载时间不小于2秒，用户响应时间不小于3秒。"
                        首屏: 2s  响应: 3s

  1.8.5.1.1 & 1.8.5.2:
    "支持首屏加载时间不小于3秒，用户响应时间不小于5秒；"
                        首屏: 3s  响应: 5s

  → 同文档内同名参数(首屏加载时间/用户响应时间)
    在1.8.2系与1.8.5系给出不同值
  → 两种可能: 真实不一致 OR 不同形态/子产品的合理差异
  → 恰是64号架构中"需S2/S3确认作用域"的标准案例
```

### 发现3：精度瓶颈=作用域绑定缺失

| 假阳性模式 | 案例 | 本质 |
|---|---|---|
| 硬件清单表 | doc03 clock_frequency 29个值(3.9.1节) | 每行是不同设备的时钟频率，非冲突 |
| 显示分辨率 | doc02 resolution 1920×1080 | 不同显示器的分辨率，非参数 |
| 词面过松 | availability匹配到"可用性"各种语境 | 表面形式歧义 |

**结论**：裸S1(参数名+值)的高召回低精度，**验证了原子schema中"作用域槽"的必要性**——
`{参数名, 操作符, 值, 单位, 作用域}` 的作用域槽（主语/设备/功能绑定）是精度关键。

### 发现4：数值抽取噪声（量化）

```text
[doc14] 恢复时间: 值[(12, ''), (0.5, '小时')]
  → "12"是表格行号被误抽为数值
  → "0.5小时"才是MTTR真值
  → 粒子化时需行号过滤(表格行ID模式: 纯数字+无单位+行首位置)
```

**全量统计（19,476个数值槽）**：
- 疑似编号噪声（纯数字+无单位+无操作符）：**18,599（95.5%）**
- 无单位数值：18,817（96.6%）
- `subject_candidate`槽填充率：**0.0%**（schema有槽但从未填充）

**结论**：
1. 现有quantity抽取噪声率极高 → S1c数值卫生过滤是**必做前置**（非可选）
2. 作用域槽在schema中存在但从未填充 → **这正是本研究的贡献空位**：
   Atomizer的作用域绑定（表格行首列主语/句子主语/泳道）是要新建的能力，也是S1从"高召回低精度"到"可用精度"的关键路径
3. 参数表面形式匹配本身是有效过滤器（397/11,869=3.3%通过），噪声主要残留在通过后的值级（如doc14的"12"）

## 三、对64号架构的实证修正

```text
实证前假设: S1确定性规则 → 高精度低召回
实证后事实: S1确定性规则 → 高召回, 精度取决于作用域绑定

修正后的S1定义:
  S1a 参数-值抽取:    确定性, 已验证可行
  S1b 作用域绑定:     精度瓶颈所在, 需原子schema的作用域槽
      - 表格行: 行首主语列(设备名/功能名)自动绑定
      - 正文句: 主语候选(subject_candidate槽已有)
      - 图节点: parent_id回溯到泳道/区域
  S1c 行号噪声过滤:   确定性, 简单规则可解
```

### 作用域绑定的实现路径（按成本递增）

```text
路径1(零成本): 结构性作用域
  表格行首列/段落主语/图泳道 → 与参数槽绑定
  例: "XX设备的时钟频率" vs "YY设备的时钟频率" → 作用域不同 → 非冲突

路径2(低成本): S2 BGE上下文相似
  两claim的上下文句(前后句)cos < 阈值 → 作用域可能不同

路径3(残差): S3 NLI判作用域
  结构和BGE都判不动时, NLI判两描述是否同一对象
  输出=候选标记(非结论), 符合64号信号独立原则
```

## 四、S1发现候选的分层确认流程（以doc02为例）

```text
S1检出: 响应时间 3s(1.8.2) vs 5s(1.8.5)
  ↓
S1b作用域绑定尝试:
  两处文本高度同构("支持首屏加载时间不小于X秒，用户响应时间不小于Y秒")
  → 句式相同, 作用域槽未显式区分(无"在XX形态下"前缀)
  → 结构无法排除冲突 → 进入S2
  ↓
S2 BGE上下文相似:
  1.8.2的上下文 vs 1.8.5的上下文
  → 若章节主题不同(如不同部署形态) → cos差异大 → 疑似合理差异
  → 若上下文同质 → 疑似真实冲突
  ↓
S3 NLI(仅残差):
  NLI(句A, 句B) → contradiction?
  → 输出候选标记 source=nli
  ↓
L3 LLM复检(最终裁决):
  "doc02的1.8.2与1.8.5对响应时间要求不一致, 是真实缺陷还是不同形态配置?"
  → Finding(附完整证据链: S1值对+S2上下文+S3标记+原文位置)
```
