## 1. 总体设计思想

### 1.1 两个研究对象的流水线关系

本研究评测两个衔接的对象：**上下文关联**（从多模态文档语料中召回证据，回答"检索能否把正确的证据找回来"）与**一致性校验**（在召回的冻结证据上判定答案，回答"证据在场时判定能否做对"）。二者共用16份真实GJB 438C军用SRS语料，但评测协议各自独立（R@1 vs 三态macro-F1/检出率）——检索质量决定判定上界，判定质量决定检索结果的最终可用性。分开评测使我们能分别归因失败：判定错误究竟是"没找到证据"还是"找到后判错"。

### 1.2 三条贯穿性认识论原则

**原则一：标签可证性阶梯。** 评测标签的可靠性不是二元的（gold/非gold），而是一个阶梯：**构造性sound**（标签由构造过程程序化证明，如"污染值必须在证据中"由断言门强制）→ **silver复核**（强模型thinking模式重裁+claim级引用校验，但显式声明非gold、标注者间κ如实报告）→ **人工gold**（逐条期望理由+定位标注）。数据集构建的全部设计围绕"如何在不牺牲规模的前提下把标签推上更高阶梯"。

**原则二：防泄漏纪律。** 一切调参、阈值标定、规则设计只允许接触开发集；测试集每配置只评一次；切分按主题整簇隔离（防"记住主题"）；偏差用held-out对照主动量化而非掩盖。

**原则三：辖区对照。** 不追求"一个方法在所有数据集上全胜"（那样的表通常有泄漏），而是用**受控对照实验划分方法辖区**——同基座换训练数据、同模型换任务形态、同质量换成本，每个对照回答一个科学问题。

### 1.3 开放世界契约（横贯两个方向的投影）

一致性侧的核心语义契约是**"缺席≠反驳"**：证据标记completeness=open时，检索证据中查不到不构成矛盾（判NIE），排除性判定必须由封闭性证明支撑——这条契约从不在检索命中中推断。它在检索方向有对应投影：查询的gold绑定采用"生成来源锚定+多gold诚实披露"而非"单gold强指定"。同一个认识论（证据的在场性≠穷举性）在两个方向以不同形式约束设计。

## 2. 数据集构建方法论

### 2.1 标签可证性阶梯的实现模式

三级阶梯在本项目中的实例化规模呈金字塔：**人工gold 17条**（真实违例）→ **silver 91条**（真实QA复核）→ **构造sound 4500+150+394条**（训练合成/跨文档/变异注入）→ **公开gold 18,486条**（WTQ等移植）。规律是：**语义深度与可证性越高，规模越小**；团队用"构造协议换规模、诚实披露换可比性"而非静默混合不同阶梯的标签。

构造性标签的共同机制是**双层程序化断言**：构造期自检（逐候选验证sound条件）+ 落盘后独立复核（从产物文件重读重检）——断言对象是**模块真实看到的线性化文本**而非原始HTML（表格单元格拆分后的拼接形态）。这个细节是多次踩坑后的教训：对原始HTML成立的断言可能在线性化后失效。

### 2.2 构造性基准：sound标签的设计原则

**跨行污染作为sound refute的构造范式。** 要造"可证明为矛盾"的负样本，不能随机扰动（"与证据不同"≠"被证据反对"——证据没绑定关系的值只是缺席，属NIE）。我们的范式：**从同表其他行取真实存在的值，绑定到错误主体**（"X功能支持手持设备"，手持真实存在于值域但X行的注册值是{平板,桌面}）。矛盾的存在性依赖**证据侧的绑定结构**而非文本差异——这既是sound性的来源，也埋下了后文"双登记定律"的实验伏笔。N样本的构造对偶：删除支撑span（开放世界下缺席无矛盾）+效果性声明（标记词经全文检索验证缺席）。每条样本携带`label_proof`与可程序复查的check_tokens。

**EGT三态合成：训练数据的文法定律。** 训练残差判定器需要三态标签的监督，而全部现有合成范式（MiniCheck/Auto-GDA/FISCAL）都是二元——矛盾被折叠进"不支持"。我们把上述构造范式推广为三态合成（扰动→refute，删除→NIE），并发现了一个此前未被报告的规律：**合成数据的claim形态分布与标签sound性同等重要**。第一代近拷贝文法（在证据语句上做小改动）在合成分布上dev=0.965、真实迁移仅0.50——模型学到的是"找文本差异"；第二代叙事文法（用真实答案的表述风格断言表格行的值，污染值来自跨行）使refute召回0.375→0.875。**标签对但形态错的训练数据会负迁移**——这是构造性合成的核心方法论教训。

**变异注入：与真实违例的交叉对照。** 48算子对91条真实QA的answer做受控单边破坏（恒等变异守卫、参数从冻结证据派生），期望检出。它与17条真实违例构成互补证据链：合成变异有可控分布（算子×漏检率矩阵），真实违例有生态效度（自然分布+人工确认）。二者的对照产出了本研究最重要的实证发现之一（见§4）。

### 2.3 真实基准：冻结协议与silver标签链

**冻结协议。** 91条真实QA（合作方提供的04号SRS配套数据）的检索证据一经确定即冻结：每个证据块携带`evidence_id/scope/completeness`契约，输入哈希三重记录（源文档/审计/构建），冻结ID=内容哈希。冻结的目的不是工程洁癖，而是**把"检索质量"与"判定质量"解耦**——评测判定器时证据字节级不变，判定错误不能再归因于检索漂移。冻结协议同时强制执行开放世界契约：completeness=closed必须携带穷举证明，且"closed永不从检索命中推断"。

**silver标签链的三步演进及其方法学价值。** 初始双LLM独立标注（两个提供方）得到一个**必须如实面对的数字：Cohen κ=0.227**——LLM标注者在三态边界上一致性很低（"措辞不匹配的叙事声明"一个判矛盾一个判改写）。这个低κ本身是数据：它证明三态边界模糊不是本系统的问题而是任务的本质困难，也直接论证了gold人工标注的必要性。随后升级为单强模型thinking模式全量重裁，协议含三个校验层：claim级分解（每条原子声明独立判定+证据引用）→程序化引用校验（拒绝引用不存在的证据块）→聚合一致性修正（重算并修正3条与声明聚合规则冲突的标签）。终态分布S=6/R=8/N=77，全链显式标记"非gold"。

**真实违例的转化协议。** 17条违例来自对04号文档的深度人工阅读（非自动发现）。转化为评测集的方式有讲究：**answer断言违例内容**（14条，如正逆追踪矛盾取正向一侧断言——自相矛盾的文档使"正确校验行为"唯一化为refute）或**断言应有内容**（3条，证据中的缺陷值反对正确声明，如错别字"平版"反对"平板"）。每条携带`rationale_for_expectation`（期望refute的逐条块级论证）+定位gold——**期望标签本身必须被论证**，"全部期望refute"不是先验而是逐条证明的结论。

### 2.4 公开基准的移植与勘误

移植公开基准的目的不是刷分而是**方法族通用能力的可比性**（外部研究者可以对照复现）。移植原则：统一三态语义映射（entailment→support/contradiction→refute/neutral→NIE）、seed=42子采样按原序恢复（可复现）、训练池与测试零重叠显式校验。

移植中产出一个方法学副产物：**OCNLI官方测试集的标签编码勘误**。文件内prompt文本声称"0=蕴含/2=矛盾"，但两个独立证据（明显蕴含语义锚点对对齐label 2；二值dev子集交叉一致）证明真实编码**相反**（0=contradiction/2=entailment）。处置原则：**文件内声明不可信，以实证映射为准**——这与"closed不从命中推断"是同一认识论：任何声明的语义都要有独立证据。

### 2.5 检索基准的构建（方向一）

**查询构造的演化：泄漏协变量的显式治理。** 表格深度检索基准（438查询×1207表）的查询构造经历三代：初版LLM读表格深部行生成，暴露了**单向量截断盲区测不出**的问题（docT5query从前800字符生成查询，引用内容天然在可见窗口内）且60%为复述式；第二代引入**反拷贝硬约束**（禁逐字4字+/语义化问法/事后overlap过滤），查询-证据overlap均值从0.525降到0.130——**把泄漏程度作为协变量逐查询写入数据集**供分层报告；第三代扩展未覆盖文档并引入**多gold诚实协议**（模板复制产生的近重复文档如实按多gold处理，歧义查询gold=0或>10拒绝）。图片检索（899查询×379图）采用**生成者/使用者双视角**（训练侧docT5query"生成者视角"与评测侧"使用者提问"prompt策略独立）+内容验证式gold（CJK bigram重叠阈值过滤死图）+宿主chunk从训练triples移除（chunk级防泄漏强于query级）。

公开移植（WTQ/FeTaQA/DuRetrieval）承担**模态负对照**角色：DuRetrieval的纯文本短段落上稠密段落级召回优于单元级（0.879 vs 0.837）——为表格单元级检索的适用边界提供了对照证据。

## 3. 评测流程与效度纪律

### 3.1 指标体系：每个指标回答一个特定问题

| 指标 | 回答的问题 | 设计要点 |
|---|---|---|
| R@1/MRR@10（检索） | 证据召回的排序质量 | 多gold取首个命中rank；未命中计入分母（不粉饰） |
| macro-F1（三态判定） | 类不平衡下的均衡判定质量 | **未取整均值为唯一正典口径**——历史上两支工具链的取整分歧由冻结语料逐位复现裁定，防口径漂移 |
| 检出率（违例/注入） | 真实缺陷的发现能力 | 带**目标命中守卫**（rationale级关键词+定位基准=refute claim引用的块）——区分"检出目标违例"与"检出共享证据中的兄弟违例" |
| LLM调用数 | 成本 | 与质量并列报告，构成Pareto而非单点 |

### 3.2 防泄漏纪律：切分→扫参→终评→偏差量化

**切分**：91QA按29个功能主题簇**整簇原子分配**到dev(45)/test(46)——同主题零跨侧（否则"记住该主题"就能在test兑现）；切分只接触question文本与silver标签，不接触任何模块预测。**扫参**：全部阈值网格（60配置）只在dev上跑；实测发现该语料的阈值空间被压平（60配置只出现3个macro-F1值）——可过拟合自由度本身有限，这是数据集的一个内在性质。**终评**：test每配置只跑一次，legacy全91数字直接读既有runs不重跑。**偏差量化**：乐观偏差=legacy自评−held-out同配置，实测**+0.0145（2.0%）**——主动量化代替掩盖；同时诚实处理口径陷阱（修复后代码的混合口径差-0.11被显式标注为"含代码改进效应，不可读作held-out更高"）。

### 3.3 统计检验与功效诚实

全部关键对比用paired bootstrap（1000次/seed=42/同索引重采样/未取整指标）。两个设计细节：每对用各自独立的Random(42)流，使所有对比对的重采样索引相同、p值直接可比；CI取2.5/97.5百分位线性插值。更重要的是**功效诚实**：n=91且refute正类仅8条时单条翻转±0.1 F1——四对内部对比中两对不显著，论文固定措辞"一致改善但个体不显著"，显著性主张显式让位给违例专项集（16/17）与受控对照实验，**不硬拗**。

### 3.4 baseline设计：每行是一个方法族假说

内部六行覆盖完整假说空间：B0多数类（**任务非平凡**——acc 0.846但macro-F1 0.306，防"高准确率=好"的类不平衡谬误）、B1零样本NLI（**域差距**真实存在）、B2 LLM直推（"直接用LLM"的上限）、B3纯符号（专家贡献）、B5纯LLM残差（无专家时L3的行为）、B4全配置（成本上限）。公开五行覆盖方法族：嵌入法（BGE三元中心——docstring如实暴露"嵌入对称性无法区分矛盾/中立"的结构弱点，不做双阈值粉饰）、中文NLI零样本、多语言NLI零样本、公开监督（CMNLI微调）、LLM直推。**所有行列共用同一评测内核**，保证可比性。

### 3.5 消融的因果归因

最强配置上一次只关一个组件（单变量差分），中性结果**如实报告并归因**——id_join在91QA上消融中性（仅1次claim级触发且被冗余覆盖），其价值由17违例集承载（5/5检出）：**两个评测集互补构成组件贡献的证据链**，单一数据集的消融表不足以定论。

### 3.6 复现协议

每次实验落runs目录：config+**git_sha**+config哈希+result（永不覆盖写）——复现的第一要素是知道跑的是哪版代码。LLM调用全走磁盘缓存（键=模型+消息+参数的哈希；同prompt重跑零成本零漂移——这是对"LLM不可复现"的结构解药）；调用计量三角（invocations/api增量/缓存命中）区分"逻辑成本"与"真实API成本"。回归锚点：关键数字的缓存复现断言（B2=0.6105逐位复现）、跨文档06号子集与旧run的逐位一致检查。fp16训练非确定性（±0.05 macro-F1）作为已知风险如实披露。

### 3.7 效度保证链

```
标签可证（防噪声当真值） → 防泄漏（防dev-on-test） → 统计检验（防随机波动当差异）
→ 复现协议（防缓存漂移/版本混淆） → 多评测集互补（防单集偏差定论）
```
每环防一种特定的效度威胁；任一环缺失都会使下游环失去意义。

## 4. 对照实验：方法辖区的科学划分

三组核心对照，每组控制变量回答一个科学问题：

**(a) 公开数据 vs 域数据**：同基座（mDeBERTa）、同推理口径，唯一差异是训练数据（公开CMNLI 50k vs EGT构造4.5k）。结果：公开监督在公开列最强（0.867）但在域列崩塌（0.276，**refute F1=0**）——公开数据≠域数据，且崩塌模式（完全不识别矛盾）比总分更能说明分布错配的本质。

**(b) LLM的任务形态辖区**：同一个GLM-5直推，在构造性任务上0.888（全场最强），在17条真实违例上0.118（**2/17，12个假support**）。构造性任务是单侧干净声明——LLM直读即判；真实违例是**跨位置双登记**（同ID两处冲突、正逆追踪矛盾），矛盾的每一半单独看都无辜，**矛盾信号只在结构化join后才浮现**。同一模型在两种任务形态上的翻转是"方法辖区划分"的最直接实证——它同时解释了为什么纯LLM路线在这类文档上不可行、为什么符号层的证据侧聚合是先决条件。

**(c) 级联的成本-质量Pareto**：B3（0次调用，refute精确1.000但召回0.625）、B4（83次，召回0.875但精确0.778）、级联（**15次=18%成本，精确1.000且F1=0.857全场最优**）。路由的关键洞察：L2的唯一失败模式是高召回低精确——所以LLM只需要为**伪refute候选**付费，support/NIE直通。升级粒度经过claim级→实例级的踩坑修正（claim级升级会漏：NLI的refute旗子可能插在错误的claim上而真矛盾claim被判NIE——升级整个实例的残差集后L3能同时看到两者）。

**双登记定律**（贯穿(b)与变异注入矩阵）：证据侧双登记冲突检出率1.0，answer侧单边破坏0.05-0.53（394注入对照）。它给出的不只是性能数字，而是**层间分工的理论依据**：符号层专责证据内部冲突（join可裁决），answer-vs-证据的语义比对归神经层——两者的失败模式互补。

## 5. 核心结果（定稿表格）

**表1 证据召回 R@1**（438自建查询+WTQ/FeTaQA/DuRetrieval）：Ours 0.486（自建表格深度检索）/0.464（WTQ）/0.954（DuRetrieval），对比BM25/BGE/LightRAG四基线。

**表2 答案一致性校验 macro-F1**（5外部baseline×5数据集：XNLI-zh/OCNLI/CMNLI-test/自建91QA/跨文档×5）：CMNLI微调公开列最强（0.810/0.867）域列崩（0.276）；GLM-5构造列最强（0.888）；**Ours级联域列最优（0.786）**。

**表3 真实违例与成本**：B3与Ours级联均16/17（94.1%）；GLM-5直推2/17；级联refute精确率1.000@15次调用（B4为0.778@83次）。

**held-out与偏差**：test=0.829（29簇切分终评）；dev-on-test乐观偏差+0.0145（2.0%）。

**消融**（最强配置单变量）：per-claim融合-0.152（单一最大）、L3残差-0.088、E1专家-0.039、enum_join-0.026。

**统计检验**：B4 vs B5 +0.166 [+0.067,+0.307] p<0.001；B4 vs B2 +0.264 p=0.002；B4 vs B3 +0.154 p=0.076（功效诚实：不显著）。

## 6. 方法论总结（可迁移的设计思想）

1. **构造性标签的sound性来自证据侧结构，不是文本差异**——"与证据不同"≠"被证据反对"；矛盾的存在性依赖绑定/注册结构，这决定了负样本构造必须结构感知。
2. **合成数据的形态分布与标签同等重要**——文法定律：标签对但形态错的训练数据会负迁移。
3. **标注者间κ是任务难度的测量，不是要隐藏的尴尬**——κ=0.227直接论证了任务本质困难与gold必要性。
4. **期望标签本身需要论证协议**——"全部期望refute"是逐条证明的结论不是先验。
5. **公开基准移植要带勘误精神**——文件内语义声明需要独立证据（OCNLI编码勘误）。
6. **泄漏治理的最高形式是协变量化**——不是删除泄漏而是测量它、写入数据集、分层报告（overlap 0.525→0.130的治理史）。
7. **辖区对照优于全面胜利**——诚实的评测表应该展示每个方法族的辖区边界，而不是某个方法的全胜。
8. **复现是效度的地基**——git_sha+config哈希+LLM缓存+永不覆盖写，四个机制各防一种证据链断裂。

### 7.3 诚实性声明
