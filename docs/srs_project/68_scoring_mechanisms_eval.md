## 二、简化原则

```text
旧(67号前):  级联的每层有自己的私有决策逻辑(三支规则/阈值/豁免)
新(本框架):  一切决策 = score(pair) ∈ [0,1] + 阈值τ 或 预算B

  score(pair) = f(七种打分器中选若干个)
  冲突检测:  score > τ_conflict → 报告
  去重压缩:  score > τ_dedup    → 合并簇
  级联的本质只剩"成本": 先跑0.02ms的, 不确定再跑60ms的
```

**打分器是可插拔的**——新打分器只需实现`(left, right) → float`。

## 三、打分方式调研：七家族

| # | 打分器 | 文献家族 | 本地实现 | 成本 |
|---|---|---|---|---|
| 1 | **rule_scope** | Fellegi-Sunter(1969)固定比较规则 | 作用域线索相等=1/未知=0.5/异=0 | 0.02ms |
| 2 | **lexical_jaccard** | 串相似度家族(Cohen et al. 2003: Jaccard/Jaro-Winkler/编辑距离) | 字符二元组Jaccard | 0.02ms |
| 3 | **template_mask** | 归一化编辑距离(结构相似) | 数字掩码后SequenceMatcher比率 | 0.02ms |
| 4 | **section_proximity** | 层级距离/路径相似(ER blocking键邻接) | 层级加权距离的倒数 | 0.02ms |
| 5 | **bge_cosine** | 句向量语义相似(SBERT系, Reimers & Gurevych 2019) | BGE-large-zh本地GPU+磁盘缓存 | 0.16ms(缓存)/9ms(冷) |
| 6 | **nli_contra** | NLI-as-scorer(FEVER的RTE通道) | mDeBERTa双向矛盾概率max | 60ms |
| 7 | **combined** | 线性融合(FS似然比简化型) | 4信号等权平均 | ≈最贵分量 |

**template_mask是本文新提出的信号**：SRS不一致的高发成因是复制粘贴漂移
（同模板改值），把数字挖掉后句式完全一致=强漂移嫌疑。

### 三个典型案例（标签的判断依据）

**案例A(doc10, 真冲突)**——GJB平行表漂移：
```text

3.10.1 表84: 便携式计算机（国产化）CPU主频不低于2.5Hz
→ 同一设备, GJB标准要求平行的运行环境表/硬件配置表, 值漂移 = 真不一致
```

**案例B(doc02, 需澄清)**——同模板异值跨用例：
```text
1.8.2.1(用户登录用例):    首屏≥2秒, 用户响应≥3秒
1.8.5.1.1(主界面组件展现): 首屏≥3秒, 用户响应≥5秒
→ 同参数名"用户响应时间"不同值; 每功能各自定值是合理设计,
   但未显式限定作用域 → 一致性味道, 需求评审应要求澄清
```

**案例C(doc14, 合理差异)**——配置表不同设备：
```text
便携式服务器:   DVI 1600×1200 + VGA 1280×1024   (表46与表47一致)
便携式计算机:   1280×1024                        (两表一致)
→ 16份SRS共享同一硬件清单模板; 不同设备行=合理差异
→ 作用域提取失败(裸"显示"线索)导致误报为强候选
```

**抽取错误类(12对)**：availability表面词"可靠性"误命中参考文献表
（GJB 450A-2004的2004被当参数值）、追踪表章节号、优先级数字。

## 六、五个发现

### 发现1：融合是唯一完美分离器（AUC-strict=1.000）

doc10真冲突在**所有信号上都高分**（rule=1.0, template高, BGE=0.94,
NLI=0.996），而每类假阳性都**至少在一个信号上失败**：
- 配置表合理差异：rule_scope低(0.17)
- 抽取错误：lexical极低(0.09)
- 作用域未知噪声：rule=0.5被拉低
→ **信号互补性 > 任何单一信号**——弱监督理论(66号支柱2)的实证。

### 发现2：NLI是矛盾探测器，不是作用域判别器

NLI对真冲突给出0.996，但对合理差异也给出0.816——
"i7四核2.0GHz" vs "16核1.5GHz"被NLI判为矛盾（两句确实不能同真），
**但它们描述的是不同设备**。NLI看不到行首的设备名（作用域）。

→ 这实证了64号的架构决策：NLI只能做S3残差信号（在作用域已确认后
判"值是否矛盾"），不能做独立ranker。**花钱最多的信号(60ms)单独用
反而最差(smell视图0.608)。**

### 发现3：廉价的确定性规则是工程最优（AUC-smell=0.939, 0.02ms）

rule_scope比BGE和NLI都便宜3000倍，却在smell视图领先。
**精度瓶颈不在打分方式，在作用域绑定**（65号结论再次实证）。

### 发现4：章节邻近是反信号（AUC-strict=0.224）

反直觉但符合GJB结构：真冲突恰恰发生在**跨章节**的平行表之间
（3.9.1运行环境 vs 3.10.1硬件配置），而合理差异集中在**同章节**的
配置表内。→ 好的特征在错误的方向上很强——教科书级的特征工程教训。

### 发现5：成本谱系决定级联顺序

```text
0.02ms(rule/lex/templ) → 0.16ms(bge,缓存命中) → 60ms(nli)
   3000倍差距 → 级联的意义=成本, 不是决策逻辑(第二节简化原则的实证)
```

## 七、去重打分（同接口的另一应用，设计+初数字）

去重=冗余检测，与冲突检测共用打分接口但用**相似方向**的信号：

```text
冲突打分:  同实体+异值 → 矛盾信号(nli_contra/rule_scope高=嫌疑)
去重打分:  同实体+同值/同信息 → 相似信号(template/bge/lex高=合并)

S1已产出的冗余对: 273对(值完全相等, 零成本确定)
近重复对(同信息异表述): template_mask>0.95 且 bge>0.95 的簇
  → doc02的1.8.2.1与1.8.3.2(同文异处)正是此类
```

**初数字**：273对确定性冗余=零成本去重已压缩12.6%的原子
（346→~73实体级条目待聚类验证）。

### 排错的两个基础设施bug（记录供复现）

1. **torch/numpy加载顺序**：`import torch`必须先于
   `algorithms.context_linking`的numpy链，否则Windows下OpenMP运行时
   (libiomp5md.dll)冲突→CUDA推理静默崩溃。eval脚本顶部已加顺序注释。
2. **mode字符串**：`BgeLocal/NliLocal.ensure()`成功返回`"cuda"`而非
   文档字符串声称的`"gpu"`——检查`in ("gpu","cpu")`会永远失败。
   （库层文档与实现不一致，已在调用侧兼容，库修复另立任务。）

## 九、诚实声明（实验局限）

1. **规模**：48对, 正例7(smell)/1(strict)——统计功效极低, AUC置信区间宽
2. **单标注者**：本人标注, 无第二标注者IAA
3. **P@7受并列影响**：rule_scope的1.0有运气成分(第五节注)
4. **AUC-smell含抽取错误为负类**：若排除, 语义打分数会上升
5. 结论方向可信(信号互补性/作用域瓶颈), 具体数字需扩标验证
