# 64 NLI角色冲突分析与修正：信号独立的三层架构

日期：2026-10-27 | 状态：矛盾已解决，框架已修正

---

## 一、你发现的问题，精确定义

不是“同一个模型干两件事”——是**误差相关的自确认循环**：

```text
NLI(粒子A, 粒子B) = contradiction
  → 升权送下游
  → 下游再用NLI(证据, answer_claim)判定
  → 两次NLI共享粒子A → 误差相关
  → 选择器的假阳性直通Finding，不被纠正

更严重的是：
  NLI(粒子A, 粒子B) = entailment
  → 删除粒子B
  → 下游永远看不到粒子B
  → 选择错误不可恢复
```

**违反的原则**：最终判定V不得是选择信号S的确定函数（信号独立性）。

---

## 二、文献怎么处理的

| 系统 | 选择用什么 | 检测用什么 | 分离原则 |
|---|---|---|---|
| FEVER | 与claim的**相关性排序**(SBERT) | NLI | 选择器不消费判定信号 |
| TabFact | 无选择（整表给定） | 表格NLI | 天然回避 |
| AVeriTeC | verdict与evidence质量**分开评分** | — | 判定对≠证据对 |
| Self-RAG | ISREL token | ISSUP token | 架构共享，信号按任务分离 |
| 多跳QA | 最终答案弱监督 | 中间NLI | NLI从不当选择器 |

**铁律**：选择器不消费判定信号；判定不条件于选择器独有信号。

## 三、修正方案

### 核心原则

```text
让结构信号选（确定性、免费、误差与NLI不相关）
让符号/级联判（既有CascadeVerify不动）
NLI只在没有结构的地方喊"可疑"——喊完必须由别人核实
```

### 修正后的框架

```text
top-50 → Atomizer拆成粒子
  ↓
[选择层：非NLI信号的三支决策]
  S1 结构匹配（确定性，免费）：
     同参数+同值   → 冗余簇（删除，留代表）
     同参数+不同值 → 冲突候选（升权）
     不同参数     → 互补（保留）
     信号源: GJB词典23参数 + 10单位族 + ID join

  S2 BGE相似度（预计算，免费）：
     高cos + 同owner → 冗余
     中等cos       → 保留
     信号源: feature_snapshot_v1的27473×1024维

  S3 残差NLI（仅结构判不动的文本对，~几十对/查询）：
     contradiction → 候选标记（升权，但非结论）
     entailment   → 冗余候选（待S1/S2交叉确认）
     neutral      → 保留
     信号源: 本地mDeBERTa
  ↓
VerificationPack（每个conflict_pair标注来源：struct/bge/nli）
  ↓
[检测层：既有系统，不消费选择信号]
  L1 确定性专家 + Z3 → 独立裁决数值约束
  L2 残差NLI（证据 vs answer_claim，元组≠粒子对）
  L3 LLM升级复检
  ↓
Finding（附确认通道归因：struct_confirmed / bge_confirmed / nli_pending）
```

### 三层信号独立

| 层 | 信号类型 | 误差特征 | 成本 |
|---|---|---|---|
| S1 结构匹配 | 确定性规则 | 无误差（或已知精确规则误差） | 免费 |
| S2 BGE相似 | 嵌入距离 | 嵌入空间误差 | 免费（预计算） |
| S3 残差NLI | 语义蕴含 | NLI模型误差 | ~50ms/对（仅残差对） |
| L1 符号检测 | Z3/规则 | 无误差 | 免费 |
| L2 NLI检测 | 证据vs claim | NLI模型误差（与S3不同输入） | ~50ms/对 |
| L3 LLM复检 | 生成式 | LLM误差 | ~2s/对 |

**关键**：S3和L2虽然都用NLI模型，但**输入元组不同**（粒子对 vs 证据-claim对），误差不相关。且S3的输出只是“候选标记”，必须经L1或L3确认才成为Finding。

## 四、具体例子

### 例子1：参数冲突（S1直接处理，不需要NLI）

```text
粒子A：{参数名:响应时间, 操作符:≤, 值:200, 单位:ms}  来源: 表2行3
粒子B：{参数名:响应时间, 操作符:≤, 值:500, 单位:ms}  来源: 正文3.2.1

S1结构匹配：
  参数名相同 + 值不同 → 冲突候选
  处理：升权，标注 source=struct
  Z3验证：200 ≤ 500 → 两约束不矛盾但不同 → 送方向B判定
  NLI完全不需要参与
```

### 例子2：文本冗余（S2处理，不需要NLI）

```text
粒子A："提供SQL访问功能"  来源: 表2行1
粒子B："提供原生SQL访问功能"  来源: 图3节点1

S2 BGE相似度：
  cos(A,B) = 0.91 → 高相似 + 同owner区
  处理：冗余簇，保留信息量更大的B
  NLI不参与
```

### 例子3：真正的残差（S3才用NLI）

```text
粒子A："系统应支持数据归集功能"  来源: 正文3.2.1.2
粒子B："数据归集包含结构化和非结构化两类"  来源: 合格性表行12

S1结构匹配：无法对齐（一个是功能声明，一个是分类描述）
S2 BGE相似度：cos = 0.54 → 中等，不确定

S3 残差NLI：
  NLI(A, B) = neutral → 互补，保留
  NLI(B, A) = neutral → B不包含A的信息
  处理：两个都保留
```

### 例子4：S3标记冲突但需下游确认

```text
粒子A："软件部署在各级机构的信息处理设备上"  来源: 正文1.2
粒子B："软件部署在服务器和客户端两类设备上"  来源: 3.10环境需求

S1结构匹配：无法对齐
S2 BGE相似度：cos = 0.42 → 低

S3 残差NLI：
  NLI(A, B) = contradiction → 可能冲突
  处理：标记为候选，source=nli
  下游：L3 LLM复检 → 确认是否真冲突
  （不能因为NLI说了contradiction就直接出Finding）
```

## 五、与63号（E-Atom原始设计）的对比

| 方面 | 63号原设计 | 64号修正 |
|---|---|---|
| 选择信号 | NLI三支 | 结构匹配→BGE→残差NLI（层级递进） |
| NLI角色 | 主要选择器 | 仅残差选择器（S3，占少数对） |
| 检测信号 | 未明确 | 符号/级联（L1-L3，独立于选择层） |
| 循环风险 | 高（选择和检测共享NLI） | 低（结构/BGE选，符号/级联判） |
| NLI调用量 | top-50全粒子对(~3000对) | 仅残差对(~几十对/查询) |
| 可解释性 | NLI输出难解释 | 结构匹配可解释(参数名+值+单位) |
| 成本 | 高(~150s/查询) | 低(~几秒/查询) |

## 六、修正后的论文叙事

> **信号独立的三层证据精选**：
> 1. 结构信号选（确定性、免费、可解释）
> 2. 嵌入信号选（预计算、廉价）
> 3. NLI仅在结构盲区标记可疑（升权但非结论）
> 4. 检测层独立于选择层（符号/级联裁决）
> 
> **不是NLI做一切，是各层做各的事。**
