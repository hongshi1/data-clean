> v0.1 调研+设计 | 2026-11-23 | 触发: 用户洞察"召回本质是一个question对应一张图片，在图片中做切片召回"

## 0. 一句话定位

**召回的本质是三层固定/半固定关联，而非全库自由检索**：
(question ↔ evidence image) 是数据集给定的**固定关联**；真正的算法问题是 **问题文本 → 图内切片**（grounding式召回，方向A）与 **答案声明 → 切片观测比对**（验证式校验，方向B）。两者恰好对应研究项目的方向A/B分工。

---

## 1. 数据模型的本质（当前系统真实结构）

### 1.1 三层关联

```
层1  QA↔Image     固定关联（数据集给定: 每个QA对携带evidence image）
                  ——不是检索问题, 是证据绑定
层2  question→chunk  图内召回（真正的算法问题）
                  "右侧人员未佩戴安全帽" → {人员#3(x=68%), 安全帽#3(NO-Hardhat)}
                  ——约束解析+切片选择, grounding
层3  跨QA聚合     实体/图像共享 → 图谱k-hop激活（现有graph层）
                  ——浏览式宏观关联, 非证据定位
```

**关键认知**: 层2是校验的前置（方向A产出检测对象），层1已经由数据集解决。我们此前把"召回"主要做在了层3（k-hop图谱），而**校验真正需要的是层2的图内切片召回**——即用户指出的本质。

### 1.2 当前实现的两层错位

| 需求 | 现状 | 缺口 |
|---|---|---|
| 层2切片召回 | `_real_chunks_for_image`返回**全量**chunk（不筛选） | 无"该问题相关的切片"排序/过滤——召回数据"全而不准" |
| 空间接地 | `_demo_person_bbox`的left/right词（模拟遗留） | 真实chunk无空间约束解析（"右侧人员"无法定位到具体框） |
| 声明比对 | `_STATUS_MAP`答案极性×观测状态三态 | 未分解声明（"右侧人员"的spatial+state组合无法逐项核） |

## 2. 相关工作定位

### 2.1 任务形态同构的工作

| 工作 | 任务 | 与我们的同构 | 与我们的差异 |
|---|---|---|---|
| **SNLI-VE** (Xie et al. 2019, visual entailment) | premise=图像, hypothesis=文本 → entail/contradict/neutral | **三态语义完全同构**(support/refute/NIE) | 其premise是整图embedding; 我们的premise是**结构化chunk观测**(可解释、可定位) |
| **NLVR2** (Suhr et al. 2019) | 语句-图像对 → true/false | 语句↔图像核验形态相同 | 无chunk级证据链; 我们要求"哪个框支撑/驳回" |
| **RefCOCO系** (referring expression comprehension) | "右侧的人"→bbox | 层2接地的子问题 | REC只做定位不做属性核验; 我们要"定位+属性+计数"联合 |
| **FEVER/多模态事实核验** (Fakeddit等) | evidence retrieval→claim verification管线 | 管线同构(检索→核验) | 其evidence=文档段落; 我们=图内切片(空间约束是新维度) |
| **88/91号文档** (声明分解+聚合) | per-fact分解→判定→聚合 | 直接复用其结论 | 其面向文本证据; 需扩展视觉观测侧 |

### 2.2 差异定位（可写进论文的贡献点）

1. **检索单元是"图内约束切片"**：召回=约束解析(τ实体/σ空间/α属性/κ计数)→切片过滤排序，非dense全库检索——监督场景问题模板固定（"XX区域/位置人员是否YY"），约束解析比稠密检索更准且可解释。
2. **三态NIE的显式原因学**：不可核验≠失败，NIE带原因标签（时序型/观测缺失/指代歧义），对应需求工程"无法判定"的可解释语义——88/91的聚合设计已预留此接口。
3. **声明-切片-观测的闭环**：真实CV检测(real_cv)使观测侧不再是模拟，声明↔观测矛盾真实可检（已验证：接入真实检测后refuted 1→6）。

## 3. 方向A算法：约束解析召回（Constraint-Parsing Chunk Recall）

### 3.1 问题形式化

给定问题 q 与其证据图的全部切片 `C(img) = {c₁...cₙ}`（person/ppe chunk，含bbox/置信/姿态/佩戴状态）：

```
召回(q) = argmax_{c ∈ C(img)} score(c | W(q))
W(q) = {τ实体类型, σ空间约束, α属性约束, κ数量约束}
score(c) = w₁·m_τ(c) + w₂·m_σ(c) + w₃·m_α(c) + w₄·conf(c)
```

### 3.2 约束解析器（question → W(q)）

- **规则层（P1可实现，词表已有基础）**：
  - τ：NER词典（人员→person chunks；安全帽→ppe/helmet）——`KG_NER_DICT`/`ENTITY_TYPES`现成
  - σ：右侧/左侧/中间/画面边缘 → x分位约束（x>67% / x<33% / 33-67%）——`_LEFT_WORDS/_RIGHT_WORDS`升级为分位过滤
  - α：未佩戴/佩戴/倒地/趴伏 → state/pose约束
  - κ："N人/多人/所有人员" → 计数约束（所有→全称量词）
- **升级层（P2）**：少样本LLM解析（Qwen2.5-1.5B在栈内）→ JSON约束模式输出，规则层做兜底与校验。

### 3.3 切片匹配器

| 匹配项 | 实现 | 数据来源（已有） |
|---|---|---|
| m_τ | chunk类型匹配（person/ppe） | real_cv chunks的`type`字段 |
| m_σ | bbox中心x坐标分位 | real_cv bbox（像素坐标） |
| m_α | `wearing_state`/`pose`字段 | real_cv（真实YOLO输出） |
| κ不足 | 命中数<声明数 → NIE候选（观测缺失） | 计数比对 |

### 3.4 与图谱k-hop的关系（不是替代）

- 层2约束召回 = **微观证据定位**（校验的输入）；层3 k-hop = **宏观跨QA浏览**（图谱视图交互）。
- 现有架构两者并存：`activate` API（k-hop）保留；新增**切片召回API**（约束式）服务校验管线。
- 这也回应"召回数据不全"的体验问题：图谱视图的召回=层3；校验用的召回=层2，两者不该混用同一topK截断逻辑。

## 4. 方向B算法：分解-接地-校验（Decompose-Ground-Verify）

### 4.1 管线

```
答案声明("画面中右侧人员未佩戴安全帽")
  →① 分解: 原子声明 = {主体:人员, 空间:右侧, 客体:安全帽, 状态:未佩戴}
  →② 接地: 主体+空间 → 具体chunk(人员#3, x=68%)          ← 方向A的召回结果
  →③ 观测: 该chunk关联的ppe观测(NO-Hardhat, conf=0.72)
  →④ per-fact判定: 声明状态(未佩戴) vs 观测状态(Hardhat) → refute
  →⑤ 聚合: 全部原子声明 → verdict(support/refute/NIE)     ← 91号文档的assertion-aware聚合
```

### 4.2 三态语义与NIE原因学

| verdict | 条件 | 已有实例（真实数据验证） |
|---|---|---|
| support | 全部原子声明与观测一致 | QA"画面中无人员"↔ppe_c1_002真实检测0人 |
| refute | ≥1原子声明矛盾 | QA"有人员未佩戴"而YOLO观测全员Hardhat（refuted 6条） |
| NIE | 不可核验，带原因标签 | (a)**时序型**：睡岗"长时间静止"单帧不可证（44条中已按此输出） (b)**观测缺失**：κ不足 (c)**指代歧义**：σ无法唯一接地 |

### 4.3 NLI回退层

结构化约束覆盖不了的声明（复杂表述/复合事件）：
- **premise** = 序列化观测（"检测到5人；人员#3位于右侧(68%)佩戴Hardhat(0.72)..."）
- **hypothesis** = 答案声明文本
- Erlangshen-330M-NLI → entail/neutral/contradiction → support/NIE/refute
- 注意复用64号文档的**标签映射纠偏教训**（0=CONTRADICTION, 1=NEUTRAL, 2=ENTAILMENT——接反则全盘颠倒）
- 规则层优先、NLI兜底的级联=场景1 CascadeVerify范式的迁移（75号文档的既定路线）。

### 4.4 与17项引擎的关系

- 现有`_STATUS_MAP`（答案×观测三态）= 该管线的**规则v0**（不接地、不分解、全图聚合）。
- 算法化升级 = C-3跨模态检测从"答案极性×任意观测"细化为"**per-claim接地核验**"——发现力提升的直接来源（refuted 1→6已示范）。

## 6. 开发路线（建议优先级）

**P1 约束解析召回（直接缓解"召回不全/不准"）**
1. 新增约束解析器（规则版）：question → `{τ, σ, α, κ}` JSON
2. chunk过滤排序：`recall_chunks(image_id, W(q))` 按score排序返回
3. 前端召回组接入：召回内容按"与问题相关的切片"排序（替代全量平铺）
4. 测试：20对人工标注期望命中切片 → 命中率

**P2 声明分解+接地校验（升级C-3为per-fact）**
1. 答案声明分解器（规则+少样本LLM双路）
2. 接地：原子声明主体+σ → 具体chunk（P1的召回结果）
3. per-fact判定 + NIE原因标签
4. 快照测试：44 QA对的verdict冻结（当前refuted=6为基线）

**P3 NLI回退 + 聚合（91落地）**
1. 序列化观测 → Erlangshen NLI → 三态映射（复用64号标签纠偏）
2. assertion-aware聚合接入17项引擎总报告

## 7. 评测设计

- **召回（方向A）**：约束→切片命中率（人工标注20对：期望切片集合的Precision/Recall）
- **校验（方向B）**：44 QA对verdict vs 答案标签混淆矩阵（support/refute/NIE三分类），与`_STATUS_MAP` v0基线对比
- **可解释性**：per-fact证据链（哪个chunk、什么属性、为何矛盾）逐条可追溯——图谱视图的跨模态映射卡片即展示层

## 结论

用户的本质洞察把系统从"图谱式全库召回"校正为"**固定QA↔图 + 图内约束切片召回**"：
- 方向A=约束解析召回（τ/σ/α/κ → 切片过滤排序），与SNLI-VE/REC/NLVR2定位差异在"结构化约束切片"这一检索单元；
- 方向B=分解-接地-校验（声明→原子→切片→属性比对→三态聚合），三态NIE显式原因学是需求工程侧的可写贡献；
- 两者在现有代码上均有清晰落点（P1/P2/P3），real_cv真实检测已使观测侧就绪。
