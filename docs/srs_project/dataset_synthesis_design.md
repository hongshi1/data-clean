# 数据集合 成方案与可信度论证

> 基于多Agent调研（4个Agent并行：多模态QA合成方法/SRS领域数据集/合成数据可信度/AI基础设施）
> 日期: 2026-08-18
> 定位: 路线二（数据集合成）的方案设计与可信度论证

---

## 一、调研结论（4个Agent核心发现）

### 1.1 注入式合成有学术先例且被顶会接受

**CrossCheck-Bench（AAAI 2026, arXiv:2511.21717）**：从真实图文素材出发，合成注入矛盾（synthetically injected contradictions），经450+专家小时多阶段标注校验，含15K QA对，覆盖感知/整合/推理三层、七种原子能力。与我们"真实Pair+规则注入"的方法高度一致。

**FRED（arXiv:2507.20930）**：在金融QA语料中按用户定义的错误分类法插入标签化错误（inserting tagged errors），gold标注由规则确定（因为错误是规则插入的，答案天然确定）。与我们的"答案由规则确定"完全一致。

**PIE-V（arXiv:2604.15134）**：将"错误规划（心理学规则）"与"文本改写（LLM）"分离，规则保证可控性、LLM保证流畅性。与我们的四段式（事实提取→规则注入→LLM改写→双LLM验证）结构一致。

### 1.2 纯LLM生成已被证伪，混合策略是可行路径

**Korn 2026（arXiv:2606.25550, AIRE'26）**：LLM无法可靠(i)生成高质量需求(ii)合成注入requirement smells(iii)检测smells，单人或单LLM都不够。后续解决方案：**规则注入保证逻辑真值 + LLM仅改写表层语言 + 人工抽检校准**的混合策略。这正是我们的四段式方法。

**LLM-Modulo（Kambhampati et al., arXiv:2402.01817）**：LLM提议+外部验证器约束，比直接在合成数据上训练更鲁棒。我们的Z3验证gate就是这个"外部验证器"。

### 1.3 Z3验证合成矛盾是前沿且被验证的方法

**VERIMED（Hall & Eiers, 2026, arXiv:2605.13817）**：用LLM将需求译为形式逻辑，再用SMT求解器查询不可满足性（UNSAT），经反例引导修复把验证准确率55.4%→98.5%。我们已有Z3实现（tools/srs_consistency_checker_v2.py），可以直接复用此范式。

**SAGE（arXiv:2605.02545）**：构建"solver-verified"数据集——用求解器证明合成矛盾真不可满足。与我们P4/P5/P6注入后跑Z3验证unsat完全一致。

**Adedeji et al.（2026, arXiv:2607.24275）**：将伦理需求形式化为deontic时序逻辑，用Z3做反例验证。

### 1.4 中文SRS数据集完全空白

arXiv检索"GJB"返回0条，"Chinese requirement NLP"返回0条有效结果。中文军事/国防SRS的NLP研究为零覆盖。**我们的16份真实GJB 438C中文SRS（490K字符）是稀缺独有资源，无任何竞品。**

现有需求工程数据集对比：

| 数据集 | 语言 | 规模 | 模态 | 矛盾检测 | 真实矛盾 |
|--------|------|------|------|---------|---------|
| QuRE (2025) | 英文 | 2111条 | 纯文本 | 词汇级smell | ❌ 合成 |
| PURE (2017) | 英文 | 79篇 | 纯文本 | 无 | ❌ |
| CrossCheck-Bench (2026) | 英文 | 15K QA | 图文 | 跨模态矛盾 | 真实+注入 |
| TSRCDF-SS (2025) | 英文 | 句对 | 纯文本 | 句对冲突 | ❌ 合成 |
| **我们** | **中文** | **16份SRS** | **图+表+文** | **四类不一致** | **31个双源验证** |

### 1.5 合成数据可信度的最强组合

四个Agent一致认为：**"规则注入保证逻辑真值 + Z3求解器形式化验证UNSAT + 确定性锚点双源验证 + 最小人工alt-test锚定"**，而非依赖LLM自证一致。

## 二、合成方案设计

### 2.1 目标

为我们的检测器（路线一）构建一套评测集，证明"检测器能检出25项A类跨位置不一致性"。评测集不是微调训练集，是**检测能力的验证基准**。

### 2.2 25项A类校验（我们的检测范围）

从实施方案文档的40项校验中筛选出25项"跨位置/跨模态不一致性"（A类），排除15项"单位置内容质量审查"（B类）：

| 层 | A类项数 | 具体校验项 |
|---|:---:|------|
| 术语 | 8 | 同义异名/同名异义/枚举集合/状态告警术语/指令名称/量纲单位/信号接口命名/缩写代号 |
| 参数 | 10 | 时间约束/周期参数/阈值边界/融合对齐/资源占用/值域范围/存储时长/守时精度/降级阈值/故障时长 |
| 逻辑 | 6 | 模式切换优先级/异常处置策略/事件时序/数据流流向/工况分支完备性/权限访问控制 |
| GJB合规 | 1 | 需求可追溯性 |

### 2.3 评测集数据结构

每条评测数据包含：

```
{
  "id": "eval_0001",
  "pair_id": "1_004",
  "doc": "02界面集成框架...",
  "section": "1.8.1",

    "entity": "开发工程生成",
    "entity_id": "PZXQ-GN-JMKFKJ-JMKF-KFGCSC",
    "occurrences": [

      {"location": "text", "section": "3.2.1.1", "text": "3.2.1.1 创建服务工程"},
```

### 2.4 合成流程（五阶段）

**阶段1：检测对象提取**

从366个Pair实例中提取检测对象。每个检测对象 = 一个实体在文档中所有出现位置的聚合。用现有的上下文关联（双图融合4通道，recall=0.809）完成。

提取5类检测对象：
- 功能名+ID（用于术语层8项校验）
- 接口属性（用于参数层接口属性校验）
- 数值参数（用于参数层10项校验）
- 流程步骤（用于逻辑层时序校验）
- 表头字段（用于GJB合规层校验）

预计产出：约2000个检测对象。

**阶段2：正例构造**

对每个检测对象，确认其在图/表/文中的表述一致，构造正例。用字符串匹配/集合比较/数值归一化方法检查一致性。如果一致，标注为正例（label=consistent）。

预计产出：约600条正例。

**阶段3：负例构造（注入不一致）**

对每个检测对象，用32种注入方法制造不一致。每条负例的gold_label由规则确定（不是LLM判断），可追溯到method字段。

32种注入方法与25项校验的对应：

| 校验项 | 注入方法 | 注入操作 |
|--------|---------|---------|
| 术语①同义异名 | T1错字/T2截断/T3字序 | 功能名字符级修改 |
| 术语②同名异义 | T4多名 | 两ID同名 |
| 术语③枚举集合 | T8枚举缺失 | 删减模式集合 |
| 术语④状态告警术语 | T9告警术语 | 同一状态换术语 |
| 术语⑤指令名称 | T1变体 | 指令名改字 |
| 术语⑥量纲单位 | P2单位替换 | 单位换不换算 |
| 术语⑦信号接口命名 | T1变体 | 接口名改字 |
| 术语⑧缩写代号 | T6缩写 | 全称换缩写 |
| 参数①-⑩全部 | P1数值翻倍/P3属性交换/P4操作符/P5值域/P6精度 | 数值/属性/操作符级修改 |
| 逻辑①模式切换 | L9模式切换冲突 | 优先级矛盾 |
| 逻辑②异常处置 | L2异常流悬挂 | 引用不存在E编号 |
| 逻辑③事件时序 | L1步骤交换 | 步骤顺序交换 |
| 逻辑④数据流流向 | L7数据流反转 | 方向反转 |
| 逻辑⑤工况分支 | L8分支删除 | 删降级分支 |
| 逻辑⑨权限控制 | L10权限矛盾 | 权限放宽 |
| GJB⑤需求可追溯性 | G4追溯链断裂/G1字段缺失 | 追溯表/字段缺失 |

预计产出：约600条负例。

**阶段4：评测集组装**

按25项校验×四类不一致组织。每项至少10条正例+10条负例。

| 类别 | 校验项数 | 预计正例 | 预计负例 | 合计 |
|------|:---:|:---:|:---:|:---:|
| 术语 | 8 | 200 | 200 | 400 |
| 参数 | 10 | 200 | 200 | 400 |
| 逻辑 | 6 | 150 | 150 | 300 |
| GJB合规 | 1 | 50 | 50 | 100 |
| **合计** | **25** | **600** | **600** | **1200** |

train/test按文档号划分（01-10为train，11-16为test），正负比1:1。

**阶段5：检测器评测**

用三层检测器跑评测集，计算按四类×三层的P/R/F1。

### 2.5 新增6种注入方法

**T8枚举集合缺失**：文本说"支持手动、自动、应急3种模式"，注入为图中只画2种。检测方法：集合比较。

**T9状态告警术语不一致**：同一状态在文本叫"通信异常告警"，注入为在接口表叫"链路故障标志"。检测方法：跨位置术语统一比较。

**L7数据流方向反转**：框图显示单向输入，注入为文字描述有反向输出。检测方法：VLM提取框图数据流方向 vs 文字描述。

**L8工况分支删除**：文本提到3类场景，注入为流程图只画2类。检测方法：文本场景集合 vs VLM提取流程图分支集合。

**L9模式切换优先级冲突**：文字说应急最高优先级，注入为状态机允许自动夺回。检测方法：LLM提取优先级规则 vs VLM提取状态机转移。

**L10权限控制矛盾**：文字说普通用户不能改，注入为流程图允许普通用户进入。检测方法：LLM提取权限规则 vs VLM提取流程图操作路径。

## 三、可信度论证（5层保证）

### 第1层：真实数据打底

**做法**：366个Pair Dataset来自16份真实GJB 438C SRS文档。事实提取从真实数据中提取。注入只是在真实数据上做确定性修改。

**学术先例**：CrossCheck-Bench（AAAI 2026）从真实图文素材出发。QuRE（2025）用2111条真实工业需求。

**为什么可信**：检测对象是真实的，"原值"可以翻回原始文档核对。

### 第2层：规则注入保证逻辑真值

**做法**：32种注入方法全部是确定性操作，seed=42可复现。LLM只改写语言表达，不决定改什么、不判断对不对、不编造事实。

**学术先例**：FRED的"错误由规则插入，gold标注天然确定"。PIE-V将"错误规划（规则）"与"文本改写（LLM）"分离。LLM-Modulo"LLM提议+外部验证器约束"。

**为什么可信**：注入不依赖LLM，直接解决Korn 2026"LLM无法可靠注入smell"问题。

### 第3层：Z3求解器形式化验证

**做法**：参数类注入（P4/P5/P6）后跑Z3求解器，unsat才确认真矛盾。solver.unsat_core()返回矛盾源约束。

**学术先例**：VERIMED（arXiv:2605.13817）用SMT验证UNSAT，准确率55.4%→98.5%。SAGE（arXiv:2605.02545）构建"solver-verified"数据集。

**为什么可信**：Z3是数学求解器，unsat是数学证明不可满足，不是LLM的"判断"。

### 第4层：双源交叉验证

**做法**：31个真实矛盾经MinerU和textutil两个独立解析器确认。双模型标注kimi+claude 92%一致。

**学术先例**：CrossCheck-Bench 450专家小时验证。Dynamic Capability Scoping κ=0.917。

**为什么可信**：两个独立来源都确认的矛盾，不是某一个工具的幻觉。

### 第5层：可复现+可追溯

**做法**：固定seed+确定性规则+固定prompt，同输入同输出。每条注入记录method字段可追溯。

**学术先例**：FRED错误分类法约束注入空间。OmniDocBench（CVPR 2025）四步质量保证。

**为什么可信**：审阅人可以拿method字段翻回原始文档核对，可以重新运行脚本验证结果。

### 与Korn 2026的对比

| Korn 2026的问题 | 我们的解决方案 | 学术先例 |
|----------------|-------------|---------|
| LLM无法可靠生成smells | 规则注入，不依赖LLM生成 | FRED/PIE-V |
| LLM无法可靠检测smells | Z3求解器验证unsat | VERIMED/SAGE |
| 单人或单LLM不够 | 双源验证+双模型标注+Z3数学证明 | CrossCheck-Bench |
| 合成数据与真实分布有偏差 | 真实16份SRS打底 | CrossCheck-Bench/QuRE |

## 四、路线二5层架构

```
L5 评测集输出层
    1200条带标注评测集(600正+600负)
    → 交付给路线一的检测器

L4 评测集组装层
    正例(一致) + 负例(注入不一致)
    train/test划分(按文档号)

L3 注入构造层
    术语注入8种(T1-T9) / 参数注入6种(P1-P6)
    逻辑注入10种(L1-L10) / GJB合规注入7种(G1-G7)
    共32种, seed=42可复现, 答案规则确定

L2 事实提取层
    从Pair Dataset提取5类检测对象:
    功能名+ID / 接口属性 / 数值参数 / 流程步骤 / 表头字段
    【外部输入】GJB规则120条 + 专家词典 + Gold Standard 223条

L1 数据源层
    16份真实GJB 438C SRS文档(.doc)
    ↓ MinerU解析 + textutil双源 + 章节感知切片 + 图表配对
    → Pair Dataset 366个 + 切片5231条
```
