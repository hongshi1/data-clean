## 一、方法详解

### 1.1 问题

SRS一致性校验的证据链：**检测项(问题) → 召回证据池 → 下游NLI裁决**。
召回池被三类坏证据污染：

```text
① 错误scope干扰: 查"BLOB插入"召回"数据库初始化"证据(文本相似, 实体不对)
② 粒度错配:     NLI句级训练, 整个表格HTML/整段直入即失效(SumMaC)
③ 形态不符:     "见表40所示"式指针文本无实质内容
```

现有精排是**排序**（ordering）；本模块是**减法**（subtraction）——把不该进
NLI的证据删掉、把太粗的证据拆到NLI能消化的粒度。

### 1.2 模块结构（三谓词合取）

```text
keep(e) ⟺ F1(e, q) ∧ F2(e) ∧ F3(e)
          ↓任一失败 → 删除 + RemovalRecord{stage, reason_code, detail}
```

**F1 作用域过滤（删①类干扰）**

```text
锚点抽取 extract_anchors(question, answer):
  · PZXQ式ID:      正则 [A-Z][A-Z0-9]+(-[A-Z0-9]+)+   (标识符比对的核心锚)
  · 英文词(≥3字符): 小写化匹配(大小写不敏感)
  · 中文4-gram:    连续汉字段滑动窗口(避开"用例/需求"等2字通用词的误命中)

删除条件: 证据块锚点命中数 = 0
豁免机制: 问题/答案含PZXQ式ID时(标识符类检测项),
         含ID的证据块不做scope删——多实体ID比对所需证据天然不含查询词
         (实证: doc04的17违例中5个实例的gold证据是被豁免救回的)
护栏:     F1删光全部 → 回退保留全部(记fallback), 只做F2/F3
```

**F2 粒度归一（解②类失效，主力增益）**

```text
规则(依据SumMaC"证据侧粒度须可被句级NLI消费"):
  含<table>/<tr>   → 表头行+数据行配对 → "表头：值"行语句
                     (正则捕获到闭合</td>, 兼容<td><p>嵌套)
  长度>160字或多句 → 句级切分(。；！？)
  其他             → atomic(原样)

语句预算: 总语句>25时按语句级锚点命中排序, 保高命中语句
```

**F3 形态过滤（删③类无内容载体）**

```text
纯指针文本("见表X所示") 且 无锚点命中 → 删 shape_violation.pointer
(豁免: 命中锚点的指针不删——交叉引用型检测项的gold证据本身是指针,
 实证: VIO-15的gold="数据同步共享服务软件环境需求见表40。")
```

### 1.3 输出契约（可审计）

```text
EvidencePack = {
  kept:    [{evidence_id, statements[行/句级], granularity_class,
             anchor_hits, provenance}]
  removed: [{evidence_id, stage: F1|F2|F3,
             reason_code: scope_mismatch|shape_violation.*, detail}]
  stats:   {n_in, n_kept, n_removed, by_reason, fallback}
}
```

每条被删证据带理由与信号快照——减法决策可复核、可消融、可进论文附录。

## 二、七方法基线对比

### 2.1 方法与设置

| 方法 | 代表什么 | 选择 | 粒度 |
|---|---|---|---|
| B0-raw | 现状(无模块) | 全部 | 原始整块 |
| B0-norm | 粒度消融 | 全部 | 归一 |
| B1-topk3-raw | 通用RAG"排序式减法" | BGE相似度top-3 | 原始 |
| B1-topk3-norm | 排序式减法+粒度 | BGE top-3 | 归一 |
| B5-rand3-norm | 压缩伪效应对照 | 随机3块(seed=42) | 归一 |
| **B3-ours** | **本文减法模块** | **F1+F3** | **归一(F2)** |
| B4-oracle | 选择上限 | 定位gold直选 | 归一 |

```text
金标: doc04的17个真实违例(全部期望refute, 35个定位gold证据引用)
裁决: premise=证据, hypothesis=答案; refute ⇔ max p_contra > τ=0.5
误报率(swap): 池_i × 异检测项实例的答案触发refute的比例(85对)
  — 精度侧代理: NLI对无关答案伪判矛盾的控制能力
```

### 2.2 主结果表（成功率改变 × 有效证据误删框架）

| 方法 | 检出成功率 | Δ成功率 | 误删有效证据 | 保留块 | 伪矛盾率* |
|---|---:|---:|---:|---:|---:|
| B0-raw(无模块) | 6/17 (35.3%) | — | 0/35 | 90 | 67.1% |
| B0-norm(仅归一) | 11/17 (64.7%) | **+29.4pt** | 0/35 | 90 | 74.1% |
| B1-topk3-raw(BGE截断) | 6/17 (35.3%) | ±0 | **9/35** | 51 | 58.8% |
| B1-topk3-norm(BGE+归一) | 11/17 (64.7%) | +29.4pt | **9/35** | 51 | 70.6% |
| B5-rand3-norm(随机删) | 11/17 (64.7%) | +29.4pt | **18/35** | 51 | 72.9% |
| **B3-ours(减法模块)** | **11/17 (64.7%)** | **+29.4pt** | **0/35** | 72 | 72.9% |
| B4-oracle(gold直选) | 9/17 (52.9%) | +17.6pt | 0/35 | 35 | 68.2% |

\* 伪矛盾率=池×异项答案触发refute的比例——主要反映NLI自身scope盲区
（看到不同ID就判矛盾），受方法影响次级，作为局限注脚而非头条指标。

（双条形图：检出成功率% × 误删有效证据数，保留块数标注）

### 2.3 四个发现

**发现1：查全率增益全部来自粒度归一（F2），与选择无关**

任何"+归一"方法都从6→11。BGE截断、随机删、我们的F1/F3选择——
对查全率零贡献。**SumMaC粒度原则的领域实证：表格HTML整块直入NLI
是主要失效模式，行级"表头：值"配对后矛盾可见。**

**发现2：选择的价值在安全性——gold保留率的三分化**

```text
B3(锚点+ID豁免) 100%  vs  BGE截断 74.3%  vs  随机删 48.6%

通用相似度截断会删掉needed证据(相似度低≠不需要):
ID比对所需的"其他实体的行"与查询不相似, BGE删之 → 丢25.7% gold
随机删一半概率杀死needed → 48.6%
本文的锚点+检测项豁免 → 0误删
```

**发现3：误报率被NLI作用域盲区主导，证据选择影响次级**

全体方法58.8%~74.1%——池×异项答案的伪矛盾主要因NLI看到"两个不同ID"
就判矛盾（68号发现2在端到端的再现）。**减法能净化证据，治不了NLI
自身的scope盲区**——这指向下一步：裁决时把scope显式喂给NLI
(闭世界模板/声明构造，nli_local的既有结论)。

**发现4：定位gold直选反而降查全（9/17 < 11/17）——定位证据≠矛盾源**

gold_evidence_refs标记的是"违例在哪里"(定位)，而refute的矛盾源
常常在非gold块(如VIO-01的矛盾来自标识表219, gold却是两个节标题)。
**AVeriTeC"判定对≠证据对"的领域实证**——也说明Agent 2协议中
"删掉该块裁决依据受损"的needed定义与定位金标是两个概念，扩展
标注时必须分开。

## 三、结论

```text
减法模块的完整价值主张(在17违例上):
  查全:  35.3% → 64.7% (+29.4pt, 全部来自F2粒度归一)
  安全:  gold保留100%(BGE截断74.3%, 随机删48.6%) ← 选择智能的贡献
  误报:  与"仅归一"持平——诚实边界: 减法治不了NLI的scope盲区
  成本:  语句数15.5/实例(仅归一23.4, 有压缩), 零模型零API
```
