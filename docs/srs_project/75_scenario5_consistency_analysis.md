# 场景5一致性校验分析报告（初步）

> v0.1 初步分析 | 2026-10-29 | 输入: 场景5-科研生产现场智能监管微调数据应用设计与落地实施文档(137段, 已全文精读)
> 对照基线: 场景1(CascadeVerify, 40项体系三层架构, 91QA/17违例评测)
> 结论速览: 场景5=场景1范式的"换证据形态"迁移——文本侧13/17项可配置化直迁, 图片侧需VLM前置抽取层, 跨样本/时序是新增的语料级维度; 文档指定的两模块架构与我们方向A/B天然对齐

## 1. 场景5文档核心事实（精读摘要）

### 1.1 数据形态（与场景1的根本差异）

| 维度 | 场景1 | 场景5 |
|---|---|---|
| 校验对象 | SRS文档的answer | **图片-QA违规告警问答对**（数据集质量管理） |
| 证据形态 | 冻结文本块+HTML表格（结构化可解析） | **监控图片/视频抽帧**（像素）+ QA JSON |
| QA结构 | 自然语言answer | 结构化JSON: `{"task","answer"(0/1/2),"evidence":[...],"timestamp"}` |
| 判定语义 | support/refute/NIE | 任务自带三态: **0=no/1=yes/2=uncertain** |
| 时间维度 | 静态文档 | **时序数据流**: 实时监控采集, QA带timestamp, 相似图片=近时帧 |

### 1.2 文档指定的校验架构（段[100]——与我们方向A/B对齐）

```
上下文关联与特征提取模块  ←≈ 方向A(上下文聚合)的场景5版
  职责: 抽取图片实体/目标属性/隐患特征/QA问答对语义/上下文关联特征
特征校验模块              ←≈ 方向B(一致性校验)+跨样本扩展
  职责: 基于特征对【全量样本】做召回比对校验
```
术语层方法论(段[107]): "抽取图片识别实体、QA问答对全部文本术语 → **全局召回比对**"——与我们"跨位置聚合→注册表→join"是同一范式, 场景5叫"全局召回比对"。

### 1.3 校验的四个输出用途（段[101-105]——任务目标与场景1不同）

① 过滤低质/矛盾/不合规样本 ② 构造正样本 ③ **构造困难负样本（术语冲突/属性矛盾/逻辑漏洞/合规缺陷）** ④ 引导垂域大模型生成自洽QA
外加: 校验结果**反向回流数据清洗治理**（坏样本剔除/劣样本优化）

——即场景5的校验是**数据集生产线上的质量关卡**, 不是部署期的answer拦截。

| # | 检测项 | 落点 | 备注 |
|---|---|---|---|
| ① | 隐患判定逻辑冲突 | VLM+LOGIC-02式 | 睡岗判合规=处置矛盾 ✓ |

```
17项 = 7项纯文本可直迁(配置化兑现) + 5项需VLM抽取后迁移 + 4个新方向

新方向: 完备性检查×2 + 场景错配 + 跨样本矛盾
```

## 3. 时序维度分析（场景5的独有维度）

场景1是静态文档；场景5的数据是**时序数据流**——这既是新挑战也是免费的结构化红利：

### 3.1 数据自带的时序元数据

- **timestamp字段**（需求2）: 图片画面含时间戳(如"2026-10-17 17:20")→QA必须抄录；无→置空
- 监控图片来自**现场监控系统采集**（视频抽帧）——隐含(camera_id, 时间)元信息

### 3.2 时序带来的一致性检测（文档未显式列出但隐含）

| 时序检测项 | 类型 | 落点 |
|---|---|---|
| **timestamp抄录正确性** | QA字段级 | 纯文本+图片OCR/VLM——图片时间戳vs QA timestamp字段（PARAM类, 可直迁思路） |
| **时序平滑性**: 同摄像头近时帧结论应一致 | 跨样本 | (camera,timestamp)为聚类主键——**免费解决了"相似图片"的定义问题** |
| 时序矛盾: 同一时刻同一位置违规/不违规 | 跨样本 | 时序聚类内的answer比对 |
| 时间戳缺失/格式不规范 | QA字段规范 | 纯文本（JSON schema校验） |

### 3.3 关键洞察: 时序元数据是跨样本管道的免费主键

场景5的④（多样本结论矛盾）在通用图像里需要做图片相似度聚类（贵且不准）；**但监控数据天然带(camera, 时间)元信息**——"高度相似的图片"≈"同摄像头近时帧"。跨样本管道的第一版可以**完全绕过图像相似度**, 用元数据聚类:
```
group_by(camera_id, time_bucket) → 组内QA结论比对 → 相反结论=可疑对
```
这把A2级挑战（跨样本范式）的实现成本降了一个数量级。

## 5. 工作开展方案（三阶段, 每阶段有可测产出）

### 阶段1: 纯文本侧（零VLM, 零图片, 配置化直迁）
**范围**: QA对内部+QA字段规范+跨QA文本比对——术语②③⑤⑦+参数③+合规② ≈ 6-7项
1. 场景5的ner_lexicon（监管术语/枚举值域/行为类别）
2. 场景5的rulepack（JSON schema规范/枚举闭集/阈值边界模式/字段规范）
3. QA-JSON解析器（task/answer/evidence/timestamp字段→ClaimResult）
4. 评测种子: 文档4对问题/修正样本+构造的时序矛盾对
**产出**: 文本侧检测器+评测报告（验证配置化主张的最小闭环）

### 阶段2: 图片侧（VLM抽取前置层）
**范围**: 术语①④⑥+参数①⑤⑥+合规①③ ≈ 7项
1. VLM抽取管道: 图片→(实体, 属性, 场景, 图片时间戳)结构化描述（走缓存）
2. 抽取结果作为"图片侧注册表"进L1（范式: 图片≈另一种"文档"）
3. timestamp抄录检测（图片OCR时间vs QA字段）
**产出**: 跨模态检测能力+成本模型报告（VLM必经层的级联经济学重构）

### 阶段3: 跨样本+时序管道（语料级）
**范围**: 合规④+时序平滑性+困难负样本
1. (camera,timestamp)元数据聚类管道
2. 组内结论比对→可疑对标记→回流数据清洗
3. EGT式困难负样本构造（负样本生产线）
**产出**: 语料级一致性管道+回流闭环

## 6. 风险与开放问题

| 风险 | 等级 | 缓解 |
|---|---|---|
| VLM抽取的非确定性破坏可复现性 | 高 | VLM全走缓存+抽取结果冻结为"图片描述文件"（把场景5的"证据冻结"定义在VLM输出层） |
| VLM成本地板 | 高 | 阶段2先测吞吐; 抽取结果可复用(一图一抽) |
| 图片元数据(camera_id)是否可得 | 中 | 若无, 退化为图片相似度聚类(贵)或人工标注批次 |
| "高度相似"的定义边界 | 中 | 第一版=同camera近时; 语义相似留二期 |
| 场景错配检测的规则源(场景→规则绑定表) | 中 | 从文档3.1的判定标准块结构化(判定标准自带场景限定) |
| 三态语义映射(我们的S/R/NIE vs 任务0/1/2) | 低 | 明确分开: 我们判定的是"QA对是否自洽"(S/R/NIE), 不是替代任务标签 |

## 7. 初步结论

1. **场景5是场景1范式的换证据形态迁移, 不是推倒重来**——文档自定的两模块架构(特征提取+特征校验全局召回比对)与我们的方向A/B和"聚合→比对"范式同构
2. **分阶段可行**: 纯文本侧(6-7项)零VLM即可启动且直接兑现配置化主张; 图片侧是VLM成本问题不是架构问题; 跨样本因时序元数据的存在比预想便宜
3. **四个新方向中, 完备性检查(属性/条件遗漏)是科学上最有意思的**——"answer该说没说"是场景1体系没有的检测方向, 可成为场景5的方法贡献点
4. **评测种子已在文档里**: 4对问题/修正样本+时序平滑性矛盾, 不用从零标

**下一步建议**: 启动阶段1（场景5词典+规则包+QA-JSON解析器+文本侧检测器, 一周内可见数字）。
