## 一、当前技术方案是什么

### 1.1 核心科学问题

> **Born-Digital多模态SRS文档的一致性校验**：给定一份内嵌Visio源图的GJB格式SRS文档，如何自动检测流程图、用例描述表、正文三模态之间的不一致性？

这不是一般的"图文匹配"问题，而是：
- **结构化源**（Visio XML，100%保真）vs **半结构化表**（CSV）vs **非结构化文本**
- **已知Ground Truth**的三角校验问题
- **军事领域**（GJB 438C标准约束下的确定性检测）

### 1.2 技术架构：三通道 × 三层 × 盲测协议

```
┌─────────────────────────────────────────────────────────────────┐
│                    数据层（Born-Digital资产）                     │
├─────────────────────────────────────────────────────────────────┤
│ 通道A: Visio源直读（金标准，356图，确定性）                        │
│   .doc → LibreOffice → .docx → OLE2 → Package → page1.xml     │
│   → Shape{文本,坐标} + Connect{边} → networkx.DiGraph          │
│   准确率: 100%（源文件解析，零视觉误差）                           │
├─────────────────────────────────────────────────────────────────┤
│ 通道B: VLM提取（kimi-k2.6，语义理解）                            │
│   image.png → GLM-4V/Qwen API → {nodes, edges} JSON           │
│   准确率: 90%（正常图）/ 20%（小图<300px）—— 待通道A校准           │
├─────────────────────────────────────────────────────────────────┤
│ 通道C: OCR提取（PaddleOCR，字符识别）                             │
│   image.png → OCR → text + position                            │
│   准确率: ~90%（印刷体），布局推理弱                               │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│              方向A：上下文关联（条目聚合）                         │
├─────────────────────────────────────────────────────────────────┤
│ 双图融合聚合器（KGContextMatcher）                                │
│   ① ID-Graph硬桥: 需求ID → {正文, 表格行, 图片, 追溯表}所有位置  │
│   ② LightRAG语义图: 实体 → 关系邻居 → 语义相关chunks             │
│   ③ VLM图片匹配: 实体名 ∈ 图片key_elements                      │
│   ④ 向量检索: 实体名 → 语义相似chunks                           │
│   输出: 聚合条目{entity, occurrences[], chain_completeness}     │
│   指标: avg_recall=0.809, latency=0.01s                        │
└─────────────────────────────────────────────────────────────────┘
                              ↓
┌─────────────────────────────────────────────────────────────────┐
│              方向B：不一致性校验（三层检测）                       │
├─────────────────────────────────────────────────────────────────┤
│ 语法层(SyntaxChecker)                                           │
│   - 表头字段检测: 合格性表5列齐全? 接口表7列齐全?                 │
│   - 内容缺失检测: 空单元格/占位符"待定"                          │
│   - 模糊需求检测: "待定""适当""尽可能"                            │
│   技术: 规则匹配 + 字段完整性 + 关键词词典                        │
├─────────────────────────────────────────────────────────────────┤
│ 语义层(TermChecker)                                             │
│   - 同义词冲突: "发送"→"接收" (术语替换矛盾)                     │
│   - 缩写冲突: "DB" vs "数据库" (同一实体不同名称)                │
│   - 同名异义: "接口"在不同上下文指不同事物                        │
│   - 编辑距离: 轻微拼写差异                                       │
│   - 集合比较: 图节点集 vs 表行集 双向覆盖                         │
│   技术: 词典 + Levenshtein + 集合差 + 上下文消歧                  │
├─────────────────────────────────────────────────────────────────┤
│ 逻辑层(LogicChecker)                                            │
│   - 数值约束: Z3求解（时间预算/资源上限/容量约束）                  │
│   - 单位归一: ms↔s, KB↔MB, MHz↔GHz (10单位族)                   │
│   - 方向矛盾: 发送方↔接收方 反转                                 │
│   - 序列重叠: 流程图拓扑序 vs 用例表步骤序                        │
│   - 数据流矛盾: 输入→输出 方向反转                               │
│   技术: Z3重跑(绝不信任元数据) + 网络x拓扑 + 单位换算              │

│              盲测协议（评测可信度保证）                           │
├─────────────────────────────────────────────────────────────────┤

│                                                               │
```

## 三、具体技术如何解决问题

### 3.1 "多模态图理解"怎么解？

**问题**: 流程图/用例图是技术框图，VLM对它的理解能力有限（小图召回~20%）

**我们的解法**: **跳过感知，直接读源文件**

```
传统路线: image.png → VLM/OCR → 猜节点/猜边 → 90%准确率
我们路线: .doc → OLE2 → Visio XML → Shape/Connect → 100%准确率
```

这就是**Born-Digital**的优势：军事/工程文档多用Visio绘制，源文件就嵌在.doc里，我们直接读。

**VLM的角色降级**: 从"唯一来源"变为"待验证提取器"——用通道A(Visio)量化通道B(VLM)的准确率/幻觉率。

### 3.2 "跨章节实体关联"怎么解？

**问题**: 同一功能"服务开发支撑"出现在3.2.1正文、表2、图5、合格性表、追溯表——如何聚合？

**我们的解法**: **ID锚定 + 4通道召回**

```
ID锚定: 需求ID(PZXQ-GN-FWKFZC)是确定性锚点
  → ID-Graph: ID → {所有出现位置}
  → 这比"语义相似度匹配"更可靠(不依赖embedding质量)

4通道并行召回:
  ① ID硬桥(最可靠): ID精确匹配
  ② 语义图: LightRAG关系邻居(处理无ID的实体)
  ③ 图片匹配: 实体名 ∈ 图片key_elements
  ④ 向量检索: 语义相似chunks(兜底)

输出: 聚合条目 + chain_completeness(4类位置覆盖率)
指标: avg_recall=0.809
```

### 3.3 "不一致性检测"怎么解？

**问题**: 给定聚合后的条目对，如何判断是否矛盾？

**我们的解法**: **三层检测 + Z3重跑 + 盲测协议**

```
语法层(规则): 表头完整性/字段缺失/模糊需求
  → 确定性规则，零幻觉

语义层(词典+算法): 同义词/缩写/编辑距离/集合差
  → 词典驱动 + Levenshtein + 集合运算

逻辑层(Z3+图): 数值约束/单位归一/方向矛盾/序列重叠
  → Z3求解器(检测器自己跑，不信任元数据)
  → 网络x拓扑序比较

盲测协议:
  检测器只看: occurrences_injected + rendered_context
  检测器不看: label / answer / z3_verified
  → 消除循环验证，得到真实F1=0.941
```

### 3.4 "无Gold Standard怎么评测"怎么解？

**问题**: 没有足够人工标注怎么算P/R/F1？

**我们的解法**: **三层Gold Standard + Mutation引擎**

```
L0 确定性锚点(零标注):
  - GJB标准检测: 规则输出即gold(167条)
  - 注入样本: mutation位置即gold(1787对)
  - Visio源: 解析结果即gold(356图)

L1 Silver层(机器标注):
  - 双异族LLM交叉标注(132条, 92%一致)
  - 分歧样本 → 优先人工仲裁

L2 Gold层(人工):
  - 现有223条 + 扩展到200+目标
  - 用于锚定L1效度
```
