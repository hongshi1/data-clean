# L0 NER层技术架构详解

> 版本 v1.0 | 配套: 65号架构文档§2.1 | 实现: `entity_detector.py` + `ner_lexicon.py` + `config/ner_lexicons/*.json`
> 本文讲清楚: 抽取管线每一步做什么、jieba的确切角色（包括它不在主路径上这个事实）、配置与引擎的精确边界

---

## 0. 一句话定位

L0是一个**确定性gazetteer式实体层**：配置词典+正则做实体抽取，从证据运行时归纳文档实体表，四级链接消歧，产出术语类不一致（TERM-01/02/05/07/08）的检测。

**它不是**：基于模型的NER（没有CRF/transformer）；也不是分词器驱动的NER（主路径不用jieba，见§3的诚实说明）。

---

## 1. 管线总图（四个阶段）

```
输入: (Question, Answer, 冻结证据E)

阶段① 实体抽取 extract_entities        ← 词典+正则(确定性内核)
  Answer文本 ──→ [domain_term/pzxq_id/chinese段/quoted/mixed] 五种候选实体

阶段② 文档词典构建 build_document_lexicon  ← 运行时gazetteer归纳(从证据学)
  证据语句 ──→ {能力名, 用例名, 接口ID, 值域闭集, 数据库名, 别名对}

阶段③ 实体链接 link_entities           ← 四级消歧
  Answer实体 ──→ exact / alias / prefix / NIL(未链接)

阶段④ TERM冲突检测 detect_term_conflicts ← 五项检测
  ──→ ClaimResult(verdict + evidence_refs + TERM-XX + rationale)
```

关键设计：**抽取宽、链接严**——阶段①宁可多抽（长中文段也进候选池），靠阶段②③的词典匹配和消歧收敛。

---

## 2. 阶段①：实体抽取（gazetteer内核）

### 五种实体与各自的提取规则

| 实体种别 | 提取方式 | 配置来源 | 真实示例 |
|---|---|---|---|
| `domain_term` | 域术语词典编译成正则；**ASCII边界用前后瞻**（`\b`在中文邻接下失效：`访问BLOB数据`里BLOB两侧无空格） | `domain_terms`(9词: BLOB/SQL/JSON/INT/STRING/FLOAT/LOB/DML/API) | `BLOB` |
| `pzxq_id` | ID正则 | `id_patterns`(`PZXQ-[A-Z0-9-]+`) | `PZXQ-GN-SQLFW-SJXG` |
| `chinese` | **中文连续段**（连续汉字串，正则切分）→停用词过滤 | `stopwords`(37词) | `系统通过`、`支持在桌面` |
| `quoted` | 引号模式（「X」/“X”/『X』） | `quote_patterns` | 「连接池配置」 |
| `mixed` | 中英邻接复合词（ASCII术语+紧邻汉字） | 从domain_terms派生 | `BLOB数据插入接口写入` |

### 真实走查（生产代码输出）

输入：`系统通过BLOB数据插入接口写入大字段（BLOB）数据，调用PZXQ-GN-SQLFW-SJXG接口，支持在桌面、平板设备上运行`

```
[chinese]     系统通过                      ← 连续段, 非停用词
[domain_term] BLOB                          ← 词典命中
[mixed]       BLOB数据插入接口写入            ← 中英邻接复合
[chinese]     数据插入接口写入大字段           ← 连续段
[chinese]     调用                          ← 连续段
[pzxq_id]     PZXQ-GN-SQLFW-SJXG            ← ID正则
[chinese]     支持在桌面
[chinese]     平板设备上运行
```

注意`chinese`种别是**长段而非词**（"系统通过"不是词）——这是有意的：抽取阶段只做候选池，切词交给下游（阶段③的包含式匹配可以命中"系统通过BLOB"里的"BLOB"和用例名），切错词反而丢信息。

### 去重与排序
`(surface, kind)`去重 + 按源位置排序——保证同输入同输出（确定性）。

## 3. jieba的确切角色（诚实声明）

**事实：jieba不在当前抽取主路径上。**

- 主路径的中文实体=正则连续段（§2），**不用jieba分词**
- 原因：重构的行为保持铁律——旧版实体抽取就是连续段模式，换jieba分词会改变全部下游判定语义（91QA逐位一致将破坏），且连续段模式对下游够用（链接阶段做包含式匹配）
- jieba在架构里的位置：**预置的词级通路**——`configure_jieba(lexicon)`把配置词表（域术语/值域词/实体词）注入jieba词典（`add_word(freq=2000)`），`tokenize(text, HMM=False)`提供确定性分词。**已验证的gazetteer效应**：配置了"数据库连接状态/运行状态监控"等词条后，jieba不把它们切散——这是需要词级切分（如关键词抽取、TF-IDF、句级匹配）的场景通路
- 跨场景分词演示（`tools/demo_lexicon_transfer.py`）里jieba承担了场景对比的分词器角色（隔离进程跑，因为jieba词典是进程级累积的）

**什么时候会启用jieba主路径**：如果下游需要词级精确匹配（而不是包含式匹配），或新场景的实体是词而非短语——配置不变，引擎把`chinese`种别的切分换成`tokenize()`即可（这就是预置通路的意义：能力就位，按需启用）。

## 4. 阶段②：文档词典构建（运行时gazetteer归纳）

这是L0最"聪明"的部分：**不依赖静态词典认识文档实体，而是从当前证据动态归纳实体表**。

八类来源（全部从`linearize_context`产出的证据语句提取）：

| 来源 | 提取逻辑 | 实例（04号真实数据） |
|---|---|---|
| **能力名** | ID深度判定：`PZXQ-GN-XXX`(3段)=能力名 | 数据统一访问服务、BLOB数据操作 |
| **用例名** | 用例表字段语句（`usecase_fields`配置: Use Case名称/前置条件…） | 数据插入、二维数组输出 |
| **散文枚举** | "X包括A、B、C"式句子收割 | **真实案例：35个用例名因表格列错位在字段提取中丢失，靠散文枚举恢复** |
| **接口ID** | ID语句收集 | PZXQ-DBS-01… |
| **值域闭集** | 单元格值按顿号切分 | 方式名称{桌面,平板,手持}、运行状态{运行阶段,开发阶段} |
| **数据库名** | `entity_categories`模式（中文词干+可选V版本号） | 达梦V7.6、sqlite3 |
| **别名对** | 括号定义`X(Y)`（`alias_patterns`），动词前缀剥离（`strip_prefix_words`28词: 提供/支持/…） | 大字段↔BLOB、对象关系映射↔ORM |
| **状态值** | 运行状态字段的实际取值收集 | |

**为什么要运行时归纳**：静态词典（阶段①的配置）只认识**域通用**实体（BLOB/值域词）；**文档特有**实体（这份SRS有哪些用例、哪些接口ID）只能从证据学——这正是"场景配置+运行时学习"的两层设计：配置管域知识，归纳管文档知识。

---

## 5. 阶段③：实体链接（四级消歧）

Answer实体 → 文档词典的匹配优先级：

```
1. exact   实体精确出现于词典        "数据插入" → 用例名命中
2. alias   经别名对间接命中          "大字段" → (大字段↔BLOB) → BLOB
3. prefix  最长公共前缀择优          "BLOB数据插入" ⊂ 词典"BLOB数据操作"命中
4. nil     无任何命中               → 标记unlinked(不视为错误, 移交下层)
```

**nil≠错误**是开放世界语义在L0的体现：answer提到证据里没有的实体，可能是检索没覆盖（NIE路径），不是术语错误。

## 6. 阶段④：TERM冲突检测（五项）

| 检测项 | 触发逻辑 | 判定 | 真实锚点 |
|---|---|---|---|
| TERM-01 同义异名 | answer用X、evidence用Y、别名对证明同指 | warning(判support, method带`:warning`后缀) | 大字段 vs BLOB |
| TERM-02 同名异义/定义互换 | 括号定义对冲突：`X(A)` vs `X(B)`；**ASCII大小写归一**(sqlite3=SQLite3同产品不算冲突) | refute | 本地数据库定义互换 |
| TERM-05 用例名错配 | answer的用例名 vs 词典用例名：**字符集重合≥0.75**("数据插入"vs"插入数据"=1.0→support)或包含式 | support/refute | 数据插入 vs 数据删除 |
| TERM-07 接口ID冲突 | ID**族比对**：同族(前缀一致)不同tail→refute；跨族→另行判定 | refute | PZXQ-DBS-01 vs -02 |
| TERM-08 缩写不一致 | 全称/缩写使用与文档定义不符 | warning | |

**输出协议**：每个检测结果=ClaimResult（verdict + evidence_refs指认证据位置 + check_item_candidates=("TERM-XX",) + rationale含双方实体面），进入per-claim融合参与最终裁决。

## 7. 配置与引擎的精确边界

```
┌─ 配置(场景知识, 换场景改这里) ─────────────┐   ┌─ 引擎(通用逻辑, 永不改) ──────────┐
│ domain_terms   域术语表                    │   │ 词典匹配内核(边界前后瞻)           │
│ id_patterns    标识符正则                  │   │ 连续段切分+去重排序                │
│ quote_patterns 引号模式                    │   │ 八类文档词典归纳算法               │
│ value_domains  值域闭集                    │──→│ 四级链接(exact/alias/prefix/NIL)  │
│ entity_categories 实体类别(数据库名等)      │   │ 五项TERM检测逻辑                  │
│ stopwords      停用词表                    │   │ 字符集重合/编辑距离等度量           │
│ alias_patterns 别名模式                    │   │ jieba通路(configure/tokenize)     │
│ usecase_verbs/objects/fields 用例名判定表   │   │ (按需启用的词级通路)               │
│ strip_prefix_words 前缀剥离词表             │   │                                   │
└──────────────────────────────────────────┘   └──────────────────────────────────┘
```

**srs_scene1.json实测**：15字段、9域术语+1ID正则+2值域+37停用词+19用例动词+14用例宾语+28剥离词…——全部逐项迁移自旧硬编码（迁移脚本生成，非手抄，digest锁定行为等价）。

**跨场景迁移已验证**（06号演示）：同一引擎+doc06_scene.json（06号ID族PZXQ-YXZCFW、06号特有术语CPU/WPS/运行状态监控、含"集成阶段"的运行状态值域）→ 域词命中38→**174**。**换配置不换代码**。

## 8. 设计决策与代价（诚实账）

| 决策 | 收益 | 代价 |
|---|---|---|
| 词典/正则而非模型NER | 确定性(零方差)、零标注、免费、可审计(命中可指认词典行) | 开放域实体抽不到——每种新实体要配词典 |
| 连续段而非jieba词 | 行为保持+下游包含式匹配够用+长段信息不丢 | 候选池噪声大（"系统通过"也是候选），靠链接收敛 |
| 运行时词典归纳 | 文档特有实体零成本获得 | 依赖证据质量（列错位曾丢35个用例名, 靠散文枚举补回） |
| nil不算错误 | 开放世界语义正确 | answer的未链接实体只移交下层, L0不报错 |
| 字符集重合0.75判用例名 | "数据插入"vs"插入数据"语序鲁棒 | 阈值是经验值（91QA标定） |
| ASCII大小写归一 | sqlite3=SQLite3不误报 | 大小写敏感的真冲突会漏（本域未发现此例） |

## 9. 何时升级（预置的演进路径）

| 触发条件 | 升级动作 | 代价 |
|---|---|---|
| 需要词级精确匹配 | `chinese`种别切分换`tokenize()`（jieba通路已预置, 配置已注入词典） | 下游匹配逻辑需同步适配 |
| 实体类型开放/高变体 | 词典未命中时回退零样本模型(GLiNER/UIE) | 引入L0非确定性——需加置信门控 |
| 跨域零配置冷启动 | LLM预生成场景词典(读文档采样→生成ner_lexicon json→人工校验) | 一次性LLM成本+校验工作 |

配置化架构的意义正在于此：**这些升级动的是引擎局部或配置生成，不是推倒重来。**
