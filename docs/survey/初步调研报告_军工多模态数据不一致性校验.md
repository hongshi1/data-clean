# 初步调研报告：军工武器多模态数据不一致性校验

> 生成时间：2026-06-29
> 课题方向：军工武器多模态数据不一致性校验（多模态数据质量检测）
> 技术路线：找权威多模态军工数据集 → 数据治理工具治理 → 检测不一致性
> 模态组合：**表格数据 + 图片数据 + 时序数据**

---

## 一、执行摘要

### 核心结论
1. **没有现成的"表格+图片+时序"三模态军工数据集** — 需要自建或组合多源数据
2. **Data-Juicer 不支持时序数据** — 它是LLM训练数据治理工具（文本/图片/视频/音频），时序模态完全空白
3. **Data-Juicer 可用于图片+表格治理** — 有CSV/Parquet格式支持 + CLIP/BLIP图文算子，但无"inconsistency detection"
4. **SARCLIP 已解决"CLIP不懂军工/SAR"问题** — 有开源的SAR领域CLIP微调模型（170万SAR图文对训练）
5. **时序异常检测有成熟工具生态** — TAB/MTAD/TimeEval，但不与Data-Juicer集成
6. **跨模态不一致性检测是真正的研究空白** — 没有任何工具/论文做军工领域的表格-图片-时序一致性校验

### 推荐技术栈
| 模态 | 治理/检测工具 | 角色 |
|---|---|---|
| 表格 | Great Expectations / Deequ | 规则约束 + 模式校验 |
| 图片 | Data-Juicer + SARCLIP | 图文相似度 + 领域CLIP |
| 时序 | TAB / MTAD / TimeEval | 时序异常检测 |
| 跨模态 | 自定义（LANISTR架构参考） | 不一致性检测（研究贡献点） |

## 三、工具评估

### 3.1 Data-Juicer 深度评估

#### 能力概览
- **总算子数**：200+（filter 56、mapper 105、deduplicator 10、formatter 8 等）
- **多模态算子**：约20个跨模态算子
- **自定义算子**：支持，通过 `--custom-operator-paths` 或 YAML `custom_operator_paths`
- **ScriptOP**：Data-Juicer 2.0 引入，集成自定义 Python 逻辑
- **LLM算子**：`llm_analysis_filter`、`llm_quality_score_filter`、`llm_extract_mapper`

#### 三类模态支持度

| 模态 | 原生支持 | 具体算子 | 评估 |
|---|---|---|---|
| **表格** | ✅ | `csv_formatter`、`tsv_formatter`、Parquet、`extract_tables_from_html_mapper` | 可加载格式化，但无表格内容校验算子 |
| **图片** | ✅ 丰富 | `image_text_similarity_filter`(CLIP)、`image_text_matching_filter`(BLIP)、`image_aesthetics_filter`、`image_pair_similarity_filter` | 算子齐全，但通用CLIP不懂军工/SAR |
| **时序** | ❌ | **无任何时序算子** | 完全空白，需从零自定义 |

#### 关键多模态算子清单

| 算子 | 底层模型 | 功能 | 默认阈值 | 对军工适用性 |
|---|---|---|---|---|
| `image_text_similarity_filter` | CLIP (clip-vit-base-patch32) | 图文相似度过滤 | min_score=0.1 | ⚠️ 需换SARCLIP |
| `image_text_matching_filter` | BLIP (blip-itm-base-coco) | 图文匹配过滤 | min_score=0.003 | ⚠️ 需领域微调 |
| `image_pair_similarity_filter` | CLIP | 图像对相似度 | - | 可用于SAR-光学配对 |
| `image_aesthetics_filter` | 美学评分模型 | 图像美学质量 | - | ❌ 对军工无意义 |
| `video_frames_text_similarity_filter` | CLIP | 视频帧-文本相似度 | - | 可用于军工视频 |
| `llm_analysis_filter` | 可配置LLM | LLM多维度质量评分 | - | ✅ 可做军工知识一致性 |
| `llm_quality_score_filter` | 可配置LLM | LLM质量打分 | - | ✅ 可做军工规格校验 |

#### 核心卡点

| 问题 | 结论 |
|---|---|
| 有"inconsistency detection"算子吗？ | **没有**。只有"相似度过滤"（低于阈值丢弃），不是"检测并报告矛盾" |
| 能处理时序数据吗？ | **不能**。零时序算子 |
| CLIP/BLIP能理解军工/SAR图像吗？ | **通用版不能**，但可替换为SARCLIP（见3.3） |
| 输出是"过滤"还是"检测报告"？ | **过滤**（丢弃低分样本）。需改输出逻辑 |
| 能检测"表格规格 vs 图片内容矛盾"吗？ | **不能直接检测**。需自定义算子+军工知识库 |

### 3.2 替代/补充框架

#### 🔥 LANISTR (Google Research) — 模态组合最匹配
- **论文**：LANISTR: Multimodal Learning from Structured and Unstructured Data
- **模态**：Language + Image + Structured (tabular + time series) — **完全匹配你的三类模态**
- **能力**：多模态对齐+融合+预测，用掩码策略处理缺失模态
- **局限**：是学习框架，不是数据治理/质量校验工具
- **价值**：可作为跨模态一致性检测的架构参考
- **URL**：https://research.google/blog/lanistr-multimodal-learning-from-structured-and-unstructured-data/

#### Synaesthesia — 多模态传感器数据管道
- **能力**：PyTorch Lightning，CSV+图像+时序自动时间戳对齐
- **价值**：数据预处理/对齐管道
- **URL**：https://github.com/danieledema/synaesthesia

#### fusilli — 多模态数据融合
- **能力**：tabular-tabular + tabular-image 融合，PyTorch Lightning
- **价值**：比较不同融合方法
- **URL**：https://github.com/florencejt/fusilli

#### PyTorch Frame — 异构表格深度学习
- **能力**：支持数值/类别/时间/文本/图像列类型
- **URL**：https://github.com/pyg-team/pytorch-frame

#### Microsoft PSI — 多模态流式数据
- **能力**：传感器流数据处理（音频/视频/深度），时间流对齐
- **URL**：https://github.com/microsoft/psi

#### iStructTab — 图像-表格多模态学习
- **能力**：图表特征序列化，跨模态对齐
- **URL**：https://github.com/zadid6pretam/iStructTab

### 3.3 SARCLIP — 解决"CLIP不懂军工/SAR"的关键发现

> **这是最重要的发现之一**：已有开源的SAR领域CLIP微调模型，可直接替换Data-Juicer的通用CLIP。

- **论文**：SARCLIP/SARVLM (arXiv 2510.22665, 2025)
- **数据集**：SARVLM-1M — 170万SAR图文对
- **方法**：两阶段训练（光学遥感→SAR迁移）
- **能力**：零样本分类、跨模态检索、图文推理
- **GitHub**：https://github.com/CAESAR-Radi/SARCLIP
- **权重**：开源（非商业研究用）
- **性能**：SAR图文检索 mean recall 15.25%（通用CLIP极低）

**相关军工CLIP微调工作**：
- MSTAR + LLVM (SPIE 2025)：SAR图文问答，98%准确率
- Scattering Prompt Tuning (CVPR 2024W)：SAR目标识别的CLIP微调

## 五、研究空白与 Novelty 分析

### 5.1 已确认的空白

| 维度 | 现状 | 空白 |
|---|---|---|
| 军工多模态数据集 | 有单模态（SAR/光学）+ 少量多模态配对 | ❌ 无"表格+图片+时序"三模态军工数据集 |
| 多模态不一致性检测 | 通用领域有基准(MMIR/CrossCheck) | ❌ 军工领域零空白 |
| Data-Juicer 军工应用 | 无已知用例 | ❌ 无先例 |
| 军工CLIP | SARCLIP已有（SAR领域） | ⚠️ 但无武器规格-图片一致性检测 |
| 时序-图片-表格跨模态一致性 | LANISTR做融合，不做校验 | ❌ 无一致性校验方法 |

### 5.2 你的课题可贡献的 Novelty

1. **构建首个"表格+图片+时序"军工多模态不一致性数据集**
2. **扩展 Data-Juicer 支持时序数据 + 不一致性检测算子**（框架贡献）
3. **提出军工领域多模态不一致性检测方法**（SARCLIP + 知识图谱 + 时序异常检测融合）
4. **将 Data-Juicer 从"过滤"改造为"检测报告"模式**（工程贡献）

## 六、建议技术路线

### 路线B+C混合（用户确认）

```
阶段1：Data-Juicer 治理图片+表格
  ├── 用 csv_formatter 加载武器规格表格
  ├── 用 SARCLIP 替换通用CLIP（image_text_similarity_filter）
  ├── 自定义"规格-图片不一致检测"算子
  └── 输出不一致样本+原因+置信度（改过滤为报告）

阶段2：时序数据另选工具
  ├── 用 TAB/MTAD 做时序异常检测
  ├── 用 Synaesthesia 做多模态时间对齐
  └── 时序与表格/图片的时间一致性校验（自定义）

阶段3：跨模态不一致性检测（研究核心）
  ├── 参考 LANISTR 架构做跨模态对齐
  ├── 融合三类模态的异常分数
  └── 输出综合不一致性报告

阶段4：持续调研替代框架
  ├── 评估 LANISTR 能否直接用于一致性检测
  ├── 评估 fusilli/iStructTab 的图表融合能力
  └── 如有更优框架，替换Data-Juicer
```

### 数据集建议
- **表格**：GunsAndWeapons (HF) + GJB 4292A-2016标准字段
- **图片**：eCHFD + AMOD-V1.0 + MegaSAR-2M
- **时序**：AFRL UNICORN 2008 GPS轨迹 + ESCAPE传感器时序
- **组合**：可能需要自建，从上述数据源抽取并对齐
