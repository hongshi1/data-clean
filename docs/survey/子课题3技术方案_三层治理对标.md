## 一、子课题3三层框架与业内技术对标

### 第一层：规则推理驱动的多层级语法一致性校验

**子课题3要求**：依托领域知识图谱本体，构建字段→多字段→跨记录递进式校验

| 层级 | 子课题3描述 | 业内技术 | 开源工具 | 实践方式 |
|---|---|---|---|---|
| **字段校验** | 本体元数据→语法规则→格式净化 | W3C SHACL约束验证 | **pySHACL** (Python SHACL引擎), **Great Expectations** (300+规则) | 将武器装备本体属性约束转为SHACL形状(Shape)或GE期望(Expectation)，自动校验字段格式/范围/类型 |
| **多字段校验** | 属性耦合→联合约束→隐性异常 | 跨字段约束建模 | **PALADIN** (多阶段验证), **Pandera** (DataFrame schema), **Cleanlab** (标签错误) | 挖掘"口径×类型×重量"等物理耦合关系，构建多字段联合规则，检测单字段合规但组合矛盾的记录 |
| **跨记录校验** | 主键碰撞→取值矛盾→聚合验证 | 实体消歧+参照完整性 | **VANILLA** (KG补全+约束), **Dedupe** (实体消歧), **Splink** (概率链接) | 跨记录比对武器编号/批次号，检测重复/矛盾/缺失关联 |

**工业实践对标**：
- Databricks Medallion架构：Bronze(字段校验)→Silver(多字段+跨记录)→Gold(业务逻辑)
- Monte Carlo数据质量框架：技术层(格式)→过程层(流转)→组织层(语义)

**技术路线**：
```
武器装备知识图谱(OWL本体)
    ↓ 转化为
SHACL形状定义 + Great Expectations规则集
    ↓ 分层执行
Layer 1a: pySHACL字段校验(格式/类型/范围)
Layer 1b: PALADIN多字段联合约束(物理耦合关系)
Layer 1c: VANILLA跨记录比对(主键/参照完整性)
    ↓ 输出
语法异常样本清单 + 违反规则ID + 修复建议
```

### 第二层：跨模态多粒度语义一致性与事实核验

**子课题3要求**：文本+图像+时序统一语义表示→领域知识事实核验→多粒度一致性分析

| 阶段 | 子课题3描述 | 业内技术 | 开源工具 | 实践方式 |
|---|---|---|---|---|
| **语义表征** | 多模态特征提取+上下文感知+统一语义空间 | 对比学习跨模态对齐 | **CLIP** (图文), **ImageBind** (6模态), **LANISTR** (表+图+时序) | 用CLIP编码武器图片+规格文本，用Transformer编码传感器时序，投影到统一语义空间 |
| **事实核验** | 领域本体+语义对齐+规则推理+图推理+证据溯源 | 知识图谱推理+事实验证 | **DEFAME** (多模态事实核查), **MEVER** (声明验证), **OpenKE** (KG嵌入) | 将武器装备知识图谱作为事实基准，检测"图片显示F-16但规格表写F-35"等事实矛盾，记录推理路径 |
| **多粒度一致性** | 特征层→事件层→语义层，异常阻断+冲突反投定位 | 分层多模态验证 | **FAMDR** (AAAI 2026), **DIVER** (arXiv 2026), **CrossCheck-Bench** (AAAI 2026) | 特征层:CLIP相似度; 事件层:时序异常+图片状态对比; 语义层:诊断标签矛盾 |

**已验证的实践**（本会话实验结果）：
- OLIVES: CLIP分析OCT图片 vs 16个生物标志物 vs 疾病标签 → 检出4条冲突
- DR Progression: CLIP分析眼底照片 vs HbA1c/血压 vs 诊断标签 → 检出4条时序vs标签冲突
- H4R Welding: CLIP分析焊缝照片 vs 传感器时序 vs 缺陷标签 → CLIP+IsolationForest冲突

**技术路线**：
```
三模态输入
    ↓ 分别编码
CLIP(图像) + LLM/BERT(文本) + Transformer/LSTM(时序)
    ↓ 跨模态对齐
对比学习/注意力机制 → 统一语义空间
    ↓ 事实核验
武器装备知识图谱 + DEFAME推理引擎 → 事实层面验证
    ↓ 多粒度分析
特征层(CLIP相似度) → 事件层(时序异常+图片状态) → 语义层(标签矛盾)
    ↓ 输出
冲突诊断报告 + 推理路径 + 证据溯源 + 冲突反投定位
```

### 第三层：融合业务知识的跨模态逻辑一致性校验

**子课题3要求**：专家知识形式化→时序逻辑结构挖掘→逻辑合规校验

| 阶段 | 子课题3描述 | 业内技术 | 开源工具 | 实践方式 |
|---|---|---|---|---|
| **专家知识形式化** | 工艺规范→机器可读逻辑约束 | 本体工程+知识形式化 | **Easy Dataset** (文档→结构化), **Protégé** (本体编辑), **OWL/RDF** (知识表示) | 将武器装备工艺规范(PDF/Word)用Easy Dataset解析，提取"先投料后运行""测完才能入库"等工序规则，转为可执行逻辑约束 |
| **时序逻辑挖掘** | 跨模态语义锚定+连续时间事件图谱+物理状态轨迹拟合 | 流程挖掘+时序知识图谱 | **PM4Py** (流程挖掘), **Declare4Py** (声明式时序逻辑), **MINERful** (过程规范挖掘) | 从传感器时序+操作日志中重建实际工序流程，构建连续时间事件图谱，拟合物理状态轨迹 |
| **逻辑校验** | 拓扑匹配+约束求解+因果冲突检测 | 约束满足+因果推断 | **Z3 Solver** (约束求解), **CausalML** (因果推断), **Apromore** (流程合规) | 将数据侧逻辑拓扑代入专家规则，检测"先运行后投料""未测先入库"等因果倒置，用Z3求解约束冲突 |

**工业实践对标**：
- 制造业MES/QMS系统：工艺合规校验是标准功能
- 流程挖掘(Process Mining)：PM4Py可以从事件日志重建工序，检测偏差
- 声明式时序逻辑(Declare)：LTLf公式可以表达"投料必须在运行之前"等时序约束

**技术路线**：
```
工艺规范文档(PDF/Word)
    ↓ Easy Dataset + LLM提取
结构化逻辑约束(规则库)
    ↓
多模态数据(传感器时序+操作日志+图片)
    ↓ PM4Py流程挖掘 + 时序语义锚定
数据侧逻辑拓扑(实际工序流程)
    ↓ 代入专家规则
Z3约束求解 + 因果冲突检测
    ↓
识别"先运行后投料""未测先入库"等违背工艺逻辑的因果倒置
    ↓ 输出
逻辑谬误样本 + 违背的工艺规则 + 因果冲突证据链
```

### 3.2 数据治理流程

```
原始多模态数据(表格+图片+时序+文本)
    ↓
┌─── 第一层：语法一致性校验 ───┐
│  L1a: 字段格式/范围/类型 (Great Expectations)
│  L1b: 多字段物理耦合约束 (Cleanlab)
│  L1c: 跨记录主键/矛盾 (Dedupe)
│  → 输出: 语法异常清单
└──────────────────────────────┘
    ↓ 过滤后的数据
┌─── 第二层：语义一致性校验 ───┐
│  L2a: CLIP图片编码 + LLM文本编码 + Transformer时序编码
│  L2b: 知识图谱事实核验 (图片内容 vs 规格表 vs 领域知识)
│  L2c: 特征层(CLIP相似度) + 事件层(时序异常+图片状态) + 语义层(标签矛盾)
│  → 输出: 语义冲突诊断报告 + 证据溯源
└──────────────────────────────┘
    ↓ 过滤后的数据
┌─── 第三层：逻辑一致性校验 ───┐
│  L3a: Easy Dataset将工艺规范→结构化规则
│  L3b: PM4Py从时序+日志重建工序流程
│  L3c: Z3约束求解检测"先运行后投料"等因果倒置
│  → 输出: 逻辑谬误样本 + 违背规则 + 因果证据
└──────────────────────────────┘
    ↓
治理后的高质量数据集 → 用于垂域大模型微调
```

## 四、与Easy Dataset和Data-Juicer的关系

### Easy Dataset
- **定位**: L3a层的辅助工具——将工艺规范文档(PDF/Word)转为结构化规则
- **用法**: 上传武器装备工艺标准文档→Easy Dataset解析分块→LLM提取规则→输出结构化规则库
- **不适用**: 不能做冲突检测、不支持图片/时序分析
- **arXiv**: 2507.04009

### Data-Juicer
- **定位**: L2a层的可选框架——提供CLIP算子调用+YAML pipeline编排
- **用法**: 通过custom_operator_paths注册自定义冲突检测算子
- **不适用**: 不支持时序数据、无冲突检测算子、只做过滤不做报告
- **论文**: arXiv 2501.14755

### 正确用法
```
Easy Dataset (L3a: 工艺规范→规则) 
    → 输出规则库
    → 喂入第一层(Great Expectations)和第三层(Z3 Solver)

Data-Juicer (L2a: CLIP算子框架)
    → 编排第二层的图片分析流程
    → 通过自定义算子接入冲突检测逻辑

核心治理逻辑
    → Python自研: CLIP+IsolationForest+规则引擎+Z3+PM4Py
    → 已验证可行(6个数据集跑通)
```
